# Bounded static fallback

Read when the selected investigation depends on artifacts but a native tool,
launcher or provider is unavailable. Continue only what the available material
can establish; this guide neither installs prerequisites nor replaces native
analysis with claims based on names.

## Keep the blocker and question

Record the failed operation, observed diagnostic, target identity and missing
capability. A CLI launcher missing built runtime files, absent connected tools,
client approval rejection and unavailable engine are distinct conditions.
Use [connection and recovery](connection-and-recovery.md) for the corresponding
remedy when repair is authorized. Do not rerun unchanged diagnostics at every
follow-up or build/install unrelated tooling just to avoid reporting a gap.

Keep the user's selected subsystem and exclusions. Static file and public
document reading does not require the target app to stay open. If contact,
timing or actual behavior needs runtime evidence, specify the smallest relevant
scene and measurements before requesting that runtime step. Do not launch or
attach merely because the user asks whether to keep the app open.

## Artifact identity and locations

Retain the original artifact path, byte size and digest. Parse actual headers
or container indexes with bounds checks; an inventory of stored ranges does
not establish decompression, decoded semantics or execution.

For PE data, distinguish file offsets, RVAs, preferred image VAs and live
addresses. Translate using the containing section's measured raw and virtual
starts, not a remembered constant. A located string is data, not a function
entry. Community object-field offsets are another coordinate system entirely;
do not compare them to executable file offsets as though they were addresses.

## Name search is a candidate inventory

- Bound the source region, encoding, token length and matching mode. Distinguish
  exact full literals from substrings and shared suffixes.
- Filter the broad candidate list against the selected subsystem; matches can
  belong to a different stage, editor, library or ordinary word fragment.
- Retain a few relevant locations and explain how to trace their readers or
  writers. Do not count all matches as confirmed implementation facts.
- State negative results as “not found within this query and coverage.” ASCII
  misses do not exclude Unicode/resource names or a feature's existence.

Names, enum labels and default-looking fields do not recover values, units,
algorithm selection, event frequency or scope. Seek actual code use, decoded
configuration or a discriminating runtime observation before making those
claims. A float-returning decision callback alone does not prove a particular
AI scoring algorithm.

## Public technical sources

Prefer material maintained by the original developers or the relevant tool
authors. Pin community declarations to a commit and retain source URL, digest,
read range and uncertainty. They can expose candidate types and fields without
proving the local binary's ABI or implementation. Historical design documents
also require a separate applicability statement.

If a response is truncated, inspect smaller retained views or save the bounded
source once and read selected parts; do not parse a partial preview as complete
JSON or issue the same oversized request again. Batch independent reads but
keep each result small enough to inspect; batching does not make context free.

For a public document that exceeds a reader's size limit, use an authorized
direct read with an available format parser, inspect the relevant complete
pages and preserve page locators plus concise facts. Avoid repeated mirror
requests with the same limit, unnecessary full-text copies and unrelated
software installation. A blocked network read can use formal escalation when
authorized; it is not permission to bypass the sandbox or alter client config.

## Deliver and resume

Report answers, partial answers and concrete unknowns. Distinguish artifact
observations, public rules/designs, community declarations and independently
chosen pseudocode or examples next to the claims they support. Keep fallback
provenance in its own records; only actual REA outputs have REA Evidence IDs.

List the next useful cross-reference, resource or runtime observation for each
important gap. Reopen provider recovery when its prerequisite or environment
changes, then reuse the matching fallback work. Passing a self-authored example
does not verify the original program or concurrency/persistence guarantees.
