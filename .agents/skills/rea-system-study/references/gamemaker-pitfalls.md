# GameMaker 原生制品的语义核对

这些可选案例来自 REA 源码仓库中的 Stoneshard 历史研究，属于定位陷阱的线索，不是所有 GameMaker 版本的 ABI。复用结论前以当前制品的布局、机器指令和运行时助手核对。详细实例可在原 REA 源码仓库 `docs/studies/stoneshard/00-evidence-and-scope.md` 及 10–14 模块中查找；没有这些文档时，本文件仍可独立使用。

## 格式、登记与地址

- `data.win` 中没有普通 GML 字节码 `CODE` 块时，先判断是否为原生编译；资源容器仍能提供对象、父类、事件和配置线索，但不能仅靠资源字符串恢复算法。不要反复尝试只支持字节码的反编译路线。
- 函数登记与对象/房间数量表示索引规模，不等于活跃功能数量、生成地图大小或已理解算法数量；不同分析批次存在重叠，不能直接相加计算覆盖率。
- 静态首选 VA、RVA、文件偏移和运行时地址必须分别标注。由节表做映射，检查地址落在有原始字节的节范围内；不可复用 Stoneshard 的基址、偏移常数或把静态 VA 当作 ASLR 后的地址。
- `.pdata` 可能只覆盖函数的一个片段。追踪明确入口可达的跳转与调用，不把首片段长度当成全部函数；反汇编窗口内的邻近代码也不自动属于该函数。
- RIP 引用可能指向记录的 ID 字段而非名称指针。核对结构布局与使用点；Stoneshard 某些登记的名称指针位于所引字段前 8 字节，后 8 字节可能属于相邻记录，这一偏移不可推广。
- PE 初始槽位为零不能证明运行时一直为零。未恢复初始化链时保留未知。

## 值类型与算术

- 同样的载荷零可对应数值、布尔或特殊值。记录类型标签与转换助手，区分 false、undefined、对象哨兵和数字零；不要为了易读把它们都归并为 null。
- 已遇错误：睡眠清理写入 type `0xD` 与载荷零，早期被误读为 undefined；结合真值转换助手后更正为 false。该标签只描述已分析制品，应为新目标重新确认。
- `-1`、`-4` 等值可能是对象哨兵，不能直接当成合法实例或普通坐标。自研类型可重新设计，但研究文档保留原语义和未知。
- 区分自定义取整助手与引擎原生 round。Stoneshard 已确认某个自定义助手对有限值采用 `sign(v) * floor(abs(v) + 0.5)`；原生 round 的半值处理若未确认就不能沿用该规则。NaN/无穷、溢出与其他分支未经恢复也不能由有限值例子推导。
- 属性表中的贡献值不自动等于最终命中率、伤害百分比或格数。巨魔拍地板与投石入口中的 `30*(1+0.1*d)`、`60*(1+0.1*d)` 是局部伤害输入；距离度量和公共伤害下游需要分别确认。
- 随机函数必须核对端点是否包含、采样是否放回、权重来源、失败重试及排序影响。仅有一次样本不能证明概率分布；随机整数调用不能证明整套地图生成器已恢复。

- 浮点比较助手可能带 epsilon。恢复 `<`、`>=` 等关系时同时追比较返回约定、容差来源和异常值分支；本次预告攻击的距离门槛与出生动画阈值就使用带容差的比较，不能直接写成数学上精确的严格边界。

## 事件、持续时间与所有权

- 预告攻击中的 `2 → 1 → 0 → 释放` 建立的是逻辑倒计时。还需确认创建当轮是否消费第一次，以及状态门槛/更新阶段，才能确定玩家所见“下一回合打”。
- 配置表 Duration、运行实例持续时间、创建时加一、某阶段递减与销毁条件分开写。不能看到一个 Duration 字段就推断实际 Buff 寿命或最大叠层。
- Buff 的列表移除、属性缓存失效、失效回调与对象销毁可在不同事件发生。跟踪这些事件的调用关系，确认刷新/叠层/取消/到期/宿主死亡的路径，不把一条到期路径当成全部清理规则。
- 召唤入口可能先创建出生代理，再由动画/事件创建实体。分别追踪施法者、代理、实体、寿命 Buff 与目标引用；其他召唤物可能采用直接创建路径，不能因名字相似就归为同一机制。
- 范围标记、特效、投射物、公共命中和去重表可能属于不同对象。取消时是否移除标记、释放时取当前位置还是预告位置、重复命中去重的作用域，都要沿调用链确认。

## 存档与结论修正

- 固定快照的路径、摘要与读取范围，必要时比较读取前后摘要。多个进度不同的快照不能证明离屏 NPC 连续模拟；存档字段存在也不证明当前 EXE 使用该字段。
- 压缩主体尾部未知串不要凭长度命名为 MD5 校验。算法未确认时保持未知，不能因一次哈希不匹配宣称存档损坏。
- 更正类型、公式或时间语义时，更新正式模块、证据范围与相关总结；注明旧解释被更正，避免下一轮引用早期记录覆盖新证据。历史证据不因结论修正而静默删除。
