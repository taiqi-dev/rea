# 目标路由与能力边界

只选能回答当前问题的路线，不为“通用检查”依次跑全部提供者。矩阵用于选证据，不是各格式全部支持的承诺。

## 用户提供游戏目录时

- 先确认目录存在，在该范围内有界查看入口、目录结构和与指定模块有关的文件。区分源码工程、发行安装目录和只有资源的目录；不要先假设引擎或把游戏名当可分析入口。
- 有源码就追实际源码；只有发行制品时，按实际格式选择托管程序集、原生程序、JavaScript/ASAR 或包成员路线。Unity Mono 与 IL2CPP 分开处理，GameMaker 案例只在目标确实匹配时读取。缺少元数据、密钥、符号或本机提供者时保留恢复限制。
- 用模块相关的配置、符号、字符串或资源引用找候选，再追到调用、数据读写与状态变化。报告区分“定位到实现”“只有线索”“当前证据无法确认”，名称命中不能证明模块实现，有限搜索无结果不能证明游戏不存在该模块。
- 将用户给定的游戏目录作为静态输入；不因“调研实现”就启动游戏、附加进程、修改安装文件或采集网络。实际需要这些操作时沿用适用授权，并只解决缺失的具体范围。

## 按材料选证据

| 目标/现有材料                                       | 首选证据与入口                                                   | 需要保留的边界                                                                    |
| --------------------------------------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 完整源码仓库，包括 Web、服务端、工具、游戏和库      | 普通文件、符号、配置、契约与相关测试；问题需要时追调用与状态     | 不先运行 REA readiness/setup；源码能说明可达逻辑，不能冒充某次运行已发生          |
| 原生 EXE/DLL/ELF/Mach-O，或 Unity IL2CPP 等原生输出 | REA native 路由；选择本机实际可用的 Ghidra/IDA/Hopper 等提供者   | 源码语言、元数据、符号与混淆影响可恢复程度；不安装未获授权的引擎                  |
| .NET/CLI、Unity Mono 等托管程序集                   | 托管制品检查与实际暴露的 focused 工具                            | NativeAOT/IL2CPP 不因原项目用 C# 就走普通托管反编译；依赖解析与运行加载不同       |
| JavaScript/TypeScript、Electron/ASAR、前端构建产物  | 源文件可读时正常追踪；发行应用用 JavaScript/ASAR 分析            | minify、source map 与打包树可能只有部分信息；浏览器前端不能证明未提供的服务端逻辑 |
| 网站或浏览器应用                                    | 已给前端文件/捕获先静态分析；明确选择的已有页面再按授权被动观察  | 不默认打开别的账号、提交业务请求或抓取未指定站点；页面所有权与后端权限分开        |
| APK/IPA/MSIX/AppX/ZIP 等安装包                      | 容器清单与成员身份，再按成员格式选 Android、托管、原生或脚本路线 | 能列包不等于能解密或恢复所有平台代码；解压与运行是不同操作                        |
| 固件或嵌入式镜像                                    | 格式/区域清单，必要时按授权提取，再选内部制品路线                | Linux-only 工具、外部依赖、架构与加密边界；无法识别区域仍是未知                   |
| WASM、崩溃记录、HAR/网络历史捕获等特定输入          | 当前 REA 工具集实际支持的对应离线入口                            | 不自动获取记录中的 URL 或连接设备；历史进程/请求不是当前目标授权                  |

## 通用核对

- 先查现有工具/会话身份与范围，复用匹配证据。源码工作无需二进制会话；target-free 工具不要强行开 native session。
- 必须绑定活跃目标的工具先按既有 REA 技能打开目标，工具能力以实际暴露的 schema 和 availability 为准。文档列出了某工具不等于当前服务器提供它。
- 区分客户端审批、MCP 注册、CLI 可用性、引擎依赖与目标格式。修复真实阻塞，不为任意失败反复安装所有软件。
- 提供者不可用时，资源、源码或现有本地解析可回答部分问题。记录工具版本、字节范围与解析限制，不将 fallback 结果称为提供者实测。
- 响应截断时用保留引用、分页、小范围视图或导出继续；不要重复同一大操作，也不把截断 JSON 当完整记录。
- 经授权的制品摘要也不能证明环境、账号或后端版本不变。保存器存在不证明所有对象被保存；设定随机种子不证明所有场景稳定重现。
