# Windows IL2CPP GameAssembly 地址关联验证

日期：2026-10-26，Pacific Time。承接[元数据与成员查询阶段](il2cpp-metadata-windows-2026-10-26.md)。

## 范围与边界

参考上游 [#5327](https://github.com/morluto/rea/pull/5327)，固定提交
`52d1a72af047a73b787b8935b032786a34966036`，只接入 Windows x64 PE 静态关联。
没有接入 ELF、Mach-O、ARM64、泛型方法实例或 Ghidra seed 写入。

既有 `inspect_il2cpp_metadata` 增加显式 `binary_path`；不按文件名或邻近目录自动选择 DLL。
元数据与二进制各由现有稳定文件读取和资源所有者持有，完整结果保留两个文件的路径、SHA-256
和长度。PE 映像基址与可执行文件映射由已有 PE 格式读取者解析，IL2CPP 不另起 PE 解释器。
模块名、方法数、元数据 token、指针槽和注册表共同建立静态关联。

`method_addresses` 与元数据方法索引对齐：`code` 有首选虚拟地址与 RVA；`no-body` 表示
观察到零槽，不能推断泛型或其他生成代码不存在；`unknown` 表示方法归属无法确认。返回、字段
和参数类型从二进制类型表派生，版本 27 的同号布局存在 byref 差异，因此保留类型索引并将名称
记为未知。查询使用现有 `inspect_analysis_view`，保留第二个输入的 `binary_source`。

二进制输入上限 1 GiB，报告上限 64 MiB；名称索引、候选数组和类型渲染有单独的固定工作区。
容量失败携带其生产边界的具体限制。取消在读取、关联及命名检查点生效；失败保留已观察的来源
身份，未成功的关联不声明完整覆盖。没有目标执行、DLL 加载、进程附加、修改或保护恢复权限。

## 复核与修复

- 三个受控 PE 冲突映射先复现了错误接受。注册表扫描的原始字节只能作为候选；模块记录、
  注册字段、元数据注册记录、名称和折叠注册的指令来源均须通过格式所有者的唯一映射校验。
  五类来源冲突均已加入拒绝回归。
- 导入 Evidence 也验证模块索引、唯一图像归属及方法数，拒绝不可能的关联。方法数前缀只计算
  一次，避免图像范围与类型数量相乘的验证成本。
- 源码测试的首轮新增断言混用了内部错误 tag 与公开错误 code；公开诊断路径位于
  `details.issues`，按既有契约修正测试，没有改变错误投影。
- 首轮 Windows 门禁的措辞检查命中描述中的“No target execution”；按现有例外表记录已核实
  的只读语义，没有授予执行权限或关闭该检查。最终门禁通过。

## 真实 producer 与 Ghidra 消费者

输入来自 Cpp2IL 固定公开
[Simple_2022_3_35 样本](https://github.com/SamboyCoding/Cpp2IL/tree/b5ad444b82267cb1e4b88b8b373c008105bdea52/TestFiles/Simple_2022_3_35)，
只放在忽略缓存中，不分发、不运行。元数据版本 31、1,892,268 字节；二进制 6,481,920 字节。
二进制由生产 reader 记录的 SHA-256 为
`68220f503869134ab966f9d6c2eee04d98446638f09d8cac0c7a1fe073e90b65`。

最终源码实测：36 个模块、6,472 个二进制类型、12,409 个方法，其中 10,928 个有代码地址，
1,481 个为零槽，未知归属为 0。独立 v31/PE 字节 oracle 逐条核对全部方法的 token 槽、地址、
RVA 和可执行映射；CLI/MCP 完整结果及保留查询一致，两个输入字节未变。

同一验证继续打开 SHA-256 一致的 DLL，真实 Ghidra 回读方法索引 0 `GetRandomBytes`：
首选地址 `0x1801abd10`，RVA `0x1abd10`，文件偏移 1,748,752，16 字节与源文件一致。
显式关闭目标、MCP 会话与 transport 均成功。没有创建函数、改数据库或扩大 Windows P0 权限。

该次 CLI 约 1,100 ms，完整输出 4,305,655 字节，摘要 4,521 字节；这是单次样本测量，
不是受控冷暖对比、token 节省或性能提升结论。没有测量 CPU 时间与进程家族峰值内存。

## 限制与交付

- 名称/数量/token 一致是结构证据，不能证明两个文件来自同一构建。地址也不是 ASLR 后的运行时地址。
- 真实 producer 覆盖限于此 v31/x64 PE 样本；其他元数据布局由受控样本验证，其他原生平台被明确拒绝。
- 类型名称是类型表的 C# 风格呈现，未逐条对照 PDB 或原始托管签名；泛型方法实例、完整签名与运行时行为为 Not Run。
- 真实模型选工具任务与交互式用户验收为 Not Run。SDK 验证不替代 agent 可发现性评价。
- Ghidra 目标关闭与身份回读不等于全宿主进程家族证明；Hosted CI 与本机结果分开报告。
- 既有 REA/MCP 长驻会话需重启后才加载新工具。主检出原生组件的既有占用问题没有通过终止其他会话绕过。

证据日志位于 `.cache/upstream-il2cpp/`；必要身份与验证沿用本会话的现有授权，没有新增独立哈希工具。
