# Windows 资源关闭所有权验证

日期：2026-10-26，Pacific Time。基线为 `ad9bfa734`；本记录与实现一起提交。

## 实现与上游范围

参考上游 [#5772](https://github.com/morluto/rea/pull/5772)，合并提交为
`43ac3d1857b79c5c210a7cfb15de3d645826cf57`。仅按当前 Windows fork 的所有权边界移植，未整体合并上游。

- `CloseHandle` 失败后保留精确值；后续探测显示 open 也不能证明数字仍指向同一对象，因此禁止再次关闭或用于 I/O。只有确认不在句柄表中才释放记录。移动、替换和析构不得丢失未确认的所有权。
- 普通所有者仍持有未关闭的资源；析构时的幸存值交给进程生命周期保留者。未确认的关闭继续返回失败，不把保留资源描述成清理完成。
- 私有运行目录保留读取后关闭失败的文件 wrapper，在目录遍历前重试其关闭；读取和关闭同时失败时保留两个原因。原生快照保留失败的来源/写入句柄，已完成的字节结果保持原有含义。
- 目录遍历完成与根/父句柄关闭分阶段记录。根或父句柄关闭失败时从关闭阶段继续，不重复遍历已完成或句柄已失效的目录。遍历中的失败句柄也留在该运行目录上。
- 进程确认退出、管道结束和 Job 成员归零后，先结束本地流，再释放原生资源。部分释放失败后的重试仅调用 close，不通过已释放的 job/process 重新 kill 或 poll。

当前 fork 的 native pipe reader 与上游不同，保留现有读取方式，仅增加关闭所有权处理。没有引入上游仅适用于 POSIX 的继承管道测试或 Darwin 注释；普通 `execFileOutput` 的进程家族能力没有扩大。未进入 IL2CPP，也未修改公共 CLI/MCP schema、目标执行权限或 Ghidra Windows P0 的修改权限。

## 边界复核

原生 `Handle` 是句柄关闭判断的唯一持有者；TypeScript 保留 opaque wrapper，不重新解释 Win32 句柄数字。`WindowsPrivateRuntime` 和 `WindowsOwnedProcess` 继续负责各自清理生命周期；既有进程监督、Evidence 和快照写入者保持原有权威。

本次复核重点包括：失败后句柄值被复用的风险、替换/析构时丢失所有权、目录遍历与根关闭之间的重试阶段，以及流结束和原生释放的先后顺序。没有新增全局配置、进程查杀权限或生产故障注入入口。
