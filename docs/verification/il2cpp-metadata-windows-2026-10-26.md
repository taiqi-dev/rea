# Windows IL2CPP 元数据与成员查询验证

日期：2026-10-26，Pacific Time。本记录覆盖元数据阶段；随后原生地址关联的验证单独记录。

## 范围与所有权

按本 Windows fork 适配上游 [#3807](https://github.com/morluto/rea/pull/3807)
和 [#5326](https://github.com/morluto/rea/pull/5326)，参考固定提交
`21e0c580e7456af311ecfb12af8fc2531b429606`，未整体合并上游或升级依赖。

`inspect_il2cpp_metadata` 和 CLI `inspect-il2cpp-metadata` 只读显式选定的
`global-metadata.dat`，支持版本 24、27、29、31、39 的已声明布局。返回镜像、类型、
方法、字段、属性、事件、参数和字符串。MCP 默认保留完整 Evidence 并返回摘要，后续
`inspect_analysis_view` 的 `il2cpp-metadata` 查询支持批量索引、精确名称、所有者、
字段投影和分页。CLI 摘要要求先导出完整 Evidence，禁止覆盖既有文件。

格式解析持有索引、成员范围及所有者关系；现有 `ArtifactResourceScope` 和稳定文件读取边界
负责源文件与清理；现有 Evidence ledger 负责保留，查询从不可变父记录派生。没有第二个会话、
文件系统缓存或 Evidence writer。取消、源文件变化、损坏格式、未知版本、资源限制和清理失败
分别处理。输入上限 256 MiB，编码后的完整报告上限 64 MiB；记录数量、文本、UTF-8/JSON
扩张在相应分配与序列化前检查，每个 reader 同时只接收一次读取。

首次测试发现新视图直接引用视图聚合模块会形成循环依赖；共享错误与操作名称移到同层独立入口，
原有导出保持兼容。没有改动其他视图的解析语义。

## 限制

- 其他 metadata 版本由受控布局样本验证，真实 producer 验证为 Not Run；版本 24 不推断早期同号布局。
- 真实模型选工具任务、token、CPU 时间及进程家族峰值内存未测量。SDK 与 schema 验证不能替代 agent 可发现性评价。
- 这个阶段不恢复原生地址、成员类型、方法签名或运行时行为。加密、保护恢复和目标执行不在范围内。
- 主检出目录仍可能有既有 REA/MCP 会话加载旧组件；隔离检出的验证不代表旧长驻进程已经热更新。

日志保留于 `.cache/upstream-il2cpp/`。必要身份与验证使用本会话已授权的现有流程，未新增独立哈希工具。
