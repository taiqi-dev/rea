# Tiny Glade：水域笔画、河床与河岸

这轮从本地发行版确认了一条具体机制：**绘制笔画 → 平滑折线 → 512×512 水域栅格 → 多通道模糊 → 水域驱动地形高度与地表颜色**。河流形状可以作为沿笔画形成的水域解释；目前没有恢复自动选择源头、河网拓扑、水量守恒或水流侵蚀算法。

本文沿用 [制品身份](00-evidence-and-scope.md)。CPU 地址为 RVA，SPIR-V 偏移为原 `.precomp` 文件偏移。指令事实、公式推导与构造算例分别注明；方法、摘要和覆盖见 [水体证据账本](09-tiny-glade-water-evidence-ledger.md)。植物与水面见 [水生植物及水面](08-tiny-glade-water-vegetation-and-surface.md)。

## 1. 先把三个不同对象分开

| 对象 | 已确认表示/操作 | 不能混同为 |
| --- | --- | --- |
| 当前笔画 | Vec3 点列、绘制状态、当前/上一次脏块范围 | 河流流体粒子 |
| 水域 | `WorldRaster<512>` 与 GPU `water_mask` 的 R/G/B 通道 | 每像素水深或速度场 |
| 可见水面 | 水平面顶点和接收时间、噪声、涟漪源的片元程序 | 动态河床网格 |

`solidify_fluid_into` 处理进行中的笔画点列。这里的 `fluid` 名称不支持“正在运行流体仿真”这一结论。水面程序中的时间与涟漪也不能单独证明水量或速度模拟。

## 2. 输入怎样成为平滑笔画

发行版 `system_water::draw_water::draw_water`，RVA `0x2053590`，1650 字节，处理有效编辑模式和笔刷尺寸，水域分支调用 `DrawState::update_bounded_by_glade`（调用处 `0x2053966`）。具体模式枚举的全部取值尚未恢复。该入口同时具备擦除路径，不应把两条路径的光标投影或尺寸换算混在一起。

入口在 `0x2053B42` 直接调用：

```text
draw_raster<WaterRasterStagingSsbo, WorldRaster<512>, ...>
目标 RVA 0x2878E40
```

在持续绘制分支中，先计算光标当前位置与上一点的三维欧氏距离。距离不大于约 `0.001` 时跳过本分支的新增栅格工作；更大时增加点并调用 `ActiveRasterStroke::resample_and_smooth`。这是点输入过滤，不能据此给出画面更新帧率。

该辅助入口 `0xBD60F0` 先复制已固定的点，再处理进行中的点段，最后调用 `smooth_in_place<Vec3, UniformCurveSmoother>`，**轮数 10、闭合标志 0**。进行中点段的全部重采样细节尚未恢复；已确认的平滑如下。

每轮保持首尾点不动，内点更新为：

```text
P'i = Pi + 0.5 × (0.5 × (P(i-1) + P(i+1)) − Pi)
    = 0.25 P(i-1) + 0.5 Pi + 0.25 P(i+1)
```

三维分量分别计算；少于 3 点或轮数为 0 时返回。每轮使用该轮开始时的邻点，标量与向量化分支保存旧邻点，不把刚更新的前一点再次用于同一轮。证据为 `0x19A60D0`，标量内点算术 `0x19A66C0–0x19A6704`，轮循环 `0x19A64B0–0x19A64BC`；调用参数位于 `0xBD61ED–0xBD6208`。

**构造算例。** 前置点列为 `(0,0,0)、(1,0,0)、(1,0,1)`。第一轮中点变成 `(0.75,0,0.25)`。10 轮后为 `(0.50048828125,0,0.49951171875)`，两端不变。这个例子解释转角为何被磨圆；它是公式演算，没有执行游戏函数。

## 3. 世界坐标怎样落到水域栅格

`WorldRaster::rasterize_stroke<512,...>`，RVA `0x2879E70`，2311 字节，把点的 XZ 分量映射为：

```text
q = 512 × (XZ / 130 + 0.5)
```

因此世界 XZ 的 `[-65,65]` 对应栅格坐标 `[0,512]`。这不表示坐标 512 是合法像素索引；栅格裁剪与覆盖由下游处理。映射指令位于 `0x287A174–0x287A25C`。

该函数把首点和后续点组织成不同标签的路径命令，再调用 **Zeno 的 Mask::blend_into**，不是在这个入口里逐个生成河流三角面。输入少于两个 Vec3 点时，栅格化入口返回。

调用者传来的尺寸值 `r` 先变成 `512r/130`，随后加倍为 `2×512r/130`，写入 Zeno 构造区域。这个数值符合世界尺寸转像素宽度的作用，但当前没有完整证明 Zeno 构造字段、端帽、接头枚举与 CPU 像素合成回调，故不把 `r` 无条件称作可见河道半径，也不把包内另一笔刷的硬编码半径套到这里。

**构造算例。** 上节平滑后的中点映射到约 `(257.971154,257.967308)`；输入尺寸 `r=1` 时，加倍后的像素尺寸为约 `7.876923`。这些是映射结果，尚不是河岸边界或最终水面宽度。

## 4. 当前笔画与已提交栅格怎样分开

持续编辑路径不是直接在同一份结果上无限重复叠加整条笔画。已确认直接调用顺序为：

1. 根据平滑笔画建立本次脏块，并合并本次与上一次笔画影响范围。
2. `copy_composite_to_scratch<512>`：已提交结果复制到工作区。
3. `rasterize_stroke<512,...>`：当前整条笔画栅格化到工作区。
4. `copy_to_staging<512>`：所选结果复制到水域 staging 数据。
5. 提交分支调用 `commit_scratch_to_composite<512>`。

调用位置分别见 `0x2878F49–0x2878F85`、`0x2879307`、`0x2879344`、`0x2879382`、`0x28794F5`。这支持“已提交状态 + 当前笔画预览”的职责解释；所有状态枚举、撤销提交和取消分支尚未完整恢复。

`draw_water` 还发送与地形重算关联的消息，并调用 `ScheduledTerrainReadback::on_terrain_modified`（`0x2053AED`）。PDB 的泛型系统签名提供 `RecalculateHeightMapCmd` 等消息参数，实际指令提供写入及调用位置。消息消费的全部排序与 GPU 同步仍需继续贯通。

进一步追到的 `upload_raster_staging_to_texture<WaterRaster>`，RVA `0x5E5700`，在 ready 标志成立时取得 `WaterRasterStagingSsbo`，绑定实际 shader `country_core/upload_cpu_raster:main`，把上传 ready 清零并设置待模糊标志。这补上 CPU 栅格与 GPU 纹理之间的桥；当前路径不依赖上文尚未贯通的 `draw_water_mask`。

纹理身份还通过调用者核对：`tiny_glade::render_loop::render_world`（RVA `0xF9F00`）在 `0xFA110` 写入参数 `r8b=0x12`，`0xFA113` 直接调用上述上传函数。该 preset 与后续四次模糊使用的 `0x12` 一致，因此这里的上传与模糊不是只靠资源名称拼接。选定调用上下文已理解，整个渲染函数未完整恢复。

staging 以 8×8 像素块组织，每块 64 字节。CPU 对候选脏块取 8 行、每行 8 字节，与保存的块哈希比较；相同时去掉该脏位，不同时复制连续 64 字节并更新哈希。这里不是逐像素比较，哈希相同也不能当作数学上的字节相等证明。已选定 GPU 上传入口仍覆盖完整逻辑 128×512 范围，每个 invocation 从 u32 拆四个 u8，以 `byte/255` 向相邻像素写 `(value,0,0,0)`；没有在这个 shader 中看到按脏块提前退出。CPU 的脏块优化与 GPU 全图重写是两种不同操作。

构造输入字 `0xFF804000` 依次拆成 `[0,64,128,255]`，写入 R 约为 `[0,0.2509804,0.5019608,1]`，G/B/A 全部清零。实际纹理格式含量化，不能把小数当成逐位读回结果。

## 5. 模糊不是一个无差别的操作

`water_rasterize_from_cpu`，RVA `0xB31C80`，在选定修改标志触发时调度四次 `gauss_blur_mask`。GPU 程序通过 uniform 名与实际指令确认：

```text
K = ceil(2σ)
w(i) = exp(−i² / (2σ²)), i = −K ... K
result = Σ(valid q) w(i) source(q) / Σ(valid q) w(i)
```

水平步骤沿 X 采样，固定读输入 **R**；垂直步骤沿另一栅格轴采样，固定读输入 **G**。输出选择 1 仅更新目的纹理 **G**，选择 2 仅更新 **B**，其余通道保留。不能因为步骤写 B 就推断下一步会读 B。

边界采用有效邻域截断后重新归一化。负坐标转换成无符号后不满足 `<dims`，被排除；不是重复边缘采样，也不是补零后保持完整权重和。模糊输出的 SPIR-V image 类型为 `Rgba16f`，最终效果含半精度量化。

位置：`gauss_blur_mask.precomp` blob 0，起点 `0x66`；核宽 `0x586–0x6B2`，坐标/边界 `0x722–0x8BA`，权重与读通道 `0x8D2–0xABA`，写通道 `0xB02–0xCE6`。

CPU 实参和纹理交替关系已逐项联合核对，令 M 为实际 preset `0x12` 水域纹理、T 为临时纹理：

| 顺序 | 输入 → 输出 | σ | 方向 | 实际读取 → 实际写入 |
| --- | --- | --- | --- | --- |
| 1 | M → T | 10 | 水平 | M.R → T.G |
| 2 | T → M | 10 | 垂直 | T.G → M.G |
| 3 | M → T | 30 | 水平 | M.R → T.B |
| 4 | T → M | 30 | 垂直 | T.G → M.B |

因此，忽略每次写入的半精度舍入，最终 **G=V10(H10(R))，B=V30(H10(R))**。第三步写出的 `T.B=H30(R)` 没有被第四步读取。这里的 H/V 表示沿两个栅格轴的截断归一化卷积。

这是本版 CPU 实参、绑定和 shader 读通道联合得到的非常规结果；不是用常见做法补出来的“σ30 对称模糊”。尚未查到其他消费者怎样使用 T.B，不能扩大为整个程序的无效步骤或断言开发者意图。核对位置与源记录见 [账本](09-tiny-glade-water-evidence-ledger.md)。

由此推导：对于沿 X 无限延伸、只随 Z 变化的理想条带，G 使用 σ10、B 使用 σ30 的横截面；若条带沿 Z 无限延伸、只随 X 变化，则两个最终通道都继承水平 σ10 的横截面。这是卷积模型的方向性例子，不是游戏实际画出的河流。

**构造算例。** `σ=10` 得到半径 20、41 个采样位置；`σ=30` 得到半径 60、121 个采样位置。若与 130 世界单位/512 像素对应，10 像素约 2.5391 世界单位，30 像素约 7.6172。常量值 1 的图在有效边界上仍输出 1，因为剩余权重重新归一化。这个结果不能替代真实半精度 GPU 测试。

## 6. 河床确实由水域改变地形

`terrain_editing/rasterize_terrain_stroke.precomp` blob 0，起点 `0x98`，在地形笔画聚合后读取水域 R/G/B。**R 不为 0** 时进入以下局部水域高度分支：

```text
tG = smoothstep(0, 0.3, G)
h1 = mix(h_stroke, −0.04, tG)
tB = smoothstep(0.5, 1, B)
h_body = mix(h1, −0.125, tB)
```

`smoothstep(a,b,x)` 是 `t²(3−2t)`，其中 `t=clamp((x−a)/(b−a),0,1)`；`mix(a,b,t)=a(1−t)+bt`。原 f32 常量约为 `0.3000000119` 和 `−0.0399999991`，正文的小数是便于阅读的表达。

该栅格 pass 输出高度的单位转换与编码为：

```text
H_world = 20 × h_final
encoded = (H_world + 2.5) × 0.0377358496
        ≈ (H_world + 2.5) / 26.5
```

所以局部浅水目标为 **世界 Y = −0.8**，深水目标为 **−2.5**。证据：取通道 `0x13E4–0x1450`；水域分支 `0xCD14–0xCDD4`；输出尺度及编码 `0xFC18–0xFC9C`。另有地形读取代码使用 `mix(−2.5,24,encoded)` 解码，代数上吻合。第四轮进一步确认后续高度模糊和地表顶点的岸边修正：本段目标是中间栅格结果，不能直接称为最终可见地面；完整分层见 [水面绘制与岸边过渡](10-tiny-glade-water-render-pipeline-and-bank-transition.md)。

这说明水体不只是覆盖一个蓝色平面：**水域数据也参与河床地形高度重建**。边界条件也已确认：只有 `abs(X)>60` 或 `abs(Z)>60` 时才进入外层背景/边界过渡（`0xE340–0xE3BC`）。中央 `[-60,60]²` 且 R≠0 时，`h_final=h_body`，上述公式直接决定输出世界高度；外层约 5 世界单位边带还有背景、边界及噪声混合，不能套用中央公式。R 为 0 也有另一条基线/噪声路径。

**构造算例。** 令 R=1、笔画聚合高度 `h_stroke=0.1`、G=0.15、B=0.75，则两次 smoothstep 都约为 0.5：

```text
h1 = (0.1 − 0.04)/2 = 0.03
h_body = (0.03 − 0.125)/2 = −0.0475
局部世界高度 = 20 × (−0.0475) = −0.95
```

G 到 0.3、B 到 1 时，目标为 −2.5。若构造位置在中央范围内，上述 −0.95 是该 shader 的高度结果；位于外层边带时，还必须计算后续过渡。两者都不是游戏内实际读回轨迹。

## 7. 河岸不只改变高度，还改变材质

`terrain_editing/floor.precomp` blob 1，`0xA296–0xA3D6`，读取水域 G 并混入泥土颜色：

```text
W = sample(water_mask).g
mud = sample(material_data.mud, 10 × uv).rgb
color = mix(color_before, mud, smoothstep(0.4, 0.5, W))
```

W≤约 0.4 时这个局部混合权重为 0，W≥0.5 时为 1；W=0.45 时约为 0.5。后面还有湿润带与噪声处理，这不是完整地表材质公式。没有提取或复制泥土贴图。

`terrain_derivative.precomp` 则根据解码后的相邻高度计算中心差分：

```text
dx = (H(x+1,z) − H(x−1,z)) / (2 × 130 / width)
dz = (H(x,z+1) − H(x,z−1)) / (2 × 130 / height)
slope = length(dx,dz)
rocky.r = smoothstep(0.75,1.25,slope)
```

它直接读地形而不读水域。若消费的是水域修正后的高度，就能把新河岸坡度带入岩石遮罩；**这项跨步骤关系是数据职责推导，实际绑定与调度尚未完全贯通**。边界样本会 clamp，却仍使用两像素分母，不能解释成专门的单边差分。

## 8. 包内还有几条容易误读的路径

**另一水域绘制 shader。** `water/draw_water_mask.precomp` 已确认半径 2 的二值圆形笔刷；虽然先计算距离衰减，随后以 `d>0` 二值化。add==1 优先使用 max；subtract==1 使用 `max(old.r−brush,0)`。它的存在不证明上述 CPU 笔画链调用它。本轮没有建立它的当前调度，故不把“固定半径 2”当成游戏所有水域笔刷算法。

**水与路径相交的网格。** `water_x_paths.precomp` 顶点程序按 primitive center 的水域 G>约 0.2 筛选，结合路径中心/顶点样本及建筑遮罩改变 Y。无效分支写 NaN。输入网格、primitive center 生产者和实际调度未恢复，不能仅凭文件名断言它是桥梁或完整河岸生成器；跨驱动 NaN 的实际结果也未经验证。

其中已恢复的有效分支高度为：

```text
Y = Y_mesh − 3
  + 1.5 × P_center^0.2
  + 1.5 × P_vertex^0.2 × (1.2 + mix(−0.1,0.3,random_center))
  − smoothstep(0.35,0.6,building_vertex)
```

水域按图元中心取样，路径同时按中心和顶点取样，建筑按顶点取样，不能把三者看成同一个坐标下的混合。`random_center` 来自中心坐标整数转换及位操作，选定序列没有时间输入。证据为 blob 0，`0x1009–0x183D`。构造输入 `P_center=P_vertex=1`、建筑值 0、随机值 0.5 时，Y=Y_mesh+0.45；这仅解释局部变形，不建立实际桥梁高度或碰撞规则。

**水域读回表示。** `water/read_water_mask.precomp` 每个 invocation 处理同一行 32 个像素，将 G>0.5 与 G>约 0.2 分别打包为两个 u32。比较是严格大于，低阈值位图包含高阈值位图。512 宽硬编码保证每 32 位不会跨行；若覆盖完整 512×512，则每份有 8192 个 u32、32768 字节。这是条件容量推导，未确认实际分配与所有消费者，不能仅凭 `clutter` 名称称为导航图。

给定前六个 G 值 `[0,0.2,0.21,0.5,0.51,1]`、余下为 0，高阈值字为 `0x30`，低阈值字为 `0x3C`。例子的 0.2 按 shader f32 常量表达，恰等于阈值不置位。证据为 blob 0，`0x426–0x70E`。

## 9. 可用于独立设计的规格

以下是根据已确认职责重新组织的自研建议，**不是恢复的原作生产代码**：笔画状态独立于已提交栅格；连续编辑从已提交状态重建预览；记录前后影响范围，更新旧位置也影响到的脏块；以明确命名的软遮罩驱动河床目标、泥土带和植被资格；地形形状与水面波纹分开更新。

自研时要自行选择河宽、软边尺度、地形混合和世界边界行为。尤其应明确水平/垂直读取的通道，不能把本版观察到的写 B/读 G 差异默认为自己的设计需求。

## 未做与风险

本篇已回答：当前选定入口的点平滑、世界栅格映射、多通道高斯算术、局部河床目标和泥土混合。部分回答：编辑提交、地形失效及完整河岸生成链。第四轮新增的外缘公式、地表二次修正与水面深度/反射覆盖证据见 [10](10-tiny-glade-water-render-pipeline-and-bank-transition.md)。全部 CPU coverage 回调、完整后续地形算法、自动河网或水流物理仍未回答。

未做：没有启动、附加或修改游戏，没有读取私人存档；没有运行 GPU、性能测量或原作行为对照。原因是本轮继续发行制品静态研究。风险：局部公式并非最终全场景公式；f32/半精度、取样和边界可影响结果；同名资源仍需实际绑定证明。没有发现需要修改原游戏的事项。
