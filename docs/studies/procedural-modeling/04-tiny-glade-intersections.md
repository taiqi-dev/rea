# Tiny Glade 建筑相交：结构边界、墙洞与局部重建

发行版存在多种针对部件的相交处理。可以直接确认墙坐标转换、矩形洞口扣除、石砖的局部分割入口，以及独立生成的接缝砖梁；还没有恢复一份覆盖整栋建筑全部部件的拓扑布尔流程。本文把已贯通的局部算法与尚未贯通的连接分开说明。

配套阅读：[屋顶形状](03-tiny-glade-roof-shapes.md)、[接缝显示](05-tiny-glade-seams.md)、[证据账本](06-tiny-glade-evidence-ledger.md)。所有 CPU 地址为同一 EXE 的 RVA，正文算法为指令推导后的独立表述。

## 1. 先求建筑二维轮廓的接触点

`detect_intra_shape_corners`，RVA `0x2197140`，直接调用形状求交入口 `intersect_shapes<closure_env$4>`，`0x10C7970`，4726 字节。后者按形状 tag 选择矩形/矩形、矩形/圆、圆/圆路径。分类由具体构造器和运算支持，没有恢复完整 enum 声明。

求交前主检测器在 `0x21980E4/0x219810B` 把两轮廓扩张 `0.28`。另一些包含检查使用 `0.05`；两者不能合成一个统一 epsilon。高度区间还有 `B.min<=A.max && A.min<=B.max` 的筛选。以上是实际指令常数，单位及设计原因未知。

### 矩形与矩形：局部空间 slab 求交

将一栋矩形变到自己的局部坐标，得到中心为零的 AABB；另一栋的边也变入该空间。矩阵逆在 `0x10C7A95–0x10C7AC3` 有行列式倒数运算，随后对每条边调用 `Aabb2::intersect_ray`，`0xDEEA90`，56 字节。

该函数 `0xDEEAA2–0xDEEAC3` 实际执行减、除、min/max，普通非退化输入下是 slab 算法：

```text
t0 = (box_min-origin)/direction
t1 = (box_max-origin)/direction
t_enter = max(min(t0.x,t1.x), min(t0.z,t1.z))
t_exit  = min(max(t0.x,t1.x), max(t0.z,t1.z))
```

辅助 `is_hit`，`0xDEE720`，要求 `t_exit>=0 && t_enter<=t_exit`；调用者把候选 t 限制在 `[0,1]`，使无限射线结果成为有限边段上的交点。世界点通过 `origin+t*direction` 得到，再交给同一个交点处理回调。零方向、共线和浮点退化的完整处理尚未恢复。

### 矩形与圆：边段的二次方程

矩形边的方向是 `D=P1-P0`，调用 `Circle2d::intersect_ray`，`0xDEF380`，197 字节。指令构成：

```text
a = dot(D,D)
b = 2*dot(D,O-C)
c = dot(O-C,O-C)-r*r
delta = b*b-4*a*c
t± = (-b±sqrt(delta))/(2*a)
```

方向长度为零或 delta<0 返回无结果；调用者筛选根在 `[0,1]`，然后计算交点。这里只确认这条边段求交路径，不覆盖所有曲墙。

### 圆与圆：两个解析交点

调用 `Circle2d::intersect_circle`，`0xDEF750`，209 字节，其运算在 `0xDEF788–0xDEF819`：

```text
d = length(C2-C1)
d>r1+r2 或 d<abs(r1-r2)：无交点
a = (r1*r1-r2*r2+d*d)/(2*d)
h = sqrt(r1*r1-a*a)
Q = C1+(a/d)*(C2-C1)
P± = Q±(h/d)*perp(C2-C1)
```

该 helper 内没有观察到 `d=0 且 r1=r2` 的单独拒绝；不能自行补上一条合理的处理再当成发行版事实。更上层是否已经过滤重合圆未确认。

**独立演算。** 两圆原半径 1.72，中心 `(0,0)` 与 `(3,0)`。按已观察的 0.28 扩张后半径为 2，解析式得到 `(1.5,±1.3228756)`。这条路径从二维轮廓得到交点，无需通过三角网格扫描；它不证明其他部件也都这样求交。

## 2. 一个平面交点还要裁成有效高度段

求交入口调用交点回调，RVA `0x10C95A0`，2818 字节。回调在 `0x10C961F` 采样地形高度，在两面墙的曲线上取得段索引和插值比例，随后对高度数组做 `v_i+t*(v_(i+1)-v_i)`。每次索引有边界失败路径。

有限正常输入可归纳为：

```text
bottom = 插值得到第一面墙 +0xf8 数组的值
bottom_adjusted = bottom+(bottom>0 ? 0.46 : 0)+captured_offset
lower = max(terrain_height,captured_lower,bottom_adjusted)
upper = min(插值墙A +0xe0 数组 - 0.67*flagA,
            插值墙B +0xe0 数组 - 0.67*flagB)
lower>=upper：放弃这个交点
```

这是 `0x10C96F9–0x10C97EB` 的指令归纳。数组偏移和捕获参数尚无可靠原始字段名，不能强行指定成某种地基对象。NaN 选择还包含额外指令，以上公式不涵盖非有限输入。

回调先加入 lower/upper，再在条件满足时读取两墙的 `stone_foundation_y`，只把严格处于区间内部的值加入分界。随后调用尚未完整恢复的辅助函数，推断负责排序；直接确认后续以绝对差不超过 `1.1920929e-7` 的方式去重，并拒绝非递增子区间。这个数是当前 f32 常量，不能当一般工程几何容差。

每个子区间的中点高度用于 `stitch_kind_for_walls_at_y`，`0x2198E80`，329 字节。它返回两墙的 0/1/2/3 标签，并计算梁标志 `tagA>=2 || tagB>=2`。材质/风格的解释有上下文支持，但完整 enum 名称未恢复。

成功时写出步长 64 字节的接缝描述，包含 XZ 位置、高度端点、两条方向、两墙 ID、标签和梁标志。这里的记录布局来自指令访问，不能冒称已恢复完整 Rust 类型。检测器还处理 dirty 墙和保留/清理相交缓存；本轮未恢复全部失效与帧调度契约。

## 3. 相交区域需要转换到部件的坐标空间

建筑在三维世界中相遇，但墙的排列和洞口用沿墙的周长坐标与竖直高度处理。这种表示允许同一个洞口规则作用于不同朝向或闭合轮廓；这个职责解释是推导，具体转换由下面的直接调用支持。

`add_hole_at_shape_intersection`：RVA `0x2198FD0`，436 字节，函数字节 SHA256 `ef2c1c307c8cb73f0b6c5c2185ec11bc3f1b0ab88ba00041d8be3ffa19881cc8`。PDB 映射 `detect_intra_shape_corners.rs:838`，这是编译路径记录，不是已获取源码。

**发行版指令及辅助函数。** 在有限、正常输入路径上：

1. 取相交区域竖直端点 `y0,y1`，计算 `ymid=(y0+y1)/2`。
2. 两个 XZ 边界点各插入 `ymid`，调用 `utils::swizzlers::impl$1::xvy`，RVA `0xDF4540`。
3. 分别调用 `WallSpaceCoord::from_world_space`，`0xDEA520`，得到沿墙坐标 `u0,u1` 及高度。
4. 调用墙空间 `subtract`，`0xDEA7C0`。闭合墙使用周期差值；后续发现负跨度时再加周长 `L`，形成向前跨度 `w`。
5. 调用 `project_clamp`，`0xDEA610`，将 `u0+w/2` 投影回合法墙空间，作为洞口中心。
6. `w>0` 时写出中心、宽高及分支 tag 1；否则返回 tag 5。没有恢复这些 enum 值的原名称，不能据数字指定业务错误名。

输出四个 float 对应墙空间中心、中心高度、跨度和 `y1-y0`。指令还有 `0 × 某个中间值` 的序列；正常有限值下可消去，遇 NaN/Infinity 时不能照这个简化式推断行为。

**独立演算。** 闭合墙周长 10，相交边界在 `u0=9.5` 与 `u1=0.5`，竖直范围为 `[2,4]`。直接做普通减法会得到 -9；周期处理后向前跨度为 1，中心回绕到 `u=0`，中心高度为 3，洞高为 2。这解释了为什么跨墙轮廓起点的相交不应变成一个几乎绕整圈的洞。例子验证数学路径，没有执行游戏。

## 4. 石砖先筛相交，再交给局部分割

`split_brick_by_holes`：RVA `0x815BE0`，622 字节。`0x815CD8–0x815CDB` 和 `0x815D8D–0x815DA8` 可见洞与砖的边界测试，并在命中后直接调用 `resolve_hole_overlap`，RVA `0x146C450`。

`Aabb2::intersects`，RVA `0xDEEA30`，57 字节，指令确认普通有限值下包含接触边界：

```text
A.max_x >= B.min_x && B.max_x >= A.min_x
&& A.max_y >= B.min_y && B.max_y >= A.min_y
```

入口还对洞建立扩张后的边界用于局部处理，并维护两个并行 slice 的已消费前缀。这里已经可以确认：石砖处理是对局部砖集合及洞区域的操作；没有从函数名称推测为任意三角网格求差。

`resolve_hole_overlap` 的第一个输入是四 float 的二维 AABB，宽高 getter 分别为 `0xDEEC10` 与 `0xDEEC50`；第二输入中的元素按 40 字节访问。本轮没有完整命名这 40 字节中的所有属性。

## 5. 石砖分割按四角包含关系分类

`resolve_hole_overlap`：RVA `0x146C450`，4273 字节，字节摘要 `c2f97f284d86d12948af6bc51a2230d400f0233678b2277ea4eef978848ce340`。

**发行版指令。** 函数先检查洞口宽、高为正以及待处理集合非空，再读取当前砖的 AABB、中心和尺寸。`0x146C75F–0x146C7BE` 四次调用 `Aabb2::contains`，`0xDEEC60`，分别检测砖的四个角是否落在洞内；这个 contains 包含边界。

然后按落在洞内的角点数量跳转。相对跳转表在 RVA `0x330B288`，实际 EXE 字节解出：

| 命中角数 | 目标 RVA | 本轮解释范围 |
| ---: | --- | --- |
| 0 | `0x146C7D9` | 还检查属性和交叉覆盖；不能等同于完全不相交 |
| 1 | `0x146C850` | 根据命中角分支，计算钳制比例和新中心/尺寸 |
| 2 | `0x146C910` | 按相邻角组合处理一侧被洞覆盖 |
| 3 | `0x146D488` | 进入异常路径；轴对齐有效矩形在此分类下不应有三个角命中 |
| 4 | `0x146C810` | 将该元素从有效集合移除；必要时交换末尾元素填补位置 |

1、2 角分支使用 `inverse_lerp` 和 `[0,1]` 钳制，调整几何尺寸、中心及若干原砖属性。本轮没有逐一恢复所有属性传播、标志组合和补片次序，不能把一段标准矩形差集代码冒充完整石砖算法。

**独立演算。** 砖 AABB 为 `[0,1]×[0,1]`，洞为 `[-1,2]×[-1,2]`，四角全部在洞中，进入移除分支。另取砖为 `[0,4]×[0,3]`，洞为 `[1,3]×[1,2]`：四个角都不在洞中，但洞确实穿入砖内部，所以 0 角分支还必须处理交叉覆盖。这个例子说明角点数量只是分类入口。

## 6. 木墙用矩形差集得到剩余板区

`subtract_wall_cutouts`：RVA `0x1484710`，2736 字节，函数摘要 `0f0dabbb5086412bf0e0880b6eaf531486a7961ac8393f877154f849659d0315`。PDB 对应 `construct_wall_boards.rs:1855`。

**发行版指令。** 洞口输入每次前进 16 字节，候选区域按 40 字节读取。`0x14848E7` 调用 `Aabb2::intersects_non_inclusive`，`0xDEEB90`。与石砖入口不同，此路径只接受有正面积的交叠：

```text
A.max_x > B.min_x && B.max_x > A.min_x
&& A.max_y > B.min_y && B.max_y > A.min_y
```

没有严格相交时保留原区域。命中时可见 `min/max` 对边界的夹取，以及最多四块剩余矩形的输出。布尔分支会改变拆分顺序：一支先取上下条，再在共同纵向区间取左右条；另一支先取左右条，再在共同横向区间取上下条。它们覆盖相同差集，但区域形状和后续板材分割可能不同。

令原区域为 `B=[x0,x1]×[y0,y1]`，洞与 B 的交集为 `I=[l,r]×[b,t]`。第一种顺序的独立算法表述是：

```text
下条： [x0,x1] × [y0,b]
上条： [x0,x1] × [t,y1]
左条： [x0,l]  × [b,t]
右条： [r,x1]  × [b,t]
```

退化矩形不输出。指令区间 `0x14849B2–0x1484B82` 可见正宽/正高检查；另一布尔分支的输出点例如 `0x1484CF2`、`0x1484DA5`、`0x1484F6E`，对高度要求至少 `0.050000000745...`。不能将未过滤差集的面积守恒扩大到过滤后的最终几何。

外围循环还存在计数与 `0x10` 的比较，以及“本轮是否发生改变”的记录；本轮没有恢复该计数的完整业务含义，不能将 16 当成产品最大洞数。

**独立演算。** 原墙板区 `[0,4]×[0,3]`，洞 `[1,3]×[1,2]`，得到下条 `[0,4]×[0,1]`、上条 `[0,4]×[2,3]`、左条 `[0,1]×[1,2]`、右条 `[3,4]×[1,2]`。面积为 `4+4+1+1=10`，等于原面积 12 减洞面积 2。这个算例对应未过滤且不退化的数学差集，不是实际游戏板数。

## 7. 接缝如何变成砖和梁实例

`spawn_stitches`，RVA `0x21A3960`，3521 字节，逐条读取上面的 64 字节描述。它把两条二维方向相加并归一化，形成姿态；按梁标志选择连续梁或分段砖。还有按未完全命名字段跳过某些记录的条件，不能简单说每个相交点必有装饰。

### 砖：边界点数量与砖数不同

H 为当前子区间高度。`H<=0.1` 不输出；有限正常路径在 `0x21A3E33–0x21A3EF1` 得到：

```text
k = clamp(ceil(2*H),3,1000)
n = k-1
boundaries = random_splits(n,0.2/max(H,1.2),RNG)
砖数 = boundaries.length-1 = k-2
```

`random_splits_into`，`0xDE8BB0`，的 n=2 分支直接返回 `[0,1]`；n>=3 时保留两端，内部边界为：

```text
j = min(0.495/(n-1),0.2/max(H,1.2))
t_i = i/(n-1)+(r_i-0.5)*j
```

RNG 初始状态来自两墙 ID 内部数值之和，调用 `fastrand::Rng::f32`；这是对象 ID 驱动扰动的证据，不能证明 ID 跨存档/版本稳定。

相邻边界换成 `y_i=y0+H*t_i`。一块砖的中心高度是两边界的均值，竖直尺寸是 `y_(i+1)-y_i-0.1`；另一次抽样 q 给某个横向尺寸 `0.35+0.1*q`，第三尺寸固定 0.3。模板最终朝向和 shader 变形尚未完全追踪。

| 子区间 H | 边界点数 n | 砖数 |
| ---: | ---: | ---: |
| 0.1 | 不生成 | 0 |
| 0.5 | 2 | 1 |
| 1.5 | 2 | 1 |
| 1.51 | 3 | 2 |
| 2 | 3 | 2 |
| 3 | 5 | 4 |

**接上前面的独立例子。** 取两圆交点之一，假设地形/墙高裁剪后为 `[2,4]`，区间内部没有基础高度分界且标签走砖分支。H=2，得到 3 个边界、2 块砖；j=0.1。选说明性随机输入 r=0.7，则边界为 `[0,0.52,1]`，高度为 `[2,3.04,4]`。中心高度为 2.52 和 3.52，竖直尺寸为 0.94 和 0.86。这些随机值为演示选定，没有声称来自实际游戏 RNG。

砖描述以 80 字节步长输出，随后 `spawn_stitch_bricks` 的 `0x21A56A2` 调用 `BrickTransform::encode`，`0x21A56B0` 调用实例缓冲 push。缺少对应 `WallRenderSlots` 时跳过；哈希输入包含墙 ID 对及序号。这个调用链直接支持“交点接缝产生渲染实例”的结论。

### 梁：同一高度段生成连续部件

梁分支输出步长 64 字节的描述，观察到尺寸参数为 `0.25/H/0.3`，保留从两墙选定的一个 ID；没有这套砖随机分割。位置 y 使用 y0，模板锚点没有确认，不能直接称为梁的几何中心。

`spawn_stitch_beams`，`0x21A4730`，在 `0x21A4C5C` 写入 `WoodenPlankSsbo` 实例。它还有墙 ID、序号和额外值的哈希以及 tag 位映射；本轮未追完其视觉效果。

这一段接缝的生成来自轮廓交点、有效高度与部件实例。不能用它代替屋顶主体的瓦片裁剪平面生产公式，两者尚未一一关联。

## 8. 三维相交与二维扣洞的连接边界

发行版有 `intersect_mesh_mesh`、`find_mesh_mesh_intersections`、`merge_segments_into_polylines` 等具体入口，本轮解码了其范围，不能仅凭名称将它们直接连到全部屋顶接缝。

在 `intersect_mesh_mesh`，RVA `0xBD0AE0`，1499 字节，已确认读取索引和顶点生成三角形，调用 `Triangle::intersect_triangle`，`0x14736B0`，并在特定返回 tag 后继续。后续计算三角形 AABB、扩张边界、检查交段端点和写出结果。

但 `Triangle::intersect_triangle` 又转入另一实现；本轮没有完成该实现的完整退化/共面处理。只能称为调用到三角形相交运算，不能声称已经确认具体 Möller 算法、全部 coplanar 规则、整个网格布尔，或每个建筑交叠都经过它。

屋顶的高度截面逆映射已经在 [屋顶专题](03-tiny-glade-roof-shapes.md) 恢复；瓦片侧的 GPU 平面和洞裁剪已经在 [接缝专题](05-tiny-glade-seams.md) 恢复。它们之间的所有生产者与消费者还没有完全对齐。保留这个连接缺口比画成一个完整闭环更准确。

## 9. 未做与风险

未做：没有运行两栋建筑拖动相交的场景，没有检查碰撞、导航、存档中的结果，也没有恢复所有石砖标志及退化几何分支。原因是本轮基于发行版静态指令，完整类型和动态状态缺失。

风险：同一种画面接缝可能由不同部件规则共同形成；局部二维差集不代表整个系统没有三维布尔；接触边界、尺寸过滤和周期墙坐标会改变结果。可以借鉴空间转换、局部扣洞和部件重建的原则，独立实现时需要自己的数据契约及退化规则。

第十五轮补充：[66](66-tiny-glade-seams-and-independent-building-kit-spec.md)进一步核对接缝输出类型，砖接缝通过BrickTransform.encode进入64B BrickTransformSsbo，木接缝进入80B WoodenPlankSsbo。共享实例通道不证明全部源网格/材质相同，也不代替建筑间屋顶保留侧和封口的未知部分。
