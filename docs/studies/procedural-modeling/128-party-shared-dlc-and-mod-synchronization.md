# 一人拥有 DLC、全房共享：资格、内容与 Mod 同步

2026-10-21，Pacific Time。**用户明确选择：房间里任意一位参与者拥有对应 DLC，大家就可以一起玩；提供资格的人可以是客机。** 这是本项目产品要求，取代此前尚待决定的联机 DLC 政策。默认每人仍需能合法运行本体；没有把 DLC 共玩扩大为本体免购、Steam Families 或 Remote Play。

可行方案是游戏自行授予“当前房间内使用玩法的资格”，每人 Steam 账号的购买状态仍保持真实。官方机制和先例支持这一路线，但 Steam 不会自动替游戏挂载客机资源、同步 Mod 或处理存档。保存与恢复契约见 [127](127-dlc-mod-save-and-multiplayer-persistence.md)，实施 owner 沿 [126](126-gameplay-packs-project-kickoff.md)。

## 资格由房间成员合并，模拟仍由现有 Host 拥有

以下是独立设计，字段名仅表达职责：

```text
房间可用 DLC(d) = 存在已加入当前房间的参与者 p：
    p 的当前身份认证成功
    且 p 对 d 的平台资格已确认有效

玩法可运行(m) = 玩家明确启用 m
    且 m 所需每个 DLC 都在房间可用集合中
    且所需包/API/状态兼容
    且所有必要接收端的内容准备完成
```

不能把条件缩成“Host 拥有 DLC”。例如 A 是无 DLC 的房主，B 买塔防，C 买 RPG；房间可以分别取得两种资格。但初片仍只运行一个主玩法，塔防/RPG 同时运行是否兼容仍沿原模式约束，多个拥有者的集合不自动解决玩法冲突。

Host 汇总当前认证结果并发布会话使用能力，不向客机发送“你已购买”的持久标记，也不修改 Steam 的个人拥有查询。Mod 只能声明依赖，不能作为 DLC 资格提供者。尚未完成认证的玩家可以等待内容准备或参与允许的本体流程；无有效提供者时受限玩法保持未激活，不能用 Unknown 编造已购/未购。明确无效的认证按 Steam 的身份契约处理。

P2P/听服适配可沿当前 Steam 会话身份验证后查询远端用户的 DLC 许可（官方指南给出 `UserHasLicenseForApp` 路径）；当前用户本地的安装/拥有查询只描述自己，不能回答客机 B 的许可。若将来采用可信后端，可使用服务器端 `CheckAppOwnership`；不能因此把 publisher key 放进玩家程序或现在新增后端。实际 SDK/绑定支持、认证失败码、回调顺序及离线政策由项目平台片核对，不在文档里伪造一个已完成的适配。

共享资格至少绑定房间身份、当前连接/认证世代及 DLC 集合版本。离开或明确撤销后，旧认证、下载与准备回调不能重新授予资格；保存文件也不能授予资格。平台短暂不可用与成员明确离开分开处理，不能一遇 Steam 网络抖动就销毁挑战。

## 最后一个拥有者离开时

推荐行为是**保存并暂停相关玩法，保住家园和进度**：先更新资格世代，在安全提交边界阻止新受限工作及其依赖 Mod；已接受事务不回滚、未提交任务作废；沿现有保存流程留下可恢复状态并显示谁需要重新加入。没有自动保存执行许可的当前开发阶段只实现契约，不实际触发存档。

如果还有另一位经过认证的拥有者，则继续，无需把世界转给他。短断线可保留恢复等待状态，等待/超时数值由项目现有会话政策决定；不在本研究另造一个宽限计时权威。恢复时重新核资格和冻结包集，再恢复同一波次。继续建造/钓鱼以本体依赖可安全解释为前提，细则见 [127](127-dlc-mod-save-and-multiplayer-persistence.md)。

房主退出与资格提供者退出是不同事件；如果 B 是购买者而 A 是房主，B 退出可暂停玩法但 A 仍保存世界。A 退出则沿现有房间结束/重连契约，不承诺 Host 自动接管。没有资格的人可以保留世界数据；离线单独继续受限玩法仍需自己的有效资格，不能把曾经联机共玩写成永久授权。

## 让没有买 DLC 的客机也有代码和资源

对于共享玩法必需的代码、规则、模型、动画、声音与网络定义，优先随基础游戏兼容内容向所有玩家分发，由会话资格激活。大型内容若要按需下载，也应设计合法面向本体用户的兼容内容通道；不能只放在未购买者无权下载的 DLC 专属 depot，然后指望拥有者通过房间传一份付费安装文件。

官方 DLC 和社区包仍使用统一包描述与分来源发现：随游戏只读包、本地作者 Mod、Workshop 安装内容一起参与依赖解析；相同稳定 ID 的冲突要明确拒绝/选择。资格不由文件夹存在决定，普通文件存在也不等于已激活。此前 [123](123-steam-workshop-and-dlc-design-for-demo.md) 的“大型包可独立 depot”建议在本次全房共玩要求下，必须补足未购买参与者的内容分发。

这会增加基础下载/安装体积，是换取朋友无购买障碍的明确成本；按实际大小再做可选兼容资源分发。未激活包不运行战斗/寻路，不能因为全员装有资源就持续支付全部模拟成本。

## Mod 同步要做两次

**第一步同步采用哪些内容，第二步同步运行状态。** 即使 Host 执行规则，客机仍需能解释实体/资源/协议，不能把所有 Mod 一律当作无客户端依赖。

| Mod 类型                                   | 建议准入策略                                                                                  |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 改规则、定义、几何、物品或实体表现的玩法包 | 首片保守要求必要包/版本/规则一致；Host 权威执行，客机只消费已发布状态，不再次发奖励或推进波次 |
| 明确声明且证明只有服务器需要的逻辑扩展     | 未来单独开放 Host-only 能力；必须使用已有客户端能解释的定义与协议，不能靠一个标记豁免真实依赖 |
| 纯本地界面、音量或不影响世界语义的外观替换 | 可以不要求房间统一，但需明确本地能力边界；碰撞、命中、物品身份不能归入此类                    |

建议加入链：

1. Host 在读取/激活前冻结完整依赖闭包，提供游戏协议/API、稳定包 ID、版本、来源/Workshop ID、发布修订、采用的内容身份及必要接收端清单。加载顺序和组合规则也固定，不把安装顺序当优先级。
2. 客机在准备区比较自己的内容，明确展示缺失/不兼容条目及下载来源。行为内容按已批准的 Mod 加载策略确认，不能因加入房间静默执行任意新代码；本地文件不能由房主任意路径覆盖。
3. Workshop 路径在获准后发起下载；开始/下载中/完成/解析/准备分别记录。完成回调核 App/条目/请求世代，通过包与状态兼容校验后才返回 Ready；断网、条目删除/不可见、拒绝下载都保留原因，不触碰原世界。
4. 全部必要接收端确认同一冻结包集后，发送初始世界/模块快照与同步游标，再允许实际输入。内容未就绪的玩家不提前生成实体，也不要求整个房间等候未接纳的晚加入者。
5. 运行后同步权威状态和合法命令结果。重连重新核房间/内容世代并取得当前快照，丢弃旧房间回调；包更新不得在半波战斗中热替换。

包版本与 Workshop ID 都不足以证明本地字节相同；优先沿项目已有获准的内容身份机制。当前研究没有新的摘要授权，也没有实际计算摘要。未来可采用逐字节确认或另行获准的摘要方案，不能写下一个版本号就声称精确同步已经解决。

Steam 订阅默认更新到最新；beta branch 版本关联需要开发者配合。要继续旧档，需要自己的合法内容保留/分支/迁移方案；无法获得确切旧包时诚实拒绝或迁移，不承诺“填 Workshop ID 就能下载存档时版本”。[Workshop Item Versioning](https://partner.steamgames.com/doc/features/workshop/itemversioning)

## 对当前首片和后续平台片的要求

| 当前 owner 应纳入的最小契约                                       | 以后另行接入/验证                            |
| ----------------------------------------------------------------- | -------------------------------------------- |
| DLC 资格输入区分个人与房间；不硬编码所有客机购买/仅房主购买       | 真实 Steam 身份/DLC 校验、平台回调和离线体验 |
| 保存包需求与模块状态，缺包/不兼容保护原档，保存不携带永久共享资格 | 实际不同拥有组合的联机读档与恢复             |
| 冻结必要内容集合、准备门禁与旧结果拒绝；复用现有 Host/Replica     | Workshop 下载/版本保留及完整晚加入/重连      |
| 每包目录、多来源依赖解析；规则由 Host 权威执行且预算有界          | 代码/资产分发、平台安装体积与双端性能采样    |

本次新增要求不授权抢写 World/Save/wire/UI 的共享窗口、不授权 Steam 后台、购买、上传、下载安装软件或运行验证。owner 在同一里程碑把必要接口/状态边界与已有源码对齐，由当前 Supervisor 协调；若真实超出当前闭包，列出可审阅的后继范围，不把它默默简化成 Host-only DLC。

未来最小场景：A 无 DLC/B 有且为客机/C 无；B 离开并由另一个拥有者接续；最后拥有者离开后保存/暂停再恢复；两个 DLC 分别由不同成员提供；缺/更新 Mod、下载失败与旧回调；晚加入/重连与重复奖励；无 DLC 单人读同一档。全部 **Not Run**。是否全房共玩的产品决定已明确，实际 Steam/Workshop 与项目运行正确性仍待实施和验证。
