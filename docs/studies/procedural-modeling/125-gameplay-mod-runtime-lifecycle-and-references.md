## 执行层级

推荐把外观/定义/场景包、运行脚本、官方编译模块区分开：简单 Mod 可只改数据；需要新条件、AI 或任务行为时使用受控脚本；官方底层能力按 Player/平台编译交付。将来确有高权限代码 Mod 需求时另立平台/兼容路线，不因支持 Lua 就宣称支持所有玩法或任意原生插件。

脚本得到代理接口，而不是整个 Unity/.NET 对象图。例子是 `QueryTargets(region, limit)`、`ProposeApplyStatus(targetId, statusId)`、`Subscribe(eventType)` 和模块自己的持久数据；这些名字仅是职责示意。包声明的权限只是申请，实际许可由加载器和活动模式授予，不能靠清单写一个字符串就自动生效。

写操作变成待复核命令，核心执行后返回成功/拒绝和必要事实；涉及资源、碰撞、物品和任务奖励时沿用既有所有者。暴露无限循环之外，还要约束宿主查询、生成量和异步请求密度，不能把所有性能问题留给解释器。

## 生命周期与失败

拟议状态是 `Discovered → Validated → Registered → Ready → Activating → Active → Quiescing → Inactive`，另有明确的 `Faulted`。Registered 不运行玩法；每一活动实例持有世界/会话/包世代，防止前一世界的延迟回调污染新家园。

| 阶段         | 拟议职责                                                         | 失败或重复时的边界                                                  |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------- |
| 定义与注册   | 解析包、排序依赖、检查接口、类型和模式冲突；建立候选定义目录     | 全部通过再发布候选；重复 ID 不按磁盘顺序静默覆盖                    |
| 新实例初始化 | 创建本包初始状态，注册受管任务/监听                              | 同一实例不重复初始化；所有注册物有 owner，可撤回尚未发布的注册      |
| 读档与迁移   | 先解码/验证状态，必要迁移只作用于候选，再重新建立瞬态引用与监听  | 缺包或迁移失败保留旧档；重新订阅不重新发初始奖励                    |
| 运行与提交   | 事件回调产生有界命令批；按确定规则处理并提交                     | 每批是明确提交边界；让出脚本执行不能留下持锁的半个世界事务          |
| 停用/故障    | 阻止新任务，移除自己的监听/输入/UI，取消未完成任务并隔离晚到结果 | 不假装撤销已提交的变更；保留诊断/恢复状态，不强卸其他包仍引用的资源 |

“停用当前处理器”“从世界删除玩法数据”“卸载磁盘包”是三个动作。玩法状态正在被保存或依赖者仍活跃时，应等待、拒绝或要求退出世界，不能以按钮已变灰证明卸载完成。

## 模拟与性能预算

| 工作           | 建议处理                                                             | 保留的正确性条件                                                     |
| -------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 敌人寻敌       | 共用空间查询，分批/按事件更新候选；查询结果有上限                    | 旧目标、敌人死亡、阵营/射程变化必须失效；不能每塔每帧遍历全世界      |
| 寻路与建造耦合 | 路径携带几何/导航版本；地形/建筑改变时标记受影响区域及路线           | 已封堵旧路不能继续被当作可通行；异步返回时核对世界/路线版本          |
| 波次/任务/效果 | 模块向现有调度器申请定时/事件，不给每条规则一个 MonoBehaviour.Update | 使用统一模拟时间，暂停、保存/恢复和失效必须明确                      |
| 脚本           | 每包和全体合计的指令/事件预算，限制排队与状态增长                    | 指令配额不等于毫秒上界，也不能抢占任意耗时宿主函数                   |
| 宿主重任务     | 大范围查询、批量生成、mesh/碰撞应用拆为有界任务与提交阶段            | 主线程创建/提交成本也计入；取消不使旧结果获得提交资格                |
| 渲染           | 复用兼容的模型/材质与批处理；独立看敌人、投射物、VFX、阴影成本       | 玩家选择的模式可改变画面，但不能把降画质或少模拟隐称等价优化         |
| 静止/未启用    | 无活动玩法不调度其寻敌/波次/战斗；资源依赖按需持有                   | 钓鱼、天气等本体必要模拟继续运行；“玩家没操作”不是暂停所有系统的依据 |

需要联机或回放时，权威模拟的顺序和额度应能确定；墙钟超时用于故障检测/诊断，不让不同机器按快慢随机漏掉攻击或任务事件。公平轮转、批次边界与积压处理需要作为规则保存/复现，而不是用“分帧了”替代语义契约。

**构造预算例子**：20 座塔、每塔每轮一次寻敌，可把每个模拟步的查询数限制为 5 并确定地轮转，4 步覆盖一轮；这会改变最坏响应时间，需要正式定义为玩法节奏。不能把原本要求同一步完成的 20 次查询无声分摊，再宣称行为完全相同。数字仅供演算，未作为帧率/成本承诺；实际毫秒、GC 和规模必须由自己的样片采集。

## 模式冲突与 API 版本

加载顺序解决定义依赖，不能解决两个包同时接管死亡、伤害、时间或奖励。可组合能力用稳定接口与明确委托点，互斥能力在激活前拒绝；完整新玩法可以成为单独的主模式。脚本 API 版本、包版本、状态 schema 和内容版本分别检查，发现不兼容时不能靠重新排序或吞异常继续。

模块间 API 应返回有限值/稳定句柄并声明失效语义；跨包调用同样计入预算和依赖。缓存必须覆盖包/API/世界世代等结果相关输入，不能在 Mod 更新后继续使用旧规则算出的路径或任务条件。

## 验证提案与收口

未来竖向样片至少验证：未启用时活动工作为零或可解释；塔防包/一个行为 Mod 实际改变结果；建筑改变路径；战斗中保存/恢复无重复敌人/奖励；取消/切世界拒绝旧回调；缺包/版本不符保留原档；停用后没有遗留订阅/任务；相同场景下统计脚本、查询、寻路、提交、GC、内存与渲染。

上述均 **Not Run**。本轮已交付的是公开机制依据和独立接口/生命周期/预算建议，未选定脚本库、实现插件框架或声称项目性能可达到某个 FPS。
