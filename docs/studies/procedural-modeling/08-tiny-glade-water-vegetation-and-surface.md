# Tiny Glade：水生植物、水面噪声与涟漪
本篇回答水域确定以后，植物与水面细节怎样生成。主要机制是候选网格加空间噪声筛选、按软遮罩设置实例尺寸，以及噪声/涟漪改变水面法线。它们与河床地形属于不同职责。

沿用 [制品身份](00-evidence-and-scope.md)；编辑和河床见 [水域与河岸](07-tiny-glade-water-shape-and-banks.md)，文件摘要与 CPU 调度证据见 [水体账本](09-tiny-glade-water-evidence-ledger.md)。下文的 `%ID` 和 `0x偏移` 用于核对原包指令，正文公式不依赖本机导出文件才能阅读。

本报告只读检查发行版的四个 `.precomp` 文件，共七个内嵌 SPIR-V 模块。`summary.json` 保存完整文件和模块 SHA256、模块起点、长度、入口及解析器出处；逐条指令的 file_offset 是相对原 `.precomp` 文件的字节位置，不是相对导出文本的位置。复用既有、按官方 grammar 解析操作码的脚本，检查了全部指令长度，但没有运行 SPIR-V 验证器或游戏。以下区分指令观察、公式推导及未贯通部分；不是 REA Evidence，也不是恢复源码。

## 芦苇：候选网格、软掩码和簇状分布

`water/spawn_reeds.precomp` 模块 0 从文件偏移 `0x6a` 开始，计算入口 `%2`，局部工作组 `8×8×1`（`0xca`）。全局 invocation 的前两坐标记为整数 `x,y`，`grid_dims` 记为 `D`。`0xf3e..0xfea` 实际计算：

```
c=130*((vec2(x,y)+0.5)/D-0.5)
r=U(H(x*y+x))
p=c+vec2(-0.4+0.8*r)       # 同一个扰动值加到两个坐标
uv=p/130+0.5
```

这里不是两个独立随机坐标。`H` 的整数操作见下文；`U` 由 23 位尾数构造 `[1,2)` float 再减 1，所以结果严格是 `[0,1)` 的离散数。`0x1196` 的 `%111` 是扰动后位置。越界 UV 的水体值显式设为 0；域内 `0x13f6..0x1412` 在 LOD 0 读取 `water_mask` 的 **G** 分量，记为 `W`。`0x14a2..0x14be` 读 `path_mask` 的 **R**，记为 `P`；`0x17f2..0x180e` 读建筑掩码的 **R**，记为 `B`。通道名称不建立“水深”或距离单位的含义，本报告保留软掩码数值角色。

定义由指令分支和三次多项式支持的 pulse：

```
Pulse(c,w,v)=0                         if abs(v-c)>w
             1-t*t*(3-2*t)            otherwise, t=abs(v-c)/w
S(a,b,v)=smoothstep(a,b,v)
A=Pulse(0.5,0.3,W)+Pulse(0.2,0.2,P)*S(0.6,0.8,W)-S(0.2,0.25,P)
```

证据：`%1526` 在 `0x14f2..0x15ee`；`%1527` 在 `0x162a..0x1726`；`%254` 在 `0x1742..0x17aa`。先检查 `A>0`，再计算 `p+20` 上的二维平滑标量噪声 `N`（`0x186a..0x2976`）。最终接纳条件是：

```
A>0 and N(p+20)>0.6 and W>0.55 and B<0.1
```

精确最终条件为 `%454..%460`，`0x298a..0x29da`。这说明它在掩码允许的候选网格里做空间相关的簇状筛选，不是仅按单点随机概率撒实例。

接纳后，`0x2cae..0x2d02` 计算水平尺度 `s=1+0.5*U(H(x+y))`，垂直尺度 `s_y=s*(0.5+0.5*A²)`；`0x2e2a..0x30fa` 使用角 `3.14*r`、绕 `(0,1,0)` 的旋转构造变换。矩阵的存储/乘法约定尚未全部绑定到渲染端，不能凭名称推断最终顶点轴序。`0x327a` 对指定 indirect draw 的 `instanceCount` 原子加 1，旧值 `%659` 用于实例索引；`0x32a6..0x350a` 写入 12 个 float。声明的实例 ArrayStride 为 48 字节，见 `0x71e`。

该模块没有对 invocation 与 `grid_dims` 做显式比较来提前退出；只观察到 UV 水体越界处理。CPU 入口确认芦苇调度传入逻辑范围 150×150，睡莲为 225×225；调用 helper 将逻辑尺寸向上取整为工作组。实际 shader 的 grid_dims、分配容量及芦苇尾部 invocation 行为仍需逐项核对，不能把这些逻辑尺寸直接当成工作组数或最终植物数量。

## 睡莲：两套密度域、花园重叠和独立花朵动画

`water/spawn_lilypads.precomp` 模块 0 起点 `0x70`，计算入口 `%2`，工作组 `8×8×1`。与芦苇不同，`0x1c24..0x1c90` 显式检查 invocation 是否达到 `animation_dims`，越界直接结束。候选基点公式相同，但同向坐标扰动为：

```
p=130*((vec2(x,y)+0.5)/grid_dims-0.5)+vec2(0.5*(U(H(x))+U(H(y))-1))
```

见 `0x1cf8..0x1ff4`。水体仍读 G (`0x2254`)，路径读 R (`0x2300`)。花园读 G (`0x2364..0x2380`) 后得到：

```
G=S(0.4,0.5,S(0,0.5,garden.g))
O=G*S(0.4,0.5,W)
```

`%272`、`%544` 分别在 `0x23b4`、`0x3c14`。这不是把两个掩码相乘后直接阈值化，而是嵌套 smoothstep 的软重叠。

`glade_theme_id==2` 时（整数比较 `%1166`，`0x2500`），主水域 pulse 使用 `W+0.3*N(1.83*p)` 作输入，中心约 `0.662`、半宽约 `0.393`；其他 theme 用中心 `0.45`、半宽 `0.3` 的 `W` pulse。前者的坐标缩放在 `0x2680`、噪声加值在 `0x37a0..0x37b4`、pulse 在 `0x3930..0x3a2c`。不从数字 2 推断季节或主题名称。

```
C=Pulse(0.662,0.393,W+0.3*N(1.83*p))    if theme_id==2
  Pulse(0.45,0.3,W)                     otherwise
A=C+Pulse(0.2,0.2,P)*S(0.6,0.8,W)
accept=(A>0 and N(p)>0.5) or (O>0 and N(2*p)>0.5)
```

睡莲这里没有芦苇公式中的 `-S(0.2,0.25,P)` 项。指令证据：`A` 为 `%542`（`0x3be0`）；第一噪声域在 `0x3c70`、阈值在 `0x4d7c`；第二噪声域在 `0x4f70`、阈值在 `0x6090`；两个路径通过 `0x4ee8..0x6238` 的 Phi/条件合并为最终接受标志。噪声域都是下文的二维标量 value noise。

接纳后的基本均匀尺度可写为：

```
q=clamp(A+O,0,1)
s=mix(0.8, theme_id==2 ? 1.3 : 2.0, U(H(x+y)))
  *mix(0.5,1,q)*mix(1,0.75,O)
```

见 `0x6278..0x629c`、`0x64d8..0x6564`。位置 y 通常是 0，`theme_id==4` 时写为 −0.1（`0x6334..0x6394`）。主睡莲在 `0x6ee0` 原子分配并写 48 字节仿射实例。

花朵是另一条输出路径，条件 `O>0.7 and U(H(x+y+345))>0.2`（`0x717c..0x72ec`），另一个 indirect draw 索引为常量 14（`0x7304`），并写 `lilypad_flower_buffer`，不能把它并入睡莲叶实例数量。

每个有效 invocation 都读取/写回 animation texel。`0x23d4..0x24cc` 明确读 `frame_constants.delta_time_seconds`，计算：

```
a_next=mix(a_old, G>0 ? 1 : 0, 1.5*dt)
```

这里没有局部 clamp 混合因子。花朵分支再读 animation，`r_f=U(H(10*x+10*y+45))`，令 `z=clamp(1-S(-0.2+0.2*r_f,1,a_next),0,1)`，计算 `E=z³-1.5*z*sin(3.14*z)`（`0x74b0..0x75f4`）。花朵尺度在已有尺度上乘 `0.8*O*(1-E)`，theme 2 再乘 2（`0x7608..0x769c`），其 y 位移有 `-0.3*E` 项（`0x76b8..0x76cc`）。此式可描述增长/收缩的形态，未通过运行观察确认触发频率或视觉时间曲线。

## 空间噪声与整数随机变换

植被模块通过实际移位/XOR/乘加指令构造确定性的网格噪声。以下整数均为 uint32，溢出按模 `2³²`。`H` 为：

```
a=n+(n<<10); a=a^(a>>6)
a=a+(a<<3);  a=a^(a>>11)
H(n)=a+(a<<15)
U(n)=float(n & 0x7fffff)/8388608
```

`U` 是实际 bitcast 路径的等价有限值公式，不代表已经证明统计均匀性。格点 `(i,j)` 的角值先计算 `v=(1664525*i+H(j)+1013904223)*1664525`，再依次 `v^=v>>11; v^=(v<<7)&0x9d2c5680; v^=(v<<15)&0xefc60000; v^=v>>18`，角值为 `U(v)`。芦苇第一角值证据 `0x18ce..0x1ad6` 与 `0x1e96..0x1ece`；其他三个角重复同样操作。

对于实数坐标 `p`，取 `i=floor(p)`、`f=fract(p)`、`h=f²*(3-2*f)`，将四个格点值分别按 `h.x,h.y` 双线性混合。芦苇混合为 `%927`，`0x2822..0x2976`。这是有平滑权重的标量格点噪声；没有梯度向量点积证据，不能仅因外观相似就称为 Perlin noise。种子来源、碰撞、频谱和跨版本稳定性未运行验证。

## 水噪声 LUT：源纹理的三次权重滤波和差分通道

`lut/water_noise.precomp` 模块 0 从 `0x66` 开始，入口 `%2`，工作组 `8×8×1`。它依赖外部 `blue_noise_textures.uniform_64x64_ldr_rgba`，实际通过 `OpImageQuerySizeLod` 获得尺寸；资源名称不替代纹理内容或真实绑定的验证。

每次重采样，输出像素 `k` 转为 `uv=(k+0.5)/output_dims`。若源图尺寸为 `d`，令 `a=uv*d`、`b=floor(a-0.5)`、`t=a-(b+0.5)`。每轴三次权重为：

```
w0=-0.5*t+t²-0.5*t³
w1=1-2.5*t²+1.5*t³
w2=0.5*t+2*t²-1.5*t³
w3=-0.5*t²+0.5*t³
g=[w0,w1+w2,w3]
q=[b-0.5,b+0.5+w2/(w1+w2),b+2.5]/d
```

然后实际做 3×3 次 LOD 0 纹理采样并按 `g_x*g_y` 加权。第一组的权重/坐标为 `0x6da..0x8fa`，九次采样从 `0x95a` 到 `0xe66`，R 分量结果 `%279` 在 `0xebe`。这是三次权重分组的滤波算法；是否恰好等于标准 16 点 bicubic 重建，仍依赖调用时 sampler 的线性过滤与寻址模式，不能仅凭 `samplers.llr` 名称断言。

同样重采样执行五次：中心，以及输出像素的 `±(1,0)`、`±(0,1)`。整个模块有 45 条 `OpImageSampleExplicitLod` 指令，全部已解析。令这些结果为 `F0,Fx+,Fx-,Fy+,Fy-`，最终：

```
output=(F0, 0.5-(Fx+-Fx-)/3, 0.5-(Fy+-Fy-)/3, 1)
```

X 差分 `0x20ca..0x20f2`、Y 差分 `0x32fe..0x3326`、最终 `%1125` 写图在 `0x333a..0x3376`。这是编码的有限差分，不是未经尺度校准的世界空间解析导数。该模块本身没有时间输入或水体 mask 输入，也没有地形模拟循环。

## 水面：平面几何、四层法线噪声和最多 32 个涟漪源

`water_plane.precomp` 有两对顶点/片元模块，顶点模块的全部操作码及参数完全相同。模块 0 (`0x8d`) 的 `0xacd..0xbd1` 把网格输入的 XZ 乘 130，写世界位置 `(130*x,-0.01,130*z)`，原始法线固定 `(0,1,0)`。波纹没有在这个顶点入口改变几何高度。

下面只完整追踪复杂片元模块 1 (`0xc1a`) 的水噪声/涟漪局部链，未恢复全部反射、折射、阴影和光线查询流程。其 `theme_id==4` 分支直接绕过动态法线，见 `0x4fda..0x5036`；不把整数 4 解释为具体季节。

四层参数由实际常量数组及循环给出：`s=[2,4,8,12]`、`amp=[2,2,0.5,0.2]`。方向用固定种子 `[17,18,20,21]` 生成两个随机数并减 0.5 后归一化；时间 `T=float(game_time_sec)+game_time_frac`。偏移为 `o_j=3*T*dir_j`，见 `0x509a..0x50f2`、`0x51e6..0x5216`、`0x59a2..0x5aa6`。

每层旋转角 `theta_j=(j+1)*10.1664075851`，用 sin/cos 构造二维矩阵 `R_j`（`0x5cee..0x5d8e`）；采样 UV 是 `0.012 * ((s_j*x+o_j) row-multiply R_j)`，见 `0x5dd2..0x5e32`，`x` 为片元世界位置 XZ。将 LUT RGB 映射为 `(R-0.5,2*G-1,2*B-1)`，乘 amp，再将差分两项乘 `s_j*0.012`。差分向量乘该旋转矩阵后逐层累加，见 `0x5e92..0x6022`。该链实际使用 LUT 的差分通道建立法线扰动，不是每层生成新的水域拓扑。

涟漪缓冲的字段为 `position[32]`、`smoothed_position[32]`、`intensity[32]`、`count`；指令确实读这些字段并把 count 夹到最多 32（`0x60ca..0x624e`）。对每个源令 `p0,p1` 为两个位置、`I` 为强度：

```
m=(p0+p1)/2; v=3*(p1-p0)
d(q)=length(m-q)
D(q)=d(q)+dot(m-q,v)
F(q)=sin(16.365*D(q)-6*T)/(1+max(d(q),D(q))^4)
delta=(F(x-(0.01,0))-F(x), F(x-(0,0.01))-F(x))*0.5*I
normal=normalize((noise_dx+sum(delta.x),1,noise_dz+sum(delta.y)))
```

中心公式 `0x625e..0x6426`，两次偏移 `0x643a..0x668a`，差分/强度/累加 `0x66b2..0x6766`，最终法线 `0x67ca..0x6906`。这里差分乘的是 0.5，没有除以 0.01。源的创建、平滑、强度生命周期和哪些操作触发涟漪不在这四文件中，仍未知。

## 水域轮廓如何可见：软掩码并非片元裁剪

复杂片元模块只有一次 `water_mask` 纹理读取：`0xf43a..0xf47a` 采样 G `%13123`，域外返回 0。该值的唯一数值消费者在 `0x1060a`，计算 `W+0.2*N(x)²`，然后形成 `blend=0.1+clamp(0.2*(1-S(0.7,0.85,...)),0,1)`。它进入局部泡沫/岸边辐射混合的链，未进入最终 alpha 或片元 discard。泡沫语义同时得到邻近变量用途支持，但完整材质尚未恢复。

最终输出指令 `0x10a56..0x10aba` 为：先相加反射、折射、上述局部辐射项，结合体积消光与散射得到 RGB，构造 `float4(rgb,0)` 并写颜色。模块 1 和模块 3 均无 `OpKill`/`OpDemoteToHelperInvocation`。模块 3 (`0x12e20`) 不含 `water_mask` 名称，已看到 `0x1a878..0x1a8ac` 构造并写 `water_rt_ray_buffer`，未把它当作另一份完整颜色着色器。

第四轮进一步追到实际两个三角形的水面网格、主深度视图到水面 attachment 的拷贝链、EarlyFragmentTests 和延迟反射的四位逐像素覆盖。**这份复杂颜色片元的 G 掩码采样不是几何轮廓裁剪，最终 alpha 也不是该掩码值。** 初次可见覆盖与后续反射补色必须分开；固定管线与河岸几何的完整补充、证据及剩余缺口见 [10](10-tiny-glade-water-render-pipeline-and-bank-transition.md)，本篇保留原来的局部材质/植物范围。

未做：游戏运行、GPU 调试、所有真实绑定/采样模式核对及完整 CPU/GPU 调度。风险：静态公式适用范围、未核对的同名资源、主题枚举、缓冲容量和剩余动态渲染状态仍有不确定性；第四轮已确认的固定状态另见 10。原游戏文件未修改。


## 贯通的构造算例

以下将 shader 中间采样值作为给定输入，核对资格、尺寸和状态输出。它们没有执行原作整数种子或 GPU，不代表某个真实格点恰好产生这些数值。

**芦苇候选。** 前置状态为一格候选，给定 W=0.65、P=0、B=0、N(p+20)=0.7。水域 pulse 的归一化距离为 0.5，结果为 0.5；路径 pulse 及路径扣除项均为 0，因此 A=0.5。A>0、噪声>0.6、水域>0.55、建筑<0.1 都成立，允许输出实例。再给定尺度随机数 0.5，得到水平尺度 1.25、垂直尺度 0.78125。若只把建筑遮罩改为 0.1，严格 `<0.1` 不成立，实例被拒绝。原子实例数量与缓冲写入是接纳后的步骤，不是预先生成一个完整网格植物集合。

**睡莲与花朵。** 取非 2、非 4 的主题，W=0.5、P=0、garden.g=0.5，则嵌套 smoothstep 得到 G=1，软重叠 O=1。水域 pulse 约为 25/27，q=clamp(A+O,0,1)=1。给定相应噪声>0.5、尺度随机数 0.5，候选通过，基本叶尺度为 1.4×1×0.75=1.05。若花朵随机值也给定为 0.5，则 O>0.7、随机>0.2 都成立，允许另一条花朵输出。两者用独立计数和缓冲，不能把叶数量当作花数量。

**动画一步。** 沿用花园重叠场景，给定 a_old=0、dt=1/60 秒：a_next=0.025。随后 G 变为 0，下一步按相同 dt 得到 0.024375。这是混合公式演算，未证明游戏实际以 60 帧/秒调度，也未证明 dt 的产品上限；本段没有 clamp 混合因子。

**静止涟漪源。** 令 p0=p1、T=0、I=1，忽略基础噪声，在源中心取 x=m，则 F(x)=0；向 X 或 Z 负方向偏移 0.01 得到约 F=0.1629205，因此两个法线分量各增加约 0.0814603。它改变片元法线；顶点入口仍写 Y=−0.01。这说明局部波纹可以由显示扰动生成，不能据此宣称进行了河床或水量更新。

## 独立设计建议与剩余问题

自研时可以把水域资格、空间簇状分布、实例变换和增长动画分开，使用自己的参数、随机函数和资产。确定性格点噪声可以提供局部稳定性，但原子分配的实例输出次序、缓存重建与跨版本种子稳定性没有在本轮建立，不能承诺原作植物编号稳定。

本篇已回答：芦苇/睡莲的选定筛选与尺寸公式、独立花朵输出、动画局部状态、LUT 采样算术、水面平面位置和选定法线/涟漪公式。部分回答：完整水面材质及植物刷新。水面固定状态和可见覆盖的后续进展见 [10](10-tiny-glade-water-render-pipeline-and-bank-transition.md)。涟漪源创建/销毁、所有主题职责、真实资源容量及运行时性能仍未知。
