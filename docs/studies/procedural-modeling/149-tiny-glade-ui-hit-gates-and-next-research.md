## 显示标志先于交互注册

对进入本轮查询且通过前置索引/实体读取的控件，`0x14297D165` 先把 `UiInteractionState+1` 清为 0，随后 `0x14297D169–0x14297D16C` 检查 `+0==1`。不满足时直接回到遍历分支，不执行本控件后面的 WidgetParams 构造和 `UiState::add`。

随后读取布局二维尺寸，取两个分量的最小值：`0x14297CA99` 建立 float 0；`0x14297D17E–0x14297D186` 在普通有限尺寸下，只要最小值不大于 0，也跳过注册。该门在命中框额外扩张之前，所以不会因为后面加 padding 而把零尺寸控件重新变成可点击目标。

这和出现动画读取的是不同事实：[144](144-tiny-glade-ui-motion-static-chains.md) 已证明显示位关闭后，出现进度可以从当前 p 逐渐减到 0。因此在这个路径里，**目标显示已关闭但 p 仍大于 0，不要求等待退场结束才停止新交互注册**。具体画面仍需其他渲染消费者，不能由这段单独承诺可见退出效果。

边界同样重要：未注册本次 widget 不独立证明上一轮已经捕获的拖动、按压或焦点资源全部取消。`ui_update` 的释放、失焦、菜单打开等交互结束入口已有 [133](133-tiny-glade-confirm-cancel-input-mapping.md) 的部分证据；精确的旧捕获清理到本轮门控之间仍需进一步调度核对。

**构造例。** 自行设某个按钮出现进度 p=0.6，此时逻辑显示位从 1 改为 0。出现消费者下一次仍可以计算退场尺寸；本函数读到显示位为 0 时，本次不调用该按钮的 `UiState::add`。这说明逻辑禁用新命中可以早于视觉归零，不证明旧按压捕获恰好在同一更新结束。

## 命中框不是原样照搬可见尺寸

通过门控后，选定指令按如下步骤生成交互 AABB：

1. 读取布局尺寸 `d=(w,h)`（`0x14297D172`）与布局中心 c（`0x14297D1B9`）。其上游是 144 已恢复的 Taffy 布局输出，不另造一套按钮位置。
2. `0x14297D196–0x14297D1AA` 计算 `k=10*s1*s2`，其中 s1 来自一项资源的 `+0xE8`，s2 来自另一项资源的首 float。这里保留实际来源，不把它们未经类型核对就分别命名为 DPI 和玩家缩放。
3. `0x14297D1AE–0x14297D1B2` 将 k 同时加到宽和高，`0x14297D1D4` 调 `Aabb2::from_center_dims(c,d+(k,k))`。
4. 后面的 WidgetParams 构造消费这组扩张后的范围。`0x14297D373` 实际调用 `UiState::add`。

**10 是整个尺寸的增加量，不能说成每条边扩大 10。** 若两项缩放均为 1，则每侧多 5。节点尺寸本身已经可能包含聚焦或出现倍率；因此命中框也可能跟随布局变化，而不是一个完全固定的原始矩形。

注册前另有可选矩形相交排除：`0x14297D212` 调 `Aabb2::intersects`，选定标志成立且相交时，`0x14297D21D` 跳回遍历。该排除矩形的完整类型与所有写端本轮未接齐，不指定它必然是哪一种弹窗，也不由此推出所有界面重叠的优先级。

**构造例。** 自行设 c=(100,100)、d=(80,40)、s1=s2=1，则交互尺寸为 (90,50)，范围为 x=[55,145]、y=[75,125]。原布局范围为 x=[60,140]、y=[80,120]，每侧扩了 5。若相邻目标也扩张，最终谁获得输入还取决于 UiState 的仲裁，不能只根据 AABB 猜测。

## 聚焦反馈不等于持久选中

本函数先清 `UiInteractionState+1`，再在后续条件成立时写回 1，例如：

- `0x14297D236–0x14297D260` 检查一个当前资源的实体匹配后写回。
- `0x14297D560–0x14297D598` 在额外标志、显示位为 1 且 `UiWidgetContext::is_active()` 成立时写回。

144 已接通这个 `+1` 对聚焦动画及父子显示的消费。这支持“聚焦是一种由当前交互重新投影的表现状态”，不支持“这个字段就是玩家已选择的持久工具”。两个写端之前的全部资源身份仍有缺口，因此不把其中某一条直接命名为所有手柄或鼠标行为。

WidgetParams 还显式采用 `no_history_recording`、`occlude_by_world(false)` 和 `allow_negative_distance(true)`，调用分别在 `0x14297D2FF`、`0x14297D315`、`0x14297D32B`。这些是 UI 注册属性，不代表世界建造命令不进撤销，也不能把其中任何一个标志当作“UI 永远获得最高输入优先级”。

**构造场景。** 已选择工具 A，把焦点移到 B。现有静态证据允许 B 的聚焦表现变化；没有证据表明这里只因聚焦就把正式工具切成 B。自研主分类、子工具均应从已有工具状态显示选中，再叠加聚焦动画，避免把“指到了哪个”误作“当前正在用哪个”。

## 检查与交接用途

新增回读通过 11 个交互原字节锚点、4 个直接调用与命中尺寸常数 10；已有菜单/点击核心回读仍保留 20 个锚点和 typed command 核对。构造例只检查局部算术，未进行游戏、Unity、输入或性能运行验证。

适合 NC11 增补的行为是：逻辑显示/输入门控与视觉进度分离，明确隐藏时旧捕获的处理，选择稳定命中区域或有意跟随布局，并把选中、聚焦、按压分开。它们是实现与验收要求，不是已检查用户项目后的问题诊断。所有真实手感、命中效果、跨帧取消与性能仍 **Not Run**。
