# Tiny Glade：菜单进入、退出到实际绘制参数

2026-10-23，Pacific Time。续接 [144：UI Motion 静态链](144-tiny-glade-ui-motion-static-chains.md)。本轮进一步连接菜单请求、当前状态、Mei 节点、渲染参数和菜单按钮类型；点击与工具排时序见 [147](147-tiny-glade-click-completion-and-row-timing.md)，独立实施交接见 [148](148-ui-motion-dedicated-supervisor-handoff.md)。

**已接通的是菜单状态变化到控件绘制的实际路径。所选状态提交器不等待退出动画；Mei 这段绘制消费也不自动插值位置和透明度。** 这不能扩大成“整款游戏没有菜单动效”：上游标量写端、其他页面和最终合成仍有覆盖缺口。

## 状态请求到当前菜单，没有“退出动画已播完”条件

[135](135-tiny-glade-menu-tool-exit-and-timber-cleanup.md) 已定位菜单关闭请求。本轮重新读取对应函数，而不是把旧结论当新验证：

| 环节         | 实际位置                                         | 选定行为                                            |
| ------------ | ------------------------------------------------ | --------------------------------------------------- |
| 请求关闭     | `do_gui_escape_menu`，`0x14033E84E–0x14033E862`  | 将目标 tag 写成 2，调用 `NextEscMenuState::set`     |
| 保存请求     | `NextEscMenuState::set`，`0x140A003A0`           | 处理旧资源并复制 0xA0 B 状态，不是时间插值器        |
| 消费请求     | wrapper `0x1411D8C00`，`0x1411D8DDB–0x1411D8E10` | 取目标 tag，写回 12 作为无待处理请求；12 时跳过提交 |
| 关闭通知     | `0x1411D8E10–0x1411D8E4A`                        | 目标为 2 时追加 `EscapeMenuJustClosed` 通知         |
| 当前状态生效 | `0x1411D8E6D–0x1411D8E85`                        | 写目标 tag 和状态载荷，另保存前态                   |

所选提交区间没有读取动画进度、结束时间或 completion token。**菜单关闭通知不等于最后一个退出像素已经绘制，也不是玩家已经看到退出完成的证明。** 通知还发生在该函数写当前状态之前，不能据它独立建立消息消费与画面先后。

`EscMenuState::is_open/is_closed`（`0x140A00340/0x140A00370`）也主要按状态 tag 分支；其中一个特殊变体还读取 `+8` 的布尔值。tag 2 的闭合判断成立，但不能用它概括所有特殊页面和遮罩模式。

**构造例。** 已有待提交关闭请求 tag 2。提交器取出它并把请求槽置为 12，追加关闭通知、更新当前状态。它没有先等某个 `p==1`。之后哪次 UI 构建和哪次渲染消费该状态，仍由调度决定；本例不能把“一次函数调用”换算成实测一帧。

## Mei：节点复用和渲染参数，而非隐含的 tween 播放器

`do_gui_escape_menu` 在 `0x14033E0A7` 调用 `MeiContext::reuse_or_create_node`，随后装配模板与插槽。选定 `assets/ui/menu/esc.ron` 的实际活动声明包括 Horizontal、Vertical、Gap、Padding 和 `logo/contents/bottom/buttons` 插槽；部分图标示例在注释中，不能算运行中的按钮树。

节点复用函数 `0x14072C2D0` 先查当前表，未找到时尝试从另一张表取出旧记录。选择性复用内容与本轮属性初始化需要分开解释：

- 返回的节点值指针为桶尾地址减 `0xD0`（`0x14072C64C`）。
- 重新插入当前表的初始化路径在 `0x14072C5F3`、`0x14072C62A` 写 float 1，分别对应返回节点的 `+0x84`、`+0xC4`。
- 命中当前表的快速返回分支不经过这两次初始化；不能把以上说成“每一次调用都清空所有 UI 状态”。

`mei_post_update`（`0x14072EEF0`）中的尺寸/布局与绘制消费已进一步连接：

| 数据             | 指令位置                  | 本轮可确认的意义                                                           |
| ---------------- | ------------------------- | -------------------------------------------------------------------------- |
| 单位标量         | `0x14072F600`             | 将 float 1 装入本段使用的 `xmm10`                                          |
| 节点颜色缩放标量 | `0x14072FE9B–0x14072FEA8` | 计算 `1 * node[+0xC4]`，写到 `node[+0x84]`；这段没有 dt 或缓动函数         |
| 几何             | `0x140730EEC–0x140730F2B` | 读取 `node+0x88` 的二维尺寸和 `+0x90` 的位置，按半尺寸得到中心             |
| 实际渲染参数     | `0x140730F3D–0x140730F7D` | 将尺寸/中心与 `+0x84` 标量写入传给内容渲染器的参数；该标量位于参数 `+0x18` |
| 内容分发         | `0x140730F86`             | 通过内容 vtable 的 `+0x68` 槽调用 render                                   |

因此本段既不自动运行“从 0 淡入到 1”，也不在旧、新位置间计算缓动。它会消费上游提供的节点值；若上游确实逐次改写这些值，就可能构成动画。**本轮还没有恢复主暂停菜单每个上游标量/位置写端以及最终画面合成，不能把局部的单位初值当成全屏必然硬切。**

这也修正了一种容易产生的误读：模板存在横排、节点可复用、渲染有透明度相关标量，都不独立证明存在进入/退出时间线。

**构造例。** 新节点进入该初始化分支、其本地缩放标量为 1，且上游没有再修改它，则本段算出的渲染标量也是 1，不会自行生成 0、0.5、1 的序列。若要出现该序列，必须继续找到一个真实写入者或其他合成阶段；不能凭动效习惯补写。

## 菜单按钮类型已用 vtable 对齐

144 中 `widgets::impl$6` 的具体类型原先保留未知。本轮找到 `.rdata` 的 vtable `0x14329C948`，并与 PDB 类型名函数交叉核对：

| 槽      | 地址          | 身份/用途                                 |
| ------- | ------------- | ----------------------------------------- |
| `+0x30` | `0x1422F64A0` | PDB 明确为 `type_name<MenuButtonContent>` |
| `+0x58` | `0x140729540` | 所选 MenuButtonContent 的 pre_update      |
| `+0x60` | `0x140728A60` | prepare_layout                            |
| `+0x68` | `0x140729570` | render，正是 Mei 的实际分发槽             |

这比仅凭编号或相邻函数位置推断类型更强。所选 render 在 `0x1407295AE` 读取参数 `+0x18`，交给 `scale_u32_packed_srgba_color` 后调用 `TextFragment::render`。本段还按聚焦/强制高亮标记选择颜色，但没有在这个 108 B 函数中推进缩放脉冲或位移动画。

菜单输入也有明确的共同出口：

- `mei_pre_update` 在 `0x14072DDB2` 调 `clicked()`，成功后 `0x14072DDBC` 置交互 bit `0x10`；所选导航确认路径也转到同一写端。
- MenuButtonContent 的热键 pre_update 在 `0x140729558` 调 `MainActionSet::just_pressed`，通过后 `0x140729564` 置 bit `0x20`。
- `NodeContext::used` 在 `0x14072CE1E` 测试 `flags & 0x30`。这把点击/确认和热键激活接到一个“本轮使用”判断，不是动画完成判断。

**构造例。** 同一 MenuButtonContent 的鼠标点击写入 `0x10`，热键写入 `0x20`，两者都会使 `used()` 为真；这不代表产生两份业务命令，也不证明它走工具栏的 `UiPlaySelectAnimation`。菜单业务回调的去重和全部具体按钮的动作映射没有在本轮穷尽。
