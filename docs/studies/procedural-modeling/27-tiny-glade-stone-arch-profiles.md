# Tiny Glade 石拱形状与高度

发行版石拱的主轮廓是立方冠形，特定端部再混合单侧二次形。道路采样得到的抬升量是输入：石拱生产者会结合最高轮廓点、该点地面Y、墙参数和后续高度上限，改写整个高度数组。不能把道路遮罩的指数抬升直接当最终拱线，也不能把所有拱形叫半圆。

洞口分段前置见 [26 洞口范围与合并](26-tiny-glade-road-openings-and-merge.md)，铺砖和显示见 [28 拱砖与显示](28-tiny-glade-arch-bricks-and-rendering.md)，身份和范围见 [30 证据账本](30-tiny-glade-road-arches-evidence-ledger.md)。下面都是匹配发行版的静态指令和构造演算。

## 执行对象与调用链

`construct_arches`，RVA `7F0120`，按墙ID选中当前墙和它的104字节路径子段。`7F171C` 原始材料字段分支进入木框或石拱；石拱的实际调用在 `7F17D9`，目标 `create_stone_arch_profile`，`811D10`。

104字节记录的三个Vec分别保存高度、Vec3位置和曲线参数，LoopRange在+58。这些数组有不同单位和用途，不能把它们都当无类型的圆弧点。profile改写高度Vec；之后 ArchWalker 才把位置Y与新高度组合为三维拱线。

输入H/B可以由调用者提供，也可以从当前子段求出。调用者另传D，来自墙记录+294；完整上游编辑规则未知，不能把D固定成某个默认门高。

## 普通轮廓：立方冠形

`ArchFunction.remap_t`，`811820`，普通tag!=1的指令在 `811850–811885`。令：

```text
c(t) = (2*abs(t−.5))³
f_cubic(t,q) = 1−(1−q)*c(t)
```

对t∈[0,1]，两端f=q，中点f=1。q随当前节点的原始高度变化，所以它不是固定的一条标准曲线缩放。

**构造算例。** q=.25时，t=[0,.25,.5,.75,1]得到f=[.25,.90625,1,.90625,.25]。靠近冠部的增长很快；公式中没有圆、椭圆或平方根圆弧计算。这只解释选定分支，其他风格不能据此归为同一种形状。

## 端部轮廓：单侧二次与立方混合

tag=1时，第二字节选择r=t或r=1−t。代码以边段长度Ledge计算：

```text
w = clamp(inverse_lerp(2,1,Ledge),0,1) = clamp(2−Ledge,0,1)
f_quadratic = 1−(1−q)*r²
f = w*f_quadratic + (1−w)*f_cubic
```

`inverse_lerp` 的 `DE8220` 实际执行 `(x−a)/(b−a)`，因此混合方向是：短段≤1全二次，长段≥2回普通立方。不能把它倒写为 `clamp(Ledge−1)`。

进入tag1需要原始墙类别+258==2，并且 LoopRange 起点或终点触及相应输入端点（`811EAA–811F1A`）。这些枚举和端点参数的完整产品语义未恢复，不赋予“哥特”“拱券风格”等未经证明的名称。Ledge在 `811F60–811FAE` 累加相邻Vec3的欧氏距离。端部还按 `.1875` 的距离比例裁边/重采样XZ，保留原Y；仅有闭式f不能完整替代这一几何过程。

**构造算例。** q=.25、r=t：Ledge=1时，f(0)=1、f(.5)=.8125、f(1)=.25；Ledge=1.5时w=.5，f(.25)=.9296875；Ledge≥2时f(.25)=.90625。反向r=1−t会把单侧形状镜像到另一端。

## 从无量纲轮廓到实际节点高度

profile先选择H/B（`811D8A–811E99`）：optional结构tag=1时直接用调用者+4/+8；否则：

```text
H = max_i(baseY_i + oldHeight_i)
B = 取得上述最大值时的节点baseY
```

B不是所有点中最低地面，也不是整个子段的平均基座。等高节点的选择受实际比较分支影响，不由常见“稳定最大值”习惯补写规则。

随后 iterator producer `13EA400` 调 fold `141FDE0`。`141FF5E–1420108` 核得逐节点计算：

```text
t_i = i/(pointCount−1)
q_i = .5*clamp(oldHeight_i/D,0,1)
f_i = remap_t(t_i,q_i)
C = max(H−3.5,B)−1
newHeight_i = f_i*(H−baseY_i) + (1−f_i)*max(C−baseY_i,0)
```

这里H、B、baseY、oldHeight和newHeight都是不同量。函数把新Vec替换旧Vec（`812681–812693`），不是保留旧抬升再叠加新高度。D来源指令在 `7F1780`，optional H/B传递在 `7F1793–7F17C3`。

对于原始墙类别≤1，`812696–812795` 还有进一步上限：按LoopRange索引取墙+E0/+E8数组，正常有限值下执行：

```text
newHeight_i = min(newHeight_i, limit[index_i]−baseY_i)
```

该limit数组完整业务来源未恢复。不能无条件把主式输出称为最终拱高。

## 完整构造算例

前置：选择普通tag分支；假设原始类别为2，但该子段两个端点都在墙内部，因而不触发端部二次混合，也不进入类别≤1上限分支。五个点baseY均0，oldHeight均4，D=4，调用者不覆盖H/B。

1. 求最大值：H=4，B=0。
2. 每点q=.5；C=max(.5,0)−1=−.5，下方项夹为0。
3. t=[0,.25,.5,.75,1]，f=[.5,.9375,1,.9375,.5]。
4. 得newHeight=[2,3.75,4,3.75,2]，实际拱线Y=baseY+newHeight。

结果是抬高端部、冠顶4的立方轮廓。若某点baseY变为1，且其他状态保持H=4、D=4、oldHeight=4，则该点按自己的baseY扣除高度；例如中点f=1得到newHeight=3，世界Y仍4。这是条件演算，真实输入变化还可能同时改变H/B或其他墙参数。

## 独立实现规格与未知

可借鉴的结构是：先以覆盖得到候选段；为每段保存地面位置、抬升和曲线参数；再由段级H/B与节点级q生成轮廓；最后应用明确高度约束，交给按长度排列构件的消费者。独立实现需要自行定义风格、参数、退化行为和资产，不使用恢复代码作为生产实现。

尚未恢复：D和optional H/B的完整编辑来源、枚举产品名、端部裁边全部分支、limit数组完整来源，以及N=1、D=0、重合点、垂直段的调用端防护。常数来自选择的发行版，不能当长期不变的公开契约。

未做：没有启动游戏或执行原函数，没有用实际场景验证宽窄拱、地形高差和所有材料模式。

风险：无量纲轮廓、初始道路抬升、受限制的节点高度与最终可见砖边界是不同阶段；仅复现一条公式会漏掉端部重采样、地面高度和后续上限。
