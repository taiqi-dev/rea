## 对综合 demo 最有用的结论

第一，**分享作品和增加游戏内容是两套输入契约**。沙堡的地图方法候选、SUMMERHOUSE 的块布局文件都不能自动变成新模型/材质加载器。先确定上传的是“已有构件怎么摆”，还是“增加一种新构件”；两者都可由 Workshop 分发，但游戏要分别验证。

第二，**内容层可以统一，权利和来源必须分开**。内置、官方免费包、本地作者包、Workshop 包、正式 DLC 可共用稳定资源 ID、依赖检查和注册流程；Steam 下载状态、DLC 使用资格、存档启用集合各由自己的事实来源提供。不能因为文件已落盘或作品声明需要 DLC，就直接授予使用资格。

第三，**程序化结果不宜成为 Mod 的唯一权威**。建筑/地图保存参数、seed、稳定内容 ID 与版本；派生 mesh、LOD、碰撞及缓存由自己的现有系统建立。若未来允许 Mod 改变几何生成规则，就必须额外解决接口版本、旧世界迁移和失败原子性；不应在首个 Workshop 里同时开放。

第四，**内容可导入不等于成本可控**。自研需同时考虑每个资产和世界整体的纹理驻留、材质批次、几何/LOD、阴影和碰撞成本。按需加载和稳定批处理键优先于把所有订阅包一次性加载。数值门槛留给本项目规模与实际采样，不把参考游戏单文件限制当自研推荐值。

以上四点是独立设计归纳，不声称四款原作都已实现。详细状态、ID 示意、失败案例、平台 API 与分阶段交付见 [123](123-steam-workshop-and-dlc-design-for-demo.md)。

## 建议下一步

现在无需继续穷尽没有明确入口的游戏。最有价值的下一片是：**制定一个可脱离 Steam 使用的最小内容包与建筑蓝图契约，写清稳定 ID、版本、缺依赖、失败不污染世界和性能准入，再由项目现有负责人对齐已有实现。** 本轮只完成调查与建议，没有越界接入用户项目。

Workshop 集成随后验证上传更新、订阅安装和错误状态；DLC 再验证资格/安装/内容可用的区分。Steam 当前还支持按 beta branch 关联 Workshop 内容版本，但要主动配置，不能把它当作任意历史 Mod 的自动回滚系统。[官方版本机制](https://partner.steamgames.com/doc/features/workshop/itemversioning)
