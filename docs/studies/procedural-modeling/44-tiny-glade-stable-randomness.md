# Tiny Glade 稳定随机：对象种子、局部序列与空间噪声

发行版没有表现出单一的“全局随机器负责所有细节”。已确认的来源包括墙身份混合、局部分割种子、从零开始的屋瓦随机序列、实例计数器和空间噪声。它们的稳定条件不同；固定种子本身并不能保证建筑改形后每块砖或瓦仍保持原身份。

本篇串联新增证据与先前专题。[屋瓦布局](41-tiny-glade-roof-tile-layout-and-clipping.md)、[木墙板](43-tiny-glade-wooden-wall-board-layout.md)分别解释对应生产者；[局部重建](45-tiny-glade-shared-invalidation-and-rebuild.md)解释变化发布。身份与本輪复核见[第十一轮账本](47-tiny-glade-four-systems-evidence-ledger.md)。以下是静态规则及条件推导，未观察实际编辑画面。

## 1. 普通墙底种子确实混入墙身份

`construct_walls(808800)` 遍历墙ID并查Public墙状态。`8096B9` 对当前ID调用getter，`8096CC–8096DA` 用返回整数和PublicWallState的一个qword：

```text
S = wallId * 0x4B28021 + publicWallValue_at_0x48
```

运算按64位机器整数溢出。Public状态基址是当前记录尾指针−`0x2A8`，被加数读取于尾指针−`0x260`，所以value偏移为`+0x48`。字段的原始业务名、谁修改它和创建时取值尚未完整恢复；这里只能称每墙输入数值。不能凭它参与随机就声称它必然是UI中的“重新随机”计数。

`80AC7A–80AC81` 把S送入 `1446690 WallConstructor.from_curve`。这补齐了前轮[砖行研究](36-tiny-glade-brick-row-layout.md)的底seed来源，不是通过hashmap的随机查找器产生墙砖布局。哈希表桶的随机key与几何seed分别解释。

### 构造例：身份稳定的条件

wallId=7、每墙值=11，S=551,649,522；wallId=8时S=630,456,595。若保持id和值，仅改变某个高度输入，S不因上述公式改变。但下游边界数、区域索引和随机调用次数可能改变，因此最终砖块不保证一一保持原样。

更换id或改每墙值都会改变S。该公式不包含时钟；这只说明选定构造路径的直接输入，没有证明其他系统都不使用时间。

## 2. 墙行身份进一步改变随机序列

先前发行版指令确认，设B为纵向边界数、r为裁后记录索引：

```text
横分seed     = S*0x154DF + B*0x159 + r*0x96A3DD
辅助seed     = S*0x91E   + B*0xDF  + r*0x91FD
厚度seed     = S*0x15B3  + B*B     + 0x2A6 + r
行端seed     = S*0x17D32 + B*0x8BA
```

因此B变化会改变多条随机流；墙顶裁段使r改变，也会影响其他记录。r不是永久砖ID。不同用途各有混合，不能把“同一墙seed稳定”推成“所有随机分量都稳定”。

### 构造例：加高跨过分行门槛

保持S和r，B从5变6：横分seed增加345；厚度seed增加11；行端seed增加2234。相同候选的最终随机值是否变化仍需实际RNG求值，但这些输入已经不同。若增加一个开口使裁后记录索引改变，还会叠加r项。

CPU正弦另将整数seed转float，并使用高度边界生成参数；同一个高度值和seed沿墙重复使用同一波形链。原始整数身份和浮点参数不是相同表示，较大整数转float会丢低位；不能用波形参数当唯一对象ID。

## 3. 木墙板的种子关联区域和端点

新恢复的大板拆分函数 `14882C0` 不只是依次抽取所有板宽。一个选定分支按墙ID、片段计数和长轴端点float位模式混合：

```text
seed = wallId
     XOR (pieceIndex * 0xF4243)
     XOR ((u64(u32bits(axisMin)) * 0x10C6F)
          XOR (u64(u32bits(axisMax)) * 0x17CFB))
```

位模式先零扩展为u64，再做64位乘法和XOR，乘加按mod2^64；不能按u32乘法截断。各子片在split处重新生成相应seed。pieceIndex来自区域/类别分组的计数，完整上游身份仍部分未知。尺寸阈值和区域方向决定是否进入拆分，详见[木墙板布局](43-tiny-glade-wooden-wall-board-layout.md)。

这个规则把随机拆分关联到当前区域几何。端点改变，即使墙ID不变，混合输入也变；洞口使区域重新拼接和编号，同样可能改拆分。

### 构造例：只移动区域上端

固定wallId与pieceIndex，axisMin=0。axisMax从1到2时，float32位从`0x3F800000`变成`0x40000000`，乘法项随之改变。后续不能无条件沿用先前长板断点。此例隔离混合规则，不是重放完整木墙。

## 4. 屋瓦的局部随机状态从零开始

在本轮选定装配器中：

| 路径 | 实际初始化 | RNG使用 |
| --- | --- | --- |
| 矩形 `2812C70` | `2812CFC` 将局部Rng qword置0 | 同一局部cell送内部随机f32调用 |
| 圆形 `2816BA0` | `2816C24` 将局部Rng qword置0 | 同一局部cell送随机调用 |

没有在这两处初始化中混入时间或墙ID。固定初态、相同调用次序及相同算法意味着相同随机序列；调用次数或分支变化会重新对应到不同瓦片。

`E02880 Rng.f32` 已恢复为：

```text
state += 0xA0761D6478BD642F           // u64 wrap
product = state * (state XOR 0xE7037ED1A0B428DB) // 128位乘积
bits = (product_low_u64 XOR product_high_u64) 的低32位
U = bitcast_f32((bits>>9) | 0x3F800000) - 1
```

这给出[0,1)的f32；它是已定位局部RNG的规则，不能宣称全游戏都采用这一种算法。

### 构造例：重复与插入调用

两个装配调用都从state=0开始，第一次均先加固定增量，再做相同128位乘法和bit转换，得到相同U。若其中一个分支多消耗一次RNG，后续第k块构件会消费另一序列位置。固定seed能解释相同输入重算的可重复性，不能替代瓦片身份匹配算法。

## 5. 实例seed与布局RNG并非同一个字段

矩形屋瓦的实例counter从0开始（`2812EEA`），写入64B RoofTile的`+34`；某些额外输出与主输出共用counter，随后才递增。圆形counter也从0开始（`2816D0B`）并在内循环递增。**实例seed可能重复**，不能视为唯一瓦片ID。

普通转角又有两种seed：RNG为`cornerIndex+sumY`，实例计数从sumY开始逐合格band组递增；同组碎片共享。sumY来自附近洞中心高度的整数转换，见[转角研究](37-tiny-glade-brick-corners-and-noise.md)。

seed字段通常给显示变形一个确定输入，几何、对象身份与随机状态仍各有作用域。具体生命周期必须看生产者与资源所有者，不能根据字段名合并。

## 6. 空间噪声与物理槽位也会改变细节

已确认的普通砖GPU路径按空间场产生XZ位移，曲梁另使用物理实例槽位和顶点Z构造截面扰动；曲梁下垂则按seed生成幅度，详见[显示篇](39-tiny-glade-wall-and-timber-rendering.md)。

由这些输入可以推导：移动几何会改变空间采样位置；更换物理槽位可能改变那条截面扰动链。尚未恢复所有分配规则，不能断言“建筑只是平移时任何细节都永久稳定”，也不能说重建一定换槽。

陆地植被还会按栅格坐标生成候选，见[植被专题](46-tiny-glade-land-vegetation-and-exclusions.md)。候选位置稳定与排除资格变化是两层计算：道路、水域或建筑改变，可令原候选不再合格，而不是一定重抽所有随机点。

## 7. 独立实现可以建立更明确的稳定契约

自研时可分别定义：对象永久ID、布局区域ID、随机流用途和显示实例槽位。对需要保留的细节，应让seed关联稳定的逻辑身份；对需要随尺寸重排的内容，应明确关联当前几何，并保存哪些构件允许重新分配。不要把GPU物理槽位当永久身份。

可以用相同输入重建、只改高度、移动开口、插入新区域、删除再创建这五类操作验证自己的稳定规则。上述是独立设计建议，原游戏全部操作的稳定性仍需运行场景才能确认。

风险：序列位置、区域计数、浮点转换和物理槽位都可能影响细节；局部确定性不等于跨版本、跨硬件或跨操作身份稳定。
