## 实施选择与产品边界

1. 先核现有世界/命令/资源/时钟/保存/Host-Replica/导航/战斗/Mod 入口；已有能力直接扩展，不平行新造一套世界或账本。项目中的 `Workshop` 一词也可能指建造工作坊或联机功能，名字相同不证明已经接了 Steam UGC。
2. 若已有适用的脚本/规则运行器，优先复用。否则可先用受约束、版本化的事件—条件—动作规则实现行为 Mod，明确其能力与限制；不能把参数替换包装成通用脚本支持。新增外部依赖、VM 或 native loader 不在本次隐含安装授权内，先形成具体必要性与选型提案，继续不依赖安装的实现。
3. 初片默认不永久破坏原家园、不启用付费购买或奖励绕过。复用已有挑战/世界会话边界；没有适用边界时先设计最小原子方案，再申请实际共享写入窗口，不能先私造一套临时世界/存档桥。永久损坏、完整 RPG 和所有玩法组合仍是后继产品范围，不塞进这片。
4. 模块状态是同一保存事务中的扩展数据；World/wire/schema 的具体版本只能在实际 main 与唯一窗口上冻结。旧格式必须严格识别并显式迁移，错误保留；不能用 sidecar 存档或“暂时兼容”绕过完整消费者。
5. 首片可交付本地内容链，Steam Workshop 上传下载、正式 DLC 上架/购买资格实接和任意高权限代码插件属于后继片。保留适配边界，不伪造 Steam 订阅/拥有结果，不把本地 Ready 冒充线上可用。
