# Tiny Glade：点击动画触发、完成命令与按钮排时序

2026-10-23，Pacific Time。续接 [144](144-tiny-glade-ui-motion-static-chains.md) 的三个断点：开始交互的命令到底插入什么、完成时移除什么，以及整排按钮是否按序号错峰。菜单自身的输入与绘制另见 [146](146-tiny-glade-menu-state-to-render-motion-boundaries.md)。

**已确认所选工具栏开始交互分支排入 `UiPlaySelectAnimation`，进度到 1 时排入该组件的移除命令。** 两者携带实体身份，经 ECS 命令发布；不是立即销毁按钮，也不是菜单通用的完成通知。所选父子显隐与进度消费者没有按序号延迟，仍不足以断言所有 UI 都绝无错峰。

## 身份、方法与复核

沿用 [146](146-tiny-glade-menu-state-to-render-motion-boundaries.md) 的同一 EXE/PDB 身份、基址与静态限制。回执位于 ignored `.cache/procedural-modeling/tiny-ui-motion/`，关键读取由 [ui_motion_publication_probe.py](tiny-glade/tools/ui_motion_publication_probe.py) 复核。没有运行游戏或 Unity、检查用户工程或新增摘要。

本轮的关键变化来自 DbgHelp 的完整泛型名：同一地址可能另有 size=0 的 mangled alias。只看这种 alias 会丢掉类型；本轮将完整 typed name、真实 call/LEA 和消费者指令对齐，没有仅凭名字宣布调用成立。

| ------------ | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 触发条件     | `0x14297D40B–0x14297D413`                       | `render_taffy_ui_to_widgets` 调 `dragged()`，只在返回 tag 3 时进入所选反馈分支                            |

| 反馈参数     | 常量加载 `0x14297CAB7`、写入 `0x14297D456`      | 所选参数为 float `0.2,0.2`，进度初值为 0                                                                  |
| 命令回调     | `0x14297D43F` → `0x1411AE9E0`                   | 队列回调的完整类型含 `entity_command::insert<UiPlaySelectAnimation>`                                      |
| 有效实体检查 | `0x142351070`，特别是 `0x142351080–0x1423510A5` | 按实体索引/代次和当前位置验证后，才继续实体操作                                                           |
| 实际组件插入 | `0x1423510E2` → `0x142355C60`                   | 完整泛型为 `entity_command::insert::closure_env$0<UiPlaySelectAnimation>`；有实际 bundle/storage 插入路径 |

由此，144 中“参数载荷可能对应选中动画”的断点已接上。对**这一条开始交互分支**，结合已恢复的消费者，幅度 `A=0.2`、时长分母 `D=0.2` 成立。不能把它推广成所有菜单点击、所有工具或所有设备的唯一默认时长。

`dragged()==Started` 与另一处 `clicked()` 不同：后一处在 `0x14297D5E3–0x14297D647` 写点击事件。开始反馈可以早于业务激活/成功，不应把弹一下当作建筑已经提交。

**构造例。** 一个已通过前置筛选、有效的工具按钮进入 Started 分支，排入实体 E 和上述参数。命令应用后，E 具有该动画组件，动画系统才能消费它。若 E 在应用前已失效，实体检查阻止写入另一个复用索引的实体；具体错误处置还有 wrapper 的策略，不等同于“保证按钮一定播放”。

## 进度到 1，排入的是移除组件

已恢复的局部计算不变：

```text
q = clamp(q + dt/D, 0, 1)
u = 0.1 + 0.9*q
factor = 1 + A*(4*u*(1-u))^2
```

`ui_select_animation` 在 `0x14297BF5A–0x14297BF64` 读取写回后的 q，与 float 1 比较；不相等或无序比较时跳过所选完成分支。等于 1 时：

1. `0x14297BF81` 取回调 `0x1411AF020`，写入队列；载荷包含实体身份和错误处理函数。
2. 完整类型明确为 `entity_command::remove<UiPlaySelectAnimation>`。
3. 回调经 `0x1411AF089` 调 `0x142363DE0`，实际进入 BundleRemover 移除该组件，而非 despawn 按钮实体。

倍率在 q=1 时回到 1。完成命令也不是立即的状态删除：它仍需命令队列被执行。所选 wrapper/实体操作内部有 flush 调用，但**这不独立证明动画系统与输入、布局、渲染之间的全局 deferred 屏障或同帧顺序**。

特别要保留一个边界：实体代次保护不等于动画代次保护。所选完成命令携带 E，不携带某次 pulse 的独立 generation。旧完成与新触发同次更新交错时，最终谁先应用尚未查清；不能报告已经观察到吞动画，也不能保证旧移除绝不影响新组件。

**构造例。** 自行给稳定有效的本分支 `dt=0.05`。组件应用后，四次有效更新的 q 为 0.25、0.5、0.75、1，最后一次输出中性倍率并排入移除命令。按钮逻辑实体保持存在。四次更新不等于命令应用起点必然落在玩家按下后的第一帧。

自己的实现应明确成功、失败、短反馈和命令结果各自的所有者；重触发与完成回调使用自己的动画代次或取消令牌，具体规则见 [145](145-independent-cozy-ui-motion-spec.md)。这是独立改进建议，不冒称原作已有相同机制。

## “一排出现”分三种机制看

### 普通父子工具排

`ui_show_if_parent_in_focus` 在 `0x14297EA11` 读取父 `UiInteractionState+1`，在 `0x14297EA63` 写子 `+0`；附加条件仍可能再覆盖显示位。`ui_animation_state_update` 的所选消费者只按每个子项自己的进度和共同 dt 做 `p += ±4*dt` 并 clamp，未在该区间读取子序号、每项 delay 或目标开始时间。

所以**已覆盖链是共享显隐目标、各项独立进度推进**。若所有子项从相同 p 开始、同次打开且受到相同后续条件，它们就同步缩放。这个结论有明确前提，不能越过尚未穷尽的初始化和其他写端。

`add_toolbar_item` 的选定构建入口在 `0x142B557FD` 调用已由完整 PDB 类型确认的 `Commands::spawn<(...TaffyNode,UiInteractionState,UiAnimationState,...)>`。附近有零值初始化，但本轮没有逐字段恢复整个 Rust tuple 的内存重排，**不把相邻零写直接认作每个动画字段的完整初值证明**。

### 布局联动造成的顺次位移

144 已接通临时倍率 → Taffy 尺寸 → 重算布局 → 按钮中心/尺寸。不同宽度、对齐或已有聚焦状态能让邻居看起来先后移动，不要求存在 `delay=i*step`。文字 bounds 下限也可能让一个按钮比另一个更早达到可见尺寸。

### QuickToolPalette 的另一组进度

`quick_tool_palette_update`（`0x1411C66A0`）另有自己的资源与门控：活动分支在 `0x1411C6F39–0x1411C6F5A` 将 `dt/0.1` 加到资源 `+0x58` 并以 1 截顶；`+0x5C` 的另一进度按方向以 `4*dt` 往返。另一个 `+0x61` 标志打开时，`0x1411C71EF` 先算 `6*dt`，在后续遍历里有条件加到选定记录的标量，所有记录满足结束比较后清该标志（`0x1411C7508–0x1411C7522`）。

这是另一套进度/完成门，不应和普通子工具排、主暂停菜单合成一条时间线。本轮没有完整还原这里每个记录的组件映射，因此也不把上述 `dt/0.1` 或 `6*dt` 宣称为逐按钮错峰。

**构造例。** 四个普通子按钮初始 p 都为 0，同次目标打开、各收到 `dt=0.05`，则 p 均到 0.2、缓出均为 0.488。这是同步出现的演算。若要证明原作逐个错峰，必须找到某个真实初值或显示位写入者按 i/时间延后；本轮仍未得到该证据。独立方案可以有意增加错峰，但须标为自己的设计。
