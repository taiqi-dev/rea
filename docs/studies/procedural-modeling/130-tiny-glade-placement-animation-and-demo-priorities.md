# Tiny Glade：建造出现动画、局部过渡与 demo 优先级

后续 [131](131-tiny-glade-placement-lifecycle-and-animation-handoff.md) 已确认新屋顶两路零进度初始化，并把第二路接到尖顶实例的 `roof_animation_t` 与上传；确认/取消/连续编辑/历史回放分别说明。[132](132-demo-building-feedback-state-and-update-budget.md) 提供独立交互与成本规格。下文未决项保持本轮历史范围。

2026-10-21，Pacific Time。用户观察到放房子有动画；木框专题见 [129](129-tiny-glade-timberframe-placement-preview.md)。本篇区分 CPU 动画进度、实例的顶点表现、瓦片运动与贴图平滑，给出适合独立 demo 的实施取舍。**这些局部效果已有静态依据，但木框何时退出、建筑何时完全接管显示的时序还未闭合。**

本轮未启动/附加游戏，未检查或修改用户工程，未录制画面或做 GPU/FPS 验证。公开商店说明强调建筑会逐件装配砖、石、板材，它支持产品表现的方向，不能替代下文实现证据。[Tiny Glade 官方商店](https://store.steampowered.com/app/2198150/Tiny_Glade/)

## 先区分四层运动

| 层次           | 已确认的实现片段                                                                                                     | 能解释什么，不能解释什么                                                            |
| -------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 木框及交互提示 | 独立 `timberframe` 生产器；signifier 有动画时长、easing 与动画系统入口                                               | 可以单独设计“候选变尺寸、确认/取消后消退”；本轮没有把所有 setter 与木框实际调用连接 |
| 屋顶 CPU 状态  | `system_roof::visual::roof_animation::roof_animation` VA `0x142808270`、1,119 B，更新两个相邻 float 并限制到 `[0,1]` | 存在持续的动画参数推进；两字段与所有 shader 成员的逐项对应尚未完全建立              |
| 组件顶点表现   | 尖顶读取 `roof_animation_t` 并使用衰减振荡缩放                                                                       | 至少这个局部不是只提交一次最终形状；不能推成每面墙和每块木板都用同样曲线            |
| 瓦片运动       | `roof_tiles_gravity` compute 使用逐实例状态、帧步长、速度与接触/粘合处理                                             | 有局部可动细节；不是完整刚体、碰撞或整屋物理施工证明                                |

成品出现、编辑时的几何平滑、拆除/撤销退场和普通 UI 提示需要分别追。不能因为都有动画，就假定它们共用一条时间轴、同一缓存失效规则或一个整栋模型 AnimationClip。

## 屋顶进度：有连续状态，但还不能承诺固定时长

本轮实际读取 CPU `roof_animation`。`0x1428085BA–0x14280866C` 存在两路参数的推进/回退：读步长、乘比例、加到现值、限制到 `[0,1]`，然后回写。常量包括 `-4`、`-10`、约 `2.8571429`、约 `3.3333333` 和分支倍率 1/2；第二路还受约 `0.99` 阈值控制。

关键写点为 `0x14280863C` 的第一 float 和 `0x14280866C` 的相邻第二 float。代码会区分 `Roof::is_flat` 与另一状态位；该状态位的完整语义、字段名以及创建/撤销时怎样初始化仍待追。不能直接把这些比例写成“放置一定播放 0.3 秒”或认定哪一路对应哪类构件。

这给自研一个有价值的职责拆分：正式形状/版本先确定，显示状态按自己的进度到达目标；进度不是另一个世界状态或每帧重新执行一次建造命令。具体何时出现与退出要消费真实提交结果，不能在失败请求之后仍把房子动画播放为建造成功。

## 尖顶回弹：局部公式已经可以说明为什么有弹性

本轮重新解析 `instanced_roof_spire.precomp`，四个模块共 2,574 条结构指令；所选 vertex 模块文件偏移 159。实例类型明确含 `roof_animation_t`。`0x15FB–0x1703` 中的可读表达为：

```text
s(t) = 1 + 2^(-10t) * sin((10t - 0.75) * 2.094395160675049)
p = position + 0.5 * s(t) * vertex_morphed
```

这是指数衰减的振荡：缩放会超过目标再回落。以归一化 t 作独立算术代入，`t=0` 时 s 约 0，`0.1` 时约 1.25，`0.2` 时约 1.125，`0.6` 时约 0.984375，`1` 时约 1.000488。**t 不是已经确认的墙钟秒数**，这些数字也不是测得的动画帧；原点、参数变形和其它条件仍影响最终画面。

该 shader 与旧专题 [05 尖顶](05-tiny-glade-seams.md) 的身份和公式相符。本轮补的是新机器的解析复核与 CPU 状态入口，没有把已有公式包装成首次发现，也没有恢复所有 CPU→GPU 字段绑定。

## 瓦片并非跟整栋屋顶一起硬切

重新解析 `roof_tiles_gravity.precomp` 得到 1 个 compute 模块、403 条指令，偏移 108；`RoofShingle` 含 `scale__t`、`animation_t` 及已有的高度/压缩运动字段。旧 [02](02-tiny-glade.md) 已分析加速度、积分、接触和粘合，本轮确认相同制品和字段仍存在。

这说明建造的“活起来”可以来自不同尺度的运动：主轮廓短暂回弹，少量局部构件有自己的响应。自研无需让每块砖都成为 GameObject/Rigidbody；先用自己的组件/实例参数实现一层可见过渡，再根据表现价值决定是否需要逐片运动。这里没有测得原作的 CPU/GPU 收益。

木框共用的 `nani_wooden_plank` vertex 模块主要读取 `transform`、seed、颜色来源与 flags，所选结构没有独立的 `animation_t` 成员。它可能通过上游变换更新产生运动；不能仅由屋顶曲线推断每根木框梁也读取同一动画参数。

## 一个容易误认的名字：建筑栅格动画

`rasterize_buildings_animate.precomp` 名字很像“房屋出现”。但本轮取得的 153 条 SPIR-V 指令只显示它逐像素读取一张 mask、保持第一分量，并将第二分量向第一分量混合：速率由第一分量是否小于 0.5 选择 3 或 0.5，再乘 frame delta。最终写回 `(原第一分量, 混合结果, 0, 0)`。

这是所选贴图通道的时间过渡，不能独立证明木框→实体网格或逐砖出现的效果。最终 mask 消费者与完整调用时序未在本轮跟完。把所有名字里有 animate 的 pass 都计入“建造动画”，会混淆几何、交互和栅格这三种成本。

## 借鉴到综合 demo：按这四步做最划算

以下是独立建议，尚未读取当前项目代码或执行实现，不替项目 owner 冻结工期、共享窗口或验证结果。

| 顺序                      | 应得到的玩家体验                                             | 实现边界与成本控制                                                                   |
| ------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 1. 参数同源的框架预览     | 玩家看清房屋范围、高度和接地，拖动时前后建筑不被完整预览遮住 | 复用现有候选几何/校验；少量梁/线段，材质共享、采样有界；预览不写存档/历史            |
| 2. 确认后的短暂出现/回弹  | 确认后成品有轻微展开、落定或回弹，失败时不会出现成功表演     | 消费正式成功/几何发布结果；动画作用在显示层，不额外提交建造命令或复制碰撞权威        |
| 3. 编辑、取消、撤销的过渡 | 改尺寸连续，取消与撤销收得干净，快速连点不出现旧房子回弹回来 | 按实体与最新版本替换目标；新操作接当前显示值，旧回调失效；切世界/读档有明确重置      |
| 4. 适量声音和局部细节     | 尺寸变化、放置落定有对应轻声音，必要时少量瓦片响应           | 以有意义事件/数量变化节流；限制同时动画实例与阴影，先不引入逐砖刚体和大量独立 Update |

对于有塔防/角色碰撞的自研项目，视觉过渡不能悄悄改变正式占用、路径、命中或建造成功时点。显示与最终物理形状暂时不同，应选择不会误导操作的幅度或在发布边界控制可交互时点，并保持一份正式几何。是否缩放整屋、只缩放装饰/顶形或分部件揭示，由实际表现和碰撞需求决定，不直接照搬自由造景游戏。

**独立状态算例：** 临时候选 C7 随指针改变尺寸；玩家确认后请求 R8 成功，正式实体 B12/版本 V24 发布，显示层从当前值过渡到 V24。过渡未完又提交尺寸 V25，显示接当前值转向 V25，R8/V24 的迟到结束回调不能覆盖 V25。若撤销，消费已有历史结果并释放相应显示；不另造动画历史或保存器。读档可以直接重建最终视觉，避免整张地图重新播放建造并重复音效，这项产品选择需 owner 明确。

这里应优先研究的最后断点是：**输入候选→木框生产/释放→正式命令与几何发布→出现进度重置**。它直接影响可用性；继续追所有材质槽或逐砖运动参数对当前 demo 的收益更低。主轮廓和预览先完成，再决定是否投入昂贵的逐构件动画。
