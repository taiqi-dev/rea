# Tiny Glade：G-buffer 输出与 `gbuffer_tex` 句柄对应

[72](72-tiny-glade-cpu-render-bindings-and-lifecycle.md)证实了两个 pass 的 CPU 注册，但保留了纹理句柄同一性。本轮在**同版发行 EXE/PDB 的静态指令**中继续追到 shader 参数绑定：`render_world` 创建的 `gbuffer` 图资源记录进入 `main_pass` 首个 color attachment，后经结构复制进入 `deferred_raster` 的 shader 参数第 1 绑定；发行版 `solid_light_sun_sky` fragment 的 `gbuffer_tex` 正是 set 0 / binding 1。因此这个绑定在所追分支上使用该 G-buffer 图资源记录，不再只是两个 pass 名称或像素格式相容的推断。

## 证据范围

目标是 [70](70-tiny-glade-update-and-render-costs.md) 已核对身份的 `C:\Software\Steam\steamapps\common\Tiny Glade\tiny-glade.exe` 与同目录 PDB；地址均为 EXE preferred VA。正式 `digging-a-hole/tools/pdb_probe.py` 用精确掩码定位，VS2022 `dumpbin /DISASM /RANGE` 读取目标函数。新原始投影位于 ignored `.cache/procedural-modeling/static-chain-followup/tiny-glade/` 的 `render-world-setup.txt`、`solid-shader-args.txt`、`half-res.txt`、`grass-velocity.txt`、`apply-shadow.txt` 和符号 JSON；连续调用处复用 [72](72-tiny-glade-cpu-render-bindings-and-lifecycle.md) 的 `.cache/procedural-modeling/render-chain-followup/tiny-glade/{render-world-slice,main,deferred-raster,deferred-graph-raster,solid-binder}.txt`。SPIR-V 装饰指令复用 `.cache/procedural-modeling/followup-art-updates/tiny-solid-light.json`。没有运行、附加或读取私人存档，也没有开启共享 REA native session。

## 逐跳句柄链

| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 创建                       | `render_world` 的 `0x1400FA851–0x1400FA874` 将 `0x142E4260A` 的 7 字节字面名 `gbuffer` 放进资源描述并调用 `GraphApi::create_raw_resource`；返回的 32 位句柄在 `FA87A` 写入局部资源记录。`FA8B8–FA8F0` 整理记录，`FA9C3–FA9D8` 将其前 24 B 拷至 `[rbp+7B0h]`。                                                                                                                                                    | `[rbp+7B0h]` 是本次创建的 G-buffer 图资源记录；相邻 `velocity` 是另一次 `FA941` 创建，不是同一句柄。                                                                                      |
| 作为输出 attachment        | `0x1400FABBC` 以 `r8=&[rbp+7B0h]` 调 `main_pass`（`FABCD`）。其 `0x1409ACB48–0x1409ACBA0` 构造字面名 `G-buffer` 的 raster 参数：首个 color attachment 的资源指针 `[rbp+58h]=r8`。                                                                                                                                                                                                                                | pass 的输出 attachment 指向上一步资源记录，而非仅与其同名。                                                                                                                               |
| 保存与再次传参             | `render_world` 的 `0x1400FB89C–0x1400FB8D3` 把 `[7B0h..7EFh]` 复制到 `[5F0h..62Fh]`，`0x1400FBA1D–0x1400FBA52` 再复制到 `[198h..1D7h]`。所以首个 24 B 记录从 `[7B0h]` 到 `[198h]`。`0x1400FBC3E` 取 `r13=&[198h]`，`0x1400FC30A–0x1400FC314` 以 `r8=r13` 调 `deferred_raster`。                                                                                                                                  | 被传给光照函数的结构首项是 G-buffer 记录的按值副本。`+0x18` 是另一项：`7B0h+18h=7C8h`，复制后为 `198h+18h=1B0h`；不能把它当成首项。                                                       |
| 从 pass 捕获到 shader 参数 | `deferred_raster` 在 `0x1409EA405` 保留 `r8` 为 `rdi`，`EA6E4` 把它存入本地捕获块 `[rbp+80h]`。其 `GraphApi::raster` 专门化在 `0x14175BC73` 取第五实参所指的捕获块；`BD25` 从块 `+0x30` 取回该 G-buffer 结构指针，`BD81` 写到 shader 实参块 `+8`。`0x14175BEBA` 以这个实参块调用 `shader_with_compatible_args`；后者 `0x1419E7346–0x1419E7392` 复制实参并调用 `solid_light_sun_sky::vs_main::bind_entry_point`。 | shader binder 收到的实参 `+8` 指向同一个 G-buffer 图资源记录副本。第五实参的寄存器/栈对应由 Windows x64 调用约定与该专门化的 prologue 一起核对；不是把附近的 `r13` 名称直接等同资源类型。 |
| 精确绑定号                 | binder 的 `0x140ADDEEA` 读取实参 `+8` 指向的资源，`0x140ADDFFF–0x140ADE04C` 将它加入从 0 起的绑定索引 `+1`；调用者 `0x1419E7365 / 7384` 先把索引基址设为 0 并传给 binder。`solid_light_sun_sky` fragment 的 `OpDecorate` `w1539`、`w1543` 分别给名为 `gbuffer_tex` 的 ID 419 指定 `Binding 1`、`DescriptorSet 0`；ID 425 的 `depth_tex` 为 binding 2（`w1547 / 1551`）。                                         | **set 0 / binding 1 的 `gbuffer_tex` 取自 `render_world` 创建并用作 G-buffer color attachment 的资源记录。** 深度与速度记录有独立位置，不能靠相邻地址混称。                               |

以符号 `G` 表示 `FA874` 返回并写入资源记录的句柄值：`G` 位于原始记录 `[7B0h..7C7h]`，按 16 B 加 8 B 两段复制到 `[198h..1AFh]`；光照 binder 的实参 `+8` 指向该副本并登记为 binding 1。这里的 `+0x18` 是记录步长，**不是新纹理 ID**。这是一项地址和字段的构造演算，没有伪造实际运行句柄数值。

## 边界与核验

`render_world` 复制后、调用 deferred 前还将该结构指针交给 `late_forward_and_deferred_pass`、`extract_half_res_depth_normals`、可选 `reconstruct_grass_velocity` 和 `apply_screen_shadows`。已读函数体中未见对首个 24 B 记录的直接写入：前两者围绕它构造 pass/资源访问，草速度函数只在 `+0x18` 与 `+0x30` 构造附件，屏幕阴影函数读取其字段。仍不把这些局部反汇编提升为整个渲染图的不可变性证明；图资源版本、别名、图编译后实际纹理对象与 GPU 执行结果尚未观测。**本轮结论是 CPU 图资源记录及 binder 槽位的同一性**，不是每个运行帧必经该 shader、无中间图变换或最终像素效果。

验证：重新读取 PE `.rdata` 的 `gbuffer` / `velocity` 名称，核对上述函数地址、复制区间、第五实参、binder 索引与两条 SPIR-V `OpDecorate`；本文相对链接和文本检查通过。目标运行、GPU 抓帧与耗时测量为 **Not Run**，本任务限定静态证据。
