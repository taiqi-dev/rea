## 如何读这组文档

- **发行版指令**：实际 EXE 的 x86-64 指令，或实际包内 SPIR-V 指令支持公式、分支或直接调用。
- **符号/行记录**：匹配 PDB 支持函数位置及编译时文件名，不能独立证明算法。
- **推导**：从已确认的局部公式说明几何效果，或提出职责解释。
- **独立演算**：我们重新表达公式并计算例子，没有执行游戏函数。
- **未知**：未贯通的调用、类型字段、分支或运行语义。未知处不拿常见做法补齐。

CPU listing 中的地址是 **RVA**，首选 VA = `0x140000000 + RVA`。本轮选定 `.text` 函数的文件偏移 = `RVA - 0xC00`；不能把这个换算套到所有 PE section。SPIR-V 文档中的偏移是原 `.precomp` 文件偏移，不能与 CPU RVA 相加。

## 算术检查

`math-validation.json` 记录以下独立检查；使用 Python 双精度，不能证明发行版 f32 的逐位一致。

1. 在五种形状参数上检查 20 点幂曲线的端点、单调性和逆映射，共 100 个点。
2. 用固定随机种子的 2000 对有限轴对齐矩形核对未过滤差集的面积，以及四角包含计数不会为 3。此模型不复制石砖全部属性规则，也不涵盖木墙尺寸过滤后的面积。
3. 两组平面/位移核对 `d' = d + dot(p_before-p_final,n)` 在相应顶点保持判定值。**Flat** 插值使它不构成整片三角形或每个片元的严格不变保证。

三组均通过。专题里的具体例子是公式演算，不是原游戏截图、存档或运行轨迹。

文档复核：8 份 Markdown 以 UTF-8 读取，25 个相对链接目标存在，代码围栏配对，无尾随空白。EXE、PDB 及本轮直接引用的 5 个 shader 输入共 7 个制品重新计算 SHA256 一致。瓦片片元的平面条件及 Flat decoration、屋顶高度/屋脊的常量和分支做了额外指令抽查；接缝报告对未恢复的排序辅助函数保持推断。

本机复核产物为 `study-validation.json`、`math-validation.json`、`tinyglade-symbols/roof-formula-examples.json`、`roof-assembly-formula-examples.json`、`tinyglade-intersections/findings.json` 与 `tinyglade-seams/seams-findings.json`，均位于总身份文档列出的聊天产物根目录。它们记录局部覆盖，不代表整款游戏恢复完成。
