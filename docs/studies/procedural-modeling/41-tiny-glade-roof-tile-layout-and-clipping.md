# Tiny Glade 屋瓦铺排：矩形、圆形与实例姿态

本轮把CPU瓦片生产者与GPU实例字段对应起来，并恢复圆形屋顶的分层环排、每环数量、随机旋转和剖面倾角。矩形屋顶已有分段公式得到继续验证，非默认裁平面也找到生产链，详见[42](42-tiny-glade-roof-edge-planes-and-seams.md)。完整末排、屋脊拓扑和最终姿态仍部分未知。

屋顶剖面与尺寸见[03](03-tiny-glade-roof-shapes.md)，随机稳定条件见[44](44-tiny-glade-stable-randomness.md)，身份与复核见[47](47-tiny-glade-four-systems-evidence-ledger.md)。下面是匹配发行版的静态调用/指令推导，内部单位没有校准成米。

## 1. 先清旧，再按当前屋顶资格装配

`1F46490 assemble_roof_tiles` 在 `1F46A65→1F4A6C0 RoofTileSsbo.clear` 清当前对象旧瓦片，随后检查flat和Public墙资格。符合非flat条件后，选定路径按roof的raw byte分派矩形 `2812C70` 或圆形 `2816BA0`。

因此清旧是实际调用，不是仅由符号名猜测。无新瓦片的资格分支也可能发生在清旧之后；不能把它当成保留旧瓦片。后续[50消息与索引回收](50-tiny-glade-roof-edit-messages-and-regeneration.md)补通执行对象选择和clear内部机制；全部类型分支及最终GPU上传时序仍未完整恢复。

## 2. 输出明确是64B瓦片记录

矩形装配器的五个输出调用点 `2813872/281403C/2814216/28155F7/2815877` 到闭包 `2816720`；圆形的 `281764A/28178B9` 到 `2817E20`。这些闭包实际调用 `1F49FD0 RoofTileSsbo.push`，writer以四次16B拷贝保存一个64B记录。

CPU写入、half打包和 `nani_instanced_roof.precomp` 的 shader字段/Offset共同确认：

| 字节偏移（十六进制） | 内容 |
| --- | --- |
| `+00` | base_position，float3 |
| `+0C` | current_height |
| `+10` | clipping_plane，四half |
| `+18` | scale三个half及t一个half |
| `+20` | rotation_quat，四half |
| `+28` | wall_slot_id |
| `+2C` | 压缩velocity |
| `+30` | animation_t |
| `+34` | seed |
| `+38` | is_circle |
| `+3C` | is_main_roof_body |

64B既保存几何也保存动画/裁剪参数，不能当成4×4矩阵。字段名来自shader元数据，CPU原始完整类型没有恢复。当前对应建立到专用writer及字段布局，完整render-graph绑定/上传身份仍未独立追完。

### 构造例：定位同一实例的属性

记录基址S：裁平面占S+16..23，四元数占S+32..39，实例seed在S+52，两个标志在S+56/60。改变裁平面不会按此布局直接覆盖四元数；将80B木梁格式套进来则会错位。

## 3. 矩形分段：保留端点，随机内部界线

沿用前轮已确认的矩形剖面/映射链，选定区间按世界尺度曲线总长Lws得到：

```text
N=max(2,roundf(Lws/.625))
requestedJitter=.125/Lws
```

N是边界点数量，初始区间数N−1。`random_splits`固定0/1，内部边界为：

```text
j=min(requestedJitter,.495/(N-1))
u_i=i/(N-1)+(U_i-.5)*j
```

这个尺度控制分段数量，但查点仍沿原剖面弧长表；尚未证明整体严格按世界空间等弧长排瓦。矩形还有其他边/轮廓循环，不能用一个循环的区间数当整屋瓦数。

Lws=5时N=8，j=.025，形成7个初始区间。U=.5时相应内部界线保持i/7。新增实际输出桥表明这些局部位置、尺度、四元数与裁平面被打进64B瓦片，而不是仅存在于一个尚未使用的剖面函数。

## 4. 圆形屋顶按剖面层与圆周分别分割

`2816BA0` 先用世界剖面长度L决定纵向边界数量：

```text
N=max(2,ceil(L/.4375))
q_k=k/(N-1), k=0..N-2
```

该环排循环不取最后q=1。第k环使用：

```text
r=worldProfile.x(q_k)+L/N
Y=worldProfile.y(q_k)
centerXZ=circleCenter + q_k*roofTipOffsetXZ
```

其中L/N参与半径扩张，不能把生成环半径直接认作原剖面半径。上端额外输出另有路径。

每环令perimeter为当前圆周长，先计算半径相关因子：

```text
c=clamp((r-.9)/(.3-.9),0,1)
f=1-.5*c
K=max(5,ceil(perimeter/(.5*f)))
requestedJitter=f*(L/N/.7)/perimeter
```

请求K+1个角向边界，仍经random_splits的cap和固定端点。每环另外取 `theta=U*2π`，用其旋转边界点。半径较小会改变f及目标角向尺度，但下限K=5仍存在。K是当前环的区间数量，不是全屋实例数。

### 构造例：一条剖面上的六个候选环

L=3，N=7，q=[0,1/6,2/6,3/6,4/6,5/6]。给某一环提供剖面x=4/7，则r=1，f=1，perimeter=2π，K=13，请求14个边界。

requestedJitter≈.0974418，但cap=.495/13≈.0380769，所以实际采用cap。某内部U=.5时没有边界偏移；另给环旋转U=.25，整环角偏为π/2。这是指定输入的演算，不是某实际游戏对象的采样。

## 5. 剖面斜率参与瓦片倾角

圆形输出链读取当前剖面段的切线，计算：

```text
alpha=atan(dy/dr)
beta=.5*(alpha+.1745329201) // 约加10°再取半角
tiltQuaternion.xyz=(-nz,0,nx)*sin(beta)
tiltQuaternion.w=cos(beta)
```

(nx,0,nz)来自当前角区间中点的水平法向并经过环旋转。这里使用atan的比值，不能换成atan2。之后还有SIMD法向旋转、正交frame构造和分支矩阵转四元数；**上式是中间倾斜四元数，不是已完全恢复的最终存储rotation_quat**。

位置链还使用角区间两端弦的中点；scale包括剖面、弦长及厚度相关量。全部变换顺序、轴约定、重叠尺寸和退化分支未完整简化。

### 构造例：倾角中间量

dr=−1、dy=1，alpha=−45°；加10°后半角beta=−17.5°。水平法向(1,0,0)对应轴(0,0,1)，中间四元数约为 `(0,0,-.3007058,.9537170)`。此例不宣称这就是最终写入值。

## 6. 主体、额外边排和上端输出分别保存标志

矩形普通区间输出之后，一个条件路径可以额外输出另一64B记录，复用当前裁平面和counter seed，但t/scale和raw标志不同。该额外记录写is_circle=0、is_main_roof_body=2；不能因为名称是main而把值2擅自解释成唯一“屋脊类型”。

圆形在环排循环后还有独立输出（`28178B9`）：宽松默认裁平面、is_circle=1、is_main_roof_body=2，部分动画量和t置零，尺度第三分量包含.1。它证明末端还有额外产物，尚未证明原网格就是某种尖顶或封帽。尖顶另有已知子系统，见[05](05-tiny-glade-seams.md)。

这些分支足以否定“只用N−1环解释全屋顶”。完整屋脊/檐边/末排的资产拓扑与全部资格仍未知。

## 7. 随机重复性和动画另有状态

选定矩形、圆形局部RNG均初始化零，实例seed另由counter写入；某些额外输出共享当前counter。公式和稳定性条件见[44](44-tiny-glade-stable-randomness.md)。位置、t、current_height、velocity和animation_t分别保存，不能将它们当成同一个生长进度。

既有GPU重力/粘合更新见[02](02-tiny-glade.md)。本轮没有运行瓦片动画，也没有把静态装配次序升级为逐帧物理模拟证据。

## 8. 独立实现原则与边界

可独立采用“纵向剖面层 → 每层周向分段 → 姿态/重叠参数 → 额外收口构件 → 实例动画”的分工。为了保持可解释性，应分别定义边界数、区间数和输出实例数，明确额外构件能否共享随机输入。最终姿态应由自己的网格轴约定和尺寸要求设计。

未做：未恢复完整矩形frame、末排拓扑、原网格与所有重叠尺度；未运行场景或确认完整上传/调度。

风险：边界数量不等于瓦片总数；中间倾角不等于最终四元数；局部随机序列稳定不等于编辑后每瓦身份稳定。
