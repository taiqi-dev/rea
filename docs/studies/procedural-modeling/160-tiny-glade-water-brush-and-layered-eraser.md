# Tiny Glade：水笔刷、分层橡皮与岸边派生更新

2026-10-24，America/Los_Angeles。新增人类需求已通过官方 `read_thread` 核对：用户希望我方用统一水笔刷替代自由湖岸坐标表单及分开的池塘/河流入口，并在底栏加入按层橡皮；绘水后按地表生成岸边装饰，冬季结冰。截图一是用户项目的当前水景界面，截图二是 Tiny Glade 的橡皮分类参考。截图只作线索，不把用户项目已有/期望现象全部归给 Tiny Glade。

制品身份、原始证据目录及工具边界沿 [155](155-tiny-glade-menu-snapshot-and-hover-visibility.md)。本轮没有读取 Unity 源码、玩家存档或配置，也没有运行游戏。

## 水区域：共同遮罩，不必区分池塘与河流对象

已证链见 [07](07-tiny-glade-water-shape-and-banks.md)–[10](10-tiny-glade-water-render-pipeline-and-bank-transition.md)：点输入经平滑，写到共同 512² 水域栅格，再上传、模糊并驱动河床、湿岸和水生植物。当前笔画、已提交 composite、scratch 预览与 staging 各有职责。这里的 fluid 名称不证明流体仿真。

`draw_water`（RVA `0x2053590`）有绘制与擦除路径，并在选定修改处调用 `ScheduledTerrainReadback::on_terrain_modified`（`0x2053AED`）。连续笔画分支先把 composite 复制到 scratch，再把当前笔画加入预览，提交才合回 composite；影响范围同时包含前后位置。

这说明我方“用同一水层绘制长水道或较宽水域”有可参考的表示方法；**尚未完整恢复原作所有正/负笔刷混合运算、相交区域合并、分割后的身份规则和撤销提交分支**。共同栅格不等于已证明连通域对象的 merge/split 协议。

性能也要分层看：原作所选 CPU 路径会筛脏块，但已分析的 GPU 上传仍覆盖完整逻辑图，不能说它每个 GPU pass 都只处理脏块。自己的实现应先满足正确性，再按真实瓶颈确定局部上传/滤波范围。

## 本轮新增：EraserLayer 的七个实际枚举

`EraserLayer` 的 Debug formatter（preferred VA `0x141B6ED80`）按字节 tag 查两张长度/指针表；deserialize visitor（`0x141B6E950`）逐字匹配并返回同样的 tag，未知分支向 unknown_variant 提供数量 7（`0x141B6EA1F`）。不是只从图标推断：

| tag | 原始名称 | 本轮允许的解释                             |
| --- | -------- | ------------------------------------------ |
| 0   | All      | 存在全层选项；所有最终删除消费者未逐个贯通 |
| 1   | Wall     | 墙相关层；不能扩写为所有建筑/摆件都等价    |
| 2   | Path     | 道路层                                     |
| 3   | Bulldoze | 与 Wall 分开；完整业务边界仍未知           |
| 4   | Water    | 水层                                       |
| 5   | Garden   | 园艺层；不能直接宣布包含所有独立装饰       |
| 6   | Tree     | 树层，与 Garden 分开                       |

`TempEraser::eraser_layer`（`0x140A3B010`）对输入 raw mode tag 减 2 后索引 13 字节表：2/3→Path，11→Water，12→Tree，13/14→Garden，其余返回 raw 7。`effective_mode`（`0x140A3B030`）还检查有效位集 `0x1E03` 和临时擦除状态，满足才构造擦除模式，否则保留传入模式。**原输入 tag 的全部产品名称未恢复**；不能把 helper 的可选临时擦除说成已确认截图全部按钮的输入映射。

`brush_size_override`（`0x140A3B080`）也按模式分派：部分分支取尺寸载体的 +0、+4、+8，另一个对 +8 乘 .75；其他分支无 override。它证明临时橡皮并非所有模式强行共用一项笔刷尺寸，不证明我方必须复制这些数值。

复核器 [menu_environment_probe.py](tiny-glade/tools/menu_environment_probe.py) 检查这七个字符串、数量、实际查表和选定位集；原始记录为 `eraser-temp.asm.txt`、`eraser-layer-fmt.asm.txt`、`eraser-layer-visitor.asm.txt`。`*eraser*` 的宽查询命中上限，不能当全产品函数清单；七枚举的结论来自所选具体代码/表，而非该宽查询的完整性。

## 给 Supervisor 的独立实施规格

1. **一层水、一次笔画事务。** 水笔刷编辑既有水域权威；池塘/河流是绘制形状，不另建两套持久状态。连续移动合并预览，抬笔提交一条历史，取消恢复；不靠隐藏旧入口冒充笔刷已完成。
2. **橡皮带明确目标层。** 花草、树、水、道路、建筑等目标取我方真实分类；All 需要清晰反馈。自动岸边派生物与玩家摆放物分开标识，删水只清理失去资格的派生物，不误删同处用户石头或摆件。
3. **局部失效含旧范围。** 笔画前后影响区域加上岸宽、滤波和装饰邻域，统一失效高度/岸材质/水面/植被/碰撞必要消费者。结果带世界与水层版本，过期任务不发布；别在每个 pointer move 全场扫描所有装饰。
4. **资源与稳定布局。** 草/沙/岩地按真实地表资格选择资源包模型和材质；位置/稳定键尽量使未受影响区域不乱跳。已有手工摆件保留，资源缺鱼/冰材质时先报告能力缺口，不自行生成美术模型。
5. **季节与撤销。** 冰/水表现投影正式季节和水域，不删除水数据再重建另一存档层。撤销一笔恢复同一水域和相关派生资格；切季节不隐式改变地形历史或鱼玩法状态。
6. **存档兼容。** 现有自由湖岸/池塘/河流存档在明确迁移前继续可读；大表单退出玩家界面与旧数据退役分开进行。不得创建第二套保存/历史/联机 authority 来绕开兼容。

这些是我方独立规格，需既有水景/环境/UI owner 协调共享范围后实施；本报告不创建 owner 或授位。建议先完成“水笔刷+水层橡皮+撤销+局部刷新”，再接资源包岸边细分与季节表现。鱼的玩法/联机需求另定，不为装饰研究扩张到全生态模拟。

**后续验收候选，均未运行。** 重叠两笔、擦穿成两片、擦到旧岸边、取消拖动、连画后一次撤销、删水后旧异步结果到达、季节切换再读档，以及同位置玩家石头不丢失。游戏、GPU、Unity、存读档和画面验证均 **Not Run**。
