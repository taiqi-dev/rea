# Unity/URP：综合沙盒 demo 的柔和光影、植物与水面方案

2026-10-22，Pacific Time。这是按用户“综合 demo 相似风格”的目标重新设计的实现规格，不是原作 shader 的移植源码。**Tiny Glade 本机发行版采用 Rust/rhapsody/Vulkan，选定模块声明 Slang；可以在 Unity/URP 独立做类似观感，不需要先重造它的渲染框架。** 原作证据分别见 [140：光照/阴影](140-tiny-glade-lighting-brdf-and-soft-shadow-filter.md)、[141：风参数](141-tiny-glade-wind-producers-and-frame-constants.md)、[142：水面选择](142-tiny-glade-water-reflection-refraction-and-fallback-gates.md)。

没有读取 `3DSandboxTest`，不知道它当前 Unity/URP 版本、材质体系和瓶颈。本篇以公开 **Unity 6.0（6000.0）文档**说明入口，实施时须匹配实际项目包版本；不是已经适配或验证的项目方案，更不是约 10 FPS 的归因报告。

## 建议的首个可交付范围

先完成一套共享的环境调色和主光、一个石/木/灰泥材质家族、一个有根部权重的植物风函数，以及一个单水位的平静水面。保留现有建造/挖掘/存档权威；渲染只消费它们的几何和视觉版本，不新增一份世界状态。

| 层次 | 首片独立实现                                                    | 后续按证据升级                         |
| ---- | --------------------------------------------------------------- | -------------------------------------- |
| 光影 | 单主光、可调天空/阴影色、受控粗糙度、少量真实倒角，URP 标准阴影 | 自定义漫反射响应、局部接触效果         |
| 植物 | 共享 shader 中的低频弯曲和小幅叶片微动；实例稳定 seed           | 大规模 GPU 可见性和按距离减少微动/阴影 |
| 水面 | 水位平面、两层自制滚动法线、环境反射、场景颜色折射、深浅吸收    | 单独量测后的 SSR 或限预算平面反射      |
| 后期 | 统一曝光/色调规则，先保证清晰层次                               | 小幅景深/调色；以编辑可读性为约束      |

这是建议范围，不能承诺同一预算在未知硬件上达到多少帧。复杂软件光追、自定义 G-buffer、全套时域 GI 不属于首片必要条件。

## 光照：先一致，再增加定制

使用 Lit/Shader Graph 保留 URP 的灯光和阴影接入，先调整低金属度、高粗糙度的材质家族、稳定色差、法线与小倒角。若确需自己控制漫反射，再编写独立 HLSL 光照函数：通过 `Lighting.hlsl` 和 URP 灯光入口取数据，不以没有阴影输入的纯颜色函数代替全部光照。[Unity 6.0：光照方法](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/use-built-in-shader-methods-lighting.html)。

主光受影应使用 `GetMainLight(shadowCoordinates)` 或相应 shadow 方法及匹配的变体；该接口返回 `shadowAttenuation`。阴影预算先按镜头实际需要设置距离、级联、caster 范围和软阴影质量，不能直接复制原作“3×1024”并当作 URP 相同布局或成本。[Unity 6.0：阴影方法](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/use-built-in-shader-methods-shadows.html)。

环境光可先采用项目选择的环境探针/球谐输入；自定义材质可以通过 `SampleSH(normalWS)` 接入探针信息，反射有独立入口。它不是任意室内位置都正确的动态 GI，家园可编辑后的遮挡/光照有效性仍需自己的规格。[Unity 6.0：间接光方法](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/use-built-in-shader-methods-indirect-lighting.html)。

**本产品可选的简化受光规格**：主光漫反射与可见性相乘，天空/地面补色保持独立，AO 只按职责衰减间接分量，最后加受控高光。参数在一个环境配置中定义，材质只保留家族差异。不要把“阴影色抬亮”误写成关闭物体互相遮挡，或同时叠多套环境补光使画面过曝。

需要屏幕效果时再引入 Renderer Feature，并声明输入、目标和执行时机。官方支持向 URP 加 pass、改变部分绘制；这不是必须 fork 整个管线的要求。[Unity 6.0：Renderer Feature](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/urp-renderer-feature.html)。

## 植物：一个视觉时钟，明确前后帧

独立设计数据流：环境状态拥有当前/上一帧时间与风参数；实例拥有稳定 seed、柔度和局部根部权重；网格提供叶片轴/顶点色。主颜色、ShadowCaster、DepthOnly、需要时的 DepthNormals 和运动向量使用相同变形规则，避免可见树冠已弯曲、阴影和遮挡仍停在原处。

示意规格可将位移拆成 `根部权重 × 低频整株摆动 + 叶片权重 × 高频微动`。用自己的振幅、频率和相位；参数变化时按产品约定连续插值，不逐对象创建新材质。距离变远时先减高频和小叶片投影阴影，不能让 LOD 切换随机重置相位。绘制 bounds 纳入最大偏移，选取/碰撞保持正式几何语义。

URP Lit Graph 提供顶点 Position、Normal 等输入，可承载这类独立变形，具体坐标空间以 Graph 设置为准。[Unity 6.0：Lit Graph](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp-lit.html)。

**时域条件必须单列：** 官方 Time-Based 运动向量会以当前/上一帧 Time 两次计算顶点图，但要求其他自定义参数不逐帧变化。若阵风、强度或缓冲内容变化，应保留前后两份参数并计算实际前一位置，或使用匹配版本的 Custom Motion Vector 入口。只把 Time 值减去 delta 不能恢复上一帧的天气参数。透明材质也不享有该文档所述不透明材质的运动向量支持。[Unity 6.0：运动向量与顶点动画](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/features/motion-vectors-shader-support.html)。

## 水面：反射来源与混合权重分开

首片由正式水位生成低密度平面/水域块；水岸覆盖和可编辑河床由地形权威提供。shader 用两层自制法线形成柔波，局部涟漪先按距离/强度选少量源。只更新视觉源列表，不每帧重建河床或 collider。

URP Asset 的 Depth Texture 可提供场景深度，Opaque Texture 是绘制透明网格前的场景颜色快照，官方明确可用于水折射；它通常不含后续透明对象。[Unity 6.0：URP Asset](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/universalrp-asset.html)。水材质不可同时采样并写入同一未定义来源；执行时机、颜色来源及深度版本必须清楚。

下面是**本产品的独立规则**，不冒称原作完整算法：

1. 将场景深度和水面深度转到同一线性/观察空间，求水下厚度，浅岸减少法线扰动，防止读出岸上物体。
2. 扰动 UV 越界、缺深度或取到水前方遮挡物时，回退到未扰动 UV；无法得到有效背景时向水色/环境反射退化。
3. 折射 RGB 乘自定吸收 `exp(-absorptionRGB*thickness)`；反射先取环境，不自动增加实时反射相机。
4. 以连续 Fresnel 权重混合两者，水面近处和掠视结果分别调色；避免通过高透明叠层“堆出水感”。
5. 质量档改变法线层数、涟漪上限、反射来源和目标尺寸；缺少高级输入时有明确低档路径。不同档位不改变存档水位、可挖区域或碰撞规则。

**构造演算。** 设计值 `absorption=(0.2,0.08,0.04)/米`、厚度 2 米时，透过率约 `(0.6703,0.8521,0.9231)`；变为 0.1 米时约 `(0.9802,0.9920,0.9960)`。这是自己的参数，说明深浅过渡怎样独立于 mesh 密度，并非推荐照抄原作常数。

若以后增加历史反射，至少在相机跳变、目标尺寸变化、无效深度和相关世界编辑版本变化时拒绝陈旧历史。是否采用分块局部失效要由现有项目资源体系决定，本篇不预设第二份编辑历史或单独的世界时钟。

## 成本与实施顺序

先完成共享光照/材质，再接植物统一变形，最后做基础水面。每片单独开关以便以后采样。按批次/相机发布公共常量，实例数据集中维护；禁止把“实现风格”变成每棵树每帧重写 mesh、每块砖克隆材质或每片水增加一台相机。

性能预算同时看主色、深度、阴影和运动向量的重复顶点工作，以及水面屏幕覆盖、纹理采样、场景颜色复制、历史纹理和额外相机。构造例：1920×1080 下水覆盖 25%，约 518,400 像素；每像素增加 4 次采样，单个相关 pass 约多 2,073,600 个采样调用，尚不含过滤展开、overdraw、MSAA 和其他 pass。这是工作规模估计，不是 GPU 毫秒或 FPS。

本次仅做静态规格和官方接口核对。以后获得项目调查授权，再读取现有材质/渲染路径，选最小切片适配；运行验收应覆盖编辑后阴影、风与深度轮廓一致性、天气切换、岸边/前景折射、反射缺失退化和相同场景的帧时变化。当前这些以及 Unity 编译、运行、画面和性能采样全部 **Not Run**，不以参考游戏的算法替代本项目性能证据。
