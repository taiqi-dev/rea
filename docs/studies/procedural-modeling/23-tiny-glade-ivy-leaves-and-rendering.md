# Tiny Glade 常春藤：枝叶生成、动画与显示

叶片生成器消费枝段事件，经过随机与空间噪声筛选，保存两端点身份和独立动画状态。叶片、花和枝条随后分别转换成 GPU 实例；CPU 中的粗细与尺寸参数还会经过着色器映射。本篇不把这些中间值直接称为最终世界尺寸。

依据发行版 `ivy_leaf_spawner`（`A725F0`）、动画、上传及两个包内 shader 的实际指令。身份与全部本机记录见 [25](25-tiny-glade-ivy-evidence-ledger.md)，枝点和事件生产见 [22](22-tiny-glade-ivy-growth-and-wall-following.md)。

## 枝段事件怎样变成叶片候选

生成器迭代 32 字节事件：`+8/+10` 是两个枝点 ID，`+18` 是 Ivy 分组键（`A72AA9/A72AE2`）。按身份取回 40 字节枝点，不在本函数内按固定间距重采样整条藤。

先取 `U∈[0,1)`，`U<0.4` 跳过；再在 `2*A.position+(89,-3456,-34)` 调 `FastNoise.get_noise3d`，结果 `<=−0.05` 跳过（`A72C27–A72C2C`、`A72EEA–A72F06`）。第一道门允许约 60% 的均匀抽样值，并不意味着最终 60% 的枝段都有叶片；噪声及后续条件仍会排除候选。具体 FastNoise 配置未恢复。

位置使用：

```text
n = normalize((normalA+normalB)/2)
t = normalize(B.position-A.position)
(x,y) = 随机单位圆盘样本
P = A.position + 0.15*x*(n×t) + 0.15*y*t
```

圆盘辅助函数 `1B1E5A0` 先各取 `2U−1`，拒绝 `x²+y²>=1`。`n×t` 没有再归一化，故在两者不垂直时并不是单位轴；0.15 是位置散布参数，不能称为叶片间距。

**构造演算。** `A=(0,0,0)、B=(1,0,0)`，两端法线均 `(0,0,1)`，圆盘样本 `(0.4,-0.2)`。于是 `t=(1,0,0)、n×t=(0,1,0)`，位置为 `(-0.03,0.06,0)`。若门控抽样 0.7、噪声 0.2，则通过这两道筛选。退化端点、相反法线等输入的完整保护尚未恢复。

## 朝向、大小和出生延迟

生成器多次计算 `G=sqrt(-2*log(U1))*sin(2πU2)`，实际数学调用经本地符号核对，非有限径向结果有重试分支。随机状态初始化和完整跨模块重放仍未知。

主叶方向（`A7368D–A73859`）为：

```text
theta = 80° * clamp(Gtheta/1.5,-1,1)
d = min(abs(Gdown)/1.5,1)
n_leaf = normalize(Ry(theta)*n - (0,d,0))
```

旋转轴是世界 Y，而不是枝条轴。另一方向供花路径使用（`A733AE–A734CC`）：

```text
n_flower = normalize(n + (clamp(Gx,0,1)-0.5,
                          clamp(Gy,0,1)-0.5,
                          clamp(Gz,0,1)-0.5))
```

这三个扰动经 `[0,1]` 夹取，并非对称高斯偏移。尺寸与延迟分别为：

```text
k = min(abs(Gsize)/3,1)
s = lerp(0.8,1.2,k)
delay = 0.3*U
```

**构造演算。** 上例中取 `Gx=Gy=Gz=0.5`、`Gtheta=Gdown=Gsize=0`，则两条方向均为 `n`，生成尺寸 `s=0.8`。延迟抽样 0.5 得 `delay=0.15`。这是条件演算，不声称某个指定种子必给这些抽样。

## 104 字节叶片状态与动画

`IvyLeafStorage.add`（`A5E970`）按 Ivy 键向分组向量追加；以下为两条实际写入分支的共同布局：

| 偏移 | 已确认内容 |
| --- | --- |
| `+0/+8` | 两个关联枝点 ID |
| `+10/+18` | Ivy 键、关联墙查询键 |
| `+20/+2C/+38` | 位置、主叶方向、枝段方向，均为 Vec3 |
| `+44/+48/+4C` | 生成尺寸 `s`、枝粗细导出的倍率 `m`、增长进度 `g` |
| `+50/+54/+58` | 延迟、32 位种子、花方向 |
| `+64` | 未恢复语义的尾部 4 字节 |

`m` 和 `g` 初始为 0。`ivy_leaf_animation`（`A50140`）按两个点 ID 查回粗细，写：

```text
m = 0.5 + 0.25*(thicknessA+thicknessB)
若 g<1 且 delay>0：delay -= dt
否则进入增长分支：g = min(g + 2*dt,1)
```

延迟分支即使本帧减过 0，也不在同一分支立刻增长（`A50490–A504AC`）。`dt` 从时间资源字段 `+28` 来，上游更新及调用频率未核全。

**动画演算。** 初始 `delay=0.03、g=0、dt=0.05`。第一次得到 `delay=-0.02、g=0`；第二次才得到 `g=0.1`。两端粗细为 0.4 和 0.6 时，`m=0.75`。相关点缺失时还有条件诊断，不能将它称为无条件自动修复机制。

## 枝条怎样由根到尖变细

`ivy_branch_thickness_animation`（`A74090`）根据当前点数 `N` 和逻辑队列序号 `i` 写：

```text
a = 1 - exp(-N/10)
thickness_i = (1-i/(N-1))*a
```

所选入口没有通过 `dt` 积分粗细的证据；它依据点数和序号计算。`N=0` 不进循环，`N=1` 的除零/NaN 行为尚未完整恢复。

**构造演算。** `N=4` 时 `a≈0.329679954`，粗细序列约 `[0.329679954,0.219786636,0.109893318,0]`。上传时形成三条相邻枝段；点的身份来自序列，而不是强制等于 `[0,1,2,3]`。

## 叶片和花是同种子的互补分流

叶与花分别走 `B93360→16067E0→C623A0`、`B93360→15FA8C0→C61AC0`。两条 closure 用同一个记录种子初始化本地 RNG，并读取相同的首个随机浮点值：

| 首个随机值 | 分类 |
| --- | --- |
| `<0.85` | 叶路径 |
| `>=0.85` | 花路径 |

所以这不是“先放一片叶，再独立以 15% 概率额外加一朵花”。后续墙查询等条件仍可能让实例不存在。花迭代路径另有 1000 的上限（`B9381C`），不是已经证实的全游戏总花数限制。

两条路径生成共同的 48 字节 GPU 结构：

| 偏移 | 字段 |
| --- | --- |
| 0/12 | 位置 Vec3 / 大小 float |
| 16/28 | forward Vec3 / seed u32 |
| 32/44 | branch_dir Vec3 / arch_height float |

叶用主叶方向，花用另一方向；大小均为 `S=s*m*pow(g,0.3)`。墙缺失时叶路径的 `arch_height` 回退值是 10000，花路径是 2.8；不能抹平这两个分支。关联墙字段的完整产品语义尚未恢复。

**构造演算。** `s=0.8、m=0.75、g=0.25` 得 `S≈0.395852373`。首个随机值假设为 0.2 时归叶，0.9 时归花；同一记录的两条 closure 不会凭独立抽样同时命中这两个互补条件。

## GPU 怎样把实例变成叶片和枝管

两个 shader 各解析到四个内嵌模块；本节核的是 blob0 顶点消费，偏移均为原 `.precomp` 文件偏移。

叶 shader 的结构 Offset 精确对应上述六字段（`0xE67–0xECB`），实际加载在 `0x2437–0x252F`。输入网格顶点先乘 `0.75*S`；原始主题值 4 的分支再乘 0.85。

普通叶分支的局部基：

```text
b = normalize(lerp(branch_dir,(0,1,0),lerp(0.5,1,abs(branch_dir.y))))
z = forward
x = normalize(cross(z,b))
y = normalize(cross(x,z))
```

之后按基变换并加实例位置。另一材质字段分支使用不同基轴并沿 forward 偏移 0.1；没有把该字段擅自命名为花品种。

**构造演算。** `forward=(0,0,1)、branch_dir=(1,0,0)` 时，`b=normalize(0.5,0.5,0)`，`x=(-1/√2,1/√2,0)`，`y=(1/√2,1/√2,0)`。局部 X=1 的网格顶点沿 x 轴移约 `0.75*S=0.296889280` 再加位置。地形与道路条件还有后续隐藏/位置变化，不能称为无条件最终可见顶点。

枝条上传为另一套 48 字节布局：起点与粗细、终点与粗细、法线、`arch_height`。`9487C0→15F2D70→15DCFF0` 将 N 个点映成 `max(N−1,0)` 条相邻段。

枝 shader 根据地形采样解码 `lerp(-2.5,24,R)` 并加到两端 Y，再用端点差和墙法线构造管轴。网格局部 y 小于 0.1 使用起点粗细，否则使用终点粗细；横截面坐标缩放为：

```text
XZ_scale = lerp(0.0168,0.084,thickness)
Y_scale = distance(endpointA,endpointB)*1.1
```

道路条件还可能先衰减粗细并限制到 0.2，但不是所有枝段都无条件使用该限制。

**构造演算。** 使用上面四点粗细序列，首段两端 XZ 比例约 `0.038954491` 与 `0.031569661`。端点距离为 1 时局部 Y 比例为 1.1。这是输入网格坐标缩放；不知道原网格横截面半径就不能称为世界管径。

## 上传、调度和风的证据边界

上传字节数为 `48×实例数`，经过实际容量检查；叶调用点 `B93722`、枝调用点 `948ABB` 进入 `GraphicsDevice.update_buffer_bytes`（`E55470`）。零实例跳过写，成功路径保存实例计数。启动代码还创建枝/叶材质与显示对象；完整驱动提交顺序、资源增容及帧频仍未贯通。

所选 leaf/branch blob0 虽声明公共 `FrameConstants`，本次没有找到读取其 time/wind 字段用于形变的指令。已证的叶片动画是增长尺寸，不据公共字段名添加风摆公式；也不将这个有限搜索结论扩大成“整个游戏没有植物摇摆”。

已回答：事件到叶片、两道筛选、位置与朝向、尺寸/延迟、点身份关联、增长与粗细、互补叶花分类、实例布局、部分顶点变换及实际上传。

未回答：全部 RNG/噪声配置、所有退化保护、其他 shader 变体、完整道路与裁剪公式、全局调度和实际画面。未做游戏运行或性能测试；风险是条件和配置缺口仍可能改变最终可见结果。
