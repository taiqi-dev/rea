# Tiny Glade：水面反射、折射和延迟补算的条件

2026-10-22，Pacific Time。续接 [139：波纹与预算](139-tiny-glade-water-shader-and-demo-budget.md)、[10：水面渲染链](10-tiny-glade-water-render-pipeline-and-bank-transition.md)。范围是同版 Windows 发行制品的静态路径；没有运行游戏或检查用户 Unity 工程。

**反射与折射首先是按视角混合的两个分量；反射信息从哪里取得，才有屏幕命中、历史有效性和延迟补算等选择。** 所选延迟补算 compute 实际遍历自有 BVH/三角形数据，本轮没有硬件 RayQuery 指令证据。

## 原作实际混合关系

以下 `w` 为 `water_plane.precomp` 片元模块 1 内 word 偏移，模块起点为容器字节 3098、16301 words。`V` 来自视线反方向，`N` 是选定分支构造的水面法线。`w6123–6158` 计算：

```text
F = 0.04 + 0.96*(1-dot(V,N))^5
reflection = incomingReflection * F
transmissionWeight = 1-F
```

反射分量乘 `F` 的实际指令在 `w14695`；折射所用权重在 `w13267` 写成 `0.96 - 0.96*(1-dot(V,N))^5`，即 `1-F`。折射不是直接乘一个常量透明度：`w13238–13277` 还读取 `GlobalParams.water_color`，以负颜色系数乘距离量后取指数，形成逐 RGB 通道的透过率，再与折射取样和焦散项组合（`w14700–14705`）。这与吸收随路径变长的结构相符，不证明原作水体严格物理守恒。

**构造演算。** 正视 `dot(V,N)=1` 时 `F=0.04`；余弦为 0.5 时 `F=0.07`；掠视余弦 0.1 时 `F≈0.60687`。后者透射权重约 0.39313，还要乘颜色吸收。不存在“余弦超过某个固定阈值，就完全从折射切成反射”的这条局部逻辑。

## 折射颜色从哪里来

所选入口先追踪屏幕深度中的折射候选位置。`w8004–8018` 根据求解出的参数在两个射线端点之间插值为 `refraction_hit_cs`，转成 UV；`w8053` 从 `half_depth_tex` 读取深度以重建位置，`w8125` 用同一 UV 对 `refraction_tex` 取 RGB。后续由重建位置计算距离、吸收和岸边/焦散相关输入。

这段并未以“屏幕反射是否成功”决定要不要取折射纹理，它们是两条数据流。折射求解本身也有屏幕边界、深度间隔与迭代分支，本轮没有把全部 miss/越界分支恢复成一份完整规格。10 已证明折射复制 fragment 只按屏幕位置复制来源 RGB；它不是另一个从任意视角重新渲染整个场景的证据。

## 反射路径的选择条件

| 条件层次             | 已核的选定分支                                                                                                | 不能外推的结论                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 是否构造水面 pass    | `water_surface_pass` 在 `0x140B025D7` 比较 `DRAW_WATER_SURFACE==1`；不等于 1 则转到返回段                     | 不是已接通的玩家画质菜单，也不是硬件光追能力门                               |
| 法线/主题特殊处理    | shader `theme_id==4` 可跳过动态波纹，且另有后续主题分支                                                       | 本轮不把数字 4 直接解释成某个季节名或所有冰面路径                            |
| 接受屏幕反射候选     | `w11509–11567` 要求迭代成功标志，并通过两个额外深度/区间比较；`w11624–11706` 还可从 quad 邻 lane 取到有效候选 | 不是“UV 在屏幕内”就足够；全部 root-finder 中间值的物理含义仍未逐一命名       |
| 候选成功后取历史颜色 | `w12404–12454` 检查 `history_valid!=0` 且 `frame_counter.index!=0`；合格才在 `w12489` 取 `taa_history_tex`    | 此处没有直接以所选 `reprojection_tex.z>0` 作额外门，不能照搬阴影专题的历史门 |
| 屏幕候选失败         | `w11715` 的失败分支进入延迟射线追加区；`w12308` 实际写请求记录                                                | 不是所有水像素无条件软件求交，也不是“历史无效”就走同一 miss 分支             |

`w12723–12734` 表明：屏幕候选成功但历史无效时，这个**屏幕历史反射分量**选零；这并不证明最终水面为黑，因为后面还会加入太阳高光等其他分量。不能用常见 SSR 经验把静态结果改写成“历史失效必定立即回退到天空”。

成功候选仍有散射/消光修正：`w12636–12714` 读取体积散射与消光纹理，再修正历史颜色。完整历史创建、相机切换失效和所有变体选择尚未闭合。

## 延迟补算是实际软件求交

`water/deferred_rt.precomp` compute 模块起点字节 **106**、21600 words。它不只是保留了 BVH 变量名：

- `w5322–5364` 先读请求数，以 global X 与数量比较，超出便退出，然后读取具体请求。
- `w6226–6291` 等实际读取 `rt_scene.rt_bl_bvh` 的 packed node 数据；有子节点位操作和遍历循环。
- `w8691–8756` 实际读取 `rt_scene.rt_triangles`，解包几何；`w8843–8997` 用 cross/dot、距离除法和重心坐标非负判断来接受更近三角形交点。形式对应射线与三角形的 Möller–Trumbore 类求交结构，是数学结构归类。
- 对这个完整选定模块检查，没有 `OpRayQuery*` 指令；资源是普通结构缓冲中的 BVH 和 triangles。这里足以称所选分支为 compute 软件射线求交，不能据此否定程序其他模块可能存在不同能力。

CPU `water_surface_pass` 在 `0x140B02A6C` 注册水面 raster，随后构造请求参数 compute，并在 `0x140B02C3F` 调 `dispatch_indirect`。10 已核到参数 `(ceil(n/64),1,1,n)` 与 64×1×1 工作组，以及 2×2 覆盖位：没有屏幕命中的合格 lane 组成一条半分辨率请求，后续只回填覆盖位为真的像素。它减少的是进入后备路径的工作和请求重复，不表示不需要相应 BVH、材质和历史资源。

**构造演算。** 一个 2×2 组只有 lane 0、2 进入有效追加覆盖时，mask=5、owner=2；后备求交完成后仅更新这两个目标像素。全局 n=65 时派发 2 个工作组，额外线程通过 n 上界退出。这个算例沿用 10 的位定义；本轮不宣称已核全部计数容量/溢出处理或实测射线数量。

## 适合综合 demo 的独立选择规则

建议先明确自己水面的三件事：正式水位/岸线由玩法几何决定；法线和涟漪只改变外观；反射来源按预算选，反射/折射权重按视角连续混合。Unity 路线见 [143](143-unity-urp-cozy-style-independent-rendering-plan.md)。

第一片可用自己的环境反射与 `_CameraOpaqueTexture` 折射，不需要先建第二台实时反射相机，更不需要为了相似观感实现软件 BVH。屏幕折射缺深度、UV 越界或误采前景物体时，应退回未扰动的背景 UV，并向水色/环境反射平滑退化；这是自研规格，不能写成原作已存在的完整 fallback。

以后确需 SSR/平面反射时，单独规定可见水面门、分辨率、有效深度、历史拒绝及无数据的环境 fallback。编辑建筑/挖掘会让历史数据陈旧，不能只凭相机不动就复用。原作的半分辨率覆盖思想可借鉴，但源缓冲布局和恢复代码不进入产品。

## 验证和缺口

[lighting_wind_water_probe.py](tiny-glade/tools/lighting_wind_water_probe.py) 回读 Fresnel 常数/乘法、历史门、追加写端、BVH/三角形读取及求交锚点；本轮共新解析 4 个相关文件的 5 个模块，均未见结构解析拒绝。完整原始输出留于 ignored `.cache/procedural-modeling/tiny-light-wind-water/`，跨机器需以同版合法安装重跑。

已回答：局部反射/折射权重、折射纹理读取、所选屏幕历史门与 miss 后备分支、软件求交和按覆盖回填。部分回答：迭代接受条件、CPU 图注册。未回答：所有 shader 变体选择、完整折射 miss、历史生成/失效、BVH 更新成本和 GPU 屏障执行。未做运行、抓帧、画面和性能验收，均 **Not Run**。
