# Tiny Glade：墙绘制命令槽的静态来源

后续的[命令初始化与槽 23](81-tiny-glade-command-initialization-and-slot23.md)补查空输入创建、初始零数据和另一套完整模板的资源身份；本篇的逐槽证据保留原范围。

承接 [77](77-tiny-glade-draw-callback-mapping.md) 的 `CustomDrawFn` 回调。本篇把墙 compute 写入的资源追到最终 `indexed_indirect::draw_fn` 读取，并核对逐槽公式。**同一 `DrawIndexedIndirectBuffer` 资源已由 CPU 类型键与绑定字段接通；所查三个写命令的墙 compute 都由 CPU 选择基址 `0x10=16`。** 因此可确认这些 shader 的绝对写入槽为 `16…22`。墙目录其余 compute 也已逐个检查，仍未找到槽 23 的生产者；不能把名字或 20 B 格式当成该槽身份证明。

## 相对索引、字段与绝对槽

两个 shader 的 `DrawIndexedIndirectCommand_natural` 都含五个 32 位字段：`count` 偏移 0、`instanceCount` 偏移 4、`firstIndex` 偏移 8、`vertexOffset` 偏移 12、`firstInstance` 偏移 16；runtime array stride 为 20 B（pass2 `OpDecorate [888,6,20]`，shadow `[519,6,20]`）。本轮所见主要写入是对 **`instanceCount`** 做 `OpAtomicIAdd(+1)`，没有据此声称其余四字段由同一 shader 初始化。

`globalParams.draw_indirect_buffer_offset` 是两个 shader 的 uniform 结构**成员 0、块内偏移 0**：pass2 `OpMemberName [658,0,...]` 与 `OpMemberDecorate [658,0,35,0]` 在包偏移 `0x6D6/0x158E`，shadow 对应结构 393 在 `0x7DE/0x130E`；两者均为 set 0 / binding 0。对应 CPU 赋值链可逐字节追到 `16`：

- pass2 在 `0x1409BA3F4` 把 `0x10` 写到 `[rbp+180h]`，随后 `0x1409BA40D` 以 `r8=&[rbp+140h]` 调绑定 wrapper，因此专门化绑定函数的 `rsi+40h` 正指向 `[rbp+180h]`。wrapper `0x1417A3E82–3ECC` 为第一个动态常量块预留 12 B，`0x1417A3FB4` 调 `generate_draw_lists2::cs_pass2::BindEntryPoint`。后者 `0x141A27351–360` 以 `[rsi+40h]` 的 u32 写入该块；偏移来自 wrapper 初始清零的绑定描述符 `[rbp+18h/+20h]`，此时为 0。因此 pass2 `B₂=16`。其前置 reset 节点在 `0x1409BA2D1` 显式以 `r9d=0x10` 调专门化绑定 wrapper；reset shader 同一成员也位于块偏移 0（包偏移 `0x27C`）。
- shadow 在 `0x1409BA843` 把 `0x10` 写到 `[rbp+128h]`，`0x1409BA85C` 以 `r8=&[rbp+F8h]` 调绑定 wrapper，因此专门化函数的 `rsi+30h` 指向 `[rbp+128h]`。wrapper `0x1417937CC–380C` 为第一个动态常量块预留 12 B，`0x1417938E2` 调 `generate_draw_lists_shadow::main::BindEntryPoint`；`0x140BB13C9–3D9` 从 `[rsi+30h]` 读取 u32，按初始为 0 的块内偏移写入该常量块。因此 shadow `Bₛ=16`。

pass2 shader 在包偏移 `0x432A–0x437A` 读取该字段，形成 `16 + clamp(x,0,1) + 2·(condition?1:0)`，即绝对槽 16…19，然后原子增加 `instanceCount` 并记录砖列表。其前置 `reset_pass2_inst_counts` shader 在 `0x520–0x540` 限定 invocation `<4`，于 `0x558–0x69C` 读取同一基址，对槽 16…19 保留 `count/firstIndex/vertexOffset/firstInstance`、将 `instanceCount` 清零。CPU 两节点的同一 `[rbp+E4h]` 句柄链使重置与追加指向同一资源；实际节点执行仍取决于调用分支与图编译。

shadow shader 在 `0x2BAE/0x2BC2/0x2BDE`、`0x3636/0x364A/0x3666`、`0x40BE/0x40D2/0x40EE` 分别访问 `16+4=20`、`16+5=21`、`16+6=22` 的 `instanceCount` 并原子增加。每次增加周围有各自条件控制及砖列表写入，不能把三个命令各解释成一次无条件 draw，也未从这一个 shader 证明 shadow 三槽的清零来源。

## 墙目录剩余 compute 的生产者集合

四个剩余 compute 的解码结果把此前“两种增量 shader”的范围扩大为墙目录**全部七个 compute**。`generate_draw_lists`（670 条 SPIR-V 指令）、`fill_instance_indirection`（119 条）、`prefix_brick_chunks`（340 条）均无 `draw_commands` storage 变量；中间一个有 `brick_draw_list`，不能将其当成 20 B 间接命令。`prefix_brick_chunk_subtotals`（359 条）则确实有第三处命令写入，不能漏算：

| --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |

`startup_walls::glade_startup_walls`（`0x140B967E0`，9,614 B）的直接调用列表另作有界检查：`0x140B978F7/0x140B97A6D/0x140B97D5D` 是建立三个含 `CustomDrawFn` 的实体；其余直接调用包括纹理、网格、pipeline 与 binding set 建立，但未见 `DrawIndexedIndirectBuffer`、`replace_with_data`、`nani_upload_derived_buffers`、`GpuWorld::set_draw_list_params` 或 `GraphicsDevice::create_buffer` 的**直接调用**。这只能排除这个 startup 函数里的直接模板/缓冲建立调用，不能排除其他启动函数、内联写入或稍后 CPU 上传命令模板。就墙目录七个 compute 的显式 `draw_commands` 写者而言，已穷尽为 prefix subtotal（槽 16）、pass2（槽 16…19）、shadow（槽 20…22）；槽 23 的 CPU 模板来源及其他目录 shader 写者仍未知。

`r9` 选择来自 [77](77-tiny-glade-draw-callback-mapping.md) `0x1409640E0–0x14096426C`；偏移来自 `0x140AF4D64–7A`。本轮重新检查回调原指令：`0x1409640E8` 先将入口 `r8b` 零扩展保存到 `eax`；阶段 3 跳至 `0x1409641AE` 设置分组字节 1，随后到 `0x1409641DB–1E2` 前**没有改写 `eax`**，故 `eax&3=3`，`0x14|3=0x17=23`。它并非 shadow `+5=21` 的误读。`r10b` 是 payload 组别判断，不能代替 `eax` 的命令索引。

例：CPU 已证 `B₂=16`。再构造 pass2 的 `x=1` 且布尔条件为真，索引为 `16+1+2=19`，地址是 `19×20+4=384` 字节处的 `instanceCount`；之后回调若经墙组/阶段筛选选中 `r9=19`，`draw_indirect` 从 `19×20=380` 读取整条 20 B 命令。两个地址相差 4 B 正是字段偏移，而非两个 buffer。这里假设的是 shader 条件与回调筛选同时成立，**不是**观察到游戏帧里的 draw。

**已答与未答。** 本轮闭合了 CPU typed buffer 的同键读写、三个墙 compute 写者的 CPU 基址/索引、墙目录七个 compute 的显式命令写者集合、shader 绝对写入槽 16…22 和回调 20 B 读取。重新检查 `r8b→eax` 也确认阶段 3 选择槽 23，不需改 [77](77-tiny-glade-draw-callback-mapping.md)。尚未恢复槽 23 的生产者及所有可能重置/模板来源；`shadow +5=21` 与回调槽 23 的差异是真实的**当前证据缺口**，不能通过改名消除。故绝对槽 `16…23` 的完整逐项生产者身份仍是**部分回答**，不是“需运行才能回答”的断言。运行、GPU 抓帧和 FPS 验证均为 **Not Run**。
