## clicked() 的实际条件已经接上

`UiWidgetContext::clicked`（`0x1408FFA90`）依次要求：

```text
UiState[+0x18] == 2
UiState[+0x19] == 1
UiState[+0x38] == thisWidgetId
```

定位分别为 `0x1408FFA93`、`0x1408FFA99`、`0x1408FFAA3`。`dragged()` 也要求相同的交互分支与控件 ID，才返回 `+0x19` 的子状态，否则返回原始值 2。旧研究已核过 DragState 的 Started=3、持续状态=4、Finished 为 0/1；这里进一步证明 **Finished 子状态 1 是 clicked() 接受的那一个**，不再只根据枚举数值猜测。

`ui_update`（`0x140BF00B0`）的所选结束路径，在 `0x140BF08F1–0x140BF0900` 计算：

```text
endPayload = (currentHitKind != 2) AND (currentHitWidgetId == capturedWidgetId)
```

随后在 `0x140BF095D–0x140BF0966` 写交互分支 2 和该子状态。当前没有候选时入口将 hit kind 置为 2（`0x140BF04C0`），所以“没有命中”不满足点击条件。

结束触发包括主动作状态与额外结束标记，[133](133-tiny-glade-confirm-cancel-input-mapping.md) 已覆盖释放、失焦、菜单打开、退出消息的部分来源。本段计算的结束载荷没有直接编码所有结束原因；**不能把 Finished=1 简称为所有业务操作的 Confirm，也不能仅凭一次结束通知证明取消必定不会激活**。需要一起核对当次候选和上游取消路由。

**构造例。** 捕获按钮 A 后释放：若当次首个有效命中仍是 A，则上述局部条件可写 Finished=1，A 的 clicked() 为真；若当前命中变成 B 或无命中，则写 Finished=0，A 的 clicked() 为假。两种情况都不代表建筑命令已经成功。

## 登记表消失时，捕获参数仍可能保留

`UiState::add<String>`（`0x1409008D0`）在 `0x1409009AB–0x1409009CE` 把 widget ID 和参数引用写入 UiState 的 `+0x98` 表。它建立的是本轮登记，不是活动捕获的唯一寿命所有者。

在持续交互、尚未转入结束分支的路径中：

1. `0x140BF0BED–0x140BF0C69` 用捕获的 widget ID（状态 `+0x38`）查登记表。
2. `0x140BF0DE2–0x140BF0DF4` 找到时取新登记参数；未找到时回退到捕获状态原来保存的参数引用。该回退通过实际条件移动和引用读取确认，不是因“拖动一般应持续”而推断。
3. `0x140BF0EB1` 写入 `(outer=2, substate=4)`，并保存选定参数引用，继续该交互。
4. 本轮更新末尾 `0x140BF134C–0x140BF1353` 清空 `+0x98` 登记表；活动状态持有的引用与登记表不是同一个寿命。

结合 149，可得有限但有用的结论：隐藏让所选工具栏停止新登记，**不能仅靠这个动作指望旧捕获立刻结束**。原作保留参数可能服务于离开目标后仍需持续的拖动，但本轮不臆测开发者意图，也不宣称所有页面都允许隐形交互。

**构造例。** A 已被捕获，主动作仍保持按住；A 因页面变化不再登记。若执行到上述持续分支，查表失败仍使用旧参数并保持持续状态。之后释放若命中已刷新为无候选，点击判定失败。隐藏、命中刷新、ui_update 和页面构建之间的完整阶段次序尚未全部恢复，不能据此承诺恰好零帧延迟。

这也是自研应明确的区分：滑条允许指针离开后继续拖，不等于整个页面关闭后仍允许该拖动；两者应由不同条件控制。

## 重叠候选不只是看谁最后绘制

`hover_intersection`（`0x140BEF0A0`）构造候选、过滤、排序后发布给 UiState；`ui_update` 在 `0x140BF0414–0x140BF0434` 读取该向量的第一项作为本段当前候选。新证据包括两组候选：

| 分组                                                   | 实际所选排序                  | 静态可确认规则                                                          |
| ------------------------------------------------------ | ----------------------------- | ----------------------------------------------------------------------- |
| `WidgetIntersection`，每条 0x38 B                      | `0x140BEF985` → `0x14151B930` | 小排序分支比较记录 `+0x20` 的 float，普通有限数按升序；相等时不向前插入 |
| `(&WorldCanvasLayer, WidgetIntersection)`，每条 0x40 B | `0x140BEF966` → `0x14151BE80` | 小排序分支按 layer 指针所指首字节升序，相等时不向前插入                 |

排序后，`0x140BEF9C1–0x140BEFA79` 从普通候选计数的尾部追加去掉 layer 指针的第二组记录。因此在该发布结构中，两组不是简单混合后统一按绘制顺序排序。`+0x20` 的完整数值生产者本轮未恢复，不能把它直接说成屏幕 z、DrawOrder 或世界距离。

已展开的是候选数 2–20 的分支；21 及以上另走 stable sort 入口，本轮没有逐指令展开。部分负值候选还受 flags bit `0x4` 筛选（`0x140BEF6E0–0x140BEF6F4`），不得把所有负值一概排除。

**构造例。** 自行给同组候选 A、B 排序标量为 0.2、0.1，则所选分支把 B 排在前面；相等值不在该比较中互换，但这不证明跨帧平局顺序恒定，因为上游登记和并行收集顺序尚未固定。没有从这里推导“创建得晚的一定优先”。

## 给独立 UI 实现的规则

建议沿现有 UI 状态与输入所有者实现，不增设第二份工具或业务状态：

- 按下时绑定 `widget ID + 页面代次 + 按压序号`。隐藏/禁用、页面替换或所有者回收时显式取消该捕获，记录原因；取消不发送成功激活。
- 按住时取消后，不把同一个仍未松开的物理输入交给新页面 B；等它释放，再允许新的一次按下，避免穿透。
- 释放只激活原所有者，且核对当前显示/可用、代次、未取消以及该控件自己的 release-inside 契约。滑条的离开目标续拖与按钮点击分别定义。
- 重叠时规定页面/遮罩层、控件次序和稳定的最终平局规则；视觉放大、透明度和命中 padding 不隐式改写优先级。

建议验收四个最小场景：A 按下→隐藏→松开；A 按下→B 页面出现→松开；重叠边缘 A/B 连续移动；滑条拖出范围后继续与关闭页面取消分别验证。运行、视觉与用户验收仍全部 **Pending / Not Run**，这不是对用户项目当前缺陷的诊断。
