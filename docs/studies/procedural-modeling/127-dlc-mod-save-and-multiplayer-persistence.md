# 玩法 DLC、Mod 与联机存档的恢复契约

2026-10-21，Pacific Time。用户新增要求：不同 DLC 带来不同存档内容，联机保存与 Mod 同步也需要支持；**房间里任意一位参与者拥有相应 DLC，全员可以一起玩**。前半句输入有拼写歧义，本篇按“不同 DLC 会带来不同存档结构/内容”解释，没有据此假定必须为每个 DLC 单独建立一套世界存档。

结论与独立建议：**一份家园保存事务，包含核心世界、包依赖清单及各模块的版本化状态；房主保存权威世界，客机接收状态；购买资格在当前会话重新检查。** 不同战役可以有不同存档槽，但不因 DLC 数量增加而复制房屋、库存、时钟或保存器。共享 DLC 的资格与文件分发见 [128](128-party-shared-dlc-and-mod-synchronization.md)，原首片范围见 [126](126-gameplay-packs-project-kickoff.md)。

本轮阅读公开技术资料和已有项目 owner 的 Scope/交接记录；未启动游戏、Unity、Steam 后台，没有读取真实玩家存档或采集网络。项目当前完整存档接入是否完成，以 owner 的当前源码和 Records 为准。

## 保存什么：核心、模块、内容身份分开

以下是逻辑字段，不要求增加新的顶层文件或照搬名称。实际修改沿现有 World/SaveService/Host-Replica；共享格式版本只由项目授位后冻结。

| 数据               | 需要保留的内容                                                                             | 不应混入的内容                                                 |
| ------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 核心世界           | 世界稳定 ID、核心 schema、提交版本、建筑/地形、现有资源账本、统一模拟时间                  | 每个玩法各自复制的世界/库存/时间                               |
| 包需求记录         | 稳定包 ID、包版本、API/状态 schema、依赖闭包、来源/Workshop 定位、发布修订及采用的内容身份 | 安装路径、仅靠订阅 ID 推断的“相同内容”                         |
| 玩法模块状态       | 塔防波次、已经生成及存活的实体、剩余效果、任务阶段、规则持久变量、调度游标、结算身份       | 函数、监听委托、场景对象指针、旧任务句柄                       |
| 玩家在此世界的状态 | 已有玩家身份下的该世界进度、装备/任务归属；复用现有账本和玩家记录                          | 客机自行声称的奖励或另一份可独立覆盖世界的存档                 |
| 迁移/历史          | 已采用的迁移身份及结果、必要的旧 schema 识别、存档分支来源                                 | 一次内存中的“迁移做过了”标记                                   |
| 资格诊断           | 可以记创建时所需 DLC/能力，供提示                                                          | 可恢复成有效权限的永久“某好友已购买”布尔值、登录票据或会话密钥 |

每个 DLC 可以独立升级状态 schema，核心世界也有自己的 schema；包版本升级不等于状态迁移已完成。即使当前模块停用，也不能抹去其状态。恢复到运行对象后重新绑定监听和显示，不能重放开局生成/任务奖励来代替恢复。

内容身份机制沿项目已经批准的方式使用；本轮不计算新摘要。只有版本文本不足以证明包字节一致，必要时使用被允许的逐字节比较或另行获准的内容校验机制。存档只记录需求，不把整个订阅目录、原作资源或平台认证材料塞进保存文件。

## 缺 DLC、缺包与不兼容应当产生不同结果

| 读档条件                                 | 建议行为                                                                    | 原档与现有世界                             |
| ---------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------ |
| 文件/API 完整，房间有人提供有效 DLC 资格 | 通过依赖和状态校验后恢复；本人未购买不构成拒绝理由                          | 候选完整成功后原子发布                     |
| 文件完整，当前没有任何有效 DLC 提供者    | 保留模块状态并暂停受限玩法；若核心家园能独立解释，可继续合法的建造/生活功能 | 不删除塔、任务或进度，不把无资格误报成坏档 |
| Steam 暂时无法确认资格                   | 显示等待确认；保存可恢复状态，不把 Unknown 改成“已购买”或“未购买”           | 不永久改写拥有信息或毁弃进度               |
| 缺纯外观包                               | 仅在该包明确不影响几何/规则时允许有标识的预览；保留原资源身份               | 不把占位模型写回成替代资产                 |
| 缺会影响几何、物品或规则解释的必要包     | 拒绝正常可写加载并列出依赖；能安全隔离时才提供明确的只读预览                | 不清空不认识的对象或字段，不覆盖原档       |
| 包更新、状态 schema 不兼容               | 在候选上迁移、校验完整闭包；失败保留原因                                    | 原档与当前活动世界不变                     |
| 用户主动卸载玩法                         | 先停活动任务/提交并保存，再解除挂载；“删除进度”是另一个明确动作             | 退订或失去资格不等于授权删除数据           |

“没有资格”与“没有解释这些数据的代码/资源”不同：只有前者才可能安全暂停模块后继续同一家园。未知模块仅保存原始块也不自动获得可写加载资格；必须证明世界引用、校验、命令和保存能完整保留语义，否则只读或拒绝。当前首片不必为任意未来插件实现通用加载器，但应避免现在就静默丢未知数据。

## 联机保存：只有一份权威世界

**沿现有 Host/Replica：房主拥有这个房间的保存责任。** 客机发送请求并显示已发布状态；存档要包含同一个提交边界上的家园、玩法和资源事实。晚加入/重连取得的是房主的内容需求与世界快照，不能把自己上次的波次或旧敌人回填给房主。

初片建议把家园物资和挑战收益保留在该房主世界。个人设置继续本地保存；若项目已经有角色持久数据，复用现有玩家记录，不能再建一套 Mod 背包。将来允许跨房携带角色/战利品时，必须额外定义来源、重复导入和所有权转移事务，不能在本轮把“联机支持存档”顺便解释成随意跨档搬运。

一次挑战结算必须同时改变已有资源账本和模块的结算凭据，重复网络消息、回调、重连或恢复不能再次发放。稳定结算身份使用现有世界/会话/事件身份组合；单独在客机或仅内存保存一个 `rewarded` 标记不足以证明崩溃后的唯一性。

默认不依赖客机保存房主世界；若未来提供“导出房主快照”，必须是明确操作，保存为新的世界分支并保留来源，不冒充原世界的持续共同写入。房主退出后的接管不是自动获得的能力，本轮不新增 Host migration 或常驻服务器。

## 一次保存、恢复和失去资格的构造例子

以下为独立规格算例，不是运行结果：

1. A 是房主且没有塔防 DLC，B 拥有，C 没有；三人都能运行本体。B 的身份与塔防资格被验证，三人的必要内容一致，A 开启挑战 S7。
2. 某波已经生成 12 个敌人，其中 5 个死亡。保存候选记录 7 个存活实体、该波生成完成、效果剩余时间、规则游标与尚未结算；不会只存“当前第 2 波”。
3. A 完成原有保存事务。下次 A 单独读档时没有 DLC 提供者：模块保持暂停，12/5/7 的事实保留；若家园不依赖缺失定义，A 可以继续建造，不能重新生成 12 个敌人。
4. B 再次加入并完成身份/资格与内容核对，恢复同一 S7 的 7 个实体。效果按统一世界时钟的暂停/恢复契约重新建立到期点，不为 DLC 新造时钟，不因家园已运行一小时而补算一小时战斗。
5. 最后一个敌人死亡时，奖励 30 单位与 S7 的结算凭据一起提交；重复完成消息不再增加 30。断线期间已接受的事务保留，未提交的旧回调须重新检查会话/内容/资格世代。

若某个缺失包定义了房屋的真实碰撞或关键物品，第 3 步不能直接继续可写家园；按上表保留原档并说明缺包。这样不会以“DLC 共享失效”为由破坏核心建筑。

## Steam Cloud、备份和文件成本

Cloud 负责账号跨机器文件，不负责把房主账号的世界分发给朋友；朋友通过游戏网络加入。不要把客机临时快照、Mod 安装目录、绝对路径或本机画质设置混入正式云存档范围。[Steam Cloud](https://partner.steamgames.com/doc/features/cloud#Steam_Cloud_Overview)

首先复用当前项目事务。以后若体量足够大，才评估核心与不同频率的数据分文件，并定义一份提交清单如何同时引用各块及上一份有效版本；文件写完/云同步先后都不能造成半份新世界。Cloud 动态同步的批次提示也不替游戏证明自己的原子性。本轮不更换保存格式、不接平台后台、不做真实读写。

## 交给项目的最小接入与待验证项

当前 `gameplay-packs-td01` 首片应先把塔防/行为 Mod 的包需求、模块状态、结算凭据和缺包失败保护接入已有 World/Save/Host-Replica；把“本地个人资格”和“房间共享资格”留为不同输入，避免硬编码每个客机必须购买。未来 Steam 与 Workshop 实接分别排期，不用假返回值宣称已经支持。

未来获准验证时覆盖：B 为客机仍能提供 DLC；A 无 DLC 保存后单独读档保留数据；B 回来精确恢复；缺 Mod/坏迁移不替换当前世界与原档；晚加入/重连不重生和重复奖励；云端旧档与本地新档冲突不静默覆盖。这些场景目前全部 **Not Run**。

已回答的是保存职责、特殊字段、失败边界和 DLC 共享对恢复的影响；任意插件兼容、跨世界角色迁移、Host 接管、真实双端/Steam/Cloud 行为未验证。
