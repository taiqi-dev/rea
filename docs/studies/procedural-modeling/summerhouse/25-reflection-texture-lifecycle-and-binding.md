# SUMMERHOUSE：平面反射纹理的生命周期与水体绑定

接续[24：其他矩阵与 viewport 写端](24-other-projection-and-viewport-writers.md)。**静态可见的资源所有者是每件 `PlanarReflectionRenderer`：它以源 `Camera` 对象为键保存一台反射相机，反射相机持有一张临时 `RenderTexture`。每次通过门禁的回调把该纹理写给组件所列的 `WaterObject` 的 renderer 属性块，然后才渲染反射相机。**纹理只在首次创建、组件 `renderScale` 与记录值差距大于 `0.02`，或禁用时发生该实现可见的分配／释放；单独的源像素尺寸、URP scale 变化没有对应的尺寸失效检查。这是 CIL 分支结论，不是运行帧观测。

## 创建、缓存与更新

| 阶段         | 静态机制与定位                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 激活与回调门 | `OnEnable 0600003B / IL_0000…0016` 先 `InitializeValues`，把当前 `renderScale` 记到 `m_renderScale`，再将实例加入全局列表并调用 `EnableReflections 06000040`。后者检查全局 `AllowReflections` 和 `VREnabled`，通过时订阅 `RenderPipelineManager.beginCameraRendering`，并把组件列出的水体采样开关设为 1。`OnWillRenderCamera 06000046 / 0000…0068` 排除无效相机上下文、不可见 bounds 和 Overlay 相机。订阅存在不证明某帧真的触发。                                            |
| 键与复用     | 实例字段 `reflectionCameras` 是 `Dictionary<Camera,Camera>`，键为源相机对象，值为反射相机。通过门禁后，`OnWillRenderCamera / 0069…009E` 用该源相机 `TryGetValue`；反射相机为 null 时创建，否则复用。不同源相机可各有独立反射相机及纹理，同一组件的16个水体却共用当前回调绑定的纹理。字段没有按源相机消失、画面尺寸或 URP scale 清理键的可见路径。                                                                                                                             |
| 首次分配     | `CreateReflectionCamera 0600004F / 0000…00FF` 新建隐藏且 disabled 的 `Camera`，复制源相机，配置 mask、renderer index 等，然后在 `00EA…00F2` 调 `CreateRenderTexture 06000050`，于 `00F2…00FF` 写入字典。纹理由 `RenderTexture.GetTemporary(descriptor)` 获得，并存入反射相机 `targetTexture`。`CreateRenderTexture / 0000…001A` 按 URP HDR 能力和格式支持选择格式；`003E…004E` 给 descriptor 设16位 depth buffer 并分配；`0053…0086` 只给纹理命名。没有从名称推断格式值。     |
| 尺寸         | `GetRenderScale 06000047` 返回 `clamp(renderScale × UniversalRenderPipeline.asset.renderScale, 0.25, 1)`。`CreateRenderTexture / 001B…0039` 把源相机 `scaledPixelWidth/Height ×` 此比例各自以 `conv.i4` 转成整数，作为 descriptor 宽高。这是反射纹理尺寸，不是主相机最终 viewport。                                                                                                                                                                                           |
| 现有键失效   | `OnWillRenderCamera / 009F…00E0` 比较 `abs(renderScale - m_renderScale) > 0.02`；成立则对当前反射相机旧 `targetTexture` 调 `ReleaseTemporary`，新建纹理，并将 `m_renderScale` 更新为当前组件 scale。`<= 0.02` 不重新分配，也不更新记录值。比较只见这两个字段；没有比较源相机像素宽高、URP asset scale、HDR 格式或 descriptor。`SetQuality 0600003F / 0023…004A` 可写 `renderScale`，随即调用 `InitializeValues` 把记录值同步，故其当前 CIL 路径不能靠上述差值使已有纹理重建。 |
| 每次通过门禁 | `OnWillRenderCamera / 00E1…0102` 先把当前反射相机纹理写到水体，再更新反射相机属性与透视；`013A…0141` 使用 `RenderSingleCamera` 绘制该反射相机。所读回调没有 `try/finally`，不能据此保证渲染异常时的跨帧状态或纹理可用性。                                                                                                                                                                                                                                                     |

因此，“缓存键”是源 `Camera` 引用，纹理本身不另建尺寸键。字典作用域是一件 `PlanarReflectionRenderer`，不是插件全局共享；`m_reflectionCamera` 只是当前回调取出的工作字段。若场景同时由多台合格源相机触发，同一批水体属性块随回调改写为**最近一次通过回调所绑定**的反射纹理；实际相机调度和可见画面尚未观察。

## 水体材质侧与清理

`PlanarReflectionRenderer` 静态构造器 `06000059 / 0010…0029` 把字符串 `_PlanarReflectionsEnabled` 与 `_PlanarReflection` 转成 shader property ID。`ToggleMaterialReflectionSampling 0600004D` 遍历组件的 `waterObjects`；单对象重载 `0600004E / 0000…0025` 在 `WaterObject.props` 的 `MaterialPropertyBlock` 中 `SetFloat(_PlanarReflectionsEnabled, 1/0)` 并调用 `ApplyInstancedProperties`。`UpdateWaterProperties 06000052 / 0000…005C` 对非 null 列表项调用 `SetTexture(_PlanarReflection, reflectionCamera.targetTexture)` 并再次应用属性块。`AddWaterObject 0600004A` 与 `RemoveWaterObject 0600004B` 也相应切换开关并改列表、重算 bounds；它们不是这五份场景的序列化引用来源。

`WaterObject.get_props 0600006B` 懒创建 `_props`；`CreatePropertyBlock 0600006D / 0000…0017` 先调用 `MeshRenderer.GetPropertyBlock` 读取既有值；`ApplyInstancedProperties 06000073 / 0000…0019` 将该块交给 `meshRenderer.SetPropertyBlock`。`WaterObject.AssignMaterial 06000076` 才写 `Renderer.sharedMaterial`，反射组件上述方法没有调用它。因此这里的纹理绑定作用于各水体 renderer 的属性块，而非为16个水体改写共享材质资产。目标 shader 如何使用这两个属性、最终采样位置与实际画面未在本轮静态范围验证。

`OnDisable 0600003C` 从全局实例列表移除并调用 `DisableReflections 06000041`。后者取消回调订阅、把列表中非 null 水体的开关设为0，然后枚举该实例字典：对有效反射相机的 `targetTexture` 调 `ReleaseTemporary`、`DestroyImmediate` 其 GameObject，最后 `Clear` 字典（`DisableReflections / 0018…0091`）。下次启用后字典为空，合格源相机将走首次创建。此清理路径**未见**把每个水体属性块里的 `_PlanarReflection` 显式清成 null；它只关闭采样开关并释放临时纹理。不能仅凭这一点推断最终 shader 是否读取已释放纹理，也不能把该路径说成材质资产已删除。缓存会保留到禁用或显式 scale 差异分支，未见按帧释放。

## 当前场景可达性与贯通算例

[场景解析](../../../../.cache/procedural-modeling/static-config-followup/summerhouse/scene-camera-components-final.json)在 `level0…4` 的五份发行场景中找到：`level0` 无 `PlanarReflectionRenderer`；`level1…4` 每关各一件，组件 path ID 分别为 `513/434/626/472`，每件 `m_Enabled=1`，本 GO 与父 `Level Environment` 都为 active，每件引用16个已确认的 `WaterObject`。四件的 `rendererIndex=1`、`renderScale=0.5`、`renderRange=500`，mask 分别是 `87/247/247/87`；四份组件字段均完整消费 `296/296 B`。这说明各关的**序列化配置允许**反射路径进入，不能证明关卡实际加载、源相机符合门禁、水体 bounds 可见、全局允许反射、非 VR、Shader 采样或任一运行帧实际绘制。`level0` 不能凭本轮五场景注册记录走这个本地组件路径；动态添加／未查资源仍未知。

以 `level1` 为**条件演算，不是游戏观测**：若 path ID `513` 的组件启用并通过订阅／可见性门，某源相机 `scaledPixel=1920×1080`、URP scale 假设为 `1`，则 `clamp(0.5×1,0.25,1)=0.5`，首次纹理 descriptor 为 `960×540`，键为此源相机，16个水体的属性块得到该纹理。第二次同源回调复用相机和纹理，并再次绑定。若仅把源像素尺寸改为 `1280×720`，本 CIL 不因尺寸差异重建，旧 `960×540` 仍被复用；若把组件 `renderScale` 直接改为 `0.53`，相对初始记录值 `0.5` 的差距为 `0.03>0.02`，先释放旧纹理，再按当时源像素与 URP scale 创建新纹理，例如 URP scale 仍为1时得到 `678×381`（`1280×0.53` 与 `720×0.53` 转整数）。另从初始 `0.5` 仅改为 `0.51` 时，差距 `0.01`，仍复用旧尺寸；真实尺寸与格式需运行数据确认。若改动经 `SetQuality` 发生，还必须考虑它先同步 `m_renderScale` 的分支，不能套用直接改字段的结果。
