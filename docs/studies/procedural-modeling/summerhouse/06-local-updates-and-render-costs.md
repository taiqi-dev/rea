# 局部更新、动画与渲染成本边界

本文沿用[固定的 SUMMERHOUSE 1.2.12 程序集身份和证据边界](00-evidence-and-scope.md)：`Assembly-CSharp.dll` SHA-256 `f4e8bf23299a5e4a916d4bd955e108d2f3760117e5850adf10926ee6aa8379de`、MVID `84569538-a19f-4c17-8ccf-f40b95e99253`。主要依据同一 DLL 的离线 CIL，方法 token 和方法内 `IL_xxxx` 偏移仅适用于这份字节；REA 元数据 Evidence 分别为 `ev_54b382ffc96c6759d706f9d8a92e4a47dfef51824cb2864da333334241793076`（块/组合/网格）、`ev_dbf130a1797c92e37522986abf7c5c20d073a126086d567887d76411e92c7ddf`（放置器）及 `ev_f1ce68a56c8253ecef304bbb32c0ed4c255a54b6241698c5491eb722f51a1c7d`（顶点色/画笔）。全文仅分析静态可达路径，没有启动、附加或计时游戏。第 4 篇的资源引用计数仅给出发行包中预制件的结构，不代表同时在场的实例数或可见 Renderer 数。

## 修改一件块时更新什么

| 输入                 | 状态变化与查找                                                                                                                                                               | 更新范围、输出和证据                                                                                                                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 建造模式每帧移动预览 | `BuildingBlockPlacer.Update` 将**一个** `previewBlock` 送入 `PreviewPosition`；后者吸附 XY、重新求 Z、检查镜像并通知位置事件。深度采样会对该预览块的采样点射线查询物理世界。 | 不逐个遍历 `allPlacedBlocks`；但物理射线的内部成本由 Collider 和场景决定。若 `showGrid` 为真，还重画该块的占格高亮。`0x06000097 IL_0029..0056`、`0x06000093 IL_00BF..0141`、`0x0600005F`。                |
| 点击放置             | `PlaceBlock` 实例化选定预制块，调用 `OnPlace` 放置缩放动画，加入 `allPlacedBlocks`，然后调用 `CombinationManager.OnBlockPlaced`。                                            | 新增一件块；随后扫描可用组合并可能作整块替换、奖励、解锁、闪光。这里没有邻接网格融合、整栋 Mesh 重建或局部几何补缝。`0x060000A6 IL_0117..017D`、`0x06000059 IL_0000..0006`、`0x060000F6`。                |
| 销毁模式点击         | `DestroyTarget` 对射线命中的一个块先在列表中 `Contains`、`Remove`，再 `OnDestroyBlock`、登记撤销。                                                                           | 列表查找最多扫描当前 N 件；所读路径**没有**再次调用组合判定来撤销附近奖励。`0x0600009F IL_0000..0051`、`0x0600005B IL_0000..000B`。已解锁进度、撤销重建和真正画面需另验，不能据此断言删除后最终组合状态。 |
| 组合命中需替换       | `OnCombinationSatisfied` 调 `FindBlockToReplace`，再 `ReplaceBlock`；后者验证旧块在列表中，记原世界位置和镜像状态，移除并销毁旧件，实例化奖励件、播放放置动画并入列。        | 更新一个块实例及其预制子对象，奖励块可有不同数量的 MeshFilter；该方法没有再调用 `OnBlockPlaced`，故不递归搜索新奖励可参与的其它组合。`0x060000F8 IL_00AA..0107`、`0x060000A7 IL_001E..00DB`。             |
| 拖动已放置块         | 在已读 `BuildingBlockPlacer` 方法表和 `allPlacedBlocks` 直接写入处，未找到玩家拖动已放置实例并触发局部重新判定的入口。                                                       | 当前可证的“移动”是预览位置变化、相机/深度输入和替换时沿用旧位置。不能由这个有界搜索证明游戏或 Unity 其它程序集绝无移动功能。                                                                              |

组合不是空间邻居索引。`OnBlockPlaced` (`0x060000F6 IL_0000..009D`) 顺序走 `availableCombinations`；`CombinationSatisfied` (`0x060000F7 IL_0034..0215`) 先按新块 `saveID` 收集配方锚需求，再对每个锚、每个需求计算 `落点 + 需求相对位置 − 锚相对位置`，之后**线性扫描** `allPlacedBlocks` 的位置和 ID。没有用 `GridManager.GetCell` 直接取得邻居。查找会在首个失败需求或成功配方时短路；`maxOneCombo` 控制成功后是否继续扫描其它配方。这个成本属于放置事件，而非每帧。

以[第 4 篇的真实配方](04-packaged-blocks-and-combinations.md) `id=22` 作演算：`Door 07` 的 ID 130、相对 `(0,0)`，`Door 08` 的 ID 131、相对 `(2,0)`，奖励为 ID 174。假定场景已有 N=100 件，玩家把 ID 130 放到 `(10,4)`。放置器先创建实例并令 N=101；组合检测对该配方求另一需求目标 `(10,4)+(2,0)−(0,0)=(12,4)`，从放置列表逐件扫描到位置 `(12,4)` 且 ID 131 的实例才满足。如果它是第 80 个候选，这一需求至多检查到第 80 个；其它实际配方仍可能被遍历。命中后旧门会被整个奖励预制块替换、列表长度仍为 101；没有对全建筑顶点数组做一次统一重建。这是**以真实资源作输入的构造演算**，不是玩家操作录像。

## 可见材质与网格的局部代价

`PaintBlock` 只作用于当前射线目标，遍历该块子 Renderer 的 `sharedMaterials` 槽，为每槽在 `PaintBrush.materialReplacements` 中线性找引用相等的映射；至少一槽改变才写回 `sharedMaterials`，随后记录新“原材质”。Unity 2023.2 的 [`Renderer.sharedMaterials` 文档](https://docs.unity3d.com/2023.2/Documentation/ScriptReference/Renderer-sharedMaterials.html)说明 getter 返回**材质引用数组的副本**；这里替换副本里的槽位并 set 回 Renderer，不是修改共享材质自身属性，也不是 `Renderer.materials` getter 的独立材质实例化分支。未读到 Mesh 写入。证据：`0x060000A1 IL_0000..0029`、`0x06000064 IL_0000..0064`、`0x060001D9 IL_0000..0049`。另一个 `PaintBrush.Paint` 实现类似，但放置器调用的是块方法。若命中块有 R=2 个 Renderer、各 2 槽、刷子映射数 B=3，最坏需约 `2×2×3=12` 次材质对照；变动只绑定到这一个块，邻居不受这段循环直接修改。此处 R、B 是构造参数，真实值依赖实际 prefab/画笔。

射线目标的选择高亮有反复操作：`BuildingBlockPlacer.Update` 每帧先 `set_RayCastTarget(null)`；销毁、吸管、画刷模式再做一次物理 Raycast，命中则 `set_RayCastTarget(该块)`。setter 在旧目标非空时 `RestoreOriginalMaterials`，再对新目标调用 `ReplaceMaterials(Material)` 或 `ReplaceMaterials(PaintBrush)`；即使指针保持在同一块，本帧也会经历清空和再赋值。普通单材质高亮只给 layer 6 的子 Renderer 分配等长材质槽数组并写 `sharedMaterials`，没有读取 `Renderer.materials`；画刷预览走映射表。证据：`0x06000097 IL_0000..00BF`、`0x06000098 IL_0020..00AD`、`0x0600008E IL_0000..007D`、`0x06000063 IL_0000..0043`、`0x06000065 IL_0000..002B`。因此单目标的子 Renderer 数和材质槽数影响这些模式的每帧 CPU/分配，不能把它说成 N 件建筑的全表材质复制。

网格占格高亮是另一个按预览块 cell 数 K 放大的成本。**只有**有效的放置器预览、非 UI/菜单位置、存在 `GridVisualizer` 且 `showGrid=true` 时，`PreviewPosition` 才调用 `HighlightBlockInGrid`；`GridVisualizer.Start` 也仅在 `showGrid=true` 时创建底层格线 (`0x0600013C IL_0000..0046`)。`HighlightBlockInGrid` 每次先向 Unity 请求销毁上次线条，再对 K 个 cell 最多画 4K 条 `LineRenderer`，随后 `HideInternalHighlightLines` 两层遍历线条对，最多约 `4K(4K−1)/2` 次线段比较；前提是每个 cell 都在网格内。`DrawHighlightedLine` 明确新建 GameObject/LineRenderer 而非重用；它先设置线 Renderer 的 `material`，又读取该属性并设颜色。按 Unity 2023.2 的 [`Renderer.material` 文档](https://docs.unity3d.com/2023.2/Documentation/ScriptReference/Renderer-material.html)，访问这项属性可能使共享材质为该 Renderer 产生独立实例。这条分支应与建筑块的 `sharedMaterials` 绑定分开。证据：`0x06000093 IL_00EF..0119`、`0x06000141 IL_0000..006C`、`0x0600013F IL_0084..00AE`、`0x06000140 IL_0000..00BC`、`0x06000142 IL_0000..00E2`、`0x06000144 IL_0000..0043`。例如 K=2 时一次满足条件的预览更新最多新建 8 条、比较 28 对；即使预览停在同一位置，只要上述调用路径每帧继续，代码仍发出重画请求。未确认实际场景 `showGrid`、可玩帧中活跃组件或 Unity 销毁完成时点。

`SetVertexColors.Start` (`0x06000262 IL_0000..00AB`) 枚举子 MeshFilter，读取 `mesh` 和 `colors`，按选定 R/G/B 通道遍历已有颜色数组，再写回 `colors`。Unity 的 [`MeshFilter.mesh` 文档](https://docs.unity3d.com/cn/2023.1/ScriptReference/MeshFilter-mesh.html)说明首次访问会复制已绑定的共享网格，之后访问返回实例，因此该脚本**可能在启动时为每个被读的 MeshFilter 建立独立网格实例**；不是“只修改共享预制网格”，也没有顶点或三角形生成分支。是否挂在当前可玩场景的哪些对象、顶点数 V、复制后生命周期均未静态确认，不能用 673 个包内 MeshFilter 引用数当作运行时复制数。成本随实际挂载 MeshFilter 的颜色数组长度求和，属于启动/实例初始化，不是这段脚本每帧重算。

组合奖励的 `ShimmerAnimator` 对参与块的子 Renderer 读取 `Renderer.materials`，改 `_ShimmerWidth`，协程进行中的每帧只推进一个全局 `_ShimmerPosY`，末尾又遍历参与块并复位材质。Unity 2023.2 的 [`Renderer.materials` 文档](https://docs.unity3d.com/2023.2/Documentation/ScriptReference/Renderer-materials.html)明确这项读取会让材质成为该 Renderer 的独立实例；这里同一循环多次读取该属性，具体分配与缓存行为需要 Profiler 才能定量。`ShimmerAnimator` 的开始、协程和复位分别在 `0x06000272 IL_0000..002E`、`0x060003AE IL_0053..0127, IL_0179..0229`、`0x06000275 IL_0000..008A`。此效果只覆盖 `blocksInCombo`；不能把它算到所有放置块每帧，也不能把材质实例数直接换成 draw call 或显存字节。

## 时间与规模：能算到哪一步

令 N 为本次放置后的块实例数，C 为当前 `availableCombinations` 数，配方 j 有 r_j 个需求，其中 q_j 个需求的 ID 可与新块作锚。一次放置的组合核对上界可写为 `O(Σ_j q_j × r_j × N)`，另有遍历配方和收集锚的 `O(Σ_j r_j)`；成功/失败短路和 `maxOneCombo` 会降低实际访问数。构造一个上界规模：C=3，三条配方各有 r=2、q=2，放置后 N=101，则位置/ID 候选比较至多约 `3×2×2×101=1212` 次，另外扫描 6 条需求以收集锚；这不是实际场景配方数或实测次数。第 4 篇在一个 `sharedassets0.assets` 文件解析到 123 个组合，但这里不能把 C 固定为 123：场景启用集合、游戏进度和其它资源未证实。删除路径列表 `Contains`/`Remove` 是 O(N)；组合替换同样有列表查找/删除 O(N)，加一个实例的创建与销毁。Paint 单目标上界约 `O(R × S × B)`，S 为每 Renderer 材质槽数、B 为刷子映射数；目标高亮约随目标子 Renderer 与材质槽数增长；格线高亮为 `O(K²)` 的线对检查，加最多 4K 条对象创建/销毁。这里均为 CIL 推导的操作次数阶，不是毫秒、FPS 或 GPU 渲染成本。

逐帧部分还有两个不同的动画机制。`AnimationTimer.Update` (`0x06000014 IL_0000..000C`) 每帧调用两个时钟函数，各根据 `deltaTime`、速度范围和曲线推进计时，然后设置全局 shader float `_AnimationTime01/02` (`0x06000016/17 IL_0000..0077`)；这属于共享全局参数路径，本程序集方法里没有逐块 Animator 遍历。`RandomizeAnimationStart.OnEnable` (`0x060001E5 IL_0000..0077`) 则对该组件持有的每个 `Animation` 的每个 `AnimationState`，从 `[0, state.length]` 取随机起始 `time` 并 `Play`，可让实例动画错相；其 `animations` 数组来自序列化状态或 `GetAnimationComponents` (`0x060001E4`)，但本程序集内没有发现该采集函数的调用。两者不是同一个时钟；哪些 prefab 附有此组件、实际状态数与是否执行仍未知。

实际渲染成本还缺场景中活跃对象、每个 Renderer 的材质槽/网格顶点与三角面、遮挡与批处理，以及 GPU/CPU Profiler 时间。[05](05-materials-pixelization-and-camera.md)已补齐主相机接入 active PixelateLayer 的静态配置；运行时选择、目标尺寸和实际成本仍未测。第 4 篇的 `455` 个块对象、`673` 个 MeshFilter 和 `234` 个本地不同 Mesh 只证明包内对象结构与共享引用，不是同帧 draw call、内存或 FPS。结论可用于设计自研时选择“事件驱动组合查找、对象级材质更换、共享 shader 时钟”的待验证方案；实现应按自身需求重新设计，不能把上述恢复逻辑或专有资产直接搬入产品。
