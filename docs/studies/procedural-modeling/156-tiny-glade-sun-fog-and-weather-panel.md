# Tiny Glade：太阳面板、雾参数与独立锁定

2026-10-24，America/Los_Angeles。供既有 UF03 环境面板制作；身份、截图与工具边界见 [155](155-tiny-glade-menu-snapshot-and-hover-visibility.md)。已读用户 `reference-7.png`，图中图标只是视觉参考，不用它猜全部滑条的内部语义。季节选择是用户要求我方新增的能力，不能据此宣称原作太阳面板已有季节系统。

## 实际面板组织

`do_time_of_day_screen`（`0x140682F80`）实际引用 `menu/time_of_day_2`，并填充 `tod_circle`、`angle_circle`、`tod_button`。对应活动模板 `assets/ui/menu/time_of_day_2.ron` 左侧为 precipitation、fog_button、slider_0/1/2，右侧为两个圆盘和时间锁；`precipitation_controls.ron` 另定义一个强度 slider 和自己的 button。

因此图 7 中左侧并不是若干没有区分的“天气参数”：**三个雾滑条、一个降水强度，以及时间、雾、降水的独立锁定职责需要分别解释。** 模板本身不证明所有主题都显示全部槽。

## 雾：浓度、高度、陡峭度

本轮从实际保存器核对字段，避免只凭图标和偏移命名。`Weather::fog_save_state`（`0x140B86CC0`）复制 Weather 的前三个 float 和 `+0x14` 的 bool；对应 `FogSaveState` serializer（`0x140676FA0`）依次以 `thickness`、`height`、`steepness`、`locked` 作为字段名，实际引用在 `0x140676FE2/0x140677009/0x14067702D/0x140677051`。

`fill_weather_slots::closure$2`（`0x140689160`）的实际读写对应为：

| UI kind | Weather 字段 | 滑条到参数                      | 已核标签/用途                    |
| ------- | ------------ | ------------------------------- | -------------------------------- |
| 0       | +0x00        | t，所选显示/交互归一化范围 0..1 | thickness / `menu/fog/thickness` |
| 1       | +0x04        | t，所选显示/交互归一化范围 0..1 | height / `menu/fog/height`       |
| 2       | +0x08        | `1 / (20*(1-t)+2*t)`            | steepness / `menu/fog/steepness` |

第三条不是“雪花大小”。反向显示先算 `1/currentSteepness`，再作 20→2 的 inverse lerp 并夹到 [0,1]；写回再取倒数。这里是 UI/状态参数尺度，尚不能直接称 height 的 0..1 等于世界中的 0..1 米，也不等于最终消光系数。

**构造例。** t=0/.5/1 时，第三参数分别为 .05、约 .090909、.5，明显不是线性 .05→.5。浓度和高度在本段直接用 t；真实场景雾形状还取决 shader、地形、光照与渲染输入。

实际拖动的选定返回标记会将 Weather `+0x14` 置 1（`0x1406892A5–0x1406892B1`）；雾锁按钮另外切换该状态。`time_of_day` 系统在 `0x140AEC256` 检查同一 `+0x14`，为 1 则跳过其自动雾参数插值块。这接通了手动控制如何避免被自动值下一次覆盖；不需要暂停全世界来保留手调雾。

## 降水：强度与自动变化锁

`Weather::precipitation_save_state`（`0x140B86CE0`）读 `+0x10` float 和 `+0x15` bool。`fill_weather_slots` 将对应字段引用交给 precipitation 构建路径；`fill_precipitation_slots::closure$0`（`0x140689320`）实际使用单一 strength slider，并在所选操作标记成立时设手动状态。

`weather_system`（`0x140B56280`）先检查当前主题 raw ID 是否为 4：该主题的所选自动分支遇到 `+0x15==1` 会退出；未锁时根据时间正弦方向令 `+0x10` 以 `0.1*dt` 上下变化并夹在 [0,1]。非该主题分支直接把强度设为 0，发生在锁检查之前。

**构造例。** 在该主题、自动状态、正向变化时，强度 .4、dt=.1 得到 .41；手动锁为真时该自动分支不写；换到所选非该主题分支则会置 0，不能把此锁解释为“跨一切主题永久保留任何降水值”。raw ID 与主题资源的完整映射不由截图补写。

本轮没有在这个面板找到独立粒径 slider 的实际绑定，不把“未找到”升级为全产品无粒径参数。雨/雪类别、雪材质覆盖与粒子尺寸的全部运行分派仍需各自证据；我方只展示当前正式环境真正支持的控制。

## 时间圆盘、太阳方位和时间流逝

TimeOfDay 保存字段实际包含 `time_of_day`、`sun_xz_rotation`、`latitude_degrees`（serializer `0x140235CE0`）。圆盘路径分别处理归一化时间与角度，角度拖动存在 `atan2`、按 `2π` 环绕和实际状态写端（`0x14068AC17–0x14068AC60`）；因此不是只转一张太阳图标而不改变参数。

时间锁控件在 `0x140689F00–0x140689F13` 切换所取 GameConfig 的 `+0xE3`；`time_of_day` 自动推进分支在 `0x140AEBEEC` 读取同一配置位。它与上述雾锁/降水锁不是同一个 bool。环绕时间并不保证 UI 归一化 .25 在所有纬度和原作 speed-bias 下等同“日出”；面板数值和太阳路径不能凭常见时钟习惯补全。

## UF03 的独立规格与未知

- 时间、太阳方向、雾、降水各投影当前正式环境状态；拖动必须沿该所有者写入，锁定明确阻止哪一项自动演进。不要用 `Time.timeScale` 代替时间/天气锁。
- 给雾浓度、高度和衰减形状可理解的名称、值和单位；我方参数根据自己的环境系统定义，不照搬原作倒数范围假称物理等价。
- 只为实际支持的雨雪强度/粒径提供控件。季节选择作为我方新增，定义资源主题、积雪表现、过渡、保存/联机和天气恢复关系，不把视觉季节选择自动改成玩法时钟推进。
- 太阳入口/公共 UI 与 UF01 串行集成；本研究不占共享 hunk、不改变项目状态。

仍未知：原作所有降水类别及粒径消费者、精确时间圆盘与自动推进的全部曲线、每项参数到最终像素/保存恢复的全部路径。截图语义、静态调用、独立设计分别记录；游戏、GPU、Unity 和用户手感验证均 **Not Run**。
