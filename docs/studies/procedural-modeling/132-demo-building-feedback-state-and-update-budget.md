# 综合 demo：建造预览、成品过渡与打断规则

2026-10-21，Pacific Time。依据 [131 的 Tiny Glade 静态链](131-tiny-glade-placement-lifecycle-and-animation-handoff.md)，为用户的沙盒建造项目整理可独立实现的行为规格。**以下是我们的产品建议，不是原作完整还原，也没有读取或修改 3DSandboxTest 的当前源码。** 实施前应由项目 owner 对接现有命令、历史、实体、几何和 Host/Solo 发布入口，不新增第二套权威。

## 第一片做什么

建议先做一个矩形建筑的完整交互：轻量木框表达宽深高与接地关系，确认成功后成品短暂展开；继续修改从当前显示接到新目标；取消候选和撤销已提交建筑各有正确收尾。圆形、逐瓦掉落、逐砖动画和复杂碎裂随后再决定。

这比完整复制 Tiny Glade 的屋顶细节更贴合综合 demo：玩家能理解当前候选与最终结果，动画能被打断，新增成本可限制。尚无本项目采样，因此不宣称这些建议能把当前约 10 FPS 提升到某个数值，也不把增加动画当成性能优化。

## 世界状态和显示状态怎样配合

| 状态           | 保存什么                                              | 由谁决定下一步                               |
| -------------- | ----------------------------------------------------- | -------------------------------------------- |
| 正在预览       | 工具会话 ID、候选版本、同一几何求解结果、合法性与原因 | 现有工具/校验入口；只是候选                  |
| 等待确认结果   | 本次请求身份、提交的候选版本，保留的候选显示          | 现有命令成功/拒绝结果；联机沿用 Host 权威    |
| 等待成品可显示 | 已接受实体/版本、对应的几何任务或发布身份             | 现有几何发布入口；接受命令不等于网格已经可用 |
| 过渡中         | 当前显示值、最新目标、现有实体身份、呈现代次          | 显示层推进；不重复执行建造命令               |
| 稳定           | 已显示版本，移出活动动画集合                          | 实际后续编辑、撤销、删除或读档结果           |

预览、选择、碰撞、占用和正式显示消费同一几何结果/描述。可用独立的梁网格表现候选，但梁的位置从该结果提取，不能另写一份尺寸或接地求解器。视觉展开只改变显示参数，不逐帧移动正式碰撞来伪造建造过程。

“实体版本”说明逻辑目标，“呈现代次”用于拒绝旧显示结果。它们应来自项目现有身份/版本机制；若尚无呈现代次，再按该所有者补一个最小字段。撤销可能恢复相同逻辑内容，却必须让旧异步回调失效，不能仅用历史游标或内容相等判断回调仍然有效。

## 确认：等真实成功，再交接显示

一次确认只提交一次现有命令，引用本次已校验的候选。收到匹配的成功结果后等待对应几何发布；成品可以显示时，把显示目标切到该实体版本，再释放对应预览。可保留预览直到成品可显示以避免闪空，但不延迟正式世界的权威变更。

建议出现动画控制一个很小的进度/缩放参数：接地点固定，主要沿高度展开或轻微回弹，最终严格回到尺度 1。别直接照搬尖顶的中心缩放，让整栋房屋穿地。原作尖顶曲线在 t=1 仍略有偏差，自己的稳定状态直接写最终值，停止动画更新。

命令拒绝时保留可修正的候选和具体原因，不播放成功音效。确认期间工具已切换，后续成功结果仍按正式世界结果处理；只取消旧工具的显示所有权，不能静默丢掉已经成功的命令或擅自补发删除。

**独立算例：** 候选 C7 提交请求 R8，命令成功产生 B12/V24，网格暂未发布。仍显示 C7 的框架；收到 B12/V24 的几何结果后开始成品过渡并释放 C7。若几何 V23 迟到，拒绝它。这里的身份和值是构造示例，尚未在项目里运行。

## 取消：先判断有没有提交

未提交的取消终止候选会话，释放其梁实例与提示，不写世界历史、不扣资源、不留下永久碰撞。提示线可以短暂淡出；不能为了淡出让已经失效的候选继续接受点击或被保存。

提交后“取消显示等待”和“撤销正式建造”是不同操作。等待结果时不假装请求从未发生；若项目支持取消命令，沿既有协议处理，否则以真实结果为准。已成功建造的撤销走现有历史命令。

清理按会话身份进行，不能调用全局“清所有预览”：工具 A 的迟到退出回调不得释放工具 B 刚创建的框架。控制器持有本次分配/租约；对象池归还也核对这个租约。

## 连续修改：追当前目标，避免动画堆积

沿用一个活动显示记录。目标变化时，以当前显示值作为新起点，替换目标和呈现代次；不排队播放每次鼠标变化，不为每根梁起一个协程，也不在每次变化时从零重播整栋出现。

131 的实际旋转路径说明增量追赶是可行方向，但原作的指数项加最小收敛步不是所有参数的通用常数。我们可以独立采用时间步相关的平滑；旋转处理最短角差，长度/高度保持合法区间，拓扑变化等待新的正式几何发布。无法一一对应的顶点不强行插值。

**独立算例：** B12/V24 正在出现，又接受 V25 的宽度修改。保留当前可见状态，切目标为 V25；V24 的结束回调只结束自己的记录，不能把当前比例写回 V24，也不能重新播放 V24 的成功声音。同帧候选输入可合并到最新目标；已被权威接受的命令仍按原顺序保留，不能用视觉合并删除历史。

## 撤销、重做与读档

先消费现有历史系统的真实结果，再决定退场/恢复显示。撤销时立即提升或替换呈现代次，作废旧几何任务、旧动画完成回调和旧池租约；正在出现的建筑不能在撤销后被旧回调重新显示。

建议第一片采用：普通新建有短出现动画；连续改形状保持连续追赶；撤销和重做快速到正确结果，允许很短、可打断的显示过渡；读档直接构建稳定外观，不全场重新播放建造与落定声音。最后两项是产品选择，不能冒称 Tiny Glade 对所有对象都这样做。

存档只保存既有世界权威需要的建筑语义、身份和稳定生成输入；短暂视觉进度、木框实例索引和过期任务不另写进存档。既有玩法若需要真实施工时间，应在正式玩法系统定义，不能借一个显示进度冒充建造完成度。

**独立算例：** B12 的显示代次 A4 还在播放，撤销成功切到 A5 并移除其逻辑建筑；A4 的迟到网格与完成回调均不能发布。随后重做得到新的有效发布代次 A6，即便形状和 B12 原来相同，也只接受 A6 对应结果。

## 把新增性能成本限制在活动对象

| 工作       | 建议的更新边界                                                             | 暂不做的高成本扩展                           |
| ---------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| 木框       | 用自己的共享梁网格与材质；尺寸/接地/朝向改变才更新必要实例；采样数量有上限 | 为每根梁创建常驻 Update、独立材质或刚体      |
| 成品动画   | 小型活动集合推进进度；稳定后移出；已有实例缓冲只更新受影响记录/区间        | 全场每帧重建屋顶和墙来表现生长               |
| 连续输入   | 显示候选合并最新值；几何求解复用现有 dirty 与任务调度                      | 同一对象堆积无用构建任务或为动画增设世界时钟 |
| 阴影       | 候选框默认不投实时阴影；成品用现有阴影层与预算                             | 每次预览额外启动一套阴影/反射相机            |
| 退出与回收 | 所有者释放自己分配；旧结果明确丢弃并保留原因                               | 靠扫描整场对象或全局清池解决一次取消         |

Tiny Glade 所选木框消费者实际会清本分配再生成，尖顶上传会收集整个所选 query 的记录；这些是可研究的实现取舍，不能自动称为最省成本的逐项差量方案。我们的静止场景应尽可能没有建造反馈更新；是否值得合批、差量上传或保留分配，需要项目实际采样决定。

## 后续实施与验证边界

建议项目 owner 将第一片限定为“矩形框架预览 + 成品交接 + 四类打断规则”，优先接现有成功结果、几何发布与历史生命周期；只在缺少实际入口时补最小接口。参考行为和本项目当前实现的差异需在实施时核对，这份报告不要求重做现有系统。

本轮只做了静态证据与算术复核。后续获准运行时，选一个矩形房屋依次检查：确认等待期间不闪空；拒绝不演成功；取消不留交互/碰撞；连续修改无旧结果覆盖；出现中撤销、重做不复活旧对象；读档无全场音效；稳定后活动动画集合为空。性能另比较静止、单对象编辑、快速改形状与批量恢复的 CPU/GPU 帧时、分配及任务队列。所有运行、体验、联机及性能结果当前均 **Not Run**。
