# Tiny Glade 屋瓦边界：裁平面生产、传递与接缝限制

本轮确认了非默认瓦片裁平面的CPU来源，并追到GPU半空间测试：它来自**同一矩形屋顶的上下轮廓边界**。这补齐一段真实生产链，但尚未确认两栋建筑roof-roof或wall-roof相交时完整的瓦片裁切算法。

铺排与实例布局见[41](41-tiny-glade-roof-tile-layout-and-clipping.md)，GPU旧证据见[05](05-tiny-glade-seams.md)，建筑相交的其他消费者见[04](04-tiny-glade-intersections.md)，本轮复核见[47](47-tiny-glade-four-systems-evidence-ledger.md)。

后续[48](48-tiny-glade-roof-trigger-mesh-and-attachments.md)确认屋顶表面cache、RT输出与实际装饰/编辑消费者，[49](49-tiny-glade-roof-gpu-visibility-and-depth.md)补11模块资源审计、HZB及局部材质深度。完整建筑间保留侧仍未知，这些不同表示没有合并成Boolean生产者。

## 1. 默认平面与边缘平面不同

矩形前三个输出点及圆形两个输出点，写入u64：

```text
0x7BFF00003C000000
```

按小端四half解为 `(0,1,0,65504)`。在普通世界高度例中，它是宽松的默认平面；不能将它当零平面，也不能宣称所有可能输入都永不被裁。

### 构造例：默认记录解包

原字节 `00 00 00 3C 00 00 FF 7B`。点(0,3,0)的未经顶点校正判定值为65507，大于零。这只解释该平面的数值效果，没有执行shader。

## 2. 非默认平面从本屋顶上下轮廓产生

矩形装配器取得底部轮廓点B_i和顶部轮廓点T_i，二者来自本屋顶局部Rectangle2d.as_curve2。设原矩形方向矩阵M、中心C：

```text
delta0=M*(T_i-B_i)
delta1=M*(B_(i+1)-T_(i+1))
n_k=(-delta_k.z,0,delta_k.x)/length(delta_k)
P0=(M*B_i+C).x0z
P1=(M*B_(i+1)+C).x0z
d_k=-.075-dot(n_k,P_k)
plane_k=(n_k,d_k)
```

来源调用与算术在 `2812DD0/2812E9B/2812EC3`、`2814752–2814959`。n.y=0是实际构造，所以这条路径的切平面为竖直方向。两delta方向并不相同，不可只给所有边套同一法向符号。

`28152EC–2815305` 根据当前区间start u选择：u>.5取plane1，否则plane0；`2815496` half打包，`2815599` 写64B瓦记录+10。实际输出闭包再送RoofTile writer。

这里没有把另一栋建筑的轮廓作为平面输入。不能因它发生在屋面边缘就命名为建筑相交求解器。零delta、所有退化顶边和全部侧面资格未恢复。

### 构造例：带.075余量的半空间

给delta0=(0,1)（XZ坐标），P0=(2,0,3)，得n0=(−1,0,0)、d=1.925。

锚点自身判定值为−.075；点(1.8,0,3)为+.125，点(2.1,0,3)为−.175。因此余量和法向方向都影响保留侧。这个例子不能推导整座屋顶的内外方向，必须按具体边的delta排列计算。

## 3. 额外边排复用平面，却有不同构件参数

普通输出 `28155F7` 之后的一条条件路径，从保存的四float读取同一plane，`28157E8`再half打包、`2815816`写另一记录+10，最后 `2815877` 输出。两记录可以共享当前seed和平面，但scale、t和标志不同。

这确认同一区间的主体及额外输出可使用一致的切界。它没有证明额外输出一定是唯一末排、屋脊或某个原始资产种类。

### 构造例：共享边界而不共享姿态

两记录都携带half编码 `(−1,0,0,1.925)`，但一个t不为零、另一t=0，标志也不同。未变形时都面对同一CPU平面；最终可见边缘仍需各自顶点变形和校正，不能据同plane宣称两个网格完全重合。

## 4. GPU继续校正并按严格半空间裁片元

`nani_instanced_roof.precomp` vertex blob0 的 `2049–20E1` 解包四half。在顶点变形后，`8969–89F1` 输出：

```text
plane_out.xyz=n
plane_out.w=d+dot(p_ref-p_final,n)
```

片元blob1 `BA4E–BACA`，以及另一片元blob3对应路径，对 `dot(float4(positionWS,1),plane_out)<0` 执行 `DemoteToHelperInvocation`，舍弃普通片元贡献。等号处不由此比较舍弃。

对单个顶点可代数验证 `dot(p_final,n)+d_out=dot(p_ref,n)+d`。但plane输出是Flat插值，实际片元采用provoking vertex的平面，不能扩大为整块变形三角形每一点都保持同一精确CPU边界。

### 构造例：顶点校正的局部恒等式

n=(1,0,0)、d=−1，p_ref.x=1.2、p_final.x=1.3，d_out=−1.1；两判定值都为.2。这个单顶点算例不证明全部片元边界，也不代表CPU已删除三角形。

## 5. 有界续查：空间更新与底板入口没有补成相交平面链

为寻找建筑间裁切，另查两个较小入口及一个callback：

- `280E580 update_roof_spatial` 实际取Public墙max_y、比较roof+4C；变化路径更新RtMeshHandle原始64B记录，包含单位XYZ轴和Y位移，并写回roof+4C。其w分量不符合普通Mat4，RT完整布局未恢复。另拷墙形状、更新空间payload和消息记录。在选定范围内未找到RoofTile裁平面生产桥。
- `2808770 generate_roof_stone_floor_and_roof_bottom` 构造drawable描述并提交48B ECS命令；圆形选择涉及 `clamp(log2(4.5*radius),1,5)` 的整数层级。callback `FC5E70` 插入NaniInstanceDesc，没有在这个小入口中求屋瓦裁平面。

这两个入口的字节完整解码，不表示所有下游都分析完。它们提供空间/底板职责线索，不能拿函数名补上roof-roof布尔拓扑。较大的trigger-volume入口本輪没有完整展开；未确认的下游仍列为未知。

## 6. 已答与未答

已答：本屋顶边界平面的坐标来源、法向/余量、两侧选择、half压缩、主体/额外记录复用、GPU校正和片元判定。

部分回答：屋面分片和收口可由多个实例及平面共同完成；完整构件姿态与拓扑未恢复。

未答：不同建筑怎样决定保留哪部分屋顶、是否生成额外裁切描述、全部屋脊/谷线交汇和多平面退化处理。单个实例只有一plane字段，不足以推断整个系统只有一个平面。

独立实现可以按自己的屋面拓扑建立侧边半空间，再为主体与收口构件共享边界描述；建筑相交必须另行设计完整关系与退化规则。这是自研建议，不能冒充已恢复原算法。

未做：未运行交叠场景、提取原网格作交付、恢复完整碰撞/射线世界及渲染绑定。

风险：把本屋顶分片误称建筑间相交，会直接误判算法；half精度、Flat输出和变形也限制CPU平面与最终边界的等价范围。
