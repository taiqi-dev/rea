# Bad North 岛屿与模型生成

Bad North 使用作者提供的三维模块，维护各个位置可以放置的候选，通过面边界和共享顶点约束删除不兼容候选，再按房屋与可行走区域引导选择。成功布局随后恢复模块模型，合并并软化网格。[WFC 作者项目](https://github.com/mxgmn/WaveFunctionCollapse) 也列出 Bad North 使用 WFC；下面的具体行为来自用户本机托管程序集的实际 IL，身份见 [证据说明](00-evidence-and-scope.md)。

## 模块怎样表示

`Placement` 包含多个 `Claim`；一个带偏移的 `Domino` 是某种 Placement 的候选放置，因此一个模块可以跨多个格子。`Slot` 保存某个格子尚存的候选，并用方向和 key 索引支持列表。同一种 Placement 还可以带多个视觉模块变体，几何适配与视觉变体选择分开。

每个 Claim 有六个方向的边界 key、导航标志，以及八个顶点的 inside/outside 状态。其方向变换构造函数会变换位置和边端点、排序边界字符串再生成 key，说明这些约束包含几何边界信息。完整模块样本和具体资产配置未恢复。

## 选择怎样传播到邻居

`DominoFits` 检查候选的每个 Claim：邻格相反方向必须仍有同 key 的支持。`Place` 确定一个候选后，删除同格其他候选，触发 `RemoveDomino` 的连锁传播。

`RemoveDomino` 把候选从所占格子和边界支持列表移除。如果某个 key 已没有支持，就递归删除邻格中依赖该 key 的候选；共享顶点的 inside/outside 一致性也会传播。某格剩一个 idle 候选时自动放置；候选域变空则记录失败原因，使这一轮生成失败。

这种机制可以理解为 WFC 风格的约束传播。实际选择策略还包含房屋优先、带随机性的评分和导航前沿，不能据此宣称采用标准 Shannon 最低熵选格。

## 怎样生成能玩的岛

`InitializeSeed` 使用 `Random(seed+seed2)` 给候选生成布局 score 和视觉 fraction。布局 score 是默认分数乘随机系数；队列倾向较高分数。fraction 用于从同种 Placement 的视觉模块集合选择变体。

`Resolve` 先寻找目标 HouseSet 中的房屋，再从房屋的可导航位置开始扩展 openSlots。候选能扩大导航范围时获得倍率；在金币目标与密度条件允许时，房屋也获得较高倍率。`Place` 将可导航面连接的新邻格加入前沿，使接下来的选择围绕可连接区域展开。

前沿结束后，代码检查导航区域至少到达 `y<=0`，海滩总量达到 `minimumBeach`，再完成其他剩余候选并清理特定未纳入导航构造的候选。金币目标参与选择，未看到最终金币必须精确等于目标的独立断言。

**证据限制。** “navigable bounds too small” 分支实际上比较同一个 `navigableBounds.size.x+size.z` 与自身乘 0.7，不能解释成可行走区域覆盖全岛宽度的 70%。诊断字符串不能代替真实指令的比较对象。

导航还有后处理：对三角形邻接图做 flood-fill，拆成连通分量，按三角形数量降序排列，只保留第一组。这里是三角形数量最多，未证明是面积最大；记录的可达比例也按三角形数量计算。

## 失败怎样恢复

初始化适配检查完成后保存状态。生成失败会报告 breakReason，恢复 Slot、Domino 和 CornerSlot 的快照，清空当前累计状态及前沿，令 seed2 加一，以新的随机顺序重新 Resolve。

已见的是回到初始化快照重试。没有证据证明维护逐次决策栈、逐步回退上一项猜测，所以不将它描述为完整逐步回溯搜索。

## 布局怎样变成三维画面

成功后，`SavedWave` 保存已放置模块的偏移、朝向与 Placement。重建过程实例化模块的 `objectToCopy`，应用位置、旋转及镜像。基础视觉模型因此来自作者模块；生成器决定组合与实例状态。

制品有两套网格合并实现。一套按材质收集 MeshFilter，调用 CombineMeshes 再软化；另一套逐网格追加顶点、法线、UV、颜色和三角形，并处理镜像后的 winding。场景资源未解包，不能断言实际每个岛采用哪套实现。

表面位移由体素场决定。`GetNormalLinear` 从八个周围采样点进行三线性插值，得到法线 `n` 与 openness `o`，然后：

`Δ = 0.5 × n × (0.6-o)`

`Δ.y = Δ.y × Clamp01((position.y+0.105)/0.100000005)`

顶点位置加上这个位移。由公式可推导出局部膨胀或收缩，并在接近海平面时削弱垂直位移；它有助于把规则模块外表面变得圆润。该效果尚未与运行截图逐顶点对齐。

## 从房屋到成品的构造例子

设房屋 H 的东面需要步道接口。邻格候选为平地 P、台阶 S、岩壁 C，只有 P 和 S 的西面兼容。确定 H 后，岩壁所需接口失去支持，C 被传播删除。若 S 又因上边界或高度规则失败，只剩 P，则自动放置 P。P 的可导航东面把下一格加入前沿，选择继续向可连接区域扩展。

布局成功后，恢复模块、应用朝向与偏移并合并网格。若某顶点采样 `n=(1,0,0)`、`o=0.2`，位移为 `(0.2,0,0)`，单位是引擎坐标单位。若任何格子候选变空，则这一轮回到快照，用新的 seed2 重试。这是独立构造的演算，未取用游戏关卡或资产。

## 未验证范围与风险

未做：没有执行游戏、解包场景、恢复完整模块库或测量重试性能。使用已有 SDK 的最小离线 IL 解码，解码错误记录数为零，但未与另一成熟反编译器交叉验证，泛型 TypeSpec 名称也未完全展开。

风险：资产中的阈值、模块变体和组件挂载未知；静态调用不证明具体运行场景和频率。已经建立算法框架与关键公式，尚不能重现作者的完整岛屿外观或全部关卡约束。
