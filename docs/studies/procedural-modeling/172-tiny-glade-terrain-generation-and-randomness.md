## 3. 新发现的低幅基础起伏究竟怎样生成

文件 `compiled-shaders/country-core/compiled/terrain_editing/rasterize_terrain_stroke.precomp` 的模块从文件 `0x98` 开始。w1243 读取 `water_mask`，w1248 取 R；w1735–1743 在 **R 恰等于 0** 时进入 w13139 起的基础噪声分支。非零 R 走另一个水域复合分支，不能把下式套在水面或整个岸带。

世界像素位置 XZ 来自 w1271–1310：`((pixel+.5)/dims*2-1)*65`。基础起伏坐标的实际数据流为：

```text
q0 = XZ * .4 * (.5,.5) + (34,436)
q1 = T(q0)
T(x,z) = (1.9*(.8*x-.6*z), 1.9*(.6*x+.8*z))

S = .5*N(q0) + .275*N(q1)
starting_noise = .5 + S
baseCandidateNormalized = .035 * starting_noise
interiorNormalized = max(bestStrokeHeight, baseCandidateNormalized)
```

这里的小数是便于阅读的写法，原始 float32 值保留在 reader 输出中。坐标构造在 w13139–13156；循环从 0 开始、`<2` 在 w13229；初幅 `.5` 在 w13165，每层幅度乘 `.55` 在 w14375，坐标乘 `1.9` 再作 `OpVectorTimesMatrix` 在 w14380–14385；w13243（文件 `0xCF84`）加 `.5`，w13248 乘 `.035`，w13253 执行 **FMax**。这些不是根据 `starting_noise` 名字猜出的公式。

`N` 是本篇为实际内联计算起的记号，不是导出的库函数名。w13264/w13274 取 floor/frac；四个相邻格点各经 u32 整数混合、位运算和 float 位构造获得标量，随后 w14265–14350 用 `u*u*(3-2*u)` 的二维平滑权重插值四角。w14355–14360 将 `[0,1)` 标量映射到 `[-1,1)`。已读混合含 `1664525`、`1013904223` 等固定常数，但没有据此命名为 Perlin/Simplex，也没有执行或导出原作噪声实现。

本分支的 `bestStrokeHeight` 初值为约 `.01`（w1682 的 Phi）；候选只有超过当前 best 才替换。下游 w16103 乘 20 转世界高度，再做 31 中的高度编码。因而**无笔画、无水、内区、进入后续平滑之前**，按所见理论噪声范围，世界高约落在 `[.2,.8925)`；float32 误差未作逐位范围证明。这个量级解释细微地面不平，不能当成整座高山的高度配方。

**贯通构造例，未执行 GPU。** 给 XZ=(0,0)，q0=(34,436)，q1 约为 (−445.36,701.48)。为了演算，独立指定两个噪声返回值 `.2`、`−.4`，它们不是原作实测采样：S=`.5*.2+.275*(−.4)=−.01`，starting_noise=.49，候选=.01715；没有笔画时 best=.01，FMax 得 .01715，乘20 得 **.343 世界单位**。若某笔画在此候选为归一化 .1，max 选择 .1，即世界高2，而非加成2.343。真实像素中心未必正好落在世界原点，后续平滑和边缘/水域分支也尚未执行。

这个结果补充 153 的边界：启动格网与远景资源的分析没有恢复世界随机山脉生成器；现在能明确指出地形 rasterizer 还具有固定空间的基础起伏，不能再将近处无笔画表面简单描述成完全平面。

## 4. 笔画的 seed 是怎样进入噪声的

当前 native `TerrainEditingData::new_stroke`（`0x140B14280`、245 B）在 `0x140B14289` 读资源 `+0x38` 的 counter，`0x140B142A7–AA` 递增保存，再于 `0x140B142C6` 将局部低32位减回旧值。旧 counter 写入新笔画 ID（`0x140B142F3`）并作为 map key（`0x140B14310`）。同段给 p=.4、H=2.5。**这条已读创建路径直接使用计数器身份；不是每画一次都从系统时钟抽 seed。** 上限和冲突失败分支见 31；该结论不排除其他系统的随机源。

CPU 上传的 16B 记录将点数与 ID 合在同一个 u32：`countAndID=(count&1023)|(StrokeID<<10)`，详见 31。当前 shader w1883 按 1024 除以该字段，w1888 转成有符号 ID 供下游；它不是以笔画在当前数组的 ordinal 代替 ID。

本轮补出的具体消费者如下：

| 用途                     | 实际输入                                                      | 已核位置与影响                                                     |
| ------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| 第一层边缘扰动           | `qA=.2*XZ+(.5*ID,.5*ID)`                                      | w4127–4146；单层噪声 clamp 后乘5，从距离场中减去，w4219、4233–4246 |
| 第二层边缘扰动           | `qB=.5*XZ+(.5*ID,.5*ID)`                                      | w4251–4256；单层噪声 clamp 后从距离再减去，w5550–5572              |
| 第一层高度细节的坐标偏移 | 整数 `2*ID`，固定混合与另一通道 XOR `188053769`，转成二维偏移 | w5679–5836；偏移加到世界相关坐标，再采另一空间场                   |
| 第二层高度细节的额外偏移 | 整数 `ID*ID*ID`，相同固定 XOR 通道规则                        | w8229–8391；继续加偏移并作矩阵变换                                 |

高度噪声幅度还受 p、H、归一化坡面距离和局部导数控制，不能仅按 ID 推出可见高度。底 seed 一样也不意味着改 p/H 后高度细节振幅一样。完整位混合、所有高度噪声表达式和退化输入没有在本轮重建为可重放实现；上述是已核的输入与消费边。

**构造例。** 在 XZ=(10,20)、ID=7，第一层坐标为 (5.5,7.5)，第二层为 (8.5,13.5)。保持 ID 与 XZ，相同 shader 输入会再次查询同一空间位置；若删除重建取得 ID=8，两组坐标各增加(.5,.5)。这解释“相同笔画身份可稳定重算、相同形状但新身份可以不同”；不同坐标不保证随机值一定不同。若只是把已有笔画平移，世界 XZ 也变，不能承诺全部皱褶跟着笔画刚性平移。

不要混淆三种整数：StrokeID 是几何随机输入；hash map 的随机 hasher 用于查桶；w13076 递增的是 shader 遍历笔画索引。PDB 名称中出现 `std::hash::random::RandomState`，本身不能证明随机地形来自哈希表随机种子。

## 6. 为什么局部编辑通常不需要把整片细节重新抽签

已证链可以重新组织为：

```text
固定远景网格 → 背景高度图 ───────────────────┐
像素世界XZ → 固定基础空间场 ────────────────┤
笔画ID/点列/p/H → 距离与高度扰动 → 候选max ─┤
水域图 → 水岸/边缘复合 ────────────────────┤
                                          ↓
                  高度编码 → 两轴平滑 → 地面vertex位移
                              ↓
                    u16读回 → 8×8采样tile判差
                              ↓
                dirty并集 → 关联墙筛选 → 相关产物重建
```

这是一张状态/数据图，不是同步调用栈。基础场按固定世界位置采样，已有笔画的 ID 可用于重复取得噪声输入；没有要求每次重算推进一条全局随机序列。[34](34-tiny-glade-terrain-readback-and-local-updates.md) 已确认 CPU 按 u16 位差判 dirty，再按关联墙和高度条件筛选。显示格网与地形读回共享高度生产链，但完整 GPU 同步/调度、各历史方向恢复和跨硬件浮点一致性仍未闭合。

因此可以条件性推导“未变的输入可重算相同的局部场”；不能扩大成“每个像素永远相同”“每个对象只更新一次”或“必定两帧完成”。最大值竞争也会改变 winner：修改一条笔画的 H，使它超过相邻笔画，可以改变该区高度及 winner ID，即使两条笔画各自的随机输入均稳定。

## 7. 与材质 noise 和装饰分开，以及自研建议

[154](154-tiny-glade-ground-materials-and-pack-decoration.md) 的 floor fragment 也使用世界位置 noise 在 `grass_1/grass_2` 间调色；那条改的是 RGB。本轮 `starting_noise` 最终进入高度输出，再由 vertex 读取，所以属于真实几何输入。草花/石头/灌木实例又是第三层；不能将地形噪声当成自动散布完整模型的证明。

以下是独立产品规格建议，**不是已恢复的 Tiny Glade 原作实现**：

1. 在自己的既有地形权威中分别维护初始地形配方、持久笔画与显示派生。若产品需要“随机新地图”，明确保存自己的 world seed；不要因为原作局部 shader 没有该参数，就省掉自己产品所需的 seed。
2. 用自行设计的低频构图形成可建造区、缓丘和水系，再用较低幅的稳定空间场增加不平整。基础细节与主要轮廓分别控制，避免靠高幅材质 noise 冒充山坡。
3. 持久化笔画 ID 与 p/H/点列，按稳定身份和用途划分随机输入。需要编辑后仍保留的细节，不依赖全局 RNG 调用次数；需要随几何变化的细节，则明确说明稳定边界。
4. 让同一高度状态被渲染、采样、碰撞、保存及其他真实消费者读取；对量化后不变区域可跳过下游更新。跨版本 seed 算法、float32 与量化规则需有自己的版本契约。
5. 远景与植被采用自己制作或适当授权的资源包，按自己的尺度、配色和性能预算集成。本研究不给原作模型、纹理或恢复代码作为生产资产。
