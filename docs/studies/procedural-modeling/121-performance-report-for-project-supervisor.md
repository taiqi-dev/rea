## 建议交给 Supervisor 的性能线

建议由接收对话先用自己的最终采样包和现有代码契约完成下表，再给Supervisor一个有优先级的实施队列。下列是**证据驱动的排期建议**，不是本研究替项目批准的实现方案。

| 顺序               | 要产出的可审阅结果                                              | 进入实施的条件                                            | 对比与正确性边界                                                                                        |
| ------------------ | --------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 0：接续现有片      | PR #274最终状态、基线/候选包、已完成与未运行项、剩余CPU归因缺口 | 复用原owner的证据和交付；Supervisor按原串行整合规则处理   | 不将本研究另开为重复UI优化片，也不把PR存在视为合并。                                                    |
| 1：剩余静止CPU     | `Update`内互不重复的阶段耗时、调用密度、GC来源及未知部分        | 最小有界summary能解释当前主要耗时；嵌套marker不可直接相加 | 保留端口解析、地形采样、净空/落地、合法性检查、预览、撤销和世界切换的有效期。先消除重复工作，不跳校验。 |
| 2：生成与完成提交  | 受影响对象/块范围、重建/上传次数、完成与碰撞队列、过期结果规则  | 捕获证明静止或编辑时有重复重建、过大更新范围或提交尖峰    | 稳定逻辑ID和单一权威；取消、旧结果、删除、加载/撤销后不得显示或提交失效产物。                           |
| 3：绘制、LOD、阴影 | 每pass实例/批次、各LOD几何、caster/级联、CPU/GPU分项            | CPU主热点下降后，或已有证据明确指出渲染独立热点           | 分批、LOD与阴影各自成片；不同时大改材质、分辨率、阴影质量再宣称纯优化。                                 |

每个候选片需写明：**所有者与独立工作树、精确源码边界、支持它的采样/调用链、等价性和失效条件、预期改变的计数、前后验证场景、回滚边界、完成定义**。已有性能线/owner时先去重并接续，不在共享测试主树另行并发实现。是否授权后续采样和实施，沿用接收对话与Supervisor已得到的范围；本报告本身不扩大权限。

每片按相同场景/规模、相机/渲染目标、Editor/Player模式、质量设置、预热、测量区间和采集器做前后对比。优先复用项目既有有界summary，核采集开销与缺失字段；不要默认打开或加载整份raw。至少报告平均/P50/P95/P99帧时、有效帧数、归一化marker耗时与samples/frame、GC/帧、CPU/GPU可用性；帧率取明确口径，平均FPS和平均帧时倒数不混用。Deep Profiling用于定位时另列，不直接作为低开销A/B收益证明。
