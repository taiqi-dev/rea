# 掘地求财：加载失败与旧世界数据的保护边界

## 身份、问题与证据

本页续查 [02：体素保存、载入与一致性边界](02-save-load-and-consistency.md) 的失败分支。目标固定为 `C:\Software\Steam\steamapps\common\A Game About Digging A Hole\DiggingGame\Binaries\Win64\DiggingGame-Win64-Shipping.exe`（PE32+ x64、145,180,160 字节）及同目录匹配 PDB（1,659,662,336 字节）；已有 EXE/PDB RSDS GUID、age 和文件身份见 [00：本机证据身份](00-evidence-and-reproduction.md)。本轮没有重算摘要。地址均为该 EXE 首选映像基址 `0x140000000` 下的 VA，不是运行地址。

方法是本仓库 [pdb_probe.py](tools/pdb_probe.py) 读取本地 PDB，再用本机 VS `dumpbin` 按 VA 有界反汇编。新原始输出保存在本机忽略目录 [static-state-followup/digging-a-hole/](../../../../.cache/procedural-modeling/static-state-followup/digging-a-hole/)；符号查询在 `load-symbols.json` 中全部 `exhausted=true`。既有完整函数反汇编在 [save/](../../../../.cache/procedural-modeling/digging-a-hole/save/)。它们是普通静态文件和本机工具输出，**不是 REA Evidence**。没有运行或附加游戏、读取私人存档、执行原函数、做 GPU 取证或安装工具。

这里的“旧世界”专指载入前内存中的 `FVoxelData` 体素编辑树及相关状态。磁盘旧 slot、游戏角色的库存/矿物字段、云副本和渲染画面是不同对象，不能由体素函数的返回值直接推断其最终状态。

## 版本、空保存与失败传播

`FVoxelUncompressedWorldSaveImpl::Serialize` `0x143E8E360` 从解压字节读取首个 32 位值。值为标记 `0x2A` 时，下一字段读入版本、再读深度；否则在 `0x143E8E47E` 将版本设为 `0`，**把刚读到的首值当深度**，进入旧格式分支。所见分支依据版本阈值选择各字段布局，没有看到“版本大于当前值就立即拒绝”的门；这并不证明任意未来版本可正确载入。若后续读取错误触发上述重置，深度回到 `-1`，旧树保留。若某个可解包、可解析的内容给出非 `-1` 深度，则唯一的深度拒绝门已经过去，随后会清除旧树。仅凭版本不匹配或标记不匹配，不能一概断言会提前保护旧树，也不能一概断言会清空。

“空保存”有两个不同输入。压缩字节数组长度为零时，解压直接 false、输出深度仍为 `-1`，旧树保留。**内容合法但块数组为空**且深度有效时，序列化可给出一个合格的未压缩对象；`FVoxelData::LoadFromSave` 仍先 `ClearData`，再遍历零个保存块。此时玩家既有的体素编辑叶块不保留，新的数据树会依其生成器和空编辑数据工作。能否从真实 `MainSave.sav` 遇到这一种内容，本轮没有存档样本证据。

游戏自己的 `VoxelComplexController_SaveExample.Load` 蓝图已经确认调用 `LoadFromCompressedSave`；false 时只执行 `PrintString("Failed to load voxel world voxel data")`，true 才调用 `LoadFromSpawnersSave`，见 [02](02-save-load-and-consistency.md) 及本机 `save/saveexample-load.json`。因此早期失败会停下后续 spawner 恢复；若内层在清除后返回 false，蓝图提示也不会还原已被换掉的体素树。这里的静态调用链没有证明角色的其他字段已回滚、磁盘档未被以后自动保存覆盖，或提示在实际画面中可见。

## 构造演算：同一个旧世界的三种输入

设载入前世界深度为 `8`，八叉树已有玩家挖出的叶块 A，保存槽元数据中的压缩深度也为 `8`。以下是依上述指令组织的**构造输入和控制流演算**，没有制作或执行游戏存档。

1. 压缩字节数为 `0`：外层元数据深度 `8` 允许尝试解压；解压在 `0x143E6A9B2` 返回 false，临时输出仍为 `-1`；未压缩载入在 `0x1441A4140` 拒绝。A 留在原树，蓝图走失败提示。
2. 非空字节可解包，但未压缩流读取触发序列化错误标志：序列化错误分支用默认对象覆盖部分结果，深度重置 `-1`；尽管解压包装返回 true，下一层仍拒绝。A 留在原树，蓝图走失败提示。这只覆盖实际进入该错误分支的输入。
3. 解包与序列化完成，所得深度 `8`、保存块数 `0`：深度门通过；在遍历任何保存块前，`ClearData` 把旧根及 A 移除并建立新根；零块恢复不能把 A 带回。若内部错误标志未置位，载入返回 true，蓝图继续 spawner 恢复。这个例子说明**合法空内容是替换**，不等于压缩字节为空。

## 可回答条件与未知

静态证据可回答：**压缩数组为空、`DecompressData` 明确失败，或进入所见序列化错误重置分支时，旧 `FVoxelData` 体素树会在深度门前保留；成功解析为有效深度后，旧树在 `0x143E8268E` 被替换，后续加载失败没有可见回滚。** `ClearData` 清的是体素数据树、placeable items 与相关编辑状态，不等于毁掉整个游戏世界对象或磁盘保存文件。

仍未知：所有损坏/截断/未来版本输入如何设置 archive 错误标志，内层失败标志在各畸形块上的覆盖，真实 `MainSave.sav` 是否包含空而有效的世界保存对象，界面上最终地形与提示如何呈现，以及后续自动保存是否改写磁盘旧档。静态路径不足以保证“任意坏档都安全”，也不足以声称“任意坏档都会清空”。这些需要另行获准的隔离样本和运行观察；本轮 **Not Run**。
