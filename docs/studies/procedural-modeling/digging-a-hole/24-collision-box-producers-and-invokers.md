# 掘地求财：碰撞盒来源、invoker 与 octree 资格门

**更正 [23](23-mainlevel-mesher-lod-and-collision-config.md) 的 LOD 3 保留说法。** [23] 写到「LOD 3 不走可见块兜底，但专门碰撞盒分支仍可能给它碰撞资格」，当时漏读了该分支的前置门：`FVoxelRenderOctree::GetUpdates` 在 `0x143E7ACFD–0x143E7AD00` 检查当前节点 `node+0x0C`，非零即跳过专用碰撞盒循环；同一字节在 `0x143E7AD96–0x143E7AD9D` 被当作节点 LOD 与可见块上限比较。因此**在这一个函数内，专用盒只给 LOD 0 节点碰撞资格**。MainLevel 的可见块上限是 `2`，所以 LOD 3 在这两条碰撞资格支路都不能取得 bit `0x02`。这是静态控制流结论，不代表断言其他未追入口绝无碰撞、也不是实际物理接触测试。

## 盒的生产者：组件设置和世界坐标转换

`UVoxelSimpleInvokerComponent` 原生构造 `0x143DFF5F0–0x143DFF629` 写入三个通道：`bUseForLOD=1, LODToSet=0, LODRange=1000.0`、`bUseForCollisions=1, CollisionsRange=1000.0`、`bUseForNavmesh=1, NavmeshRange=1000.0`；`1000.0` 的机器表示为 `0x447A0000`。这是**该类构造值**，不自动等于任意 Blueprint 实例的最终属性。`UVoxelInvokerAutoCameraComponent::GetPrivateStaticClass` 在 `0x143DFE4AB` 指向 `UVoxelSimpleInvokerComponent` 作为父类；其全局位置实现于 `0x143E75BAF–0x143E75BC2` 取玩家 `0` 的 `PlayerCameraManager`，无 manager 时返回零向量（`0x143E75BD2–0x143E75BE7`）。因此自动相机 invoker 有 Simple 的三通道构造来源，但实际组件实例值仍可能受序列化或运行写入覆盖。

`UVoxelSimpleInvokerComponent::GetInvokerSettings_Implementation` (`0x143E760E6–0x143E7617D`) 将组件 `+0x238/+0x23C/+0x240` 映射到 LOD 标志、目标 LOD 和盒，`+0x244/+0x248` 映射到**碰撞标志及半径**，`+0x24C/+0x250` 映射到导航标志及半径；输出 `FVoxelInvokerSettings` 的相应字段是 `+0x00/+0x04/+0x08`、`+0x20/+0x24`、`+0x3C/+0x40`。这也与 PDB 反射描述符名 `LODBounds`、`CollisionsBounds`、`NavmeshBounds` 对齐。三条通道各调用同一盒 helper `0x143E58F20`，输入中心来自 `GetInvokerGlobalPosition`，半径原先是组件中的 `float` 世界长度，helper 转成 `double` 后以 `(center+radius)` 调世界接口虚调用 `+0x2B8`、参数 `1`，以 `(center-radius)` 调同接口、参数 `2` (`0x143E58F4E–0x143E58FD7`)。helper 分轴取两个整数结果的较小值为下界、较大值再加 `1` 为上界 (`0x143E58FEA–0x143E5907A`)，所以输出为**体素整数坐标的半开盒**。两个转换参数的正式枚举名称和含旋转/缩放时的精确舍入方式未从该局部指令独立恢复；不能简单声称半径总是 `1000/9` 个体素。

位置还有单独一路：`UVoxelSimpleInvokerComponent::GetInvokerVoxelPosition_Implementation` (`0x143E761DF–0x143E76206`) 取同一全局中心，经世界接口 `+0x2B8`、参数 `0` 生成整数体素坐标。LOD manager 于 `0x143E98222–0x143E98261` 对每个 invoker 分别调用 `GetInvokerSettings` 与 `GetInvokerVoxelPosition`，并在 `0x143E98333–0x143E983AA` 比较旧/新通道字段和三轴位置偏移平方是否超过按世界 `VoxelSize` 缩放的距离阈值；这是**更新检测**，不是盒的半径门。MainLevel `VoxelSize=9.0` 来自 [07](07-material-slots-and-handler-selection.md)，`InvokerDistanceThreshold` 的实际实例值和触发节奏未在本篇解析，故不推导每帧重建或精确移动延迟。

## 注册、MainLevel 的实例边界与消费

组件 `OnRegister` (`0x143E87B0E–0x143E87B28`) 在 starts-enabled 且尚未 enabled 时调用 `EnableInvoker`；`EnableInvoker` (`0x143E712FA–0x143E713B0`) 以所在 `UWorld` 的弱引用为键，把组件弱引用加入静态 `Components` 表。`OnUnregister` 走 `DisableInvoker`。`GetInvokers(UWorld*)` (`0x143E76220–0x143E762F4`) 按同一世界取数组并剔除失效弱引用；LOD manager 的 `UpdateInvokers` 从这个列表读取、排序并缓存各组件的设置和体素中心 (`0x143E97E1C–0x143E982D9`)。其 `Tick` 在 `0x143E941CA` 调 `UpdateInvokers`，发生设置或位置变化时重建传递状态。不能把全局注册表中别的世界的组件算进本世界。

MainLevel 包自身的 Zen export 表有 `1627` 项，唯一名为 `VoxelWorld` 的实例是 export `1611`，文件偏移 `621156`、大小 `448`，模板为 `/Script/Voxel.Default__VoxelWorld`（见 [12](12-initial-material-authority-and-overrides.md)）。对这份包的 name/import/export 表与已缓存角色 Blueprint Zen 表作 `Invoker` 类名/字段检索，未发现序列化的 Voxel invoker 实例；这只约束已查包，不能证明启动前没有其他关卡、Blueprint 或代码注册组件。已解析的世界实例字段 `bCreateWorldAutomatically=1`、`bUseCameraIfNoInvokersFound=1`（[07 原始属性回执](../../../../.cache/procedural-modeling/static-chain-followup/digging-a-hole/slot-and-handler-properties.json)，export `+57/+58`）。相机回退字段的 generated `SetBit` 在 `0x142F91370` 精确写 `world+0x441=1`，与下面的读取偏移对齐。`AVoxelWorld::CreateWorld` 于 `0x1441D266A–0x1441D268A` 在 `world+0x441` 为真时检查本世界 invoker 数量，若为零，再检查 net mode；符合 `0x1441D2706` 的分支才构造 `UVoxelInvokerAutoCameraComponent`、挂到世界根并 `RegisterComponent` (`0x1441D272F–0x1441D27B1`)。因此**本关卡可证的来源是“没有预先注册组件时的自动相机回退”**，不是关卡中有一个预摆放的 Simple invoker；实际运行是否触发该回退以及随后属性/相机中心是什么，均未观察。自动相机继承 Simple 的 `1000.0` 构造半径是该条件路径的原生初值，而非从组件类名推测。

`FVoxelDefaultLODManager::UpdateLODs` (`0x143E99FCD–0x143E9A03F`) 从缓存 invoker 中筛选三通道标志至少一项为真者，并将每个入选项从 `+0x14` 起的三组盒与标志，按 `0x58` 字节一项拷入 `FVoxelRenderOctreeSettings` 输入数组。`0x143E9A099–0x143E9A0C5` 同时放入全局碰撞开关、可见碰撞开关与上限；MainLevel 的正常初始值为 `(1,1,2)`，见 [23](23-mainlevel-mesher-lod-and-collision-config.md)。octree 的专用碰撞循环在 `0x143E7AD06–0x143E7AD88` 遍历该 `0x58` 字节数组，先查该项碰撞标志，再对节点盒与该项 `CollisionsBounds` 做**三轴严格相交**；相交才置 bit `0x02` (`0x143E7AD9F`)。它还受开头的全局碰撞开关与 **node.L==0** 门。未命中时，只有节点可见、可见碰撞已开且 `node.L<=VisibleChunksCollisionsMaxLOD` 才可经另一支置同一 bit (`0x143E7AD8A–0x143E7AD9D`)。后续 bit 到 Mixed Basic、section 和 Chaos cooker 的条件链见 [22](22-transition-triangles-and-collision-ownership.md)，本篇没有重新证明物理接触结果。

**构造演算（非游戏现场）。** 假设世界接口在无旋转、单位 actor 缩放且 `VoxelSize=9` 的情况下把全局中心 `(0,0,0)` 映到体素 `(0,0,0)`；人为将 Simple 的碰撞半径设为 `900` 世界单位，并假设该转换对恰为整数的 `±900/9` 返回 `±100`。盒 helper 给 `CollisionsBounds=[-100,101)^3`。一个可见与否不限、盒为 `[96,128)×[0,32)×[0,32)` 的 LOD 0 chunk 与它有体积交集；全局碰撞开关、组件碰撞标志均真时，`GetUpdates` 的专用盒支路能置 `0x02`。若把同位置节点改为 LOD 3，`node.L==0` 失败，专用盒完全不执行；MainLevel 的 `3<=2` 也失败，所以此函数不给该节点碰撞 bit。例中的 `900` 是刻意选的算术输入，**不是原生默认 `1000` 或 MainLevel 的实测属性**；世界接口的非整数舍入及实际节点存在与否仍未验证。
