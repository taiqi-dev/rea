# Tiny Glade 拱砖布局与洞口显示

发行版把石拱轮廓变成三维折线，按近似目标长度选择砖数，再沿折线采切点，为每对切点输出一个砖实例。洞口上方的普通墙砖另带拱高参数，在显示阶段裁掉洞内片元。拱圈砖默认关闭这一裁高；两种砖不能共享同一参数解释。

前置分段见 [26](26-tiny-glade-road-openings-and-merge.md)，轮廓见 [27](27-tiny-glade-stone-arch-profiles.md)，重建见 [29](29-tiny-glade-road-arch-local-rebuild.md)，制品和取证边界见 [30](30-tiny-glade-road-arches-evidence-ledger.md)。以下是发行版静态指令和独立构造算例。

## 1. 沿三维折线铺砖

`construct_arches` 在 `7F1DC0–7F1DDC` 构造 ArchWalker，目标步长 **.56**、尾段比例阈值 **.1**；随后 `7F1E70` 调 `ArchWalker.walk<closure3>`，RVA `1402590`。真实consumer调用位于 `1402AB8/1402C10`，目标 `14046E0`。

Walker构造各节点：`P_i=(x_i,baseY_i+newHeight_i,z_i)`，累计三维折线长度：

```text
L = Σ length(P_i−P_(i−1))
N = max(floor(L/.56+.5),1)
step = L/N
```

求长在 `14026DA–1402721`，计数在 `1402797–14027AD`，实际步长在 `1402849`。这不是原型的 `.2` 规则，也不是按角度等分或对连续曲线精确积分。

第二遍累积折线段长度，用剩余距离在当前段内线性插出切点。常规切分使用严格 `cumulative+segmentLength>step`；末尾 `remaining>.1*step` 才补尾砖（`140299A–1402B59`）。曲线u同时经过 `WallSpace.subtract/project_clamp`，保留开放夹紧和闭环余数规则，支持跨墙曲线首尾。

**构造算例。** 长2的直线：N=4，step=.5，切点为0、.5、1、1.5、2，输出4砖。折线(0,0,0)→(1,1,0)→(2,0,0)长约2.828427，N=5，step≈.565685。跨拐点的一块砖连接两个切点，弦长可能小于该步长，因此不是所有砖的可见长度都恰好为.56或L/N。

## 2. 每块砖的朝向、厚度轴与位置

`construct_arches::closure3`，`14046E0`，实际从两点A/B和start/end u构造仿射实例。`14047AD–14048DD` 可整理为：

```text
t = normalize(B−A)
h = normalize((-t.z,0,t.x))
v = cross(h,t)
C0 = B−A
C1 = .42*v
C2 = .7*h
translation = (A+B)/2
```

存储为9个轴float与3个平移float，共48字节。C0沿砖的连接弦，C1是拱线平面内横轴，C2是水平侧向。`.42/.7` 是实例轴尺度；实际可见尺寸还依赖网格资产的坐标范围。

**构造算例。** A=(1,2,3)、B=(1.42,2.28,3)：

| 输出 | 数值 |
| --- | --- |
| t | (.832050,.554700,0) |
| h | (0,0,1) |
| v | (−.554700,.832050,0) |
| C0 | (.42,.28,0) |
| C1 | (−.232974,.349461,0) |
| C2 | (0,0,.7) |
| 平移 | (1.21,2.14,3) |

这条producer确认的是朝向弦的矩形实例变换。未发现在此closure对内外弧分别求砖长或计算石券楔角；网格资产本身的楔形细节未恢复，不能据变换断言资产横截面。

## 3. CPU实例到64字节GPU记录

实际链为 `14047A8→BrickTransform.default(951920)`，`14049B5→encode(94C790)`，`14049C0→SparseInstanceBufferWriter.push(13F66A0)`。push的资源增容和完整提交时序没有全部恢复。

| 96字节CPU字段 | 当前拱圈producer | 64字节GPU字段 |
| --- | --- | --- |
| +0..2C 仿射变换 | 上述轴和中点 | +0压缩矩阵、+14平移 |
| +30..3C 四个Y变形值 | 保留默认0 | +20/+24，两对half |
| +40/+44/+48 三个局部拱高 | 保留默认−100 | +28两half，+2C低half |
| +4C 编号 | 两个计数器低32位相加 | +34 seed |
| +50 来源 | 墙颜色转换结果 | +38 sourceID |
| +54/+58 两端墙坐标 | 墙+290乘start/end u | +2C高half、+30低half |
| +5C flags | 保留默认0 | +3C flags |

编号的当前生成式不能保证道路拓扑变化后永久稳定。`pack_half_pair`，`94C8A0`，有Inf/NaN、溢出和次正规值分支；另有CPU能力条件转换路线，未完全展开。不能把这些packed half全部解释为高度。

普通墙的 `WallConstructor.from_curve<construct_walls.closure3>`，`1446690`，另在 `1448F8A–1448FC5` 写三项拱高、墙坐标和flags，`1448FDA` 实际调用同一encode。这建立普通墙参数的输出桥，但三项高度所有上游选择和每种子段绑定仍有缺口。

## 4. 顶点变形与局部拱高

`wall/wall_brick_lod0.precomp` 顶点模块从原文件 `9F` 开始。实例成员偏移和stride64同时由类型声明与Decorate确认。

四个Y变形值从两uint解包；在 `6773–6837` 用局部旋转后顶点坐标u=x+.5、v=y+.5计算：

```text
dy = mix(mix(d00,d10,u),mix(d01,d11,u),v)
worldY += dy
```

字段虽名 `sin_deform_y_packed`，这里执行的是双线性插值，没有重新计算正弦，不能仅凭名字添加正弦算法。

`arch_and_wallspace_packed` 的三项拱高h0/h1/h2，在 `701F–718F` 沿u分两段线性插值：

```text
u<.5：h=mix(h0,h1,2u)
否则：h=mix(h1,h2,2u−1)
```

墙坐标首尾值另插成wallUV.s；worldY作为wallUV.y。flag `0x20` 分支把第一对half复用为顶点相关轴缩放参数，最后输出h=−100（`3297–346B`、`7B93–7F77`），所以必须先判flags才能解释布局。

**构造算例。** u=.25、v=.75，四Y值[0,.2,.4,.6]给dy=.35；此前世界Y=2，则最终2.35。拱高三点[1,2,1]，u=.25或.75都给h=1.5。当前拱圈砖的Y值全0、h全−100、flags0，分别得到dy=0与禁用普通洞裁高的值。

## 5. 最终洞口还通过片元裁剪

G-buffer片元模块 `A3CF–A5B7` 读取worldY、h和flag8，普通墙裁剪规则是：

```text
flag8未置位：h>−2.5 且 worldY<h 时剔除
flag8置位：worldY>h 时剔除
```

地基Y裁剪先独立执行。这里是片元demote，不是证明CPU已经把所有洞形切成拓扑。h随顶点插值，所以既有砖实例仍能得到局部洞边。

深度变体blob3在 `1520A–153AA` 对普通下方裁剪使用 **h>0**，并另按flag8剔上方。两个pass的阈值不同；未取得运行场景，不把它解释为bug，也不宣称所有负高度情况表现一致。

**构造算例。** 普通flags0、h=1.5：Y=1.4剔除，Y=1.5保留；flag8、Y=1.6剔除，Y=1.5保留。h=−1且Y=−1.1时，G-buffer普通分支会裁，所选深度分支不因拱高执行该裁剪。当前拱圈默认h=−100，不因这条普通墙洞规则消失。

## 6. 实现职责与剩余缺口

已确认的数据关系为：路径子段高度→石拱profile→三维折线长度→两点砖变换→压缩实例。普通墙另产拱高/flags→GPU插值→片元裁洞。两条路径的默认值和输出桥都经实际指令核对，不能把它们合并成“统一布尔切网格”。

未做：没有运行游戏、恢复原砖网格、遍历所有LOD/shadow/RT材质或取得GPU时间线；未完整恢复普通墙三拱高的上游计算及整个洞边砖拓扑。

风险：输入折线精度、拐点跨越、网格资产尺寸和不同pass影响最终视觉；静态构造演算只复核已恢复的算术。没有证据时保留楔角、支柱布局及提交频率为未知。
