# Tiny Glade 常春藤：修剪与建筑变化

发行版有三种不同处理：位置请求截断枝条后缀，常规有效性检查从头尾缩短枝条，旋转或特定区域消息移除整条 Ivy。没有证据把它们合并成一个“按脏地块重新生成所有植物”的算法。

本篇依据 `ivy_pruner`（`A6F970`）、`ivy_pruner_cmd`（`A71A80`）、`is_point_still_valid`（`A72010`）及实际消息包装器。身份、精确子范围摘要和检查边界见 [25](25-tiny-glade-ivy-evidence-ledger.md)；状态基础见 [21](21-tiny-glade-ivy-roots-and-state.md)。

## 位置请求先入队，再截后缀

`remove_ivy_at_location`（`A72530`）生成 48 字节请求。`+10` 为中心 xyz，`+1C/+20/+24` 存宽、高、再次复制的宽；函数只入队，不立即删枝叶。窗口消息消费者 `8E07BF–8E080D` 实际调用该入口，故窗户相关处理能提交局部剪除请求；完整界面到窗口消息链和消费者帧序仍未恢复。

消费端 `A71D25–A71D98` 对每条 Ivy 按逻辑队首向后找第一个点满足：

```text
abs(px-cx) < w/2
abs(py-cy) < h/2
abs(pz-cz) < w/2
```

这是轴对齐范围，三个比较都严格小于，边界点不命中。命中后连续 `pop_back`，删掉命中点及它后面的所有点，不只是删除盒内的那些点。

每删一个点，以该点 ID 筛选同 Ivy 的 104 字节叶片记录：记录 `+0/+8` 任一关联端点等于被删 ID 就剔除（`A71E20–A71EEC`）。修剪还把 `Ivy+68/+84` 置零（`A71EF0–A71F4A`），停止旧末点展开插值；两字段的生长消费者见 [22](22-tiny-glade-ivy-growth-and-wall-following.md)。此入口自身没有移除整 Ivy 的 map 项。

请求头带关联身份，但本消费者按空间扫描，不用它把目标限定为某个 owner。不能称为“只剪该窗自己的藤蔓”。

**构造演算。** 点 ID 为 `[10,11,12,13]`，位置分别 `(-2,2,0)、(-0.5,2,0)、(0.5,2,0)、(2,2,0)`。叶片关联为 `(10,11)、(11,12)、(12,13)、(10,10)`。请求中心 `(0,2,0)`、宽 2、高 4：

1. 请求入队时所有点仍在。
2. 消费时 10 不命中，11 是首个命中。
3. 从尾部依次删 13、12、11；13 虽在盒外，也属于命中点后的后缀。
4. 清理关联叶片，重置展开状态。

结果为点 `[10]` 和叶片 `(10,10)`；Ivy 身份保留。不据此保证立即再次生长。

## 一个点怎样判定仍有墙可依附

`is_point_still_valid` 返回当前墙的数据指针或 0，不是简单的布尔函数。主要步骤由 `A72056–A724CD` 恢复：

1. 将点的世界 XZ 转入墙空间栅格。越界或空单元返回 0。
2. 调用墙段候选辅助函数，传入 0.5；返回的评分必须严格小于 0.365。评分的具体形式见 [22](22-tiny-glade-ivy-growth-and-wall-following.md)，不能自动理解为通常的三维最近距离。
3. 按候选的墙 ID 查询当前墙。曲线点数须至少 2，长度 `L>0`，否则进入断言诊断。
4. 候选参数必须满足严格范围 `−0.01/L < t < 1+0.01/L`。端点有小容差，但并非无限外推。
5. 查询该墙的洞记录。没有洞项则返回当前墙指针；有洞项则继续测试局部坐标。

这里洞测试坐标实际是 `(t×L, pointY+g)`，`g` 来自墙段地形端点的投影插值（`B56370`）。洞 AABB 四分量加 `(-0.1,-0.1,+0.1,+0.1)`，对有限输入包含边界，命中即返回 0。`g` 的完整存储符号约定尚未贯通，不能凭常识把实际加法改成减法。

注意与生长避洞不同：本检查纵向扩张 0.1；[22](22-tiny-glade-ivy-growth-and-wall-following.md) 中生长检查所选洞分支纵向扩张 1.0。它们是不同消费者和阶段。

**构造演算。** 栅格 8×8，世界覆盖宽深均为 8；点 `(0.25,2,0.25)` 得单元 `(4,4)`、线性索引 36。设返回评分 0.2、`t=0.5、L=4、g=0`。洞原框 `[1.95,1.95]..[2.05,2.05]` 扩成 `[1.85,1.85]..[2.15,2.15]`，局部点 `(2,2)` 命中，返回 0。若没有洞记录且其余条件成立，返回墙指针。评分恰为 0.365 或 `t=−0.0025` 均在严格边界被拒绝。

## 常规更新从两端剪，保留中段

已分析的常规阶段遍历当前 storage 中的所有 Ivy。它未使用一个已证的 dirty-tile Ivy 清单，仅检验尾端、根端，并不逐一验证所有中间点。

尾端在 `Ivy+68` 非零时用缓存目标 `+78`，否则使用队尾当前位置（`A70710–A70845`）。如果没有有效墙，删尾点并清关联叶片；若有效，还检查点是否低于当前墙的高度限制：

| 当前墙字段条件 | 高度限制 |
| --- | --- |
| `wall+2A0 == 1` | `wall+288 + 0.2` |
| 否则且 `wall+258 < 2` | `wall+288 − 0.79 − 0.1` |
| 其余 | `wall+288 − 0.46` |

`y >= limit` 继续剪尾（`A70920–A709AA`）。这些字段的完整类型和墙样式名称尚未恢复，表格仅表达实际条件，不能把每行擅自命名为某种屋顶。

尾部稳定后检查内嵌根位置 `Ivy+30`；无效时 `pop_front`，清关联叶片，再将新队首完整 40 字节复制到内嵌根点 `+28..+4F`（`A70C50–A70FB9`）。重复到根有效或队列为空。队列为空才加入整 Ivy 删除集合，在末阶段移除 map 项和队列存储。

**变化演算。** 初始队列 `[20,21,22,23]`、根副本 20，叶片连接相邻点。构造变化后的有效性：23 无效、22 有效且低于高度限制；20 无效、21 有效。

尾部先删 23 并清相关叶片，停在 22；根部删 20，把 21 复制为新根，停在 21。结果是同一个 Ivy 身份、点 `[21,22]` 和关联叶片 `(21,22)`。若两端检查最终剪空，则删除整 Ivy。这个演算不能证明保留中段的所有点对任意建筑变形都必然有效。

## 哪些变化会直接删除整条

ECS 包装器 `932730` 在 `932AE8` 直调 `ivy_pruner`；其 PDB 参数含 `CmdCheckForSheepInsideBuilding` 与 `OnCircleRotated` 消息 reader。类型名称用于确定消费关系，不替代所有消息发布者的调查。

`OnCircleRotated` 分支将消息中的墙 ID 扩成集合，匹配 `Ivy+60` 的关联墙 ID（`A70421–A70425`），随后用 `Ivy+20` 的 Ivy ID 加入删除集合，并清空它的叶片向量。这里两个身份不同；不能把 `+20` 当墙 ID。

区域消息分支先要求当前墙曲线有效，并通过原始字段 `wall+258≤1`、`wall+284<1.5` 等门控。只检查该 Ivy 的末点 XZ 或内嵌根点 XZ 是否在请求的圆/有向矩形中，命中可删除整条；不逐点扫描中段。圆包含使用 `distance² < radius²`，矩形包含采用闭边界，两者边界规则不同。

**构造演算。** Ivy A 的关联墙 ID 为 7，B 为 8；旋转消息墙集合 `{7}`。A 被加入整 Ivy 删除集、叶片长度清零，末阶段移除 A；B 保留。没有看到沿旋转墙重新定位 A 的这条分支，也没有证明下一步重建相同身份。另取半径 1 的区域，距离 0.5 的端点命中，距离恰为 1 的端点不命中；仍要先通过当前墙门控。

## 更新与显示之间的边界

CPU 剪除叶片记录，不自动证明同帧画面立即消失；需要结合 [23 的上传与显示](23-tiny-glade-ivy-leaves-and-rendering.md)。剪除重置末点插值，也不意味着重跑起点生成器或清除所有禁长条件。

已回答：位置剪后缀、按点 ID 清叶、墙/洞有效性、头尾截断、根副本刷新、消息触发整条删除、旧展开状态重置。

未回答：完整 scheduler/run-if、所有消息发布者、复杂墙合并后的全部中段不变量、各场景修剪后是否立即再长、CPU 清理到屏幕变化的帧延迟。

未做：没有运行游戏或复现建筑编辑，只做静态与构造状态演算。风险：这套端点检查不能被扩张为“每个枝点始终有效”的保证；高度与地形字段的单位、语义仍有缺口。
