# Unity 最小造房沙盒：实施规格入口

本目录把本case study的研究转为**我们独立实现的Unity最小demo规格**。本轮交付详细方案与验证夹具，尚未创建Unity工程、生成AI资产或运行demo。Tiny Glade研究事实保留在上级目录，不将这里选择的算法、参数或燃烧规则称为原作实现。

目标是一间可调整大小的小屋：生成墙、楼板和双坡屋顶；放置/移动窗户时形成真实开口；挂灯；对木质构件点火、用水灭火；破坏墙体后保留破损，保存/加载及建筑重建都不复原已经损坏的部分。

## 2. 最小版的明确范围

| 项目 | 默认选择 |
| --- | --- |
| 运行目标 | Windows桌面、单机、一栋房屋、鼠标操作、环绕相机 |
| Unity | Unity 6 LTS系列，URP；实施时复用可用编辑器并固定完整版本和包锁文件，不静默安装/升级 |
| 参考API版本 | Unity 6000.0官方文档；这不冒称本机已建立6000.0工程 |
| 建筑 | 轴对齐矩形足迹、4面直墙、楼板、双坡屋顶和山墙；平面地面 |
| 编辑 | 宽/深/墙高/屋顶升高；房屋水平位置、朝向先固定 |
| 开口 | 矩形窗洞、初始门洞、墙损坏单元形成的矩形破坏洞 |
| 装饰 | 1种固定尺寸窗框/玻璃，1种壁灯外壳/内芯/Point Light |
| 反应 | 木材可燃，石材不可燃；水增加湿度并降温，燃烧降低完整度和燃料 |
| 破坏 | 墙单元及一根木梁可以消失；洞有侧壁和对应碰撞；不做承重坍塌 |
| 保存 | 保存逻辑建筑、附着物及损坏/火水状态；加载后重建表现 |

首版不包括弯墙、任意形状三维Boolean、任意房屋相交、屋面穿窗、复杂屋脊、物理碎块坍塌、河流/水体流动、完整元素矩阵、联网、导航和大型地图。它们有明确后续入口，见06。点击“加水”先代表一次局部水作用，不需要先实现流体。

## 3. 默认小屋与固定ID

以下都是**自研构造参数**，没有沿用原作随机常数或复制包内小屋：

```text
building-demo-01：宽6m、深4m、墙高3m、墙厚0.2m
屋脊沿X，升高1.2m，水平出檐0.15m
wall-north：木质；south/east/west：石质
门door-01：south，中心(u=4.5,v=1.0)，宽0.9m、高2.0m
窗window-01：north，中心(u=2.0,v=1.6)，宽/高各1.2m
灯lamp-01：north，挂点(u=4.25,v=1.75)
梁beam-01：north，中心u=5.1，从v=0到3；固定0.12m方截面
损坏格：沿墙(u,v)固定0.5m网格
仿真步长：0.1秒
```

墙的u向由02定义，v向上；朝北是Z正方向。夹具对象不是当前已经实例化的Unity对象。

宽可在4..10m、深在3..8m、墙高在2.5..4m之间按0.5m步进；屋顶升高0.5..2m。范围是首版编辑器功能约束，不是已测性能上限。墙厚首版固定。开口和附着点必须仍合法，否则尺寸修改整体拒绝并说明哪个对象越界，不静默挪窗或删灯。

## 4. 一条必须跑通的完整流程

1. 从空定义生成小屋，所有墙有厚度、内外面和碰撞。
2. 放窗，再从u=2移到u=3；旧窗洞消失，新窗洞生成，碰撞与框体同步。
3. 挂灯；移动墙参数后灯按宿主坐标跟随，灯不产生窗洞。
4. 点燃北墙单元(8,3)，作用1秒后加水；立即灭火，完整度降低但未破坏。
5. 继续点火直到该单元破坏；出现0.5m方洞，支持该灯的墙面消失，灯和光源一并移除。
6. 打破另一墙单元、破坏木梁；重建屋顶或移动窗不让损坏部分复原。
7. 保存，清空运行表现，再加载；洞、剩余对象与火水状态一致。

第一版无需先获得精美AI模型。程序占位窗、灯和木梁必须能完成以上流程，再逐个替换外观资源。这样资产质量问题不会阻塞规则验证。

## 5. 成功信号与失败信号

成功至少要求：开口可见且探测射线穿过；洞口侧壁没有缺面；移窗不会留下旧洞；灯失去支撑后没有残留发光/碰撞；破损跨重建/存档保留；无效输入保留旧状态并给出原因。

状态面板显示所选owner ID、墙坐标、生成revision、损坏单元ID、完整度、温度/湿度/燃料和最近拒绝原因。调试视图可开关逻辑开口、实体/碰撞边界和owner标记。可隐藏屋顶Renderer观察室内，碰撞是否启用单独显示，不把调试隐藏说成物理移除。

未做：本轮没有Unity实现/编译/PlayMode验证或AI资产验收。原因是用户要求先完成详细方案并提交。风险是实际资产质量、交互手感、网格细缝和重建耗时尚未实测；后续验收明确覆盖它们。
