# 33．弩手的技能评分与一回合动作选择

[总目录](README.md) · [证据范围](00-evidence-and-scope.md) · [技能注册与协作](05-enemy-skills-cooperation.md) · [技能许可与提交](16-skill-commit-and-ai-gates.md) · [敌人自疗与生存](34-enemy-self-treatment-and-survival.md)

本篇targetTile的空间输入继续见 [41 远程AI选位](41-ranged-ai-position-scoring.md)：已补危险格/单位路径类型门禁和候选早转，全部空间比较与无路回退仍有明确缺口。

本章把真实 `o_bandit_arbalester` 的技能注册接到两个具体评分函数，再接到敌人的实际候选循环、平分处理与执行事件。静态证据支持“根据当前状态评分、许可过滤、再选动作”，不支持把弩手概括成每次固定执行“瞄准→爆头”。消耗品与技能共享一段最佳候选比较；普通攻击保留下来时，某条分支还会先交给回合动作助手，助手未处理时才进入后续装填或射击。

以下伪代码是我们重新组织的行为规格，不是恢复代码。构造输入只用于核对已恢复的局部规则，不代表游戏中捕获的一回合。

## 2．真实弩手有哪些候选，状态由谁持有

OBJT 的对象 ID `172` 是 `o_bandit_arbalester`，记录偏移 `9400672`，父对象 `3892=o_Bandit`；继承链继续到 `o_Grey_Army → c_human → o_enemy → o_unit`。本章追的是这类敌人实例的事件与状态，不是玩家弩技能界面。

`o_bandit_arbalester.Create @ 0x142994d30` 实际注册了下列远程候选：

| 注册名 | 原生调用位置 | 注册集合实参 |
|---|---|---:|
| `Taking_Aim` | `0x1429951e6` | 1 |
| `Suppression` | `0x142995259` | 1 |
| `Headshot` | `0x1429952cc` | 1 |
| `Distracting_Shot` | `0x14299533f` | 1 |

同一 Create 还注册其他技能，并存在集合 2 的配置。集合键不等于技能等级；主选择器遍历的是当时的 `skill_active_set`，不能由“已注册”推出本回合一定参与评分。远程类别门禁读取的是运行时技能类别，不能把所有弩手技能一概按同一类别处理。

已有 Create 证据还给出 `isCrossbowmanEnemy=true`、`crossbowIsLoaded=false`、`reload=true`，以及弹药数量的随机初始化。`reload` 与 `crossbowIsLoaded` 是两个独立字段；下面的判断分别读取它们，不能把二者合成一个“已装填”标记。

| 状态/数据 | 本章确认的作用域 |
|---|---|
| `skill_active_set` | 敌人当前技能候选数组 |
| `skill`、`skill_target` | 本次候选评估与最终提交在敌人实例上的工作字段 |
| `target` | 当前被选目标；`with(target)` 后字段读取主体会改变 |
| `reload`、`crossbowIsLoaded` | 敌人自身远程/装填状态，含义不能互换 |
| `consum_list` | 敌人携带的消耗品代理实例列表 |
| `unit_skill_cache` | 单位的技能评估缓存结构；不等于主循环一定从缓存取值 |
| `global.__attackBasePriority` | 普通攻击初始优先级来源；本轮未恢复其初始化数值 |

## 3．先绑定回调，再解释公式

匿名函数编号不能直接当技能名。实际优先级构造器 `0x14038ca00` 把命名字段绑定到方法地址：

| 字段 | 字段绑定位置 | 方法地址写入位置 | evaluator 入口 |
|---|---|---|---|
| `Taking_Aim` | `0x14038d448` | `0x14038d45a` | `0x140291040` |
| `Headshot` | `0x14038d688` | `0x14038d69a` | `0x140296a70` |

主选择器在 `0x143645dbe` 调用 `scr_skill_get_priority_new(0x140398820)`，后者据技能名取得这个方法并绑定单位上下文。下面两式解释的是这些已绑定的回调返回值，尚未加主循环的 extra/buff 修正，也尚未执行使用许可。

### 3.1 Taking_Aim：装填硬惩罚、命中差、相邻距离、候选计数与重复状态

入口 `0x140291040`，评分从 0 开始。先有两个早退分支：

1. 敌人自身 `reload` 为真：减 20 并返回。读取/真值判断在 `0x14029118e/0x1402911a0`，减分在 `0x1402911d0`。
2. 否则，若 `isCrossbowmanEnemy` 为真且 `crossbowIsLoaded` 为假：减 20 并返回。对应检查 `0x140291202..0x140291240`，减分 `0x14029127f`。

早退之后不会再叠加后面各项。正常分支进入 `with(self.target)`，其中攻击者从 `other` 读取，目标从新的 `self` 读取：

| 项目 | 条件或输入 | 分数 | 证据 VA |
|---|---|---:|---|
| 命中差 | 攻击者 `Hit_Chance − 目标 EVS ≤ 70` | +3 | 字段 `0x14029130e/0x140291324`；减法 `0x140291371`；与 70 比较 `0x14029137e`；加分 `0x1402913af` |
| 相邻目标 | `tile_distance(目标.id,攻击者.id,undefined)==1` | −20 | 调用 `0x1402914b2`；比较 `0x1402914e3`；减分 `0x14029152d` |
| 攻击类别计数 | `N=scr_enemy_skill_category_count("Attack",false,undefined)` | +2N | 查询 `0x14029163b`；乘 2 `0x140291650`；加分 `0x140291663` |
| 已有瞄准状态 | 自身存在 `6091=o_b_taking_aim` | −20 | 状态查询 `0x140291726`；减分 `0x140291767` |

因此在普通有限数输入、上述早退未发生时：

```text
TakingAimBase = 3×I(Hit_Chance−target.EVS≤70)
               −20×I(tile_distance(target,self)==1)
               +2×N
               −20×I(self有o_b_taking_aim)
```

`I` 表示条件成立为 1，否则为 0。`N` 是真实类别计数 helper 的返回值。本轮未完整闭合其内部过滤，不能把它替换成“所有已注册技能数量”或“所有当前可用射击数量”。等号和阈值比较经过运行时数值 helper；阈值邻近的浮点容差不能凭这份规格全部抹掉。

这是评分惩罚，不是这些字段条件下全局绝对禁止该技能。最终还要看分数基线、其他修正和使用许可；但早退得到的 −20 很容易让它输给其他候选。

### 3.2 Headshot：自身增益、目标缺血比例、头部防护与召唤状态

入口 `0x140296a70`，先读攻击者自己的状态，再进入目标上下文：

| 项目 | 条件或输入 | 分数 | 证据 VA |
|---|---|---:|---|
| 自身瞄准 | 有 `6091=o_b_taking_aim` | +2；没有则 −20 | 查询 `0x140296c12`；两分支 `0x140296c33/0x140296c5e` |
| 自身压制 | 有 `6071=o_b_suppression` | +2 | 查询 `0x140296d17`；加分 `0x140296d38` |
| 目标缺血档位 | `scr_enemy_skill_hp_points(20,undefined,undefined)` | helper 返回值 ×2 | 调用 `0x140296e21`；乘 2/累加 `0x140296e32/0x140296e3e` |
| 目标头部防护 | `target.Head_DEF < 10` | +2 | 比较 `0x140296e73`；加分 `0x140296e8c` |
| 目标召唤状态 | 目标有 `3362=o_b_summoned_entity` | −20 | 查询 `0x140296f22`；减分 `0x140296f56` |

这里的召唤判定是一个具体 buff 对象判定，不是“凡是由任何技能创建的对象都减 20”。它也不直接证明目标是否可攻击。

`scr_enemy_skill_hp_points @ 0x141dc5730` 在本调用中把未指定对象补成当前目标，第三个参数补为真。普通正 `max_hp` 路径计算：

```text
missingPercent = 100 × (target.max_hp−target.HP) / target.max_hp
HPpoints = floor(missingPercent / 20)
```

默认参数处理在 `0x141dc5a30..0x141dc5af1`；缺血差 `0x141dc5c3c`，除以最大生命/乘 100 在 `0x141dc5d0d/0x141dc5d71`，再除以输入档宽 `0x141dc5e30` 并向下取整 `0x141dc5e86`。本轮没有证明这一 helper 对异常最大生命、超额生命等输入进行通用钳制。

于是该回调的普通输入公式为：

```text
HeadshotBase = (self有瞄准 ? 2 : −20)
               +2×I(self有压制)
               +2×floor(100×(target.max_hp−target.HP)/target.max_hp/20)
               +2×I(target.Head_DEF<10)
               −20×I(target有o_b_summoned_entity)
```

缺血比例在这段实现中是评分输入，不是命中率或伤害倍率；实际攻击伤害另见 [物理攻击伤害](32-physical-attack-damage-resolution.md)。

### 3.3 一个前后状态一致的构造演算

选以下构造状态：`reload=false`、已装填、攻击者命中 80、目标闪避 20、距离 3 格、类别查询返回 `N=2`；目标最大生命 100、当前生命 60、`Head_DEF=5`，无召唤状态，攻击者无压制状态。`N=2` 是明确指定的查询结果，不声称这是某场实战的真实计数。

| 攻击者状态 | Taking_Aim 基础分 | Headshot 基础分 |
|---|---:|---:|
| 没有瞄准 buff | `3+2×2=7` | `−20+2×floor(40/20)+2=−14` |
| 已有瞄准 buff | `3+2×2−20=−13` | `2+2×floor(40/20)+2=8` |

第二行只改变同一攻击者的瞄准状态。它解释了这两个回调如何产生“未瞄准时更偏好瞄准、已有瞄准时更偏好爆头”的局部趋势。它没有证明固定连招：其他候选、extra/buff 修正、许可、移动与目标变化仍会改变最后动作。

## 4．回合入口如何真正进入主选择器

调用链并非仅靠同名函数拼接：

```text
o_enemy.Other10
  → scr_unit_skill_cache_refresh
  → 当前新状态选择入口
  → scr_update_FSM_new
      → attack case3，在skip_turn为假且到达相应分支时
          → 当前敌人user2 / Other12
              → 消耗品和技能比较、动作分派
```

关键绑定如下：

| 环节 | 直接证据 |
|---|---|
| `o_enemy.Other10 @ 0x14364a890` 刷新缓存 | `0x14364aa68` 调 `scr_unit_skill_cache_refresh` |
| 新 FSM 更新 | `0x14364b719` 调 `scr_update_FSM_new @ 0x141b546c0` |
| `attack` 字串对应 case3 | 初始化 `0x141b58b02`、case 写入 `0x141b58b1e` |
| case3 跳转入口 | 跳转表 `0x141b5aa6c` 的 slot3→`0x141b55212` |
| attack 分支发 user2 | `skip_turn` 条件附近 `0x141b55313`，派发 `0x141b5533a` |
| 主选择器 | `o_enemy.Other12 @ 0x143644cd0` |

同一 FSM 的 `0x141b54f1c` 也发 user2，但属于另一个 case4。本章不把它也叫 attack；其状态名未纳入本轮闭合结论。上述桥也不表示每帧、每个状态、每个敌人都必定执行 Other12。

## 5．主选择器的输入、候选和最终比较

### 5.1 初始化普通攻击候选

`Other12` 先有生命与目标存在检查，后取得移动/目标格查询值 `scr_enemy_find_target_tile_new(false) @ 0x1436450af`。目标“存在”检查不等于目标“存活”或“可命中”。

正常基线来自 `global.__attackBasePriority`：读取 `0x143644dbe`，加入普通攻击的 buff 修正（实参为自身 id 与 `−4`，调用 `0x143645279`）。初始候选字符串是 `"attack"`，读取位置 `0x1436450f7`；其字符串赋值初始化可追到 `0x143649084`。本轮未恢复全局基线的实际初始值。

因此初始最佳值应写成：

```text
bestScore = global.__attackBasePriority + ordinaryAttackBuffAdjustment
selected = "attack"
```

不能因为后面有“最佳分等于 1”的特判，就反推全局基线永远初始化为 1。假实体的独立分支也不能直接套在正常弩手上。

### 5.2 消耗品先竞争

到达相应分支且 `lock_skills` 列表为空时，遍历 `consum_list`。每项调用：

```text
score = scr_enemy_consum_get_priority(itemInstance, targetTile)
```

实际调用 `0x1436457a3`，与最佳值比较 `0x1436457da`。普通有序数值下，分数低于当前最佳则跳过；大于或等于则覆盖最佳值与选中实例，写入位置 `0x1436457ff/0x14364589e`。因此这段消耗品比较的平分规则是后遍历者覆盖先遍历者，尚未使用技能段的随机平分规则。

这使携带的绷带/夹板代理成为真正的动作候选，而非只影响掉落。它们的真实资源生成、评分条件和治疗执行链见 [34](34-enemy-self-treatment-and-survival.md)。携带概率、状态门禁与低评分会让候选缺席或落选；不等于受伤就必用。

### 5.3 技能再竞争：评分不等于许可

技能循环遍历 `skill_active_set`，在每轮把候选写到敌人 `skill`，重设工作目标。`Class` 查询为 0 的分支跳过：查询 `0x143645cdb`、比较 `0x143645d0a`。这里只确认该具体字段门禁，不把 `Class==0` 擅自解释成冷却或沉默。

对到达评分路径的技能，主循环分别调用：

| 输入 | VA | 本章含义 |
|---|---|---|
| `scr_skill_get_priority_new(skill)` | `0x143645dbe` | 命名 evaluator 基础分 |
| `scr_skill_extra_validate(skill,self.id,skill_target)` | `0x143645eb9` | 额外修正；本轮未恢复所有分派分支 |
| `scr_skill_attack_buff_validate(self.id,skill)` | `0x143645f85` | buff 修正 |
| 基础分与修正相加 | `0x143645f91/0x143645fa8` | 本次技能总分 |
| `scr_use_skill_or_not(...)` | `0x14364609d` | 单独的使用许可 |

使用许可为假在 `0x1436460c3` 跳过候选。许可为真，但总分低于最佳值，在 `0x1436460fb/0x143646102` 仍会跳过。技能的高基础分不保证能使用；具备资格也不保证赢得评分。

主循环还调用 AI 临时状态 reset/save/load，选中后保存候选关联状态，结束循环再加载胜出状态。`0x143646366` 保留选中的 `skill_target`，`0x14364638e` 保留技能，`0x1436463e6` 调保存，`0x1436464d5` 调加载。这说明候选目标与执行状态也参与选择，不能只保留一个字符串分数并默认所有候选共用同一目标。

### 5.4 平分规则分两类

技能总分与当前最佳相等时，`0x143646178` 进入专门分支：

1. 若当前最佳值等于 **1**，且当前选择仍为 **`"attack"`**，不让这次平分技能覆盖普通攻击。比较位置 `0x1436461c3/0x143646253`。
2. 其他平分情况调用 `choose(true,false)`（`0x1436462fa`）。选到真才替换，选到假保留。

这是逐个候选的平分替换随机过程，不是“先收集所有同分候选再等概率抽一个”。例如构造三个同分技能依次 A、B、C，已选 A 且没有特殊 attack 分支，B 与 C 各自独立触发公平二选一时，最终概率是 A=1/4、B=1/4、C=1/2；这个推导还以这些二选一实际公平且独立为前提，静态调用本身不证明随机数之间独立。不能把它描述成三者统一 1/3。

消耗品阶段已选实例若被后续同分技能比较，也进入技能段的上述一般平分路径；不会继续沿用“后者必覆盖”。

### 5.5 重新组织的局部行为规格

```text
在Other12入口条件通过后：
  targetTile = 查询目标/移动格(false)
  bestScore = 全局普通攻击基线 + 普通攻击buff修正
  selected = "attack"

  若消耗品评估分支开放：
    按consum_list顺序：
      s = 消耗品评分(item,targetTile)
      若s>=bestScore：记录item及s

  重置AI评估临时状态
  按skill_active_set顺序：
    将本候选写入skill，并准备工作目标
    若Class查询为0：继续下一个
    s = 命名回调分 + extra修正 + buff修正
    若使用许可为假或s<bestScore：继续下一个
    若s==bestScore：
      若bestScore==1且selected=="attack"：不替换
      否则按choose(true,false)决定是否替换
    若决定替换：保存s、skill、skill_target与AI临时状态
  加载选中候选的AI临时状态
  进入后续动作类别、移动或施法分支
```

这份规格只展开已确认局部；外围状态切换、武器集合切换和所有移动格评价未全部纳入，不能作为完整原作 AI 的可运行重建。

## 6．把两个真实公式接到选择器：一个明确条件下的完整算例

沿用第 3.3 节“已有瞄准”的构造状态，两回调返回 Taking_Aim=−13、Headshot=8。再明确添加构造约束：

- 普通攻击总基线为 1；这是本例输入，不是已恢复的全局默认值。
- 两技能当前参与 `skill_active_set`，通过 Class 门禁与使用许可；其 extra/buff 修正在本例都指定为 0。
- 其他技能/消耗品没有更高分；本例不为 Suppression、Distracting_Shot 等虚构分数。

步骤：初始最佳为 attack、1。Taking_Aim 总分 −13，低于 1，跳过。Headshot 总分 8，大于 1，记录其技能字符串与目标、保存临时状态。循环结束加载胜出状态；后续到达相应“所选不是 attack”的执行分支，写敌人 `skill` 并派 user1/Other11。

这证明在这些明示前提下，真实两评分与真实选择器能够产生 Headshot 胜出。若许可拒绝、extra/buff 改分、另一候选超过 8、外围状态分支改向，结果都可能变化。未经运行观察不能保证某个具体场景就采用这些构造输入。

## 7．选中后怎样执行：普通技能与治疗代理不是同一类型

`Other12` 某正常分支在 `0x143646f98` 写入选中值，`0x143646fc1` 派当前敌人的 user1，即 Other11；另一分支也有对应写入/派发 `0x143647759/0x143647782`。

`o_enemy.Other11` 对 `skill` 做字符串类型判断（读取 `0x143649568`、检查 `0x1436495b5`）：

- 字符串候选沿普通技能施法路径，调用 `scr_enemy_cast_spell @ 0x143649af2`。
- 非字符串候选进入该实例上下文（`0x143649659`），把其 `target` 写为外层敌人的目标（`0x1436496c8`），再派这个代理实例的 user0/Other10（`0x1436496f2`）。

因此消耗品代理获胜后不会凭空变成普通技能名，而是通过自己的事件执行。某个技能字符串被选中也不等于其攻击已经成功；施法入口的目标验证、资源与实际伤害结算还在后面。相关执行步骤分别见 [10](10-combat-skill-execution.md)、[16](16-skill-commit-and-ai-gates.md) 与 [35](35-attack-results-and-event-order.md)。

## 8．回合动作与装填怎样衔接：一条真实的普通攻击路径

本轮没有发现“装填必定作为独立技能参与上述评分”的闭合证据。已闭合的是选中普通 attack 之后的一条动作路径：

1. 调用 `scr_enemy_turn(false,targetTile) @ 0x14364707c`。
2. 返回真（检查 `0x14364708b`）时退出此分支，不再调用这条后续 `scr_enemy_hit`。
3. 返回假且其他分支条件满足时，非假实体路径调用 `scr_enemy_hit @ 0x143647211`。

这是进入这一具体普通attack分支后的先后关系，不证明“返回真就是已经移动”。`scr_enemy_turn(0x1411232f0)`中除了选格、转向、位置/声音与交换处理，还存在条件 `scr_attack` 调用（`0x141128736`）。因此返回真只说明所查主分支不再进入后面的hit；它具体完成了移动、交互还是攻击，必须继续追对应返回路径。完整空间代价尚未恢复。

`scr_enemy_hit @ 0x14112b860` 自身还有锁攻击、可见、距离等门禁。到达其远程分支（`is_shoot` 条件附近 `0x14112c73e`，地面字段比较 `0x14112c79c`）后，装填分支明确读取两个条件：

```text
若crossbowIsLoaded为真：进入射击路径
否则若不是isCrossbowmanEnemy：进入射击路径
否则：
  crossbowIsLoaded = true
  走装填声效/动画等路径
  跳过本次投射物发射分支
```

对应真值检查 `0x14112c7e3/0x14112c802`；装填状态写入 `0x14112c84d`。装填路径从 `0x14112cd21` 跳到 `0x14112cf98`，绕开发射段。真实射击段调用 `scr_throw @ 0x14112d4d7`，随后弩手分支在 `0x14112d67e` 把 `crossbowIsLoaded` 清成假。这里未完整恢复弹药扣除时点，也没有把 `reload` 等同于此字段。

### 构造演算：同一未装填弩手的两个分支

假定初始 `crossbowIsLoaded=false`、`reload=true`，无其他候选超过普通攻击基线，已到达上面的正常 attack 分支：

| 查询结果与前置条件 | 本分支动作 | 可确认的状态结果 |
|---|---|---|
| `scr_enemy_turn` 返回真 | 主选择器结束这条普通attack分支 | 这条后续hit/装填调用未发生；助手内具体动作仍需绑定，不等同于保证发生移动 |
| `scr_enemy_turn` 返回假，且 hit 的远程门禁通过 | 进入弩装填路径 | `crossbowIsLoaded=true`；该装填分支不发射箭矢 |

同一初始状态下 Taking_Aim 因 `reload=true` 早退返回 −20；类别为 ranged 的技能也受独立远程许可门禁约束（见 16）。但其他类别技能和消耗品仍可能赢得动作，所以不能简单推成“空弩下一回合必装填”。

装填成功不等于攻击命中；下一次射击的命中、伤害和其他状态仍要走各自结算。本轮也没有证明移动失败的所有原因，或将某个格评分等同于最短路径。

## 9．缓存失效与本次主循环：避免混淆两种实现

`scr_unit_skill_cache_refresh @ 0x141ce3050` 取得 `unit_skill_cache` 字段（`0x141ce3129`），创建新的结构对象（`0x141ce3195..0x141ce31b8`）并赋回该字段（`0x141ce31ce`）。这是替换缓存容器；在所追 `o_enemy.Other10` 路径，调用位于状态选择与 FSM 更新之前。

既有共享 `scr_unit_skill_cache_update` 还提供按技能键缓存的机制：已有成员时可以跳过重新计算，未命中时计算 priority、extra、buff、use，保存四项结构，含评分、许可、额外结果及目标。这支持“缓存内容含目标与许可”这一局部事实，不自动证明所有候选评估都通过该缓存。

本轮真正闭合的 Other12 主循环在 `0x143645dbe` 等位置直接调用评分与许可，再作比较；它没有在已追的循环中直接读取上述四项缓存。因此应分别报告：

- 已确认回合入口存在缓存容器刷新。
- 已确认实际主选择器会现场计算这两个回调所在的评分、修正和许可路径。
- 未证明共享缓存 getter 是这个主循环的分数来源，也未恢复所有缓存使用者、所有失效事件和跨事件复用次数。

AI 临时状态 save/load 与 `unit_skill_cache` 不是同一结论。前者保存胜出候选的执行关联状态；不能仅凭它存在就宣称所有评分都只算一次或所有拒绝都复用缓存。

### 缓存边界的具体例子

假设某敌人在一次 Other10 之前有旧缓存结构 C，所追路径执行 refresh 后字段指向新结构 C′，旧成员不会通过该字段自动带入 C′。此后到达 Other12 的两评分会走现场调用。这个例子能解释目标或 buff 变化后为什么不应把旧分数直接当本回合结果；它不能证明任意状态变化立即刷新缓存，也不能证明其他事件保存的旧引用已被释放。

## 11．对独立 AI 设计的借鉴

以下是自研建议，不是新增的原作事实。可以把行为拆成“候选生成→合法性→评分→平分→动作提交→结果反馈”，为每个动作保留评分来源、拒绝原因和目标。装填、移动与攻击可作为显式动作类型，避免调试时只能看到一个含多种后续行为的 attack 标签。

### 13.1 竞争分两层，五种动作不是五个平行分数

| 用户关心的动作 | 已闭合的参与位置 | 可确认条件与结果 | 不能据此推出 |
| --- | --- | --- | --- |
| 治疗 | `consum_list` 的实例候选先与普通攻击基线比较 | 所追分支要求 `lock_skills` 为空；评分 `>=best` 覆盖，后续技能仍可竞争 | 有伤必治疗、空弩禁止治疗、所有消耗品另经过技能许可函数 |
| 瞄准 | `skill_active_set` 中的字符串候选 | Taking_Aim 基础分，再加 extra/buff；经过 Class 与使用许可 | `−20` 是绝对禁止，或高基础分保证施放 |
| 攻击 | 普通 `"attack"` 为基线；Headshot 等是独立技能候选 | 普通基线可留存；获许可的技能总分可覆盖它 | 普通攻击和爆头都直接执行同一个入口 |
| 装填 | 普通attack留存之后，所追 `enemy_turn` 返回假才进入后续hit路径 | 空弩且是弩手时，hit远程分支写已装填并绕开发射 | 装填已经是与绷带/瞄准同级、拥有独立已恢复分数的候选 |
| 移动／位置动作 | 选位输入与选中后的动作分派 | `pathTargetTile` 先保存位置结果；普通attack的所追分支先调用 `enemy_turn(false,pathTargetTile)` | 所有移动都按一份分数与治疗比较，或返回true必定发生移动 |

这一结构的原生锚点是消耗品分支 `0x143645335` 读取锁列表、`0x14364538a` 调 `ds_list_empty`、`0x143645399` 在非空时跳过该段；随后 `0x1436457a3` 评分。技能另在 `0x14364609d` 调使用许可。普通attack执行路径仍以第8节的 `0x14364707c → 0x14364708b → 0x143647211` 为依据。**“先评消耗品”是遍历顺序，不是无条件治疗优先；“先enemy_turn”是执行分支顺序，不是移动拥有最高分。**

### 13.3 四组明示条件竞争例

下述普通攻击基线1、计数结果N=2、生命与距离等均为构造输入；真实权重、比较关系、调用顺序来自前文指令。指定所有未展开外围条件均进入所追正常分支，并指定不参与本例的候选缺席或低于当前最佳，不将此说成某场实战已经发生。

**例A：治疗7与瞄准7真正竞争。** 弩手已装填、reload=false、没有瞄准buff，命中80、目标EVS20、距离3、N=2，则Taking_Aim基础分`3+2×2=7`。指定其extra/buff为0且许可为真。指定绷带代理存在、锁列表为空、有流血、K=0，治疗评分后续没有改分，于是最终绷带分也是7。初始attack=1；先遍历绷带，将最佳更新为代理B、7。随后瞄准与B平分，进入一般 `choose(true,false)`；选true则换为瞄准，选false则保留治疗。本例不套attack/1保护，因为当前选择已经是代理B、7。

**例B：爆头8也可被门禁拒绝。** 延续例A，只将自身改为已有瞄准，目标HP60/maxHP100、Head_DEF5、无压制、无召唤状态，则Taking_Aim=−13，Headshot=8。指定其extra/buff为0。若Headshot许可为真，8覆盖治疗7；若许可为假，则8不参与替换，B仍是7。可构造一个拒绝原因：当前MP10、该次数据查询返回所需MP30；这是门禁的构造参数，**不是已恢复的Headshot真实表价**。两种分支都不能推成固定“受伤先治疗”或“瞄准后必爆头”。

**例C：空弩仍可能先治疗。** 指定弩手未装填、reload=true，绷带最终7、attack基线1。Taking_Aim早退−20；另有一候选虽总分13，但明确指定其运行类别ranged，由空弩门禁置许可false。没有其他更高获许可候选时，治疗B可留存，并沿第7节的代理执行路径治疗。空弩条件不阻止B，因为此处B是消耗品实例，不是已经确认经过同一ranged技能门禁的字符串候选。

**例D：attack留存才谈这条装填分支。** 改为没有可胜出的治疗／技能，attack留存，未装填且是弩手。若 `enemy_turn` 返回true，跳过这条后续hit，不能把这次事件叫作“已经装填”或保证是移动。若它返回false、非假实体路径及hit其余门禁通过，则写 `crossbowIsLoaded=true`，不发射；若攻击锁非空或FOV返回false，则即使已调hit，也绕过所追装填主体，不能保证写已装填。下一次真正走发射路径后才有清空该字段的局部写入，不能把它与当前事件合并。

额外平分边界：构造初始attack总分1，且某技能最终总分也1、许可为真，则专用attack/1分支保留attack；同为1的消耗品在较早消耗品段仍按 `>=` 覆盖attack。如果有两个治疗实例同为7，后遍历者先留下；之后同为7的技能仍需一般随机平分。**平分规则由所在阶段与当前选择决定，不能统一成“同分随机”或“治疗永远优先”。**

### 13.4 何时重新评分：静态调用时点与未知事件频率

1. 所追 `o_enemy.Other10` 在 `0x14364aa68` 先将 `unit_skill_cache` 换新容器；随后在 `0x14364b719` 更新新版FSM。到达attack case3且不skip时，再由 `0x141b5533a` 派Other12。
2. 每次实际进入本章所追Other12评分循环，消耗品在 `0x1436457a3`、技能在 `0x143645dbe / 0x143645eb9 / 0x143645f85 / 0x14364609d` 现场调用评分、修正与许可。选定候选的临时状态保存／加载不是“重新评所有候选”的证据。
3. 无证据保证每次HP、Buff、装填字段变化都立即派一个新Other12，也无证据保证装填动画内重新比较治疗与瞄准；全部全局回合调度频率、其他FSM事件和提交前所有再验证尚未闭合。

时点例：构造一次选择前未瞄准，例A输入使瞄准与治疗都7；事件最终选择瞄准，并假定后续成功建立瞄准buff。等到下一次**确实到达上述Other10→Other12路径**，与例B相同输入使瞄准−13、爆头8，现场评估会读取新状态。只知道buff已建立，却未确认第二次入口到达时，不能承诺立即重选爆头。此例将状态变化、调用触发、重新评分和施放成功明确分开。

### 13.5 可用于CGPK评审的事实与建议边界

证据足够支持“资源实例候选与技能共同竞争、许可独立于分数、分阶段平分、执行阶段还有动作门禁、入口刷新与现场评估分开”。它适合拿来检查我们自己的系统是否保留拒绝原因与候选目标，但**不证明我们应照搬其顺序、权重或逐项随机**。自研可明确设定治疗、装填与移动都是独立动作，并定义提交时是否再验资源／目标；这是我们的契约选择，不是原作完整算法复原。

仍未知：普通基线初始化、全部技能/治疗余下评分、active_set切换、所有动作分派分支、enemy_turn真返回对应每种实际行为、完整移动后是否同事件攻击、弹药消耗与被打断时序、缓存全部失效事件。没有将这些空白填为默认值。本增量不追连锁硬上限或巨石寿命。
