# 39．反射封印的目标重定向与来源归属

[总目录](README.md) · [证据范围](00-evidence-and-scope.md) · [特殊技能候选](22-special-skill-candidates.md) · [秘术换位](18-swap-and-mobile-attacks.md) · [攻击结果与事件顺序](35-attack-results-and-event-order.md) · [格挡响应与反击](38-block-reactions-and-counterattack.md)

实际飞行载体如何消费反射返回值继续见 [42 Fire Barrage投射物](42-projectile-collision-and-target-changes.md)：目标改变后跳过当前碰撞命中，再由后续Step追新目标；连锁自有碰撞与marker分支见 [40](40-chain-lightning-target-propagation.md)。

**已核的反射入口会从单位候选中寻找一个符合门禁的替代目标，不是固定返回最初施法者。替代目标自身带反射封印时会被排除；成功重定向还在替代目标上记录原目标，供后续伤害归属消费。** 这三件事有独立指令证据。没有恢复出通用递归深度计数、所有技能都反射的规则，或整个系统的全局防重入保证。

本章用真实 `Planar_Exchange` 接通“调用反射→消费返回值→修改执行参与者→后续换位与效果”局部链。另读投射物碰撞与出生入口，确认它们也消费返回值，但不将几个公共入口合成“任何伤害都可反弹”。伪代码由我们按证据重新组织，未收录原游戏代码或台词。

## 1．目标与证据范围

沿用相同 GameMaker YYC x64 制品及 EXE 首选基址 `0x140000000`：

| `E:/Steam/steamapps/common/Stoneshard/data.win` | `84034525fcdef3c6fd9803628b8de6c43fea479c930e168a95906de37a2ae19c` |

本轮复用 18、22、35 的匹配身份证据，并静态重新解码反射脚本、封印 Alarm0、换位 Alarm0、shell 碰撞及 spellbirth Other10 共五个入口。REA 提供者不可用的限制沿用 00；采用 Capstone 5.0.9 和 PE/OBJT 登记的本机 fallback，没有 REA 会话或 Evidence ID。

字段名称指针按引用地址减 8 字节解析；BSS 未在制品内初始化的值不当成默认 0。`scr_skill_reflection` 的真实注册入口是 **`0x14039dca0`**，不是参数初始化段中的 `0x14039de60`。成功分支在正常返回指令之后继续布局到 `0x14039eeed`，所以遇到首个 ret 不能停止理解该函数。

证据层级分别是：资源表/对象继承为直接制品事实；字段读写、实参和分支为指令事实；“第一个合格候选被采用”“归属记录被消费”为这些指令的控制流推导；实战频率、最终动画、所有调用者和跨事件重入为未观察范围。

## 2．封印怎样进入单位状态

配置 `Seal_of_Reflection` 行位于 `0x145e4ec70`，执行对象是 `o_seal_of_reflection`。该对象的 Alarm0 用对象常量 3968 调 `scr_effect_create @ 0x143305e4c`；反射脚本检查的也是 3968。关联由真实 ID 建立，不是根据英文名称猜效果。

| ID | 对象 | 父对象 | OBJT 记录偏移 |
|---:|---|---|---:|
| 2829 | `o_skill_seal_of_reflection` | 6199 / `o_skill` | 10226448 |
| 2931 | `o_seal_of_reflection` | 5531 / `o_target_spell` | 10257344 |
| 3968 | `o_b_seal_reflection` | 6052 / `o_magical_buff` | 10583504 |
| 3804 | `o_unit` | -100 / 无 | 10528224 |

封印持续处理经 `scr_skill_get_duration @ 0x143305b1e`，本章不把传入持续或初始化 duration 当成最终可见回合数；共享状态生命周期见 [11](11-buffs-and-effects.md)。本轮也没有恢复全部解除、保存/读档和死亡清理。

## 3．反射 helper 的输入与返回契约

根据实际参数默认与消费分支，以下用三个本章记号表示实参，不擅自给未恢复的参数加更多契约：

| 本章记号 | 参数 | 已核作用 |
|---|---|---|
| `T` | arg0 | 原目标/待处理单位；需存在且拥有封印；返回值默认仍是它 |
| `E` | arg1 | 不能选作替代目标的一个实例；未指定时补 `−4` |
| `checkTeleport` | arg2 | 未指定时补布尔假；为真时增加 `no_tp` 与 `size` 检查 |

默认补值在 `0x14039e076..0x14039e0e1` 与 `0x14039e120..0x14039e16b`。`type=0xD,value=0` 是布尔假，不是 undefined。

最开始对 T 做实例存在检查（`0x14039e1da`），之后取得 **T.buffs** 并检查 3968（`0x14039e21f..0x14039e2f0`）。若存在性或封印检查失败，沿 `0x14039ebc9` 返回原 arg0。

参数在脚本开始被拷贝到局部 RValue 存储。成功分支修改的是这个局部 arg0，并在 `0x14039ebef/0x14039ebf6` 复制到返回值。不能描述成“直接修改调用者所有保存的原目标引用”。必须看调用者是否采用返回值；第 6 节会给出真实消费者。

## 4．替代目标的逐步选择

通过 T 的封印检查后，脚本先播放相关音效与创建表现，再使用常量 **3804=o_unit** 进入候选遍历（`0x14039e67c/0x14039e6a6`）。原目标上的 `depth` 在 `0x14039e501..0x14039e5c3` 参与表现创建参数，不能仅凭这个字段名说它是反射递归深度。

每个候选 C 依次经过下列已核局部门禁：

| 规则 | 输入主体与结果 | VA |
|---|---|---|
| 排除原目标 | C.id 与 T 相同则继续遍历 | `0x14039e72a..0x14039e75a` |
| 排除指定实例 | C.id 与 E 相同则继续遍历 | `0x14039e780..0x14039e7b1` |
| 可选传送限制 | checkTeleport 真且 C.no_tp 真则跳过 | `0x14039e7d8..0x14039e802` |
| 可选体型限制 | checkTeleport 真时比较 C.size 与一个运行时常量，相等则跳过 | `0x14039e80f..0x14039e89d` |
| 距离 | `scr_tile_distance(C.id,T,undefined)` 通过 ≤8 比较才继续 | 距离 `0x14039e9aa`；常量 8/比较 `0x14039e9b2..0x14039e9be` |
| 可见性 | 当前候选上下文 `is_visible(undefined,undefined)` 为真 | `0x14039ea6f..0x14039ea7e` |
| 再次封印检查 | C 若有 3968，则跳过 | `0x14039eb4d..0x14039eb5c` |

本轮未解析可选 size 门禁的运行时常量初始化，不在此强行写成某个具体体型名。距离上限是这个反射 helper 的 **8**，不同于创建 Seal of Reflection 时的名义选择范围。共享比较 helper 含数值类型与容差处理，本文的 ≤8 规格面向普通地图整数格输入。

可见性不是“C 对 T 的视线射线通过”的直接证据。此前 [23 玩家视野与迷雾](23-player-vision-and-fog.md) 和 [24](24-investigation-and-reveal.md) 已核 `is_visible` 默认参数在正常房间内通过当前实例 id 查询 fog 可见性。这个反射调用显式传入两个 undefined，不能把它替换成原施法者的敌人视觉或一条任意单位间 LOS 算法。界外坐标与特殊实例仍保留 helper 边界。

在主函数已读的候选循环中，没有读取阵营、owner、关系表、目标 HP，也没有检查候选就是最初施法者。由此可以确认它没有在此循环显式优先选择原施法者；不能再扩大成所有技能和依赖 helper 都完全忽略阵营、死亡或其他交互条件。

第一个通过全部这些局部门禁的候选直接跳到成功段 `0x14039ee2b`，不再比较其他候选。当前函数没有距离排序或“取最近”集合。实际 with 遍历次序未恢复，不能宣称稳定选某个方向、最近敌人或随机单位。

## 5．成功输出：新目标与一次待消费的归属记录

成功段对 **候选 C** 做两项写入：

1. `C.reflection_attacker = T`：字段 `0x14039ee3c`，从局部 arg0 取得旧目标并赋值 `0x14039ee79`。
2. 把局部 arg0 改为 `C.id`：读 id `0x14039ee92..0x14039eeb6`，赋回 `0x14039eede`，随后走返回尾部。

因此来源记录中的 T 是原受封印保护的目标，不是自动等于法术原始 owner。法术载体 owner 是否变化，是另一条消费者规则。主脚本这里没有给所有载体统一改 owner，也没有把完整效果/伤害事件复制一份再投给 C。

```text
ReflectionTarget(T,E=−4,checkTeleport=false)：
  若T不存在或T没有封印3968：返回T
  执行已读表现准备
  按实际with遍历顺序检查o_unit候选C：
    若C.id==T或C.id==E：跳过
    若checkTeleport为真：
      若C.no_tp为真：跳过
      若C.size匹配该运行时排除常量：跳过
    若tile_distance(C,T)>8：跳过
    若默认is_visible查询为假：跳过
    若C有封印3968：跳过
    C.reflection_attacker = T
    返回C.id
  返回T
```

这份规格只表达已读局部，没有补入阵营规则、最近目标选择、递归深度或未核体型字符串。

## 6．真实技能消费者：秘术换位

真实配置 `Planar_Exchange @ 0x145e4fa00 → o_planar_exchange`，对象 ID 2381、父类 5531/o_target_spell；实际 `Alarm0 @ 0x1431473d0` 调此 helper。

这段执行不是单目标伤害：当前参与者 T 从 `target_array` 取得（`0x143147b59..0x143147b80`）；另一个参与者作为排除参数 E（`0x143147b96..0x143147be7`）。进入已定位反射分支后，实际调用在 **`0x14314813e`**，第三实参为真。因此它也启用可选传送/体型门禁。

返回值复制到局部变量（`0x14314814d`），与处理前参与者比较（`0x143148175`）。改变时用返回值替换当前参与者（`0x143148196`）。这个已经进入反射处理的分支若没有改变目标，则写失败标记（`0x1431481e7..0x14314821a`）；后续标记为真会销毁执行对象（`0x14314825d..0x14314827d`）。不能把此失败规则扩大到“完全没有封印的普通换位必定失败”；普通分支不等于已进入反射处理分支。

成功继续后，把当前两参与者写入执行对象的 `target_array[0/1]`（`0x1431482e1..0x1431482fb`、`0x14314833e..0x143148358`）。后续链已在 18 确认：

| 后续环节 | VA |
|---|---|
| 分别准备参与者并缓存旧坐标 | `0x143148431/0x143148965`，闭包 `0x143141d00` |
| 交叉传入坐标变更 | `0x1431490e4/0x1431492b4` |
| 分别调用后续效果闭包 | `0x143149ee0/0x143149f61`，闭包 `0x1431445b0` |
| 闭包内技能伤害入口 | `0x143144abd` |
| 闭包内效果创建之一 | `0x1431451cc` |

这贯通了命名技能的返回值消费与实际效果链。仍不保证两次位置修改是原子交换、伤害必定发生或任何反射候选都能通过后续准备。失败回滚、退款和完整伤害量未在本章恢复。

### 具体构造例子：换位被重新定向

构造当前换位参与者 T、E；T 存在且有封印3968。候选 C 不等于 T/E、没有封印、`no_tp=false`、通过 size 门禁，距离查询返回 4，正常房间内默认可见查询为真；并假定 C 是遍历中第一个合格候选。坐标输入 T=(100,200)、E=(300,400)、C=(500,600) 只作控制流说明，不冒充合法地图格中心或实战捕获。

反射 helper 将 `C.reflection_attacker=T` 并返回 C。换位调用者采用 C 替代 T，重新写执行参与者；若后续双方准备通过，则缓存 C/E 的旧坐标，交叉请求 C→E 的旧位置、E→C 的旧位置，再分别进入后续伤害/效果闭包。原 T 的坐标不会仅因“反射字段写入”而在这段成功链里承担被替换参与者的两次位置请求。

若给 C 也加封印，C 在第二次封印门禁被跳过。若其他单位也全部失败，helper 返回 T；在这里已经进入反射处理的换位分支将因此进入无改写的失败路径。这是一个有明确门禁和消费者的局部反例，不是所有反射技能共同的退款/取消协议。

## 7．其他真实入口与来源归属消费

### 7.1 投射物碰撞和法术出生确实采用返回值

`o_shell.Collision_o_unit @ 0x143dc5d50` 调反射 helper（`0x143dc60f9`），然后把结果写回自己的 `target`（`0x143dc610f`）。后续相关比较允许时派自身 user0/Other10（`0x143dc6169`），写 `is_execute=true`，再进入销毁路径。这里只闭合公共碰撞入口；尚未逐项列出实际继承它的所有投射物和命中规则。

`o_spellbirth.Other10 @ 0x143e4be50` 则传入当前 `point`、−4 与自身 `check_tp`（`0x143e4c0d7..0x143e4c164`），将返回值赋回 `point`（`0x143e4c17e`），随后继续出生流程。其 owner、target 赋值还有不同上下文的拷贝，不由 helper 名称推出“效果 owner 统一变成反射者”。没有把这两条公共链自动套到所有范围技能、持续伤害或物理攻击。

### 7.2 simple_damage 会转交 last_attacker 并清除记录

既有静态 `scr_simple_damage` 中，当前受伤单位上下文读取 `reflection_attacker @ 0x141228fe0` 并与 −4 比较（`0x141229018`）。若不等于 −4：

```text
currentUnit.last_attacker = currentUnit.reflection_attacker
currentUnit.reflection_attacker = −4
```

复制在 `0x141229050..0x141229087`；清除在 `0x1412290a7..0x1412290dc`。这段归属检查位于35所述普通HP中间写入之后，后面仍有伤害状态、保护与事件处理；它不是伤害数值计算公式。来源记录既有生产也有消费，因此不是一个仅供表现的未用字段。

可选本机旧证据：[伤害入口记录](../../../_reference/stoneshard-study/ninth-attack-native.json)、[simple_damage 解码](../../../_reference/stoneshard-study/ninth-attack-disassembly/scr_simple_damage.txt)。本章只新增归属连接，不重做 32/35 的完整伤害和死亡算法。

**归属的构造演算**：C.reflection_attacker=T，后续确实在 C 的该伤害消费分支执行时，C.last_attacker 变成 T，reflection_attacker 清为 −4。若另一次伤害在没有重新写入的情况下到达此检查，就不会再次由这份旧记录覆盖 last_attacker。未证明标记在无伤害结束、取消或跨区时如何清理；这也不是“对所有事件自动恰好一次”的事务保证。

## 8．双方都有封印时：局部防重复与未恢复的全局防护

当前反射 helper 会排除有封印的候选，成功新目标因此在此检查时没有3968。原脚本没有直接再次调用自己；成功改写后进入返回尾部，不把新目标送回循环重新做封印检查。这建立了本次调用内的有限选择流程。

如果最初施法者与原目标都带封印，原目标的 helper 会把有封印的施法者排除，而不是必定回弹给他。另一个无封印且满足门禁的单位可能被选中；没有合格候选则返回原目标。这个规则不是双封印间自动往返，也不证明原游戏存在递归反射深度上限。

`reflection_attacker` 在 simple_damage 中消费后清除，支持局部来源记录不重复应用；它不是本 helper 检查的 visited 集合。`depth` 被用于表现位置参数，不能当递归计数。目标所在的其他回调、在途法术、再次获得封印、多个效果同一时段写这个字段，以及所有间接调用者是否会再次调用反射，均未恢复。

因此只报告：**候选封印拒绝、单次调用找到即返回、伤害归属记录消费清除** 三项实证。没有证据就不添加“最多反射一次”“绝不重入”“全局深度 N”或“所有反射原子完成”的原作规则。

## 9．独立设计建议与剩余风险

以下是自研建议。我们可显式设计重定向策略（返还原施法者、最近合法敌人或有序候选）、阵营/可见规则和来源归属，将原始施法者、反射者、当前受击者分开保存。若系统允许反复反射，使用事件 ID、路径集合或深度预算；若只允许一次，保留明确的已重定向标记并在提交前重新验证目标。不要依赖名字为 depth 的字段或一个会被其他效果覆盖的单位字段来推测防重入契约。

已完成：封印身份连接、helper 输入/返回、候选门禁、成功字段写入、真实换位消费者与后续效果、公共碰撞/出生返回值消费、伤害归属记录的清除。未完成：所有技能适用清单、实际遍历次序、size 常量初始化、完整阵营/视线契约、同时多次反射覆盖、无伤害退出清理、运行时动画与回合频率。

没有启动、附加或修改游戏，没有读取新存档，也未提交推送。未运行游戏测试和 REA 构建：本轮是静态文档研究，现有闭合规则不需要扩大运行权限。剩余风险是把 fog 可见性当单位间 LOS、把记录原目标当统一改 owner、把局部封印排除当全局递归保护，以及把返回值改写误认为调用者已自动消费；正文已分别保留这些边界。

本机验证已检查正文 84 个 VA 与选定指令/明确资源来源、全部相对链接、UTF-8 与围栏配对，未发现缺失；记录见 [验证结果](../../../_reference/stoneshard-study/tenth-reflection-validation.json)。结构化局部结论和构造例子见 [反射核对](../../../_reference/stoneshard-study/tenth-reflection-findings.json)。地址检查不代替语义与运行验证。
