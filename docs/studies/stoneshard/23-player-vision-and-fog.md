# 23 玩家当前视野、探索记忆与战争迷雾

[总目录](README.md) · [证据范围](00-evidence-and-scope.md) · [敌人感知](03-enemy-perception.md) · [持久化与时钟边界](17-persistence-and-clock-boundaries.md)

本轮确认了本地地图的两套不同数据：`fogmap`供当前可见性查询使用；`fogTiles`记录已经打开过的地图格，并有序列化、保存容器和恢复路径。当前视野处理确实读取玩家位置、`VSN`和墙体网格，并使用圆边界点、缓存射线、掩码和队列。**尚未恢复所有遮挡分支，不能把它称为某个完整的标准视野算法。**

世界地图还有独立的网格与`fogString`保存路径。敌人发现玩家的概率、主动搜索陷阱、玩家听到声音的提示，都是相邻的消费者或系统；它们不等于玩家战争迷雾本身。

## 1. 身份、方法与证据等级

本篇针对既有研究中同一份 Windows x64 GameMaker YYC 制品：

| 制品 | SHA-256 |
|---|---|
| `StoneShard.exe` | `d45797505f04b9112c5fbb8e85c0f8cda2fa60aee954b4e108bad8a0dc514afa` |
| `data.win` | `84034525fcdef3c6fd9803628b8de6c43fea479c930e168a95906de37a2ae19c` |

路径、格式、摘要与原有研究一致；本轮由总调查复核身份。本篇使用注册表、`data.win`对象元数据和 Capstone 静态解码，未运行游戏、修改目标或读取新的存档。REA 提供者在当前调查环境仍不可用，所以下列地址与本机输出是本地 fallback 证据，没有虚构 REA Evidence ID。

证据层级如下：

- **直接指令证据**：字段获取、方法绑定、传参、分支、网格读写、字符串与保存键。
- **局部行为推导**：由上述读写关系解释当前视野与探索记忆；伪代码是我们重新组织的规格。
- **构造演算**：选择小网格和输入验证局部规则，不是游戏运行结果。
- **未知**：事件调度先后、全部墙角规则、最终像素明暗与完整加载时序等尚未闭合的路径。

检索复用了函数登记和字符串索引，先筛选`fog/fov/vision/visible/reveal/explor/sight`，再沿已确认的创建、事件和方法指针选择入口。本机解码输出共36个相关函数/方法；这表示已解码这些登记函数的所选`.pdata`范围，**不表示语义或全部执行路径完整恢复**。匿名方法以Create中的实际方法指针绑定核对；缓存字段名取引用地址前8字节的名称指针。没有把BSS地址误当成文件中已初始化的常数。

本机可选证据：[入口筛选](../../../_reference/stoneshard-study/seventh-fog-candidate-index.json)、[解码覆盖与调用/字段](../../../_reference/stoneshard-study/seventh-fog-native.json)、[目标身份](../../../_reference/stoneshard-study/seventh-target-identity.json)。这些本机产物可再生成，不是正文理解所必需的跨机器资料。

## 2. 数据所有权：四种“可见”不能混用

| 数据/查询 | 所有者或入口 | 已确认用途 | 不能据此保证 |
|---|---|---|---|
| `fogmap` | `o_fogrender` | 当前可见格；更新路径会清理并重写；普通单位查询读取所在格 | 该次查询代表整个角色全部外形；界外查询必定false |
| `fogTiles` | `o_fogrender`，保存到`locationsFogDataMap[tag]` | 打开的格写0；初始值1；保存/恢复探索记忆 | 地图物体或敌人也永久可见；本轮所有路径永不回填1 |
| `visible` | 各对象自身字段 | 独立的对象属性；`is_visible`显式第二参数为真时直接读取它 | 它总是等于当前`fogmap`；名字相同就具有同一语义 |
| `globalmapFogGrid`等 | 世界地图状态；`globalmapDataMap.fogString` | 世界地图迷雾更新和保存 | 它与本地26像素格、房间视野或敌人感知共享网格 |

`data.win`的OBJT记录确认：7005是`o_fogrender`，父ID为−100；5376是`o_player`，父ID为3804；4028是`o_controller`，父ID为−100。这里保留父ID，没有凭父对象名称补充继承行为。相关事件实现则由YYC登记入口确认。

字段值需要结合消费者解释。`fogTiles=0`是已打开的格，`1`保留迷雾；`fogmap`中有明确写1的当前可见分支。两张网格的真假方向不同，不能统一写成`true=已探索`。

## 3. 当前视野：输入、重置、传播与消费者

### 3.1 玩家位置和范围来源

`o_fogrender.Other12`入口为`0x144bcdf10`。在玩家对象5376的上下文中读取`VSN`，把值写到迷雾对象的`distance`，并复制玩家`grid_x/grid_y`：

| 局部行为 | VA |
|---|---|
| 读取玩家`VSN` | `0x144bce3e1` |
| 写`distance` | `0x144bce3f7`附近 |
| 玩家网格坐标传入迷雾对象 | `0x144bce438`、`0x144bce48f`起 |
| 清理`drawFogTiles`列表 | `0x144bce68b` |
| 读取并调用`fog_raycast.circle_get` | `0x144bcedca`、`0x144bcee44` |
| 从对象4028读取`wallgrid` | `0x144bcef22` |
| 调用`ds_grid_clear`重置`fogmap` | `0x144bcf190` |

重置传入的RValue位于`0x1498ff288`，该地址属于未直接恢复初始化值的区域，本篇不硬写它的数值为0。网格被重新清理、后续分支重新写入是直接证据；缺失该常数不应被普通“FOV通常这样写”的经验替代。

`circle_get`方法在`ctr_fog_raycast`构造器中绑定到`0x14008edc0`。它先`math_round`输入范围（调用点`0x14008f156`），查询缓存；缓存缺失时调用`scr_bresenhamGenerateCirclePoints`（`0x14008f37a`），随后存入缓存。这里能确认“取整范围→缓存圆边界点”，但尚未逐点恢复该辅助函数，不能由函数名证明整个最终视野就是无障碍的欧氏圆盘。

正常有限数的取整规则见[回合与伤害](14-combat-turns-and-damage.md)：`sign(r) × floor(abs(r)+0.5)`。**构造例**：若某次传入范围6.4，缓存查询使用取整后6；这不证明该角色原始`VSN`一定为6.4，也不证明半径6内每格都会可见。墙体、额外宽高和后续分支仍会影响结果。

### 3.2 遮挡结构的已知部分

`ctr_fog_raycast`入口`0x14009f510`实际绑定了下列方法，而非仅有对应字符串：

| 方法 | 实际实现VA | 已确认内容 |
|---|---|---|
| `circle_get` | `0x14008edc0` | 范围取整、缓存查询、圆边界点生成入口 |
| `ray_get` | `0x14008f8c0` | 射线缓存及`scr_raycast_mod_array`调用 |
| `raster` | `0x1400906c0` | 已定位，尚未完整解释掩码规则 |
| `mask_get` | `0x140093430` | 已定位，尚未恢复全部缓存键与掩码形状 |
| `floodfill` | `0x140096990` | 墙体/扩展墙体引用、范围取整、队列和格写入 |
| `floodfill_tile` | `0x140098740` | 邻格处理、射线与墙角相关分支、探索/当前格写入 |

`floodfill`读取`wallgrid`并保存到`losgrid`（`0x140096d24`起），记录迷雾对象和`ext_wall_grid`，清空队列（`0x140097017`），入队（`0x1400972eb`）、出队（`0x14009746e`）、写传入网格（`0x140097650`），再调用绑定的`floodfill_tile`。后者有多方向邻格分支，读取`losgrid/ext_wall_grid`，使用`ray_get`，并涉及`fogCutSprite/fogCornerMod/fogRayOffset`。

例如该方法的一条已核对分支：取得`fog_object.fogTiles`（`0x14009a215`），写该历史网格（`0x14009a2b8`），再向传入网格写数值1（`0x14009a389`；常数在`0x14009a348`构造）。前一次历史格写入的RValue初始化仍未恢复，因此**这里不借其他路径推定它也是0**；已打开格写0的直接证据在下一节。

另一事件`o_fogrender.Other20@0x144bd2a00`也存在队列、墙体网格和多方向射线处理，其`0x144bd4291`明确向`fogmap`写1。四处调用`scr_raycast_mod_array`位于`0x144bd6682/0x144bd7302/0x144bd810b/0x144bd8d72`。该包装器在`0x14096c920`调用`scr_raycast_mod@0x140758d20`；后者读取`wallgrid`、网格宽高并使用`dcos/dsin/point_distance`。这些证据说明确有墙体与射线运算，不足以把全部路径简化成“遇到第一面墙就停止”或命名为shadowcasting。

**未闭合的关键点**：Other12与Other20由谁按何顺序发送；每个墙值对应的透视规则；斜角是否允许穿过、门和透明障碍如何编码；各掩码/缓存键；`VSN`以外所有半径修正。这些应保留未知，不能给出伪装成原作的精确遮挡算例。

### 3.3 当前可见性如何消费

`scr_checkUnitFogVisible@0x1414bf970`的普通单格分支读对象`grid_x/grid_y`（`0x1414c047a/0x1414c0490`），取得迷雾对象7005的`fogmap`（`0x1414c04a6`起），转换坐标后读取格值（`0x1414c0584`），把结果返回。另有针对占格列表的分支，不能把所有对象都视为一个点。

`is_visible@0x140bbaab0`的已核对正常地图内路径：第一参数缺省时使用当前对象ID；第二参数缺省为false，按对象网格坐标调用`scr_checkUnitFogVisible`（`0x140bbb19f`）。第二参数显式为真时才直接返回对象`visible`（`0x140bbb345`起）。该函数局部返回值初始为true，坐标门禁未通过会跳过迷雾查询，因此本篇**不宣称界外返回false**。

这解释了主动搜索为何可以对原本隐藏的陷阱调用缺省`is_visible`：它检查陷阱所在格是否处于玩家当前视野，而不是要求陷阱自身已经`visible=true`。主动搜索的距离、揭示条件和后续动作见[24 探查与揭示](24-investigation-and-reveal.md)。

Other12还在`0x144bcf804`调用`scr_enemy_fog_visible_update@0x141e41400`。这说明玩家迷雾更新与敌人显示处理存在实际桥接；**不能由这一次调用推出敌人看到玩家、发现概率或AI战斗状态**。敌人视觉与听觉算法见[03](03-enemy-perception.md)。

## 4. 已探索格：完整的写入、保存与恢复局部链

### 4.1 创建和开格

`o_fogrender.Create@0x144bc8bf0`创建`fogmap`及`fogTiles`。历史网格创建点`0x144bca6c2`，清理参数明确为1（`0x144bca743`），对应`ds_grid_clear`登记读取`0x144bca759`。同时生成地点、房间和迷雾tag：`scr_locationGenerateTag`调用`0x144bca426`、`scr_locationRoomGenerateTag`调用`0x144bca462`、`scr_fogGenerateTag`调用`0x144bca4a4`，写`fogmapTag`（`0x144bca3a3`所指字段）。完整tag格式尚未在本篇恢复，不杜撰键名。

Create把`fogTilesOpen`绑定到匿名方法`0x144bc57e0`（绑定字段`0x144bc957c`）。方法把传入列表按相邻两个值组成坐标对，读取网格宽高进行门禁；有效坐标写`fogTiles[x,y]=0`（网格写入`0x144bc5e41`），列表索引递增2（`0x144bc5e73`附近）。列表的单位是本地网格坐标；本篇未证明奇数长度列表、非法DS列表或NaN的完整拒绝行为。

`o_fogrender.Other10@0x144bcd7a0`有迷雾开关与对象`visible`门禁，且要求玩家对象存在；通过后复制玩家网格位置，直接把玩家所在格写0（`0x144bcda3f`），再调用`fogTilesOpen(drawFogTiles)`（取方法`0x144bcda88`、取列表`0x144bcda9a`、调用`0x144bcdada`），并请求`fogUpperRedraw`（`0x144bcdb32`）。因此不是靠名称推断“见过的格会保存”，而是实际列表→历史网格的写入路径。

### 4.2 保存容器和字符序列

Create将`fogSave`绑定到匿名方法`0x144bc7d00`，方法指针构造位于`0x144bcb426`。`Other11@0x144bcddf0`取得该字段（`0x144bcde4f`），间接调用（`0x144bcde76`）。**本轮没有恢复所有Other11发送者，不能称每次移动都会立即写磁盘。**

该保存方法读取历史网格宽高（`0x144bc7ed3/0x144bc7f55`），外层递增x，内层递增y；读`fogTiles[x,y]`（`0x144bc8293`），转换为字符串（`0x144bc82cf`）并连接（`0x144bc82db`），最终以`fogmapTag`为键调用`ds_map_replace`（`0x144bc83ab`）写到`locationsFogDataMap`。这条局部序列化路径保存的是`fogTiles`，没有把`fogmap`替代进去。累计结果的初值来自`0x1498ff258`（获取点`0x144bc7e5e`），与恢复时字符比较使用同一RValue；初始化未恢复，故下面严格区分追加的字符内容与整个字符串。

`scr_fogsMapInit@0x1401b7800`把这个容器接入`saveDataMap`：

- `is_load_game`真：通过`ds_map_find_value`取得键`locationsFogDataMap`，赋回该字段（调用`0x1401b798a`、赋值`0x1401b79a4`）。
- 否则：创建新DS map（`0x1401b7a12`），通过`ds_map_add_map`放入`saveDataMap`（`0x1401b7ac4`）。

键字符串的初始化引用为`0x1401b7e54`，对应文本VA`0x145ab48d0`。环境中保存这些字段的全局对象slot未完全命名；使用字段和容器连接解释，不编造额外管理器。

### 4.3 房间创建后的恢复

Create按`fogmapTag`查询已有字符串（`ds_map_find_value`登记读取`0x144bca851`），按网格遍历顺序用`string_char_at`取字符（调用`0x144bcb026`），通常分支调用`real`转换（`0x144bcb136`），写回`fogTiles`（`0x144bcb283`）。还有字符比较后的回填1分支，常数在`0x144bcb1ca`明确构造；比较对象RValue在`0x1498ff258`，本轮未恢复初始化，不能将其无条件命名为“空字符串”并保证全部缺损存档自动补齐。

因此“保存探索记忆→重建历史网格”的局部链成立；**读档后当前视野如何按事件完整重算、什么时候显示第一帧、无效字符串如何报告、地图尺寸改变怎样迁移**仍未恢复。已有探索数据也不证明整个房间的动态单位同时被保存，参见[17](17-persistence-and-clock-boundaries.md)。

### 4.4 按已核对行为重组的伪代码

以下规格仅描述正常网格、有效列表和数值0/1历史格；没有补齐未恢复的事件调度和非法输入分支。

```text
创建迷雾对象：
    创建当前网格 fogmap
    创建历史网格 fogTiles，并填1
    生成地点/房间对应的 fogmapTag
    如果恢复分支取得已有历史字符序列：
        按既定格序逐字符转换，写回 fogTiles
        特定字符比较分支回填1（比较值的初始化未知）

在已通过门禁的 Other10 路径：
    fogTiles[玩家.grid_x, 玩家.grid_y] = 0
    对 drawFogTiles 中的坐标对：
        若坐标通过宽高门禁：fogTiles[x,y] = 0
    请求上层迷雾重绘

调用已绑定的 fogSave 时：
    文本 = 已登记的累计初值 C（初始化未恢复）
    按 x 外层、y 内层：文本连接 string(fogTiles[x,y])
    locationsFogDataMap[fogmapTag] = 文本

处理当前视野的局部路径：
    输入玩家坐标和 VSN
    重置 drawFogTiles 和 fogmap
    查询取整范围的圆边界缓存及墙体网格
    执行已定位的射线/队列/墙角分支（完整条件未知）
    已核对的可见格分支向 fogmap 写1
```

这里没有把Other10、Other12、Other20、Other11安排为固定时序；这是需要另追调用者的边界。

## 5. 查询与“变暗但不忘记”的构造演算

`scr_isInFog@0x141a7cfa0`把两张网格的消费关系写得较明确：

- 迷雾关闭分支返回false。
- 第三参数为false的路径把前两项像素坐标转为本地格坐标，除数26；第三参数为真则使用格坐标。本篇演算直接使用地图内整数格，避开负坐标和边缘截断。
- 第四参数为真时先读当前`fogmap`（`0x141a7d71c`）并取反真值（`0x141a7d741`）；若已经为真则短路返回。
- 否则读取历史`fogTiles`（`0x141a7d83a`）。

对正常0/1格，行为可表示为：

```text
仅查历史：InFog = truth(fogTiles[x,y])
同时查当前：InFog = !truth(fogmap[x,y]) OR truth(fogTiles[x,y])
```

第二式的OR对应短路分支，实际返回RValue不要求两个分支的类型完全相同。这也是为什么“已经探索”不等于“当前可以看见”。

**构造例：3×2历史网格。** 初始全为1。玩家位于(0,0)，传入有效`drawFogTiles=[0,1, 1,1]`，并假设Other10已通过开关、存在和`visible`门禁：

| 历史状态 | x=0 | x=1 | x=2 |
|---|---:|---:|---:|
| y=0 | 0 | 1 | 1 |
| y=1 | 0 | 0 | 1 |

先打开玩家格，再打开两个坐标对。按x外层、y内层保存，追加字符为`"001011"`；最终文本严格写作`C + "001011"`。**在构造前提C为空且恢复输入是这六个有效字符时**，正常字符转换恢复后仍得到这六个历史值。C为空是本演算前提，不冒称已恢复的常数。此3×2尺寸和输入列表由我们构造，不是实际房间参数，也不涉及玩家真实存档。

再构造某次后续当前视野：`fogmap[0,1]=0`、`fogmap[1,1]=1`。则：

| 格 | 历史查询 | 同时查当前 | 解释 |
|---|---:|---:|---|
| (0,1) | false | true | 已探索，但此刻不可见 |
| (1,1) | false | false | 已探索且此刻可见 |
| (2,1)，假设当前也为0 | true | true | 尚未打开，且此刻不可见 |

这演算验证的是已恢复的查询组合。没有用它证明(0,1)究竟被哪面墙遮住，或指定它在游戏画面中一定呈某个灰度。

渲染入口`o_fogrender.Draw0`确实同时取得`fogTiles/fogmap`（`0x144bf1605/0x144bf1624`），创建/检查surface，清透明背景、使用shader uniform并绘制surface；还检查`isFogAlternative`和`fogBehaviourEnabled`。因此逻辑状态与最终绘制之间存在独立渲染层。**什么时候变暗**在逻辑上取决于当前可见性更新，不必擦除历史探索；**具体帧、淡入时间、灰度、动画和材质效果**尚未通过shader和运行观察闭合。`isFogAlternative`已出现在渲染路径，不能凭它的名字断言切换了某两种标准FOV算法。

## 6. 世界地图揭示是另一套状态

`scr_globalmapFogUpdate@0x140450190`读取`globalmapFogGrid/globalmapFogTilesGrid`和玩家世界网格位置，调用`scr_globalmapFogGet`（`0x140450813/0x140450ffb`），并连接世界地图tilemap、山体显示、缓存和商队路径网格更新。这里只确认独立数据和调用关系；没有借本地VSN半径补出世界地图揭示半径。

`scr_globalmapFogSave@0x140593780`以`worldWidth/worldHeight`遍历世界地图迷雾格，构造`globalmapFogString`，随后访问`saveDataMap`内的`globalmapDataMap`，把字符串写到`fogString`。相关键文本初始化引用为`0x140594633`（`globalmapDataMap`）和`0x140594652`（`fogString`），保存调用的`ds_map_set`登记在`0x140593e0f`。

**具体来源例**：本地探索保存键是`locationsFogDataMap[tag]`；世界地图序列的键是`globalmapDataMap.fogString`。即使玩家当前房间的某格被打开，不能把它直接当作某个世界地图格已揭示；二者的坐标系、尺寸和保存键不同。本篇未证明哪一种地标、主动动作或地图道具如何扩大世界地图揭示范围。

## 7. 可以独立借鉴的设计与尚未回答的问题

**以下是自研建议，不是已证实的原作实现。** 对自己的游戏，可以把`CurrentVisibility`和`ExplorationHistory`作为两个有明确真值语义的状态：前者可重建，后者按地点保存。统一采用`true=可见/已探索`，避免本例两张网格真值方向相反带来的误用。单位显示、交互资格、主动探查分别明确消费哪一层，而不是复用一个含义模糊的`visible`字段。

探索保存最好独立定义尺寸、格式版本和有效性检查；演算中的单字符序列只在格值可用单字符表示且遍历顺序稳定时成立。视野实现则依据自己的墙角、透明门和多格单位需求独立选择、实现并测试，不复制目标的恢复代码或专有shader。

本轮已回答：当前格与历史格的数据分离；玩家位置/VSN的输入；真实墙体、射线、队列结构；至少一条开格→历史网格→保存容器→恢复→消费者的贯通链；本地与世界地图状态分开。

部分回答：遮挡算法和范围；逻辑不可见与渲染变暗的关系；默认对象可见性查询。未回答：完整门/角落/透明障碍判定、全部更新事件时序、shader最终输出、完整异常恢复、所有世界地图揭示动作，以及动态光源对最终视野的全部影响。

验证只做了登记/指令位置、正常分支参数、保存遍历与构造演算、本地文档链接和UTF-8检查。未做游戏运行、画面比对、存档往返或网络观察，因为本轮范围是静态局部研究。剩余风险是把局部路径推广到所有场景；正文通过保留未恢复参数、事件和边缘语义限制了这种推广。
