# 54. 背包自动整理：先堆叠、尺寸分组排序、逐件寻找空格

[总目录](README.md) · [证据范围](00-evidence-and-scope.md) · [拖拽与掉落](52-inventory-ui-drag-placement-and-dropping.md) · [堆叠与拆分](53-item-stacking-split-and-transfer.md)

**已找到真实整理对象的调用链：先对合格物品请求堆叠，再收集未装备物品，按idName分组和尺寸进行三次排序，按组逐件重新加入背包。找空格是枚举候选并检测矩形覆盖，先找到合格位置就采用；所查链没有恢复出全局最优装箱或回溯。** 重新加入失败时存在forced_drop与丢弃事件分支，不能承诺“整理永远把所有物品留在原菜单”。

本篇使用00固定的本机Stoneshard YYC x64制品，第十二轮完整摘要一致；本地PE/OBJT和Capstone 5.0.7静态读取，不是REA Evidence。未运行整理按钮、修改物品或存档。重新组织的伪代码/矩形场景供独立设计参考，不是原游戏源码或实测背包截图。

## 1. 真正的整理动作先做堆叠

`o_autosorting.Other10@0x143251300`有两个实际调用：

1. 在owner/active等条件成立的遍历里，对can_stack真、非equipped、非is_deactivated并符合delivery_time缺失等条件的物品，调用 `scr_inventory_stack`（`0x143251c6a`）。全部特殊数量和类型匹配见53。
2. 后续调用 `scr_inventory_sort`（`0x143251de0`），传入当前所属菜单/单位实例的id。

因此“把两堆箭合为一堆”和“给一组多格物品重新排位置”是两个阶段。堆叠会改变数量和实例集合；排序函数不能假定它得到的仍是按钮点击前的原始对象列表。

本轮通过完整调用者解码验证了这条链，不只凭函数名叫sort。整理对象的Create有owner_object、声音和hoverText等输入；本篇没有把所有GUI按钮绑定、快捷键和菜单皮肤一并恢复。

## 2. 收集范围、临时父容器与占格解除

`scr_inventory_sort@0x140a3a3c0`创建临时GUI容器（`0x140a3a75b`），遍历物品实例并过滤：

| 条件 | 指令位置 | 已见效果 |
| --- | --- | --- |
| item.owner等于本次传入owner | `0x140a3a891–0x140a3a8c8` | 不同owner跳过 |
| item.is_deactivated为假 | `0x140a3a8d5–0x140a3a8eb` | 已停用跳过 |
| item.equipped为假 | `0x140a3a8f8–0x140a3a90e` | 已装备跳过 |

对合格物品，派发User1/Other11以准备几何/外观（`0x140a3a932`），调用 `scr_item_cells_update(id,false)`（`0x140a3a9ea`），把物品加入临时GUI容器（`0x140a3aa92`），并追加实例id到待整理数组。

临时容器随后更新（`0x140a3abf1`）。这是先解除原占格再重新提交的实际结构，不是先计算一张完整成功的新布局、最后一次性原子替换。本轮没有闭合临时容器在每个错误/提前退出中的最终释放，不据已见正常流程断言完全无泄漏或可回滚。

过滤保证本入口不把所有已装备武器一并重新塞回格子。但其他脚本可能调用不同整理入口，例如trade_inventory_sort和sort_item_in_container不能仅因名称近似就并入这一规则。

## 3. idName分组的真实数据结构

`scr_items_sort@0x1408b8d30`对输入数组逐项取实例，读取其 `data["idName"]`并转为字符串（地图查询 `0x1408b940d`、string转换 `0x1408b945a`）。在已产生的组中比较这个字符串，相同则把该实例加入已有组的第三项。

新组是三项嵌套数组：

```text
group = [ idName字符串, [cells_x, cells_y], [itemID, ...] ]
```

第二项的尺寸取自新组首个物品。cells_x/cells_y读取 `0x1408b99ae / 0x1408b99d4`，通过 `@@NewGMLArray@@`内建构造两项数组（调用 `0x1408b9a5b`），再写group[1]（`0x1408b9a94–0x1408b9aaa`）。第三项同样构造实例数组并写group[2]（`0x1408b9b3a / 0x1408b9b73–0x1408b9b89`）。

这不是按显示中文名称或品质排序，也不是把同idName实例在此函数内再执行数量合并。堆叠已经是前一个独立阶段；同一组仍可包含多个未被合并的实例。没有在本轮恢复组内每件物品的二级品质顺序。

例如构造两件idName="arrows"的实例A1/A2，它们可被分到同一组；idName="sword"的实例S另成一组。是否A1/A2能够真正合并由53的实例身份、数量、来源和特殊属性检查决定，不能由分组本身推出。

## 4. 三个比较器：宽、高、面积

按普通有效有限尺寸数值，三个匿名比较器的返回可以重述为：

| 比较器入口 | 读取字段 | 实际返回 |
| --- | --- | --- |
| `0x1408b7a30` | A[1][0]、B[1][0] | `sign(B.width - A.width)` |
| `0x1408b7f00` | A[1][1]、B[1][1] | `sign(B.height - A.height)` |
| `0x1408b8400` | 两组width/height | `sign(B.width*B.height - A.width*A.height)` |

宽比较的减法/符号调用 `0x1408b7cbc / 0x1408b7cda`，高比较 `0x1408b81d8 / 0x1408b81f6`。面积比较分别乘A尺寸（`0x1408b86bc`）与B尺寸（`0x1408b88e4`），再减和sign（`0x1408b891e / 0x1408b893c`）。乘/减/sign数值助手在13/14/20已核对，不能把字段数组构造误读成乘法。

主函数对同一组数组连续调用array_sort，依次传上述三个比较器：`0x1408b9ce0`、`0x1408b9d6a`、`0x1408b9df4`。按array_sort公开比较约定，这些比较器分别表达宽、高、面积降序。

**三次排序不等于已证明“面积优先、同面积再高、再宽”的稳定字典序。** 最后一次比较器只比较面积，同面积返回0。当前[GameMaker官方array_sort文档](https://manual.gamemaker.io/monthly/en/GameMaker_Language/GML_Reference/Variable_Functions/array_sort.htm)说明自定义比较器的负/零/正约定，并提示排序不稳定。本轮没有恢复这个安装制品的运行时内部排序算法，不能以当前官方描述认定本制品所有内部细节，但足以说明不应未经证据承诺前两次排序一定保留为固定平分顺序。

**比较器例子：**A=2×2、B=3×1，最后比较返回 `sign(3−4)=−1`，表达A先于B。A=2×2、C=1×4时面积相同，返回0；不能从面积比较器决定A/C谁先，也不能直接用前一次高排序保证C一定先。

## 5. 重新加入：按组和组内实例顺序逐件处理

inventory_sort调用items_sort（`0x140a3ad38`）后，遍历组数组，再遍历各组group[2]实例数组。在每个物品上下文调用 `scr_inventory_add(owner,undefined,undefined)`（`0x140a3b588`）。

公共add入口 `0x1410deed0`先更新旧占格，再请求 `scr_inventory_get_cell_free`（`0x1410df653`）；找到可用格后调用attach_to_cell（`0x1410dfa70`），更新GUI节点/布局与itemID占格。两个undefined位置不能填成固定容器0或固定格0，实际默认/选择由下游拥有。

外围空格助手 `scr_inventory_get_cell_free@0x140058b30`先调用 `scr_inventory_get_containers`（`0x1400591c7`），对容器候选调用单容器找格（`0x14005952f`）。容器筛选还调用item_can_add_to_container，具有类别限制；不等于把物品放进屏幕上任意空格。

成功放入前一个物品会更新格itemID，后一个物品查询的是新的占用。所查链没有在某件失败时回头重排全部已经成功的物品，因此属于逐件提交式的局部布局。

## 6. 单容器的矩形检测与first-fit

`scr_inventory_container_get_cell_free@0x14003f0e0`查询容器尺寸（`0x14003f912`）。对应helper从itemsContainer取得columns/rows并返回二维尺寸，第一项在调用者保存到局部0x240、第二项保存0x250（`0x14003f983 / 0x14003f9f3`）。

第三参数的真值分支采用：外层0x310从0递增，比较columns；内层0x320从0递增，比较rows。按坐标取格时明确传这两个局部为列、行（`0x1400401f4–0x14004022e`）。因此这个分支是**列优先扫描，再扫描该列的行**；不是凭直觉指定从左到右逐行。另一真值分支组合/遍历方向也存在，调用默认化和特殊触发不能一律写成同一个循环。

候选位置检查物品矩形是否在容器边界内，读取cells_x/cells_y，再调用inventory_cells_get_items（`0x140040308`）取得覆盖格已有物品。数组长度不为0继续扫描；等于0时保存候选格（`0x1400403ac / 0x1400403c9 / 0x1400403e7`），并跳到返回路径（`0x140040443 / 0x140040449`）。失败初始哨兵为−4。

```text
选定列优先找格分支(container, item):
    result = -4
    对 column 从0到columns-1:
        对 row 从0到rows-1:
            如果item的宽×高矩形超出边界: 继续
            取起始格和完整覆盖格
            如果覆盖格中已有物品: 继续
            result = 起始格
            结束本次找格并返回
    没找到时返回失败哨兵
```

边界助手仍使用本机动态值及比较容差；上述规格限定正常整数宽高。所查路径使用现有cells_x/cells_y，没有在这个找格分支交换宽高尝试旋转。不能据此推广为全游戏不存在手动旋转或其他特殊容器规则。

这条逻辑是first-fit候选采用，不是只看总空格数。总空格足够但形状碎片化，仍可能放不下一个2×2物品。尺寸排序减少碎片的可能性是我们的设计推断，不是原开发者意图或装得下的数学保证。

## 7. 4×3背包的贯通构造例

给定本次只有一个允许的4列×3行容器，所有矩形格可用；已完成堆叠和清除旧占格。进入列优先first-fit分支，物品组依次为A=2×2、B=2×1、C=1×1（组内C1/C2两个实例）。面积不同，因此最后比较器决定这三组的顺序，不需要假定同面积稳定性。

1. A第一个合法候选为(0,0)，占(0,0)、(1,0)、(0,1)、(1,1)。
2. B依次排除第0列前两行，采用(0,2)，占(0,2)、(1,2)。
3. C1扫描前两列均已占，采用(2,0)。
4. C2再次查询更新后的占用，采用(2,1)。

最终逻辑占格可表示为：

```text
row0: A A C1 .
row1: A A C2 .
row2: B B  . .
```

这是明确输入下的独立演算，不是实际背包尺寸或默认物品配置。另在这个已经形成的布局中，单独请求加入一个2×2物品D，而不重新执行面积排序，当前剩余四个空格形状不能容纳它；仅根据“剩余四格”宣称成功会错。这是找格助手的碎片化例子，不是把D加入整轮排序后的结果：重新执行整理会改变物品顺序，可能找到不同布局。

## 8. 加入失败会怎样：实际forced_drop分支

inventory_add返回假时（`0x140a3b590–0x140a3b597`），当前物品写 `forced_drop=true`（`0x140a3b5aa–0x140a3b5d7`），然后派User15（`0x140a3b60d`），即52已追到的Other25丢弃路径。事件包含生成世界物品、数据地图转移和旧背包实例销毁；还有特殊门禁和forced_drop相关时间请求。

构造失败输入：本次允许的容器只有4×3，当前需重新加入的物品P尺寸2×4，没有其他可用容器；即使清空格子也没有合格矩形落点，add返回false，则这条排序分支申请forced_drop与丢弃。这是异常/受限容器输入的条件例，不声称原游戏正常配置必定产生这种尺寸组合。**这不是已观察到玩家正常背包每次整理都会掉物品，也不是一个已证明的全局原子回滚。** 真实是否触发取决于容器选择、实际全部物品、特殊规则和add的返回。

实际写入/事件调用有正证据；为什么代码选择掉落、作者是否认为正常整理一定不会失败，没有开发者意图证据。我们自研若需要保证整理不掉物品，应独立设计预排布局、失败回滚或保留溢出容器，不能声称原作已有这项保证。

## 9. 自研借鉴、完成边界与验证

独立实现可以分开“压缩堆叠、决定物品顺序、生成布局、提交布局”，把同名分组、尺寸键、容器限制、扫描次序和失败策略写入契约。若需要可复现布局，使用一个明确的总比较器和稳定实例tie-break，避免多次不保证稳定的排序；若需要全局更优填充，应另定义回溯/搜索预算和失败结果。
