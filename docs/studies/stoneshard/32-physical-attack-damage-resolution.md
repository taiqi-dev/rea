## 2. 本段的数据由谁提供

| 符号 / 状态 | 来源 | 关键限制 |
|---|---|---|
| `target` | damage_calculation的第一实参 | 不是自动把当前self当成受击者 |
| `B0` | 经过前段武器 / 倍率准备的斩击分量，局部 `rbp+0x528` | 不等于原始表行18的无条件复制 |
| `T` | 前段总伤害基数 `rbp+0x8c0`，复制到 `rbp+0x1b8` | 分母包括其他类型，格挡后没有按剩余分量重新求和 |
| `K` | 格挡路径本次读取的 target.Block_Power | 输入给damage_calculation第三实参，再转给格挡助手 |
| `F` | target.tmpDEF | 适用部位分支从该部位配置选择的DEF字段取值；另有通用DEF路径 |
| `R` | target.tmpSlashing_Resistance | 部位 / 通用抵抗字段的选择结果，不是字符串名推测的常量 |
| `P` | `1−Armor_Piercing/100` | 本篇物理分支；另有Spell_Armor_Piercing分支 |
| `G` | `target.Damage_Received/100` | 已有聚合属性，不是简单“受伤加成贡献+1” |
| `C` | 共享RValue槽 `0x1498722e0` | 本轮未核准运行初始化与全部写入；必须保留未知 |
| `D` | 分量结果经汇总取整后的局部 `rbp+0x600` | 输入BodyPartHit；其他类型 / 效果分支可改写它 |

T的前段将物理分量与非物理分量按各自倍率组合，再乘damage_calculation的第二实参；保存 `0x141253e82`。类型助手使用的分母副本在 `0x1412543ec` 保存；若原总量与0比较相等，还有把分母置1的分支（`0x1412543c0–0x1412543ca`）。不能将这个哨兵补偿扩展成所有无效 / 非数值输入都安全。

原斩击字段引用在 `0x141253857–0x141253863`；乘前段倍率并保存B0在 `0x1412544e9–0x1412544fc`。本文不重复恢复35负责的攻击结果决定流程。

## 3. 部位护甲与抵抗怎样进入输入

`scr_damage_calculation(0x141250670)` 于 `0x14125429a` 调用 `scr_get_body_part_data(0x14127aa10)`，携带目标、指定部位和两个局部标志。25已恢复默认抽选、技能指定部位与消费条件。

数据助手先把目标 `DEF` 复制到 `tmpDEF`（`0x14127af61–0x14127af98`）。适用部位配置分支随后：

1. 按实际部位键查 `body_parts` 中该部位配置；无效配置有错误提示与tors回退，见25。
2. 从配置的 `def` 取得**目标上要读取的防御字段名**，写 `Body_Part_DEF`（`0x14127baa0 / 0x14127bab8`）。
3. 用目标id和此字段名调用 `variable_instance_get`，把读出值写tmpDEF（`0x14127bb9a / 0x14127bbb8`）。因此F不是另一套“部位HP”，也不是直接从配置def字符串当数值。
4. 对 `Slashing` 等类型构造 `类型+"_Resistance"`，取目标的通用抵抗；适用部位标志真时，另构造 `类型+"_Resistance_"+配置.resist`，用通用值作为fallback获取部位抵抗。
5. 最后以 `"tmp"+类型+"_Resistance"` 写临时字段。

Slashing字符串绑定 `0x14127bcbb`，通用字段名拼接 `0x14127c1d4`、读取 `0x14127c25b`，部位resist读取 `0x14127c2ec`、部位字段拼接 `0x14127c381 / 0x14127c3c8`、带fallback读取 `0x14127c4c0`，临时字段写入 `0x14127c72c`。

**这里是字段选择 / fallback，不是本助手把通用抵抗和部位抵抗再相加。**上游属性聚合怎样合并Physical_Resistance、装备与状态，仍属于抵抗生产者；本篇用已经读出的R，不把未知字段缺省猜成0。

## 4. 已成立的格挡如何减少斩击分量

真实格挡结果调用者 `scr_attack_result_block` 读取argument0目标的Block_Power（字段 / 读取 `0x1405d8619 / 0x1405d864f`），保存到局部，在 `0x1405d8b10` 作为damage_calculation第三实参排列，调用在 `0x1405d8c49`。这是K的真实输入来源；不是使用攻击者剑表的Block_Power来防御自己。

进入damage_calculation的格挡分支后，Slashing调用 `scr_damage_block_calc` 的四个实际参数是：

```text
blockCalc(B0, K, T, 1)
```

参数准备 `0x141254d5f–0x141254db9`，调用 `0x141254de7`，返回结果写回斩击局部 `0x141254df6`。是否进入此路径由上游格挡实参真值决定（`0x141254bdd–0x141254be4`），不在这里重新抽一次格挡机会。

普通hit结果调用者给这一参数传入另一个RValue槽 `0x1497fcc28`（引用 `0x14052dcab`，伤害计算调用 `0x14052ddca`）。该槽无PE文件原始字节，本轮未绑定运行初始化，暂记为J；**不能因为调用者叫hit就把J当0，并据此证明普通命中必然绕过格挡段。**下文“未进入格挡路径”是构造的明确分支前提，不是对未知J的取值断言。

助手 `0x1412f8260` 的正常有限数值公式：

```text
share = B0 / T
blockReduction = max(C, 1 * K * share)
B = max(C, B0 - blockReduction)
_tmpBlockReduction += min(B0, blockReduction)
```

除法 `0x1412f83b0`，乘K和类型系数 `0x1412f845e / 0x1412f8498`，max `0x1412f84fc`，减法 `0x1412f8559`，min / 累计 `0x1412f85f8 / 0x1412f860e`，结果下界max `0x1412f8678`。这里没有统一先把每种类型分别取整的步骤；类型1是本次Slashing调用的真实常数，不推广给所有元素。

没有进入格挡分支时，本篇B直接使用B0。进入格挡时，护甲计算的分子变为B，但T仍是此前副本。因而不能把单类型格挡后的 `B/T` 无条件改成1。

## 5. 类型计算的七个参数与公式

Slashing实际调用在 `0x141256229`，七参数依次为：

```text
typeCalc(target, B, target.tmpSlashing_Resistance,
         target.Damage_Received/100, T,
         1-Armor_Piercing/100, 1)
```

目标临时斩击抵抗读取 `0x141256140–0x141256179`；实参数组排列 `0x1412561a9–0x1412561fb`。G来自目标Damage_Received的百分数除100（`0x1412542a9–0x141254310`）。物理穿甲系数P在 `0x141256026–0x1412560a1` 构造；法术标志成立时会选另一个字段，本篇不混用两条分支。

`scr_damage_type_calc(0x1412f6ea0)` 在B通过与0的正值比较后执行：

```text
share = B / T
armorSubtraction = max(C, 1 * target.tmpDEF * share * P)
resistanceMultiplier = max(C, 1 - R / 100)
unrounded = (B - armorSubtraction) * resistanceMultiplier * G
typeOutput = max(C, math_round(unrounded))
```

若B未通过正值门槛，内部结果初始为0，最后仍经过max(C,结果)；不是据此保证未知C下零分量必定返回0。

| 局部步骤 | 真实位置 |
|---|---|
| B正值门槛 | `0x1412f708b / 0x1412f70b0` |
| B/T | `0x1412f711a` |
| 目标tmpDEF读取 | `0x1412f7188 / 0x1412f71b2` |
| 系数1×F、再×share、再×P | `0x1412f7208 / 0x1412f725d / 0x1412f72b6` |
| 护甲扣减下界 | `0x1412f7348` |
| R除100 / 1减该值 / 抵抗下界 | `0x1412f73bf / 0x1412f73ed / 0x1412f7462` |
| B减护甲、乘抵抗、乘G | `0x1412f7516 / 0x1412f756e / 0x1412f75c2` |
| 类型取整 / 最后下界 | `0x1412f7646 / 0x1412f76d8` |

几个直接影响演算的细节：

- P是 `1−穿甲/100`，它作用于护甲扣减；不是把穿甲值直接当额外伤害相加。
- G是目标现有Damage_Received除100；不要把伤势表中的+15贡献直接替代G=1.15，除非已核准聚合后的属性正是115。
- 类型抵抗和护甲是先后不同的步骤；护甲先从分量扣减，之后才乘抵抗和G。
- B减armorSubtraction之后，**没有再立刻max一次**；最终max在取整之后。无效数值 / 超常抵抗 / 未知下限会影响边界，不能自己补一个中途截断。
- 所有max都引用C。本轮有限RIP扫描定位到读取，未闭合可靠初始化；完整模型必须保留C。

## 6. 无甲、护甲、格挡三组完整演算

以下是带明确条件的构造，不是实战测量。共同前提：Slashing输入B0=18、T=18；P=0.95来自构造的Armor_Piercing=5；R=0、Damage_Received=100是**人工输入的聚合属性**；其他分量明确构造为数值0；所有资格和正常有限数值门槛通过。

**共享未知下限只作条件约束：本算例假设C≤0，使这些max不抬高正结果及零分量；没有把目标运行C赋值为0，也未证明真实运行满足这一约束。**不接受此条件时，应使用第5节含C公式，不能报告下表为无条件原作伤害。

| 步骤 | 无甲 | 部位护甲 | 部位护甲 + 已成立格挡 |
|---|---:|---:|---:|
| 构造tmpDEF F | 0 | 6 | 6 |
| 构造目标格挡预算K | 不进格挡路径 | 不进格挡路径 | 4 |
| 格挡share B0/T | — | — | 1 |
| 格挡扣减 / 剩余B | 0 / 18 | 0 / 18 | 4 / 14 |
| 护甲share B/T | 1 | 1 | 14/18 |
| 护甲扣减F×share×P | 0 | 5.7 | 4.433333… |
| 扣甲后分量 | 18 | 12.3 | 9.566666… |
| 抵抗倍率 / G | 1 / 1 | 1 / 1 | 1 / 1 |
| 类型输出 | 18 | 12 | 10 |

math_round的普通有限数值规则为 `sign(x)×floor(abs(x)+0.5)`，不是宿主语言默认银行家舍入。因此12.3→12、9.566666…→10。

第三组的K=4是**受击目标的构造属性**，不是因为Drifter Sword表上Block_Power=4就自动拿来当目标预算。该例强调真实参数的所有权。

再保持第二组护甲条件，改成已聚合R=20、Damage_Received=110：类型结果 `round(12.3×0.8×1.1)=11`。两项分别来自R抵抗与G受伤倍率，不能把它们简单合并成“净10%抵抗”，因为取整及其他分支也会影响输出。

## 7. 从分量到BodyPartHit输入D

类型结果分别保存于局部；Slashing返回写入 `rbp+0x538`（`0x141256238`）。其他类型有自己的参数、护甲系数与输出。本函数还对不同组做汇总取整，再将物理四项与非物理组组合，最后math_round得到 `rbp+0x600` 的D（`0x14125780d / 0x14125781c`）。

对于本例明确单类型且其他分量0、C≤0的前提，其他类型输出不抬高结果，分组和最后取整不再改变18 / 12 / 10。混合类型不能只把所有未取整输入一次相加再取整：每类型、分组和最后的取整发生在不同阶段。

BodyPartHit的调用不是紧接汇总无条件发生：局部标志假值在 `0x14125787e` 绕过到 `0x14125b9ff`。满足此资格并到达后段时，参数排列为 `target, D, target.Body_Part, 总基数局部, 额外标志`；D的指针安排在 `0x14125b939–0x14125b940`，实际调用 `0x14125b9d0`。

汇总至调用之间还有按类型的进度 / 效果处理。例如Arcane正分量及特定状态路径可把D改成 `max(另一未知槽, D−Arcane分量)`，写D在 `0x141259070`。它不是本例纯Slashing的正常必经步骤，本文不将“sum的D永远等于BodyPartHit收到的D”作为所有类型的总规则。

### 接到肢体状态的同一个例子

在本例到达BodyPartHit、目标max_hp=100、当前执行上下文Bodypart_Damage=0的构造前提下，25确认的Condition损失为：

```text
loss = (100*D/max_hp)^1.05 * (1 + Bodypart_Damage/100)
```

三组分别约20.7987、13.5875、11.2202。损失送到本次所选部位，不平分六个部位；随后的Condition clamp下界仍未知，伤势 / 流血有自己的门槛。此例只计算进入该助手的量，不补一个未知初始Condition或擅自判定最终伤势等级。

## 8. 这条链是否真正得到最终HP

本篇已到真实BodyPartHit输入，且调用链确实能继续到HP应用入口：`scr_damage_with_calc` 把damage_calculation返回值交给 `scr_simple_damage`，正常正值调用在 `0x1412c045c`；35还跟踪普通剑击所走的结果路径。

但32没有恢复以下全部内容：

- 前段武器 / 技能 / 攻击倍率怎样使原始配置成为B0和T；
- 所有类型效果对D和返回值的改写、特殊回调与目标例外；
- 最终HP保护、最低生命、神模式、犯罪与受击后的事件；
- 未知C与其他RValue槽的完整初始化和生命周期；
- 带状态 / 装备的完整聚合DEF、Resistance与Damage_Received生产者。

因此18 / 12 / 10是**已解释局部链在明确构造条件下的结果**，不是无甲 / 有甲 / 格挡任意游戏角色的固定伤害。若目标没有特殊保护且后段保持此返回D，普通HP减法才可进一步得到 `HPold−D`；这一最终前提不能隐藏。

## 9. 结论状态与独立借鉴

已回答：一个真实剑配置身份；斩击与格挡真实参数顺序；部位DEF / 抵抗的字段选择；穿甲、抵抗、受伤倍率的局部公式；分量取整与汇总；三组演算及BodyPartHit输入连接。

部分回答：运行配置怎样变成B0/T；完整多类型汇总与特定效果；最终HP。未知：共享下限C和完整生产者、异常动态类型边界、全部防护与回调、实战分布。

独立自研可以借鉴“先产生类型分量，按明确预算分配格挡 / 护甲，类型抵抗分别处理，最后产出带部位与来源的伤害事件”的职责分层。实际要不要采用格挡前总量作分母、多阶段取整、共享下限或某种混合权重，是自己的设计决定，应显式定义并用边界例固定契约，不能称为原作开发意图。
