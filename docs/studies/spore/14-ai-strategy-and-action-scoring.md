# 14 借鉴设计：灵魂怎样评估 AI 策略

[目录](README.md) · [灵魂与肉体契约](13-soul-body-contracts.md) · [行动执行](11-action-plans-and-execution.md)。目标是使灵魂的偏好作用于当前肉体可执行的行动，而不是每换一种肉体就再写一个 AI。

本页固定四项特征用于解释人格权重；基于肉体实时计算可行方案、预测结果与变化处理的续篇见[16](16-soul-ai-body-assessment.md)，完整战斗与数值见[17](17-soul-ai-complete-battle.md)。两组算例使用不同的独立配置，不是通用游戏参数。

## 参考与设计边界

Utility AI（效用评分式决策）给候选行动计算可比较的分数。原作者资料说明了评分尺度、人格权重、情境分组与防止来回切换的惯性。[David Graham，An Introduction to Utility Theory，§9.2–9.7](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter09_An_Introduction_to_Utility_Theory.pdf)

这里只借鉴上述原则。下面的特征、权重、阈值、反馈算法与表格数值全部由我们独立定义，不是 Spore 或书中案例的 AI。它不需要大语言模型或训练网络。

## 三个不同尺度

长期目标：例如生存、保护同伴、完成主人的指令。战术选择：攻击哪个敌人、救哪个同伴、保持什么距离。动作执行：哪只手、如何走到位置、什么时候提交效果。前两个由灵魂策略决定；执行必须服从肉体条件与动作生命周期。

先用明确条件选择紧急情境（死亡、失控、强制效果等），再在允许的战术集合里评分。不要令“攻击评分很高”抵消已经失去控制权限或没有资源的事实。

## 评分对象必须是完整方案

```text
Candidate = { ability, target, executionMode, providerParts, plannedPosition }

ChooseAction(snapshot, soul, body):
    knownTargets = snapshot.perceivedTargets + relevantRememberedTargets
    candidates = GenerateBoundedPlans(body, soul, knownTargets)
    valid = []
    for candidate in candidates:
        legality = ValidatePlan(candidate, snapshot)
        if legality.failed:
            record Rejected(candidate, legality.reason)
            continue
        features = EvaluateOwnOutcomeFeatures(candidate, snapshot)
        if anyInvalid(features): record InvalidFeatures; continue
        score = DotNormalizedWeights(soul.profile, features)
        valid.add({candidate, score, features})
    if valid.empty: return NoAction(with explicit reasons)
    chosen = SelectWithOwnCommitmentRules(valid, currentAction)
    return chosen and decisionTrace
```

“火球”与“火球打敌人 A、由左手施放”是不同粒度。最小产品可以先选技能+目标，再由执行器确定一只合法手；当左右手可达性、损坏、占用会影响战术结果时，应把执行方案也纳入候选或反馈选择失败原因。

范围不符时可生成“移动到可施放位置后使用”的复合意图，但其接近时间、路径风险与是否可达必须参与评价。不能把远处的爪击标为当前可施放，再让执行器无条件冲过去。

## 统一单位，再体现人格

独立定义四项 [0,1] 特征：O 攻势收益、S 生存收益、C 控制/保护收益、E 资源经济性。分数：

```text
U(a) = wO*O(a) + wS*S(a) + wC*C(a) + wE*E(a)
w >= 0; sum(w) = 1
```

健康恢复与敌人伤害不是同一个数值，但都可以通过各自尺度/曲线映射到收益特征。例如 `expectedDamage / damageReference` 归一化后截到 1，资源经济性用 `1 - normalizedCost`；参考尺度需要统一，不能对每个技能分别归一化到自己的最大值，否则低伤害技能也总显得“满分”。截断会丢失超出参考值的差异，需要在数值跨度增大时调整尺度。

命中概率可以来自当前视线、距离、目标运动与有记录的估计。`expectedDamage = pHit * damageIfHit` 是构造模型；若没有可信概率，应保存 Unknown/置信度并使用明确的保守先验，而不是把任意数包装成预测模型。

未知信息与不合法不同：没看见敌人生命可以用记忆估计；缺施法手则直接拒绝。硬条件不要放进加权求和，否则高伤害分数可能“补偿”零资源或非法目标。

## 同一肉体，不同灵魂：构造算例

假设四项特征已针对同一个战斗快照计算，所有列均是我们设定的演算值：

| 行动 | O | S | C | E |
| --- | ---: | ---: | ---: | ---: |
| 爪击 | 0.85 | 0.25 | 0.10 | 0.90 |
| 灵魂弹 | 0.65 | 0.65 | 0.50 | 0.35 |
| 灵魂盾 | 0.10 | 0.95 | 0.35 | 0.80 |
| 撤退 | 0.00 | 1.00 | 0.05 | 0.70 |

| 灵魂偏好，顺序 O/S/C/E | 爪击 | 灵魂弹 | 灵魂盾 | 撤退 | 选择 |
| --- | ---: | ---: | ---: | ---: | --- |
| 好战 (0.70/0.10/0.10/0.10) | 0.7200 | 0.6050 | 0.2800 | 0.1750 | 爪击 |
| 谨慎 (0.15/0.60/0.10/0.15) | 0.4225 | 0.5900 | 0.7400 | 0.7100 | 灵魂盾 |
| 控制 (0.25/0.20/0.45/0.10) | 0.3975 | 0.5525 | 0.4525 | 0.2925 | 灵魂弹 |

这不是所有情境的恒定行动分数。真实系统每次基于快照重算特征。示意只让人看清同一肉体与同一情境下的偏好区别。没有爪时爪击从合法集合移除，好战灵魂改用当前最有价值的剩余行动；灵魂能量不足时不能凭偏好继续施法。

## 避免每帧改主意

我们采用独立滞后规则：旧行动仍合法且可比较时，新行动必须满足 `Unew > Uold + switchMargin`；例如 Uold=0.60、margin=0.08，0.65 不切换、0.69 可切换。Margin 是教学值。

执行中的不可中断窗口先由 11 管理；紧急事件按明确权限突破，不能因一帧分数稍高就取消每次前摇。需要比较旧行动剩余价值，而不是其启动时的过期评分。旧方案不合法时，不受惯性保护。

感知/评分按固定调度与事件触发执行，不需与每根骨头同频。角色动画仍可逐帧更新；人体/灵魂变化、目标死亡和通道释放可以触发再评价。具体频率是性能与反应速度选择，未提供默认游戏帧率。

## 经验反馈与策略评估

最初用可解释规则足够；等有真实反馈再加入学习。独立胜率估计可以保存成功数 s 和失败数 f，使用 `p=(s+1)/(s+f+2)`；这是带先验的二项估计，只适用于定义清楚且近似同类的尝试。某情境 3 成功/1 失败得到 4/6≈0.667，而不是保证下一次有 66.7% 命中。

部件断裂、目标消失、资源冲突不应全算“技能命中失败”；它们先归为执行故障或环境变化。情境键需要包含攻击方式、距离段、目标运动及肉体能力特征，不能按永久身体 ID 分裂全部经验，也不能无条件把旧身体的命中经验套到新身体。

比较两种灵魂策略时固定敌人、地图、肉体和种子集合，观察成功率、受到伤害、资源成本、目标完成度、非法请求次数和换动作频率。不要只以 DPS（Damage Per Second，每秒伤害）评判保护型灵魂。权重表达偏好；测试指标检验行为是否符合这种偏好。

## 候选规模与调试

N 技能 × T 目标 × P 执行部件组合可能迅速变大。先按权限、技能条件、已知目标和距离剔除，再枚举有区别的方案；多个效果等价的手可以由执行器挑选。若限制目标数量或每帧预算，记录被裁剪数量，并明确结果只是该候选集最优，不保证全局最优。

决策轨迹至少包含快照版本、灵魂配置、候选来源、拒绝原因、四项特征、总分、当前承诺和最终方案。这样能回答“为什么这次用右手”“为什么宁愿撤退”。

未做：没有真实战斗数据、AI 对局或用户项目实现。风险：特征归一化、情境预测和人格权重决定实际效果；算术通过不证明 AI 强度或趣味性。原游戏 AI 策略没有恢复。
