## 端到端构造场景

| 场景 | 前置与操作 | 应有结果 |
| --- | --- | --- |
| 同肉体换灵魂 | 相同肉体、认知与行动特征，换好战/谨慎/控制权重 | 按 14 算例分别选爪击、盾、灵魂弹；不改变伤口 |
| 无手但有灵魂技能 | 爪部为 0，纯意识法术资源充足 | 身体爪击不可用，纯意识法术可进入合法集合 |
| 灵魂记得火球但无施法手 | 符印手势模式需要特定能力，部件损坏 | 技能知识保留，报告该执行模式缺提供者 |
| 资源不足 | 灵魂能量 20，灵魂弹需 30，盾需 15 | 弹拒绝，盾可用；身体技能不因灵魂能量为 0 自动消失 |
| 多手选择 | 左前手占用，右前手可达，后手无符印能力 | 符印动作选择右前手并预约其通道 |
| 准备中断肢 | 方案依赖 P2，P2 功能失效 | 按政策取消，释放未消费预约，不发出旧效果 |
| 无关部件变化 | 攻击依赖 P2，装饰 P3 变化 | 不单凭任何版本变化就取消；核对真实依赖与映射 |
| 数组重排 | P1 删除，P2 从索引 1 变为 0 | 永久 P2 身份保持；旧索引不得直接继续使用 |
| 重复事件 | 同一 actionId/effect ordinal 被回调两次 | 本地效果提交一次，重复事件有诊断 |
| 多段技能 | 同一 actionId 的 ordinal 0、1 | 按定义分别提交，不能被错误去重为一次 |
| 换控制者 | 旧 generation=4，新 generation=5 | 新请求用 5，旧 4 的未提交请求不再有效 |
| 换身体保留灵魂 | 同魂进入不同肉体 | 重算身体执行方案，灵魂知识/能量按所有权保持 |
| AI 犹豫 | 旧分 0.60、margin=0.08，新分 0.65/0.69 | 分别保持/允许切换；非法旧动作不受保护 |
| 无合法行动 | 无爪、无有效移动模式、灵魂能量不足 | 明确 NoAction 及拒绝原因，不假造攻击 |

## 第一轮实现建议

这不是现在要求修改用户项目。没有项目路径、已有能力/存档/AI 契约时，只交付可评审的方案。

1. 用稳定部件身份建能力提供者表，能列出健康、损坏、断开和占用原因。
2. 做一个共用技能执行器，先支持单爪击和纯意识法术，校验、预约、提交、取消都有结果。
3. 给两种灵魂不同技能和评分偏好，用相同肉体对照行为；再用同一灵魂更换肉体。
4. 加入断肢/部件失效，并测试旧方案、资源和事件的清理。
5. 在已有稳定行动反馈后评估复杂战术、多手协同和经验学习。

如果你的游戏已有以上任一层，应优先适配现有契约，而非照文档重写全部结构。多人权威、战斗中任意存档、多灵魂共体与离体状态需要另外确认玩法和成本，当前文档没有把它们列为必须实现项。
