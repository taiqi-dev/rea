# Spore：技能选肢体、逐肢体姿态与编辑附着

本轮问题是：多条肢体怎样被技能动作选中；手和腿怎样获得具体姿态；鼠标滚轮改变躯干大小时，附着的部件怎样移动并影响后续姿态。范围仍是登陆后的生物阶段，沿用[前篇](01-body-parts-and-poses.md)的目标与身份，没有启动游戏或读取存档。

时间锚点：2026-10-11 20:32:52 PDT，America/Los_Angeles，对应 2026-10-12 03:32:52 UTC。

## 必须拆开的管理对象

“部件提供攻击能力”“播放哪种攻击动作”“这次哪只手参与”“何时命中并扣血”是不同问题。把它们合并为一条 limb.PlayAttack()，会丢失多肢体选择、整体姿态与伤害结算之间的边界。

社区 SDK 声明中，`cCreatureBase` 分别暴露 `PlayAbility(abilityIndex)` 与 `PlayAnimation(animationID, blockIndex, ...)`，而 `cCreatureAbility` 同时记录伤害、动画 ID、范围和冷却等数据。这是分开追查的依据，不是已恢复的调用链，也没有证明每条肢体各有独立技能实例。[cCreatureBase](https://modapi-docs.sporecommunity.com/class_simulator_1_1c_creature_base.html)、[cCreatureAbility](https://modapi-docs.sporecommunity.com/class_simulator_1_1c_creature_ability.html)

| 对象 | 本轮要回答的问题 | 当前证据边界 |
| --- | --- | --- |
| 部件能力属性 | 哪些部件贡献攻击、跳跃或社交能力，怎样汇总等级 | 本机有能力名称；精确汇总算法未知 |
| 技能实例 | 冷却、范围、目标、伤害是什么 | 社区公开字段，不是本机执行证据 |
| 动画条目 | 选择哪个动作资源、哪种体型适用 | 社区格式文档提供入口 |
| 身体参与集合 | 动的是哪些手、脚、嘴及对应骨链 | 公开动画设计支持语义选择与变体 |
| 每帧姿态目标 | 末端位置、方向、局部变形怎样随时间变 | 公开设计与前篇解释，实际参数未知 |
| 命中处理 | 动画事件怎样进入命中或扣血逻辑 | 本轮未恢复实际处理函数 |

**独立构造例子：**一只生物有两只装饰手和两只可攻击手。我们可以让装饰手参与表情动作，却只让攻击手进入攻击候选。它的伤害还可以由生物级技能数据结算。另一种自研玩法也可以按手分别结算，但需要独立定义，不能由画面里出现四只手推出。

## 原系统怎样选中具体身体

公开论文的选择器将能力、空间和层级条件求交，可选零至多个身体。标记为单个变体的通道一次只作用于其中一个，具体变体由游戏侧选择；同一变体组可让手与对应肩协同。绑定还会检查体型分支，姿态通道的混合归属按自由度管理。[动画论文 §3.1.1、§3.2.3、§4.1](https://www.chrishecker.com/images/c/cb/Sporeanim-siggraph08.pdf)

因此这里有三种容易混淆的“选择”：

1. 条件过滤得到候选身体集合。
2. 动作的身体变体确定此次参与者或组合。
3. 动画资源的 choice 确定播放哪个动作条目。

社区 TLSA 格式文档描述了带概率的 choice；SDK 的 `pChoice` 也用于动画 choice。它不能直接当作身体变体索引，不能据此写成“随机挑一只最高级手”。[TLSA 格式说明](https://github.com/Spore-Community/SporeModder-FX/wiki/How-to%3A-use-Spore-animations)、[AnimatedCreature](https://modapi-docs.sporecommunity.com/class_anim_1_1_animated_creature.html)

**独立选择演算：**自己给四只手编号 LF、RF、LB、RB，分别表示左右两侧的前后手。定义 LF、RF、RB 有攻击角色，LB 只有抓握角色。则：

```text
攻击手                  → {LF, RF, RB}
攻击手 ∩ 前排           → {LF, RF}
攻击手 ∩ 前排 ∩ 左侧    → {LF}
```

如果动作需要一只手，自研规则可以再按目标距离、可达性或占用状态选一个；如果需要两手协同，则需要明确配对约束。这个候选表和策略由我们独立定义，未证明 Spore 的 Strike 动作使用相同过滤。

**独立协同例子：**选中 RF 后，沿 RF 的父链找到它的肩部，让“手的攻击目标”和“对应肩的辅助动作”共享一次选择。否则分别从四手、四肩各选一次，可能得到手与肩不匹配的组合。这里不要求手和肩播放相同曲线；共享参与者关系与共享动作内容是两回事。

社区导出文档另有 Require channel、体型适配候选及动画事件说明：没有可选身体可以使候选失效，控制事件可以通知游戏命中时点。但事件发生和最终伤害如何结算还要追游戏逻辑，多个身体发出效果不等于多次扣血。[动画导出与事件文档](https://github.com/Spore-Community/SporeModder-FX/wiki/Exporting-creature-animations-from-Blender)

本机某个手部攻击是否选择最近手、最高能力手、随机手或所有手，仍未确认。不能把上述通用机制填成某个具体攻击的已知配置。

## 每条肢体的姿态怎样摆出来

可以用一个独立二维演算理解为什么“选择末端”还不等于“知道每个关节姿态”。设肩位于 `(0,0)`，手目标为 `(0.6,0)`，上下臂均长 `0.5 m`：

```text
肘 A = (0.3,  0.4)
肘 B = (0.3, -0.4)

肩到任一肘距离 = sqrt(0.3² + 0.4²) = 0.5 m
任一肘到手距离 = 0.5 m
```

两种肘位置都能满足骨长和手目标。独立实现还必须用参考弯曲方向、约束或姿态偏好选择结果。这里不是 Spore 求解器数值，也没有把两个固定长度关节的简单解法冒称为它的粒子求解器。

对身体分叉的情况，单独求每个末端还可能给共享父关节提出冲突要求。例如一个上臂分成两个前臂，两只手往不同方向伸，共享部分不能同时采用两套互不一致的姿态。自研实现需要按连接链统一协调，而不是每只手各挂一个互不知情的控制器。

腿也应区分正常走路与主动动作：公开资料将步态生成与非移动动作对脚的控制分开，随后一起形成姿态求解输入。[动画论文 §4.2–4.3](https://www.chrishecker.com/images/c/cb/Sporeanim-siggraph08.pdf)

**独立腿部例子：**六足行走时各脚按步态得到支撑或摆动目标；若自己的玩法要求一只前脚踢击，可以暂时给它主动目标，并重新安排其他脚支撑。是否停步、支撑资格如何更新、何时恢复，都必须定义。原游戏的具体踢击配置与切换方式未恢复。

## 鼠标交互与身体变宽

用户报告的现象是：滚轮让躯干变宽，左右部件随之分开。本轮没有自行观察这个画面，也没有测量它发生时部件是否变大、转向或改变骨长。

社区 `EditorRigblock` 公开声明包括位置、表面法线、基础朝向、用户朝向、父子节点、对称伙伴、连接器与 pinning 类型，且总朝向由基础和用户朝向组合。它为“附着与旋转不是只有世界坐标”提供研究入口，不证明具体增粗更新公式。[EditorRigblock 声明](https://modapi-docs.sporecommunity.com/class_editors_1_1_editor_rigblock.html)

社区属性字典还记录了滚轮操作结束相关的 timeout/距离、脊柱缩放邻居影响数量，以及肢体长度、角度、对称平面对齐等调节项。原游戏本机配置值、拖拽求解及撤销事务顺序均未解码。[属性字典中的 editor/tuning 项](https://github.com/Spore-Community/SporeModder-FX/blob/master/Documentation/properties.txt)

### 两条都能产生“左右分开”的路线

**路线 A：继承父节点缩放。**在独立模型中令 `M_child = M_parent(scale) × M_local`。父节点横向放大，子节点局部横向偏移也放大。若子节点完整继承尺度，肢体本身也可能变宽或变长；是否补偿需要另外处理。

**路线 B：形状相关的附着点。**保留肢体自身尺度，按新的躯干表面重新计算肩/髋的安装位置。再把安装点以外的局部姿态应用到那里，肢体可以只移开而不整体变大。

仅凭用户描述，两条路线都能解释部分现象；社区的表面法线与 pinning 字段使路线 B 值得继续追查，但没有排除路线 A、混合方式或其他表面映射。

### 独立圆截面模型

为演示路线 B，独立选择一个圆形横截面，中心 C、半径 r、固定附着方向 n、表面偏移 d：

```text
P_attach = C + (r + d) × n
左侧 n = (-1,0,0)，右侧 n = (1,0,0)
```

设 `d=0`，半径从 `0.4 m` 增到 `0.7 m`。左右安装点分别向外移动 `0.3 m`，两点间距从 `0.8 m` 变为 `1.4 m`。并没有要求上下臂长度一起增加。

要处理曲线躯干，自己的系统可以保存“脊柱上的参数位置、截面方向、安装偏移、用户旋转、对称伙伴”，随形状重算局部安装坐标系。实际 Spore 是否保存这些参数、使用表面投影还是其他坐标表示，仍未知。

### 附着移动怎样影响姿态

**独立参考姿态更新例子：**肩从 x=-0.4 移到 x=-0.7，保持上臂、前臂的局部骨长和参考弯曲，那么手的参考位置也会跟随移动。如果随后要求手到固定世界目标，求解器要从新的肩位置重新求肘部；此时手不一定跟肩平移同样的距离。

如果要求脚继续固定在地面，髋部外移就需要腿重新弯曲；如果此时是编辑参考姿态模式，脚也可以随局部链移动。这是两种约束模式，不能把编辑时外移、行走时脚不滑、以及攻击时末端到目标混为一个规则。

**独立交互流程建议：**命中部件或手柄 → 进入拖拽/滚轮操作 → 修改局部形状或姿态参数 → 更新受影响安装点和对称伙伴 → 更新参考数据与预览 → 操作结束时保存一次编辑事务。改变体型后重新建立哪些动画缓存也应有明确失效规则。此流程为自己的编辑器规格；没有宣称原程序严格按该顺序执行或采用同样撤销粒度。
