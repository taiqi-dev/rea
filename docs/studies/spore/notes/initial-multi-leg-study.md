# Spore 陆地生物编辑与多足行走研究

本研究限定于细胞阶段之后、部落阶段之前的陆地生物，以及生物编辑后多对足肢如何循环运动。核心问题可以分成两层：步态时序决定各脚的运动目标，骨架求解决定身体和关节如何到达目标。公开技术资料能够解释设计；本机静态线索能够定位后续入口，两者尚未通过函数调用链逐项对齐。

研究时间锚点为 2026-10-11 17:16:27 PDT，America/Los_Angeles，对应 2026-10-12 00:16:27 UTC。没有修改游戏安装文件、读取私人存档、启动游戏或附加进程。以下教学公式由我们独立定义，不能当作恢复出的游戏源代码。

续篇：[其他身体部件与姿态](../01-body-parts-and-poses.md)，拆分身体造型、参考姿态、动作目标和最终求解姿态，并补充本机部件与变形通道线索。

进一步追踪：[技能选肢体、逐肢体姿态与编辑附着](../02-skill-selection-and-editor-attachments.md)，区分技能、动画条目和身体变体，并解释身体加粗后附着点分开的可行模型与尚未恢复的原游戏细节。

## 开发团队公开的设计

开发团队的论文第 4.2 节描述：按近似腿长分组，用小整数比协调组间周期频率；为脚分配着地占比与周期触发偏移；抬脚轨迹随腿长适配，髋部同时运动。速度驱动参数插值，组内 1～6 只脚使用动画师配置，7 只以上程序生成，还支持不同组采用不同步态。第 4.3 节描述粒子约束式 IK，先求脊柱、再固定脊柱求肢体。[SIGGRAPH 2008 论文，第 6～9 页](https://www.chrishecker.com/images/c/cb/Sporeanim-siggraph08.pdf)

IK (Inverse Kinematics，逆向运动学) 的意思是：已知脚要到哪里，再求关节姿势。“什么时候抬脚”和“膝盖怎样弯曲”是两个问题，仅有 IK 不能自行规定多足的循环时序。

编辑器中的部件变形也有自己的机制。开发团队的 Rigblocks 资料说明，玩家的拖动手柄控制参数化变形轨迹，组合结果可以烘焙。这是形状编辑的技术入口；它本身不能证明行走步态的实现。[Rigblocks 论文](https://www.cs.cmu.edu/~ajw/s2007/0248-Rigblocks.pdf)

## 独立教学模型

下面构造一个平地、匀速、等长六足模型，只用于解释时序与落脚关系。它不是 Spore 的精确相位表、足部轨迹或 IK 实现。前、中、后三对腿分别编号为 1、2、3，左右分别为 L、R。

### 一个周期与每只脚的偏移

定义整体频率 `f = 1 Hz`，周期 `T = 1 s`，每只脚的着地占比 `β = 0.65`。定义局部相位 0 为落脚后的支撑开始。选择两组交替的偏移：

| 脚 | 偏移 δ |
| --- | ---: |
| L1、R2、L3 | 0 |
| R1、L2、R3 | 0.5 |

局部相位为：

```text
p_i(t) = frac(f × t − δ_i)
p_i < β       → 支撑
p_i ≥ β       → 抬脚前移
```

在 `t = 0.28 s`，第一组局部相位为 0.28，着地；第二组为 0.78，抬起。到 `t = 0.78 s`，两组交换角色。由于 β 大于 0.5，每周期存在两组同时支撑的重叠区间。这里没有用“六条腿六套独立时钟”，而是共享周期、为每只脚指定偏移。

如果希望各脚依次抬起，可以另选 `δ_i = i/N`。这仅是另一种教学规则：增加腿数时重新定义偏移表，不需要按每种腿数编写一个完整动作。这些偏移方案是否与 Spore 对特定生物采用的规则相同，仍需函数和运行证据。

### 支撑脚固定在地面

定义身体在世界中沿 x 轴移动，脚在支撑期的世界落脚位置 `A_i` 保持固定。相对于身体的脚目标为：

```text
F_local = inverse(BodyWorldTransform) × A_i
```

因此身体向前走，脚在身体坐标里向后扫；脚的世界位置并没有后退。这个坐标关系解释了为什么一个动画看起来“腿在往后摆”，却可以同时保持着地不滑。

例如身体速度为 `0.8 m/s`，一个脚支撑 `0.65 s`，身体移动 `0.52 m`；如果脚的世界位置固定，它相对身体也必须后移 `0.52 m`。让身体仍以 `0.8 m/s` 前进、却让脚相对身体只后移 `0.2 m`，就会产生约 `0.32 m` 的滑动误差。这是构造演算，不是本机游戏测量。

动态图中镜头跟着身体移动。地面参照点与着地脚以相同速度后移，空心脚表示摆动期；关节折线仅示意肢体连接，并没有运行 Spore 的求解器。

### 抬脚与下次落脚

自研模型可以在抬脚时确定前一次落脚点 A 和目标落脚点 B，将摆动进度归一化为 `u ∈ [0,1]`，独立选择：

```text
x(u) = lerp(A.x, B.x, 3u² − 2u³)
z(u) = groundHeight + H × sin(πu)
```

例如 `H = 0.12 m` 时，在 `u = 0.5` 脚抬高 0.12 m，在两个端点高度归零。这条轨迹只说明“离地、前移、落地”的结构。用于实际产品时还需要处理触地速度连续性、地形和目标不可达，不能把这条示意曲线直接当成完整步态控制器。

### 身体转弯和不同腿长

如果以后独立实现自己的系统，每只脚的运动输入应考虑它位于身体什么位置。刚体近似下，髋部速度可以写成 `v_i = v_body + ω × r_i`。转弯时外侧与内侧的目标不同；仅把所有腿的摆幅设成同一个值容易让脚滑动。这是自研建模建议，不是恢复出的 Spore 转弯公式。

长短腿混合时，应显式记录每条肢体的长度、可达范围、静止姿势与有效支撑资格。不能仅根据编辑器中添加了多少肢体，就默认所有末端都能着地；也不能把“显示动作”自动解释成“每只脚的物理推进力决定了角色速度”。本机是否存在不参与支撑的脚，以及怎样判定，仍未确认。

下一次静态追踪可从 `dutyfactor`、`numfeet`、`gaitgroupkey` 的数据交叉引用开始，定位脚本解析、配置读取、参数插值和逐帧更新；先把资源类型与解析器对齐，再取步态参数。出现这些名称的函数必须通过调用者与实际运算确认职责，不能只按名称命名后宣称算法已恢复。

最小运行验证场景是同一种体型分别配置两、三、四对等长腿，再配置长短混合腿。固定匀速直线、加速、停步、原地转弯和斜坡场景，逐帧记录各脚触地/离地时间和世界落脚位置。这样才能区分相位偏移、参数插值、脚滑动与目标不可达，而不是仅凭“看起来像昆虫”判断算法。

## 实际验证与风险

已完成本机 EXE 身份、PE 布局与字符串定位，选定 package 索引范围检查，并复核 EXE 完整摘要一致。证据来自普通只读工具与公开论文，没有伪造 REA Evidence ID 或原游戏运行结果。独立示意已通过腿数切换、步态切换、周期拖动、320/736 px 横向溢出和减少动态效果检查；未发生页面脚本错误。

未做：没有原生函数反编译或游戏运行观察。当前会话没有 REA MCP 工具，仓库公共启动器报告编译运行文件缺失，常见已安装 CLI/provider 入口的有界检查未找到可用实例；本轮没有为研究任务安装分析引擎、改客户端设置或构建 REA。没有运行仓库构建和软件测试，因为没有修改生产代码。

风险：公开论文描述的是开发团队当时公开的系统，不能保证与这个 Steam EXE 的每个细节一致；字符串存在不证明路径执行；教学模型不验证真实游戏的参数和边界行为。后续自研代码应根据自己的需求独立编写，并使用自己制作或适当授权的资产。
