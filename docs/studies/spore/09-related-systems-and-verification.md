## 优先方向

| 顺序 | 系统与具体问题 | 可用入口 | 需要补什么 |
| --- | --- | --- | --- |
| 1 | 动作绑定与事件：四只手究竟选哪只；显示动作和一次伤害怎样关联 | 02/03 的选择器、能力/播放入口、事件格式 | 某个技能资源 → 通道 → 身体变体 → 事件调用链 |
| 2 | 特殊运动：无脚、不同腿长、分叉、原地转弯、突然停下 | 04/05 的步态与骨链边界 | 本机分组/可达判定、运动模式切换与连续过渡 |
| 3 | 编辑重建：身体加宽后附着、姿态、镜像、形变怎样同步 | 06、EditorRigblock 字段、滚轮调节词汇 | 输入处理者与表面/连接更新的实际顺序 |
| 4 | 生物皮肤脚本：环纹/斑点怎样区分躯干、腹部、关节和腿 | 07 的 SkinPaint 和形态坐标词汇 | DBPF 类型 → 脚本解析器 → 选定皮肤脚本及参数 |
| 5 | Epic 生成：资格与角色参数怎样连接 | 08 官方 CRG 条件、herd 字段、gait_epic | 原型读取、地图放置、参数写入和步态路由 |
| 6 | 能力聚合：多个同类部件怎样形成技能等级与属性 | 部件能力、cCreatureAbility、官方原型列 | 部件 → 物种统计 → 技能等级的聚合函数；不能猜求和/最大值 |
| 7 | 部件形变与动作：肌肉粗细、嘴开合、手掌姿态怎样叠加 | Rigblocks、deformChannel、morph weights | 编辑权重与动画权重混合、局部坐标与限值 |
| 8 | 生物内容持久化：配方怎样重新生成一致模型 | recipe/baking 公开入口、选定包结构 | 稳定 ID、随机种子、资产版本、缓存键与读档重建边界 |
| 9 | LOD 与性能：多足、分叉、表面花纹和远处动画怎样降成本 | 公开 baking/简化入口 | 本机降级策略、骨骼与 UV 保留规则、缓存时序和成本测量 |

建议先追 1–3：它们直接补齐“具体哪条肢体、怎样摆、编辑后怎样重新适配”。材质已有清楚的公开算法入口，优先选一款皮肤完整追踪，胜过扩大所有字符串扫描。Epic 优先确认自然生成调用链，避免把冒险编辑器缩放字段混进来。

## 行为验证矩阵

这些是后续验证方案，**尚未在原游戏执行**。当前不需要用户保持程序打开；只有进入具体逐帧观察时才需要选定场景。

| 场景 | 记录什么 | 能区分什么 |
| --- | --- | --- |
| 同体型 2/4/6/8 脚，直线匀速 | 各脚离地/落地时刻、世界落点 | 共享相位、支撑比、脚滑动 |
| 长短腿混合 | 分组频率、目标尺度、实际骨长 | 同组/异组、是否闲置短腿、是否拉伸 |
| 原地转弯和急停 | 角色角速度、逐脚轨迹、停步姿势 | 步态时钟、落点重规划、姿态过渡 |
| 同链分叉出两个末端 | 共享关节和目标残差 | 整体分叉求解或错误的逐链覆盖 |
| 四手中仅部分有攻击能力 | 选中节点、动画变体、伤害事件次数 | 能力资格与动画选择分离、事件是否独立 |
| 身体加宽，关节参考姿态保持 | 表面点、根节点、局部/世界旋转 | 跟随表面、全局缩放或其他附着机制 |
| 同皮肤配方，腿长/粗细不同 | 环纹数量、间距、区域边界 | 固定数量、物理密度或形态归一化 |
| 笔触跨关节与 UV 接缝 | 三维连续性、mip 下边缘 | 表面脚本、图集接缝与 padding |
| 快速连续编辑并等待烘焙 | 配方版本、完成顺序、最终模型 | 同步更新、后台缓存与旧结果覆盖 |
| 多局/读档前后 Epic | 物种身份、位置、大小、数量 | 内容池选择、生成分布与持久化 |

观察不能单独证明内部函数；静态调用链不能单独证明某场景实际执行。两者应以同一目标版本和选定生物配方对齐。

## 本轮实际验证

基础拆分轮曾用独立脚本检查 12 份 Markdown：UTF-8 可读取、没有替换字符、代码围栏闭合、所有相对文件链接指向现存文件。该轮索引为 README + 00–09 共 11 份；另有一份历史副本。后续新增 10–15 的检查见 [15 续查验证](15-soul-body-scenarios-and-validation.md)。早期两份教学可视化的浏览器检查仍见各自报告，续查没有修改或重新执行它们。

独立算例检查全部通过：14 项相位、双组支撑、支撑位移/滑动、摆动端点/高度/端点导数、跨周期事件顺序、自由/固定距离约束、双骨几何、加宽附着、重心 UV、Epic 资格和自研尺度；另检查五次 Hermite 的六个端点边界条件，以及历史摘要与首次时间锚点保留，共 16 项。这里检查数学关系与文档内容，不执行伪代码整套系统，不能称作原游戏算法测试。

未做：原游戏运行、反编译、资源解码、完整自研实现、生成概率统计、视觉像素对照或仓库生产测试。原因是本次交付为研究文档且分析 provider 尚不可用，不以安装/构建变更扩张授权。

风险：算例通过只证明我们写出的关系内部一致，不能证明任意身体的求解收敛、视觉质量或与原作相同。未知列表在每个模块保留，不以伪代码篇幅掩盖证据缺口。
